# Efficient Memory Management for Large Language Model Serving with PagedAttention
<!-- slug: paged-attention · type: paper · source: https://arxiv.org/abs/2309.06180 -->

**Core Insight.** During autoregressive inference, the KV cache for each request grows dynamically and existing systems pre-allocate a contiguous maximum-length buffer per request, wasting up to 60–80% of KV memory to internal fragmentation and over-reservation. PagedAttention applies OS virtual-memory paging to KV cache: fixed-size blocks (~16 tokens/block) allocated on demand from a pool, with a block table per sequence mapping logical to physical slots.

**Guideline.** PagedAttention is an **inference-serving** technique with no training analog — include it in course material explicitly as a contrast to training-time attention kernels (FA1/FA2/FA3), so learners understand that KV cache memory management is a different problem from activation memory management.

## Technical Details
- **Problem**: prior systems (FasterTransformer, Orca) allocate a contiguous KV buffer of `max_seq_len × d_model × 2 × num_layers × 2 (K+V)` bytes per request at request start. For a 1024-token max context on a 13B model, this is ~1.7 GB per request. Actual usage at any given step is far less (the sequence is still short); the unused suffix is wasted. Internal fragmentation + external fragmentation (requests of different lengths cannot share space) wastes 60–80% of KV HBM.
- **PagedAttention**: inspired by OS virtual memory. KV cache divided into fixed-size **physical blocks** (~16 tokens/block, stored contiguously). Each request has a **block table** mapping logical block index → physical block index. As the sequence grows, new physical blocks are allocated from the pool. Blocks can be **shared across requests** (e.g., system-prompt KV blocks shared across all requests using that prompt — prefix caching).
- **Measured result**: **near-zero KV waste** (fragmentation ≤ 4% because the last block per sequence is at most 15/16 full). Throughput improvement: **2–4× vs. FasterTransformer and Orca** at the same latency.
- **KV sharing**: PagedAttention enables copy-on-write block sharing for beam search and parallel sampling — instead of duplicating the full KV prefix per beam, beams share physical blocks until they diverge. This collapses beam-search KV memory from O(beam_width × length) to O(length + small diverged suffix).
- **Why inference-only**: PagedAttention addresses the **KV cache** — the accumulated K and V tensors from all prior tokens in autoregressive decoding. Training does not accumulate a KV cache; it runs a full forward pass over the entire training sequence and backpropagates. The activation memory saved by FA1/FA2 (eliminating the score matrix) is a training concern; KV page management is a serving concern.
- **Authors**: Woosuk Kwon, Zhuohan Li, Siyuan Zhuang, Ying Sheng, Lianmin Zheng, Cody Hao Yu, Joseph E. Gonzalez, Hao Zhang, Ion Stoica.
- **Training-memory angle:** PagedAttention does **not** reduce training memory — it is purely an inference serving optimization. Its presence here is contrastive: understanding that "KV cache" means something fundamentally different in serving (persisted across decoding steps) vs. training (ephemeral attention weights computed and discarded each forward pass). In training, the KV tensors for a batch are not accumulated; in serving, they are. This distinction is a common confusion point when learners see KV-cache optimizations discussed alongside attention kernel optimizations.
