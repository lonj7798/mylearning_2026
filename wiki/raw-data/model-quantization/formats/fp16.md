# FP16 (IEEE-754 binary16, "half precision")
- **Core Insight:** IEEE binary16 packs 5 exponent bits and 10 mantissa bits into 16 bits, giving high *relative* precision (ε ≈ 10^{−3}) but a tiny dynamic range (6e−5 to 6.5e4) that forces deep-learning users to apply explicit loss scaling before backward to keep gradients representable.
- **Guideline:** Prefer BF16 over FP16 for transformer training; use FP16 only when you specifically need its higher mantissa precision (small models, embedded inference) or for accelerators that lack BF16 (older NVIDIA pre-Ampere).
- **Authors:** IEEE-754 (2008 revision introduced binary16 as a storage format; 2019 expanded usage)
- **Year:** 2008 (IEEE); 2014 (NVIDIA Pascal hardware support); 2017 (mixed-precision training recipe formalized — Micikevicius et al.)
- **URL:** https://arxiv.org/abs/1710.03740 (Micikevicius et al., "Mixed Precision Training", ICLR 2018); IEEE 754-2008 / 754-2019
- **Relevant topics:** FP16, mixed-precision, loss scaling, half-precision, overflow

## Abstract
IEEE binary16 — "FP16" or "half" — was added to IEEE-754 in 2008 as a 16-bit storage format. NVIDIA Pascal (2016) gave it hardware support; Volta (2017) introduced FP16 tensor cores. The Micikevicius 2017 "Mixed Precision Training" paper made FP16 + FP32 mixed precision the dominant training recipe of 2017–2020. The format's 5-bit exponent gives a max finite value of 65504 — small enough that loss values, attention scores, and large gradients routinely overflow; mitigated by loss scaling (multiply loss by 2^k pre-backward, divide gradients by 2^k post-backward). BF16's wider exponent has since displaced FP16 for new training runs, but FP16 remains common in inference, mobile, and as a fallback on pre-Ampere hardware.

## Key Contributions
- IEEE-standard 16-bit floating-point format.
- Enabled the first round of deep-learning mixed-precision training (Micikevicius 2017).
- Drove tensor-core hardware design across NVIDIA Volta/Turing/Ampere.
- Established the loss-scaling pattern subsequently adopted by FP8 / MXFP / NVFP4 training.

## Technical Details

### Bit layout
| Field | Bits | Width |
|-------|------|-------|
| sign s | 15 | 1 |
| exponent e | 14..10 | 5 |
| mantissa m | 9..0 | 10 |

- **Exponent bias:** 15. Unbiased E = e − 15.
- **Normal:** 1 ≤ e ≤ 30 → value = (−1)^s · (1 + m/2^{10}) · 2^{e−15}
- **Subnormal:** e = 0, m ≠ 0 → value = (−1)^s · (m/2^{10}) · 2^{−14}
- **Zero:** e = 0, m = 0 → ±0
- **±∞:** e = 31, m = 0
- **NaN:** e = 31, m ≠ 0

### Key constants
- Smallest positive normal: 2^{−14} ≈ 6.10e−5
- Smallest positive subnormal: 2^{−24} ≈ 5.96e−8
- Largest finite: (2 − 2^{−10}) · 2^{15} = 65504
- Machine epsilon ε = 2^{−10} ≈ 9.77e−4
- Total representable values: ~63500 (excluding NaN encodings)

### Dynamic range vs BF16
| | FP16 | BF16 |
|---|---|---|
| Exponent bits | 5 | 8 |
| Max finite | 65504 | 3.39e+38 |
| Min positive normal | 6.10e−5 | 1.18e−38 |
| Dynamic range | ~10^{9} | ~10^{77} |
| Mantissa ε | 9.77e−4 | 7.81e−3 |

FP16 has **~8× better relative precision** but **10^{68}× less dynamic range** than BF16.

### Failure modes in training
1. **Loss overflow**: cross-entropy on long sequences can exceed 65504 → NaN.
2. **Attention-score overflow**: softmax(QK^T/√d) inputs can exceed 65504 in deep layers.
3. **Gradient underflow**: most weight gradients are O(10^{−5}) to O(10^{−10}); the small ones round to 0 in FP16 → no update.
4. **Activation underflow**: small post-softmax probabilities round to 0 → information loss.

### Mixed-precision recipe (Micikevicius 2017)
- **FP32 master copy of weights**; FP16 working copy for matmul.
- Forward: FP16 activations, FP16 weights, FP32 accumulator in tensor core.
- Backward: FP16 gradients (with loss scaling).
- Loss scaling: `loss_scaled = loss × S` (typically S = 1024 to 65536, dynamically adjusted to avoid NaN); `grad ← grad_scaled / S` before optimizer step.
- Optimizer update applied to FP32 master copy.

### Dynamic loss scaling
Standard pattern (NVIDIA Apex, PyTorch AMP):
- Start with S = 2^{16}.
- If gradient contains NaN/Inf → halve S, skip optimizer step.
- Else if S unchanged for K steps → double S.
- Maintains S near the largest power-of-2 that keeps the smallest representable gradient above 2^{−14}.

### Hardware support
- **NVIDIA Pascal P100** (2016): FP16 storage + FP32 compute.
- **NVIDIA Volta V100** (2017): first FP16 tensor cores, 125 TFLOPS.
- **NVIDIA Turing T4, Ampere, Hopper**: FP16 + BF16 tensor cores.
- **AMD MI200+, Apple Neural Engine, Cerebras, Graphcore**: FP16 supported alongside BF16.

### Use cases where FP16 still wins
- **Inference on edge / mobile** (Apple Neural Engine, Qualcomm Hexagon): FP16 is the native compute precision; loss-scaling doesn't apply at inference time.
- **Small-model fine-tuning** where mantissa precision matters more than range.
- **Pre-Ampere NVIDIA hardware** (V100, T4) without BF16 tensor cores.
- **Some inference engines** (ONNX Runtime, TensorRT) default to FP16 weights for compatibility.
