# Algorithm crosswalk: which RL algorithm, for which domain, and why
- **Core Insight:** Every lab recipe carded here uses a critic-free group-baseline method (GRPO or a modification, CISPO, or Kimi's K1.5 mirror-descent objective) for RL at scale; PPO with a value model appears in Tülu 3 RLVR, InstructGPT RLHF, Search-R1 and VAPO. Most labs state no reason for picking their base algorithm; stated reasons attach to the modifications (KL removal, clip-higher, token-level loss, IS-weight clipping, sequence masking), and each is tied to a specific observed failure.
- **Guideline:** When choosing an algorithm for a domain, start from the failure you expect (dropped low-probability tokens, length bias, MoE routing drift, stale negatives, slow resampling in multi-turn rollouts) and pick the modification whose source measured that failure; do not cite a lab's base-algorithm choice as evidence unless the card records a reason.
- **Source type:** crosswalk of existing cards; ch-40 excerpts for [[dapo]], [[gspo]], [[vapo]] (`wiki/courses/llm-training/ch-40/excerpts/`)

## Domain → algorithm pattern
- **Instruction following:** verifier-reward RL inside a group-baseline method (GRPO in [[ifbench]], [[glm-4-5]]; joint RLVR in [[kimi-k2]], [[nemotron-ultra-recipe]]) or PPO ([[rlvr-tulu3]]), plus a model/rubric reward for quality ([[ifbench]] App. E, [[minimax-m1]]); DPO lost to GRPO on the same data ([[ifbench]]).
- **Math/code (verifiable):** GRPO with DAPO-style changes (no KL, clip-higher, token-level loss, zero-variance filtering) ([[magistral]], [[olmo-3]], [[glm-4-5]]); CISPO when many off-policy updates per batch ([[minimax-m1]]); VAPO shows a warmed-up value model can beat DAPO ([[vapo]]).
- **Search / agentic multi-turn:** GRPO-family with tool-output masking ([[deepresearcher]], [[asearcher]], [[websailor-tongyi-deepresearch]]); PPO when GRPO collapses ([[search-r1]]); throughput fixes replace resampling (DUPO) and async rollout ([[asearcher]]); step-level credit via GiGPO ([[gigpo-verl-agent]]).
- **SWE:** group-wise outcome RL on test results in sandboxes, asynchronous infra ([[glm-4-5]], [[kimi-k2]], [[minimax-m1]]); no card states an SWE-specific algorithm choice or reason.
- **Chat / non-verifiable preference:** DPO stage before RL ([[tulu-3]], [[olmo-3]]); RL against GenRM/rubric rewards ([[nemotron-ultra-recipe]], [[deepseek-v3.1]], [[minimax-m1]], [[rubrics-as-rewards]]); RLOO/REINFORCE++ are the RM-RLHF options with measured gains but no lab adoption recorded ([[rloo]], [[reinforce-plus-plus]]).
- **Large MoE:** routing-aware fixes on top of GRPO (Keep Routing in [[deepseek-v3.1]]; frozen router in [[nemotron-ultra-recipe]]) or sequence-level ratios ([[gspo]]); CISPO on the 456B hybrid ([[minimax-m1]]).
