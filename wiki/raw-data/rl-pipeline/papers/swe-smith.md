# SWE-smith: Scaling Data for Software Engineering Agents
- **Core Insight:** Reversing the usual direction — start from a working repository, synthesize a bug, keep it only if it breaks at least one passing test — yields 50,137 validated task instances from 128 Python repositories for about $1,360 and 295 GB of environments, where the authors estimate 50–150 TB for a SWE-bench-style build of the same count (§2.2, Tables 1–2); the reference answer is the reverse of the bug patch, and the failing tests are the grader.
- **Guideline:** When SWE tasks are scarce, build one execution environment per repository and synthesize many bugs inside it, validating each by fail-to-pass tests, and prefer PR-mirror, procedural or LM-rewrite bugs over LM-modify bugs, because at 1,000 instances each a 7B student reached 9.2 / 8.6 / 8.8% on SWE-bench Verified versus 5.7% for LM-modify (Table 4); do not filter tasks by estimated difficulty, because training on difficulty levels 2/4/6/8 gave 12.4 / 10.8 / 13.6 / 12.2% with no clear trend (§4.1).

## Summary
SWE-smith installs a repository once, then generates candidate bugs with four strategies, runs the test suite (2-minute cap) and keeps candidates that turn at least one passing test into a failing one. Each instance records FAIL_TO_PASS and PASS_TO_PASS tests (§A.1). Issue text is generated by an LM. The data is used here for SFT (5,016 Claude 3.7 Sonnet trajectories → SWE-agent-LM-32B, 40.2% pass@1 on SWE-bench Verified), not for RL, but the instance format (repo image + bug + F2P tests) is an RL task specification.

## Key Contributions
- Four bug strategies with per-strategy yield and cost (Table 1).
- Environment sharing per repository: 295 GB vs an estimated 50–150 TB (Table 2, §2.2).
- Ablations on bug strategy, issue text, difficulty, repository count and repository specialization (§4.1).

## Technical Details
**Strategies and yield (Table 1).**

| Strategy | Yield | Instances | Cost/candidate |
|---|---|---|---|
| LM Modify (o3-mini edits a function) | 56.0% | 17,887 | 0.38¢ |
| LM Rewrite (re-implement from signature/docstring) | 35.0% | 4,173 | 3.93¢ |
| Procedural (13 AST transforms, Table 8) | 40.2% | 15,641 | 0.00¢ |
| Combine (merge validated bugs in a file/module) | 96.9% | 10,092 | 0.00¢ |
| PR Mirror (LM undoes a real PR) | 33.8% | 2,344 | 5.53¢ |
| Total | 50.1% | 50,137 | 2.32¢ |

**Issue text (Table 5, 600 PR-mirror instances).** Original 7.8%, LM-generated 7.7%, F2P-test-as-issue 7.3%, fixed template 6.4%; test-based issues led the model to skip writing reproduction scripts.

**Difficulty.** Expert resolve rate 58.6% easy / 41.0% medium / 17.0% hard; downstream effect of difficulty level not monotonic (§4.1).

**Repositories (Fig. 5).** Performance grows roughly logarithmically with repository count (4, 25, 50, 100 repos at 700 trajectories each); values only in the figure.

**Agent behavior (§4.2).** Over 25% of SWE-agent-LM-32B trajectories contain a repeated sequence of length ≥ 10 vs under 4% for Claude 3.7 Sonnet; 53% of its failures hit cost, step or runtime limits.
