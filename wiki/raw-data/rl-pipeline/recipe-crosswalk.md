# RL recipe crosswalk: stage order, domains, graders, infra
- **Core Insight:** Across the eight lab recipes carded here, two patterns for ordering RL domains appear: staged (reasoning RL first, then general/alignment RL: Qwen3, GLM-4.5 experts, MiniMax-M1's curriculum, Nemotron 3 Nano's RLVR → RLHF → RLVR) and one joint stage (Kimi K2, DeepSeek-V3.2). DeepSeek-V3.2 gives a stated reason for joint RL: avoiding "catastrophic forgetting issues commonly associated with multi-stage training paradigms" ([[deepseek-v3.1]] card, §3). Nemotron gives a stated reason for training all environments together: single-environment training "often results in un-recoverable degradation of other benchmarks" ([[nemotron-ultra-recipe]], NR §3.2).
- **Guideline:** When choosing a stage order, write down which interference each lab measured; in these cards no lab prints a staged-vs-joint ablation with numbers, so the choice is supported by stated observations only.
- **Source type:** crosswalk of existing cards (no new primary reading except [[minimax-m1]])

Cells use only what the cited cards state. "not reported" = the card does not state it. Nemotron row = Nemotron 3 Nano 30B-A3B (the card `nemotron-ultra-recipe` covers that model). DeepSeek-V3.2 method facts are in the [[deepseek-v3.1]] card, which describes the V3.2 report.

## Instruction-following RL pipeline (synthesis)
Common stages across sources:
1. **Prompts with verifiable constraints.** Constraints attached to general instructions: IFEval taxonomy on Tülu 2 SFT prompts ([[rlvr-tulu3]], Table 22); 1 to n constraints per prompt from IFTrain + IFEval with a conflict dictionary ([[ifbench]] §3); 7 major / 151 minor constraint types ([[glm-4-5]] §3.4); IFEval/IFBench-style 46K + multi-turn 3K ([[nemotron-ultra-recipe]]).
2. **Programmatic per-constraint checkers as graders.** Sum of per-constraint verifiable rewards ([[ifbench]] Eq. 1); binary verifier α = 10 under PPO ([[rlvr-tulu3]] Eq. 7-8); code-interpreter checks plus a hack-check layer for claimed-but-unfulfilled compliance ([[kimi-k2]] §3.2.1).
3. **Model-based signal for soft quality.** Pure constraint reward lowered AlpacaEval 2 from 33.5 to 21.3 and judge quality from 7 to 6.4 ([[ifbench]] §5, Table 3); remedies: RM-gated shaping ([[ifbench]] App. E), rules + RM + critique model ([[glm-4-5]] §3.4), rule reward + model quality reward ([[minimax-m1]] §4.2.1), per-prompt rubrics with a judge ([[rubrics-as-rewards]]).
4. **Held-out constraint evaluation.** IFEval 82.4 vs IFEval-OOD 24.3 for Tülu 3 8B ([[tulu-3]] Table 31); 58 unseen constraints in IFBench ([[ifbench]]).
5. **Interaction with reasoning RL.** Long-CoT SFT and GRPO lowered constraint accuracy in 15 of 16 variants; 1k → 8k rollout length lowered hard accuracy 19.05 → 14.29 ([[scaling-reasoning-losing-control-mathif]] Tables 4-5).
6. **Stage position.** After DPO as the last stage ([[rlvr-tulu3]]); inside general RL after reasoning RL ([[qwen-3]], [[glm-4-5]], [[minimax-m1]]); inside one joint RLVR stage ([[kimi-k2]], [[nemotron-ultra-recipe]]).

## Search RL pipeline (synthesis)
Common stages across sources:
1. **Question source.** NQ + HotpotQA ([[search-r1]]); filtered multi-hop QA mix at 1:1:3:3 ([[deepresearcher]]); hard-but-solvable filtered QA plus injection/fuzz synthesis ([[asearcher]]); knowledge-graph subgraphs + obfuscation ([[websailor-tongyi-deepresearch]]; [[glm-4-5]] §3.3.1).
2. **Contamination / difficulty filter.** Drop questions the base model answers without search (pass@10) ([[deepresearcher]] §4.3); drop 0/16, ≥ 50%, or ≤ 1-turn questions ([[asearcher]] §3.2.1); drop all-correct and all-wrong ([[websailor-tongyi-deepresearch]]).
3. **Environment.** Local Wikipedia retriever ([[search-r1]]); simulated search LLM ([[zerosearch]]); live web with caching, retries, rate limits ([[deepresearcher]] §3.2); sandboxed tools with failover plus a simulated Wiki environment ([[websailor-tongyi-deepresearch]], Tongyi §3.4.3).
4. **Rollout length.** 4 actions ([[search-r1]]); ≤ 10 tool calls ([[deepresearcher]]); ≤ 30 ([[websailor-tongyi-deepresearch]]); 32-128 turns ([[asearcher]]); 128 tool calls at evaluation (Tongyi §4.1).
5. **Loss masking of tool output.** In every search source carded here ([[search-r1]] Table 4: 0.431 vs 0.343 without mask; [[deepresearcher]] §3.3; [[zerosearch]]; [[asearcher]] Eq. 1; [[websailor-tongyi-deepresearch]] §4.1-4.2).
6. **Grader.** EM ([[search-r1]]); F1 after EM reward hacking ([[zerosearch]]); F1 with −1 format penalty ([[deepresearcher]]); F1 × format or LLM judge ([[asearcher]]); 0.1 format + 0.9 LLM judge (WebSailor); 0/1 correctness (Tongyi); final-answer accuracy ([[glm-4-5]]).
7. **Infra.** Synchronous verl ([[search-r1]], [[deepresearcher]], WebSailor, limited to 50 RL steps); fully asynchronous AReaL ([[asearcher]]); step-level async on-policy rLLM (Tongyi); asynchronous disaggregated slime for agentic tasks ([[glm-4-5]] §3.5).
8. **Stage position.** Single RL stage from base/instruct ([[search-r1]], [[deepresearcher]], [[asearcher]]); after an RFT/SFT cold start (WebSailor, Tongyi); inside agentic RL after reasoning RL ([[glm-4-5]]); in specialist RL then joint mixed RL ([[deepseek-v3.1]]). [[gemini-2.5-deep-research]] names no RL algorithm or stage details.
