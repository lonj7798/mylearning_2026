# MiniMax-M1: Scaling Test-Time Compute Efficiently with Lightning Attention
- **Core Insight:** In M1's zero-RL experiments, PPO/GRPO clipping removed low-probability reflective "fork" tokens (However, Recheck, Wait, Aha) from gradient updates after the first of 16 off-policy updates per batch; CISPO keeps every token's gradient and clips the stop-gradient importance-sampling weight instead, matching DAPO's AIME 2024 score with 50% of the training steps on Qwen2.5-32B-base (§3.1, Fig. 2).
- **Guideline:** For a multi-domain RL stage, start with rule-verified reasoning tasks only and gradually mix in reward-model-graded general tasks with dynamic weighting (§4.3); monitor GenRM length bias online and recalibrate during RL, because offline mitigation "frequently failed to prevent length bias during RL training" (§4.2.2); check train/inference token-probability agreement before scaling, because a kernel precision mismatch "prevented reward growth" until the LM head ran in FP32 (§3.2).

## Summary
M1 is built on MiniMax-Text-01 (456B total, 45.9B active, 32 experts; one softmax-attention block after every seven lightning-attention blocks) (§1). Pipeline: continual pretraining on 7.5T tokens (70% STEM/code/book/reasoning; context extended in four stages from 32K to 1M) (§2.1) → long-CoT SFT, ~60% math and code (§2.2) → RL with CISPO over verifiable and non-verifiable tasks (§3-4) → a second RL run extending the output limit from 40K to 80K (§5). A full RL run took 3 weeks on 512 H800 GPUs, about $0.53M rental cost (§1, §3).

## Key Contributions
- CISPO objective: REINFORCE with sg(clip(r, 1−ε_low^IS, 1+ε_high^IS))·Â·log π, group-relative advantage, token-level normalization over all tokens in the group; ε_low^IS set large (no lower bound), only ε_high^IS tuned; no KL term; DAPO dynamic sampling and length penalty retained (§3.1, Eq. 4-5).
- Unified form with a token mask M that reproduces the PPO trust-region mask (§3.1, Eq. 6-7).
- RL fixes for the hybrid architecture: FP32 LM head (train/infer probability correlation from about 0.9x to 0.99x), AdamW β2 = 0.95 and eps = 1e-15 instead of verl defaults (0.9, 0.999, 1e-8) which led to non-convergence, early truncation when 3,000 consecutive tokens each have probability > 0.99 (§3.2).
- Multi-domain RL data and curriculum (§4).

## Technical Details
**Pipeline view (RL stage).**

|---|---|---|---|
| Math | competition problems; dedup, SFT/RL separation, decontamination; drop proofs, multi-part, binary; MCQ → open-ended; keep pass@10 in (0, 0.9) → ~50K | rule-based answer check + format reward | §4.1 |
| Logic | SynLogic, 41 tasks (e.g., cipher, Sudoku), difficulty bounded by strong-model pass@10 > 0 and Text-01 pass rate in (0, 0.5); harder later → ~53K | task-specific rule verifiers | §4.1 |

| General, with ground truth | STEM/factual with multiple valid forms | GenRM, five-grade scale | §4.2.1 |
| General, no ground truth | instruction following, creative writing; reference answer chosen by Swiss-round GenRM scoring | pairwise vs reference: −1 / 0 / 1; constrained IF uses rule-based constraint reward + model-based quality reward | §4.2.1 |
General RL set total: 25K samples (§4.2.1).

**Stage order (§4.3, §5).** RL run 1 (40K output limit): rule-verified reasoning tasks only → gradually mix in general-domain tasks with dynamic weighting, single policy. RL run 2 (80K): data re-filtered by the 40K model's pass rates, harder math/code upweighted, synthetic reasoning data downsampled because its outputs "become repetitive and homogenous" and destabilize long-context RL; output window 40K → 48K → 56K → 64K → 72K → 80K, advancing when generation perplexity converges and the 99th-percentile length approaches the window (§5).

**Instability at long windows (§5).** Late in each window, sequence tails degraded into garbled text with rising perplexity. Stated cause: negative samples grow longer faster than positives and reach the window limit first, so negative gradients accumulate in late positions under GRPO-style advantage normalization with token-level loss. Fixes: repetition early-stop, combined sample-level loss with token-level normalization, lower gradient-clipping threshold and lower ε_high^IS.

**Results (Table 2, M1-40k / M1-80k).** AIME 2024 83.3 / 86.0; AIME 2025 74.6 / 76.9; LiveCodeBench 62.3 / 65.0; SWE-bench Verified 55.6 / 56.0 (Agentless scaffold with two-stage localization, §6.1); TAU-bench airline 60.0 / 62.0, retail 67.8 / 63.5. During RL, AIME 2024 accuracy rises from 68% to 80% and average response length on AIME and LiveCodeBench exceeds 20,000 tokens (§6, Fig. 4).

## Algorithm choice: stated reasons
- GRPO rejected: in zero-RL on the hybrid model it "adversely affected training performance and failed to effectively promote the emergence of long CoT reasoning"; controlled ablations identified token clipping as the cause (§3.1).
- DAPO clip-higher rejected as the fix: "less effective in our setup, which involved 16 rounds of off-policy updates per generation batch" (§3.1).
- KL penalty: none, "similar to other recent works" (§3.1); no further reason stated.
