# Flows type vocabulary — NodeConfig, function schemas, and ContextStrategy

<!-- slug: flows-node-types · type: source · source: src/pipecat/flows/types.py (518 L), src/pipecat/flows/__init__.py -->

**Core Insight.** The entire Flows vocabulary is 518 lines of `TypedDict`s, dataclasses and `Callable` aliases — there is no class hierarchy and no graph object. A "state" is a `NodeConfig` **TypedDict with `total=False`**, so every field except `task_messages` is optional and unvalidated at runtime; an "edge" is nothing but the second element of the tuple a handler returns (`ConsolidatedFunctionResult = tuple[Any, NodeConfig | None | _NoResponse]`). The one type that carries real semantics is `ContextStrategy`: `APPEND` vs `RESET` decides whether a transition *adds* the new node's messages to the running conversation or *replaces* the whole message list with them — the single knob that separates "the bot remembers the last stage" from "the bot starts clean."

**Guideline.** Read `NodeConfig` as a *prompt+tools bundle*, not as a node. Set `name` explicitly on every node you care about (unnamed nodes get a throwaway UUID and `flow_manager.current_node` becomes useless for guards), and choose `context_strategy` per node rather than globally — it is the only place in Flows where a transition can be made to *forget*.

## Technical Details

- **`NodeConfig(TypedDict, total=False)`** (types.py:182-237) — the full field list, verbatim types:
  | field | type | controls |
  |---|---|---|
  | `task_messages` | `Required[list[dict]]` | the node's objective; the only required key |
  | `name` | `str` | node label; falls back to `str(uuid.uuid4())` |
  | `role_message` | `str` | bot persona, sent as `LLMUpdateSettingsFrame(delta=LLMSettings(system_instruction=...))`; **persists across transitions** until another node sets it |
  | `role_messages` | `list[dict[str, Any]]` | deprecated 1.5.0 list form; prepended to context messages instead |
  | `functions` | `list[FlowsFunctionSchema \| FlowsDirectFunction]` | the node's advertised tool set |
  | `pre_actions` | `list[ActionConfig]` | run **before** LLM inference |
  | `post_actions` | `list[ActionConfig]` | run **after** LLM inference (deferred to `BotStoppedSpeakingFrame` if `respond_immediately=False`) |
  | `context_strategy` | `ContextStrategyConfig` | per-node override of the manager-wide strategy |
  | `respond_immediately` | `bool` | default `True`; when `True` the node queues `LLMRunFrame()` on entry |
- **`FlowConfig` does not exist — expectation violated.** `grep -rn "FlowConfig"` over the whole repo returns zero hits; it is absent from `types.py` and from `__init__.py`'s `__all__`. There is no declarative flow document, no edge table, no `initial_node` key, no JSON schema for a whole conversation. The exported surface (`__init__.py:48-73`) is: `FlowManager`, `ActionConfig`, `ContextStrategy`, `ContextStrategyConfig`, `FlowArgs`, `FlowFunctionHandler`, `FlowResult`, `ConsolidatedFunctionResult`, `NO_RESPONSE`, `FlowsFunctionSchema`, `LegacyFunctionHandler`, `FlowsDirectFunction`, `NodeConfig`, `ZeroArgFunctionHandler`, `flows_tool_options`, `flows_direct_function`, plus the five exceptions.
- **`ContextStrategy(Enum)`** (L134-152): `APPEND = "append"`, `RESET = "reset"`, `RESET_WITH_SUMMARY = "reset_with_summary"`. The third is deprecated since 1.5.0 → "Use `LLMSummarizeContextFrame` instead — push it in a pre-action." The enum only becomes real in `manager._update_llm_context` (manager.py:831-836), which maps it straight onto a frame class: `RESET`/`RESET_WITH_SUMMARY` → `LLMMessagesUpdateFrame` (replace), anything else → `LLMMessagesAppendFrame` (add). Note the deliberate comment there: "even the first node follows the same rule: appending ensures any prior context contributions, such as by `tts_say` pre-actions, is preserved rather than replaced."
- **`ContextStrategyConfig`** `@dataclass` (L155-179): `strategy: ContextStrategy`, `summary_prompt: str | None = None`. `__post_init__` raises `ValueError("summary_prompt is required when using RESET_WITH_SUMMARY strategy")`. Summary generation is capped at `asyncio.wait_for(..., timeout=5.0)` and **silently mutates the config** back to `APPEND` on failure or timeout (`manager.py:815-822`).
- **`FlowsFunctionSchema`** `@dataclass` (L354-392): `name: str`, `description: str`, `properties: dict[str, Any]`, `required: list[str]`, `handler: FunctionHandler`, `cancel_on_interruption: bool = False`, `timeout_secs: float | None = None`. `to_function_schema() -> FunctionSchema` strips the Flows-only fields. Note `cancel_on_interruption=False` is Flows' default while base Pipecat treats `False` as "async call: the LLM continues immediately and the result is injected later as a developer message."
- **Transition-handler types** (all `Callable` aliases, no Protocol):
  - `FlowArgs = dict[str, Any]` (L59) — "Each invocation gets its own dict, so handlers may mutate it freely"; planned to widen to `Mapping[str, Any]` in 2.0.0.
  - `ZeroArgFunctionHandler = Callable[[], Awaitable[Any]]` — deprecated 1.5.0.
  - `LegacyFunctionHandler = Callable[[FlowArgs], Awaitable[Any]]` — deprecated 1.5.0.
  - `FlowFunctionHandler = Callable[[FlowArgs, "FlowManager"], Awaitable[Any]]` — the modern one.
  - `FunctionHandler = ZeroArgFunctionHandler | LegacyFunctionHandler | FlowFunctionHandler`. Dispatch is by **arity introspection**, not typing: `manager._call_handler` (manager.py:394-441) reads `len(inspect.signature(handler).parameters)` and branches 0 / 1 / else, warning once per process on the deprecated arities.
  - `FlowsDirectFunction = Callable[..., Awaitable[ConsolidatedFunctionResult]]` (L327) — shape `async def f(flow_manager: FlowManager, **params) -> ConsolidatedFunctionResult`. Schema is derived from signature + docstring by `FlowsDirectFunctionWrapper(BaseDirectFunctionWrapper)`, whose `special_first_param_name()` returns the literal string `"flow_manager"` (L461-468). The README calls this "the recommended pattern."
- **`ConsolidatedFunctionResult = tuple[Any, NodeConfig | None | _NoResponse]`** (L266) — *the edge type*. Element 0 is the function-call result delivered to the LLM (any JSON-serializable value; a `None` result means "transition-only" and `FlowManager` substitutes `{"status": "acknowledged"}`). Element 1 is: a `NodeConfig` → transition; `None` → stay on this node **and respond**; `NO_RESPONSE` → stay and **stay silent**. `NO_RESPONSE = _NoResponse()` (L247) is a module-level sentinel compared by identity (`next_node is NO_RESPONSE`). A `FlowsDirectFunction` that returns a non-tuple raises `InvalidFunctionError` (manager.py:487-490); a `FlowsFunctionSchema` handler may return a bare result.
- **`FlowResult(TypedDict, total=False)`** with `status: str`, `error: str` — **deprecated since 1.5.0, "No replacement."** (L40-56). It is no longer referenced by any handler type; the upstream contract is plain `Any`. Do not build against it.
- **`ActionConfig(TypedDict, total=False)`** (L112-131): `type: Required[str]`, `handler: LegacyActionHandler | FlowActionHandler`, `text: str`, `append_text_to_context: bool` (default `True`). "Additional fields are allowed and passed to the handler." `FlowActionHandler = Callable[[dict[str, Any], "FlowManager"], Awaitable[None]]`; the one-arg `LegacyActionHandler` is deprecated 1.5.0 and, as with function handlers, is detected by `len(sig.parameters) > 1` (actions.py:180-188).
- **`flows_tool_options(*, cancel_on_interruption: bool = False, timeout_secs: float | None = None)`** (L395) — optional decorator for direct functions; it delegates to base Pipecat's `tool_options`, which stores `_pipecat_cancel_on_interruption` / `_pipecat_timeout_secs` attributes read back in `FlowsDirectFunctionWrapper._initialize_metadata` (L485-494). `flows_direct_function(...)` is the deprecated 1.5.0 alias.
- **`get_or_generate_node_name(node_config) -> str`** (L509-518): `return node_config.get("name", str(uuid.uuid4()))`. This is the only place node identity is decided.
- **Migration angle:** the decisive ch-10 question is **"can an arbitrary state machine be expressed as a Flow?"** — and the answer from the types is **yes for the transitions, no for the guarantees**. Flows does *not* require transitions to be LLM function calls: the LLM-call path is only one producer of a `NodeConfig`, and `FlowManager.set_node_from_config(node_config)` accepts one from any coroutine, so boson's deterministic `RuleEngine → Action → ExecutionResult.pending_transition → _apply_stage_transition` chain ports directly (see [[flows-state-machine]]). What Flows *does* impose is a shape at the type level, and three of its constraints bite boson: **(1) There is no node type, so there is no edge type.** `StageDefinition.transitions: list[str]` — boson's per-stage allowlist that yields `TransitionResult(success=False, error="Transition 'a' -> 'b' not allowed")` — has no counterpart anywhere in `types.py`. `NodeConfig` cannot name its legal successors, so a ported flow can jump anywhere; boson's `StageMachine.transition()` must be kept as a pure pre-check. **(2) A node is constructed, not registered**, so the graph is not enumerable: no `has_stage(name)`, no `get_stage(name)`, no initial-stage validation (`packages/gateway/tests/test_initial_stage_validation.py` has nothing to assert against). Boson's `load_stages(config, prompts)` builds a dict keyed by name from `agents/*/stage_config.py` + `stages/*.md`; the port is a `dict[str, Callable[[], NodeConfig]]` you own, and `NodeConfig["name"]` must be set to the boson stage name or `flow_manager.current_node` guards (the pattern at `examples/flows/warm_transfer.py:658`) stop working. **(3) `ContextStrategy` is where boson gains something it does not have.** boson's `_inject_stage` only ever *appends* `f"[Stage: {stage.name}]\n\n{stage.prompt}"` as a `<system-reminder>`-wrapped user message — there is no reset path, so a long dental-intake conversation drags every prior stage's prompt through every later inference. `ContextStrategyConfig(strategy=ContextStrategy.RESET)` on a node gives per-transition context truncation for free via `LLMMessagesUpdateFrame`. Do **not** build on `RESET_WITH_SUMMARY` (deprecated 1.5.0, 5-second timeout, silent fallback) — use a pre-action pushing `LLMSummarizeContextFrame`. **Also mapping cleanly:** boson's `@tool` handlers → `FlowsDirectFunction` (docstring already carries the description); `StageDefinition.skills` → **nothing**, there is no skill concept in `types.py`; `ActionConfig{"type": "end_conversation"}` replaces boson's manual `EndFrame`-equivalent teardown.
