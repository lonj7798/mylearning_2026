# realtime_voice `VoiceSession` — a supervisor, not a pipeline
<!-- slug: rtv-pipeline-session · type: boson · source: packages/realtime_voice/realtime_voice/{pipeline/session.py,protocols.py,types.py,queues.py,clock.py} -->

**Core Insight.** The learner already built a Pipecat-equivalent, but it made the *opposite* structural bet. Pipecat's unit of data is `Frame` (127 subclasses, open for extension) and its unit of work is `FrameProcessor` (a doubly-linked list you compose). realtime_voice has **no Frame base class and no processor abstraction at all**. Its unit of data is a *closed union* of six frozen dataclasses; its unit of work is one 561-line `VoiceSession` class that hardcodes the stage order in an `asyncio.TaskGroup`. Stages are swappable (five `Protocol`s), but the *topology is not* — you cannot insert a processor, you can only replace a slot.

**Guideline.** When comparing the two, do not ask "does realtime_voice have frames?" (it does not). Ask "what did the closed union buy?" The answer is exhaustive `match`-ability, `mypy`-checkable event handling, and a single place (`_active_generation`) where staleness is decided — at the cost of every extension becoming a `session.py` edit.

## Technical Details

- **The unit of data is a union, declared once** (`types.py` L201):
  ```python
  VoiceRuntimeEvent = VADEvent | ASREvent | AgentTextDelta | VoiceEvent
  ```
  That is the whole "frame taxonomy". Adding a frame type means editing this line plus every `isinstance` chain (e.g. `transport/webrtc/transport.py:_control_event` L118-156 raises `TypeError(f"unsupported voice event: ...")` on anything else). Pipecat's `SystemFrame`/`DataFrame`/`ControlFrame` priority split has **no counterpart**; priority is not a property of the datum.
- **Payload types**, all `@dataclass(frozen=True, slots=True)`: `AudioFrame` (L48, PCM16 only — `__post_init__` raises `InvalidAudioFrameError` for any other `AudioFormat` and for byte lengths not aligned to `2 * channels`), `VADEvent` (L95), `ASREvent` (L113), `AgentRequest` (L126), `AgentTextDelta` (L134), `TextChunk` (L142), `TTSRequest` (L149), `SynthesizedAudio` (L161), `VoiceEvent` (L188). Newtypes `SessionId / TurnId / GenerationId / PhraseId` (L16-19) are `NewType("...", str)` — every frame carries `CorrelationIds(session_id, turn_id, generation_id)` (L27), which is stronger than Pipecat, where correlation IDs are not on the base `Frame`.
- **The unit of work is `VoiceSession`** (`pipeline/session.py` L89, 561 L). Docstring L90: *"Supervise audio -> VAD -> ASR -> text agent -> TTS -> queued audio."* Constructor takes the four stages as keyword args (`vad`, `asr`, `agent`, `tts`) plus `VoiceSessionConfig`. `_supervise()` (L257) opens one `asyncio.TaskGroup` and creates exactly **two** long-lived tasks: `"voice-input"` (`_input_loop`) and `"voice-asr-events"` (`_asr_loop`). Per-turn work spawns nested tasks: `f"asr-finalize:{gen}"`, `f"voice-generation:{gen}"`, and inside `_run_generation` an inner TaskGroup with `f"agent-text:{gen}"` + `f"tts:{gen}"`. **This is the analogue of Pipecat's per-processor two-task/two-queue model, but there are 2 tasks for the whole session instead of 2 per processor.**
- **Swappable slots, fixed order** — `protocols.py` (82 L) defines five `@runtime_checkable Protocol`s and nothing else:
  ```python
  class VAD(Protocol):    async def process(self, frame: AudioFrame, correlation: CorrelationIds) -> Sequence[VADEvent]
  class StreamingASR(Protocol):  async def start / push_audio / finalize / close;  def events() -> AsyncIterator[ASREvent]
  class StreamingTTS(Protocol):  async def start / cancel(generation_id) / close;  def synthesize(request) -> AsyncIterator[SynthesizedAudio]
  class StreamingConversationAgent(Protocol):  def stream(request) -> AsyncIterator[AgentTextDelta];  async def cancel / close
  class VoiceTransport(Protocol):  async def start / send_audio / send_event / close;  def incoming_audio() -> AsyncIterator[AudioFrame]
  ```
  There is **no `link()`, no `FrameDirection`, no upstream push**. Where Pipecat gets a `LLMContextFrame` pushed *upstream* to close the tool loop (`function-calling.md`), realtime_voice has one direction only.
- **Generation-ID equality is the whole cancellation model.** `self._active_generation` is compared at six separate points — `next_audio` L180, `_asr_loop` L328, `_produce_phrases` L410, `_consume_phrases` L447 and L456, `acknowledge_playout` L199 — each dropping stale work with `VoiceEventKind.GENERATION_DROPPED`. `_on_speech_started` (L284) advances the generation and *emits the VAD event before awaiting cancellation* (comment L290-292: *"Publish media invalidation before awaiting provider/Gateway cancellation"*). Pipecat achieves the same with one `InterruptionFrame` traversing N processors; realtime_voice achieves it with one integer compare in N places.
- **Bounded queues, three different overflow policies.** `VoiceSessionConfig` (L41) defaults verbatim:
  ```python
  sample_rate=16_000; channels=1; language="ko"
  ingress_queue_size=64; event_queue_size=256; phrase_queue_size=8; audio_queue_size=32
  vad_prefix_frames=5; phrase_min_chars=12; phrase_max_chars=60
  phrase_hard_max_chars=None; phrase_batch_max_chars=320; adaptive_sentence_batching=True
  ```
  Ingress is **reject-on-overflow** — `push_audio` (L164) raises `QueueOverflowError("ingress queue full; frame rejected instead of adding latency")`. Phrase and audio queues **backpressure**. The event queue is unbounded in effect (256 deep, `_emit` awaits). Class docstring L92-94: *"Ingress uses reject-on-overflow so a transport cannot silently extend user turn latency."*
- **`GenerationAudioQueue`** (`queues.py` L12, 66 L) is a hand-rolled `deque` + `asyncio.Condition` for exactly one reason: `discard_generation(generation_id) -> int` (L42) rebuilds the deque under the condition lock as an atomic filter. `asyncio.Queue` has no such operation. `close()` clears and wakes all waiters; `get()` on a closed empty queue raises `QueueClosedError`.
- **Exactly-one-terminal-event is enforced by a dict, not a state machine.** `self._terminal: dict[GenerationId, VoiceEventKind]` plus `_terminal_event()` (L516) which returns early `if generation in self._terminal`. The five terminals are `TURN_COMPLETED / TURN_CANCELLED / TURN_FAILED` (from `VoiceEventKind`, 14 values total, L170-184, dotted strings like `"assistant.generation_dropped"`).
- **Shutdown order is hand-sequenced** in `close()` (L231): emit `SESSION_CLOSING` → cancel active generation with `semantic_interrupt=False` (comment L239-241: *"Closing a transport is lifecycle cleanup, not a customer interruption"*) → `_ingress.put(_STOP)` → `asr.close()` → await supervisor → `vad.close()` → `agent.close()` → `tts.close()` → `_audio.close()` → emit `SESSION_CLOSED` → `_events.put(_STOP)`. Pipecat gets this from `EndFrame`/`CancelFrame` propagating through `link()`ed processors; here it is 24 explicit lines.
- **Sentinels instead of frames.** `_STOP = object()` (L37) is pushed onto the ingress, event, and phrase queues to terminate loops, so every queue is typed `asyncio.Queue[X | object]` and every consumer does `cast(...)`. This is the direct cost of having no `EndFrame`.
- **Expected but absent:** `clock.py` (16 L) declares `MonotonicClock(Protocol)` and `SystemMonotonicClock` — `grep -rn MonotonicClock` shows **neither is imported anywhere in the package or the dental gateway**. Dead code. `VoiceSession` takes `now_ns: Callable[[], int] = time.monotonic_ns` directly (L108); tests inject `FakeMonotonicClock` from `testing/fakes.py` instead, and `clock.py` is not re-exported from `__init__.py`.
- **Also absent:** any `Pipeline` / `PipelineTask` / `PipelineRunner` equivalent, any `ParallelPipeline`, any observer plane, any frame-level metrics. `errors.py` (30 L) is the whole error surface: `RealtimeVoiceError(Exception)` with `InvalidAudioFrameError(RealtimeVoiceError, ValueError)`, `QueueOverflowError`, `QueueClosedError`, `ProviderError`, `ProviderTimeoutError(ProviderError, TimeoutError)`, `SessionClosedError`.
- **Migration angle:** This is the collision, not a gap. `VoiceSession` *is* boson's `Pipeline` + `PipelineTask` + `FrameProcessor` base + interruption machinery, fused into one class. Porting to Pipecat replaces `session.py`, `queues.py`, `protocols.py` and most of `types.py` outright — nothing survives as a Pipecat plugin, because Pipecat wants `Frame` subclasses and `FrameProcessor` subclasses and realtime_voice has neither. The two pieces that *do* port cleanly are the ones Pipecat lacks equivalents for: `AudioTextPlayoutLedger` and `KoreanPhraseChunker` (see [[rtv-vad-chunking]]). Conversely, `StreamingConversationAgent` is the one slot Pipecat has no analogue for — Pipecat assumes it owns the LLM call, whereas boson deliberately delegates to `GatewayConversationAgent` (`agents/dental-w-tool-gateway/voice_server.py` L163) so stages/rules/tools stay text-native.
