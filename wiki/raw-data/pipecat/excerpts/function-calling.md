# Function Calling in Pipecat — registration, invocation, result frames, adapters

<!-- slug: function-calling · type: source · source: src/pipecat/services/llm_service.py, src/pipecat/adapters/, examples/function-calling/ -->

**Core Insight.** Pipecat has **no multi-turn tool loop inside the LLM service**. A service performs exactly one inference per `LLMContextFrame`, and if the model emitted tool calls it fires them and returns. The "loop" is closed by the *pipeline*: the assistant aggregator writes the tool result into the shared `LLMContext` and pushes a new `LLMContextFrame` **upstream**, which re-enters the same service. Think-act-observe is a topology, not a `while` block — and consequently it has **no turn cap**.

**Guideline.** Advertise tools by putting them on the `LLMContext` (`LLMContext(tools=[...])`) and let handlers auto-register; reach for `register_function` only for a catch-all (`function_name=None`) or to attach a handler to a name you don't control. Return results by awaiting `params.result_callback(result)` — never by returning a value, and never by calling the LLM yourself.

## Technical Details

- **Registration, three routes** (all land in the same `self._functions: dict[str | None, FunctionCallRegistryItem]`):
  1. **Direct function** — a plain async callable whose first parameter is `params` and whose docstring supplies the schema. `ToolsSchema.__init__` (`adapters/schemas/tools_schema.py:54-66`) wraps any `callable` tool in `DirectFunctionWrapper(tool)` and calls `wrapper.to_function_schema()`. `DirectFunctionWrapper.invoke(args, params)` (`adapters/schemas/direct_function.py:279`) is literally `await self.function(params=params, **args)`.
  2. **`FunctionSchema(name, description, properties, required, handler=None)`** (`adapters/schemas/function_schema.py:20-58`). When `handler` is set the service registers it automatically.
  3. **`LLMService.register_function(function_name, handler, *, cancel_on_interruption=None, timeout_secs=None, cancellable_by_llm=None)`** (`services/llm_service.py:879`). `function_name=None` installs a catch-all. Option precedence is documented as **explicit argument > `@tool_options` decorator > default** (L890-893).
  `register_direct_function` (L986) still exists but is `@deprecated` since 1.4.0, "Use `LLMContext(tools=[...])` instead", removal in 2.0.0.
- **Auto-registration from the advertised tool set.** `LLMService.process_frame` L712-723 calls `self._sync_registered_tool_handlers(frame.context.tools)` on **every** `LLMContextFrame`; `_register_advertised_tool_handlers` (L1167) registers direct-function wrappers (L1197-1212) and `FunctionSchema.handler`s (L1218-1230), marking each `auto_registered = True` so it can be pruned when no longer advertised. Explicit registrations win and are never pruned.
- **`@tool_options(fn=None, *, cancel_on_interruption=True, timeout_secs=None, cancellable_by_llm=False)`** (`direct_function.py:292`) attaches `_pipecat_cancel_on_interruption` / `_pipecat_timeout_secs` / `_pipecat_cancellable_by_llm` and returns the function unchanged — it registers nothing.
- **`FunctionCallParams`** (`llm_service.py:114-155`) — the single argument every handler receives:
  `function_name: str`, `tool_call_id: str`, `arguments: Mapping[str, Any]`, `llm: LLMService[Any]`, `pipeline_worker: PipelineWorker`, `context: LLMContext`, `result_callback: FunctionCallResultCallback`, `app_resources: Any = None`, `worker_runner: WorkerRunner | None = None`. (`tool_resources` is a deprecated alias for `app_resources`, 1.2.0 → removal 2.0.0.) The callback protocol is `async __call__(self, result, *, properties: FunctionCallResultProperties | None = None)` (L101).
- **Invocation path**, end to end:
  1. Provider service parses tool calls out of the stream and builds `FunctionCallFromLLM(function_name, tool_call_id, arguments, context)` (`frames.py:1330`), then `await self.run_function_calls(function_calls)` — e.g. `services/openai/base_llm.py:588`.
  2. `LLMService.run_function_calls(function_calls)` (L1437): fires the `on_function_calls_started` event and broadcasts `FunctionCallsStartedFrame` (L1455-1456); assigns one shared `group_id = str(uuid.uuid4())` when `group_parallel_tools=True` (L1461) so the LLM is re-run exactly once after the last sibling settles; resolves each name to a registry item, falling back to `self._functions[None]` then to `_build_missing_function_call_registry_item`; dispatches via `_run_parallel_function_calls` or `_run_sequential_function_calls` per the `run_in_parallel=True` constructor flag (L305).
  3. `_run_function_call(runner_item)` (L1547) re-resolves the handler at execution time, broadcasts `FunctionCallInProgressFrame` (L1576-1583), arms a `timeout_handler()` when `item.timeout_secs or self._function_call_timeout_secs` is set (L1650), builds `FunctionCallParams` and awaits `item.handler(params)` (L1683) or `item.handler.invoke(...)` for direct functions (L1656). A raising handler is caught at L1689 → `push_error(..., category=ErrorCategory.APPLICATION)` and the call is settled with `FUNCTION_CALL_ERROR_MESSAGE_TEMPLATE` on the handler's behalf.
  4. `function_call_result_callback` (L1589) sets `runner_item.settled = True` for final results, rejects late/duplicate results (L1607-1613), cancels the timeout task, and broadcasts `FunctionCallResultFrame`.
- **Result frames** (`frames.py`): `FunctionCallsStartedFrame` (L1349, `SystemFrame`), `FunctionCallInProgressFrame` (L2164, `ControlFrame, UninterruptibleFrame` — carries `cancel_on_interruption` and `group_id`), `FunctionCallResultFrame` (L770, `DataFrame, UninterruptibleFrame` — `function_name, tool_call_id, arguments, result, run_llm, properties`), `FunctionCallCancelFrame` (L1363). Both in-progress and result frames are **uninterruptible** by design: "once a result is generated we always want to update the context." `FunctionCallResultProperties(run_llm, on_context_updated, is_final=True)` (L748) lets a handler stream intermediate updates (`is_final=False`, async calls only) or suppress the follow-up inference.
- **Per-provider differences live in `src/pipecat/adapters/`.** `BaseLLMAdapter(ABC, Generic[TLLMInvocationParams])` (`base_llm_adapter.py:53`) declares four abstract members: `id_for_llm_specific_messages` (L92), `get_llm_invocation_params(context, **kwargs)` (L101), `to_provider_tools_format(tools_schema) -> list[Any]` (L114), `get_messages_for_logging(context)` (L126). `from_standard_tools(tools)` (L166) merges `builtin_tools` (e.g. the generated `cancel_<name>` tools) then dispatches to `to_provider_tools_format`. Escape hatches: `ToolsSchema(standard_tools, custom_tools: dict[AdapterType, list[dict]])` with `AdapterType.GEMINI` / `AdapterType.OPENAI` (`tools_schema.py:21-31`), and `LLMSpecificMessage(llm, message)` for provider-native message shapes. There are **12** concrete adapters (anthropic, aws_nova_sonic, bedrock, gemini, gemini_live, grok_realtime, inworld_realtime, mistral, open_ai, open_ai_realtime, open_ai_responses, perplexity), 3,647 lines total.
- **Real usage** — `examples/function-calling/function-calling-openai.py:36-52, 101`: the whole tool definition is a docstring.
  ```python
  async def get_current_weather(params: FunctionCallParams, location: str, format: str):
      """Get the current weather.

      Args:
          location: The city and state, e.g. "San Francisco, CA".
          format: The temperature unit to use. Must be either "celsius" or "fahrenheit". ...
      """
      await params.result_callback({"conditions": "nice", "temperature": "75"})

  context = LLMContext(tools=[get_current_weather, get_restaurant_recommendation])
  ```
  Filler speech during the call is an event handler, not loop code (L97-99): `@llm.event_handler("on_function_calls_started")` → `await tts.queue_frame(TTSSpeakFrame("Let me check on that."))`. The explicit-schema variant is `function-calling-advanced-functionschema.py:62-86` (`FunctionSchema(..., required=["location","format"], handler=fetch_current_weather)`, reading `params.arguments["location"]`). There are 45 examples in that directory.
- **No loop, stated plainly.** `OpenAIBaseLLMService.process_frame` (`services/openai/base_llm.py:590-613`) handles one `LLMContextFrame` → one `_process_context()` → optional `run_function_calls()` → `LLMFullResponseEndFrame`. Nothing re-prompts. The re-prompt comes from `LLMAssistantAggregator._maybe_push_context_after_function_result` pushing `LLMContextFrame` **UPSTREAM** ([[llm-service-context]]). `grep -rn "max_turns\|max_iterations\|max_tool_calls" src/pipecat/` returns **zero hits** — there is no ceiling on tool→inference cycles. The only bounds are per-call: `function_call_timeout_secs` (constructor, L307) or `timeout_secs` per tool.
- **Migration angle:** This is the head-on collision with `packages/basement/basement/loop/agent_loop.py` (561 L). `run_agent_loop(runtime, user_input) -> AsyncIterator[StreamEvent]` (L176) owns `while turn_count < runtime.config.max_turns:` (L208), calls `runtime.provider.stream(messages=ctx.get_messages(), system=ctx.get_system_prompt(), tools=tools)` (L250-254), and dispatches through `_execute_tool_uses(runtime, tool_uses, hooks, api, ctx)` (L393). Porting means **deleting the loop, keeping the tool bodies**: each `@tool` becomes a direct function or a `FunctionSchema(handler=...)`, and the loop body's responsibilities scatter — turn bounding is *lost* (Pipecat has no `max_turns`, so a runaway tool cycle needs a custom `FrameProcessor` counting `FunctionCallsStartedFrame`), hooks (`ON_TURN_START`, `PRE_LLM_CALL`) map onto `llm.event_handler(...)` and processor placement, and `_reconcile_cancelled_tool_uses` (L56) / `_await_tool_boundary` (L113) are largely subsumed by `FunctionCallCancelFrame` + `settled` + the uninterruptible result frames. The ToolRouter meta-tool trick (L221-235: expose only `use_tool`/`use_skill` from `meta_tool_names()`, hiding native specs) survives unchanged as a two-entry `LLMContext(tools=[use_tool, use_skill])` with dynamic swaps via `LLMSetToolsFrame` — and `add_tool_change_messages=True` on the aggregator pair is the built-in answer to the hallucination problem that motivated it. `runtime.exposed_meta_tools` has no Pipecat field; it becomes application state read when building the `ToolsSchema`.
