# realtime_voice WebRTC stack — aiortc, a token-authorized manager, and a control channel that forbids audio
<!-- slug: rtv-webrtc-transport · type: boson · source: packages/realtime_voice/realtime_voice/transport/webrtc/ -->

**Core Insight.** boson's WebRTC layer is ~960 LOC against aiortc and lands almost exactly where Pipecat's `SmallWebRTCTransport` lands — same library, same 20 ms Opus pacing, same PyAV resampling, same data channel. The two real divergences are *policy*, not plumbing: boson bakes in an HMAC-token session authorization layer (`WebRTCSessionManager`) that Pipecat has no equivalent of, and it makes the control channel a **validated, sequence-checked, audio-forbidden JSON protocol** where Pipecat's `on_app_message` is an untyped passthrough. Everything Pipecat has that boson does not is *breadth*: video, screen share, renegotiation, ICE restart, multiple transports.

**Guideline.** If you keep boson's transport, you keep an auth model and a protocol contract you would otherwise have to write on top of Pipecat. If you adopt Pipecat, budget for re-implementing `WebRTCSessionManager` and `ControlEvent` validation as application code around `SmallWebRTCConnection` — they are not in the box.

## Technical Details

- **File sizes** (~960 L excluding `errors.py`/`optional.py`/`__init__.py`): `manager.py` 248, `control.py` 226, `peer.py` 231, `tracks.py` 216, `buffer.py` 123, `config.py` 64, `transport.py` 168. Pipecat's `transports/smallwebrtc/` is 2,176 L across `transport.py` (1,085), `connection.py` (825), `request_handler.py` (266).
- **`WebRTCTransportConfig`** (`config.py` L34), real defaults verbatim:
  ```python
  ice_servers = (IceServer(("stun:stun.l.google.com:19302",)),)
  data_channel_label = "boson-control";  input_sample_rate = 16_000;  output_sample_rate = 48_000
  output_channels = 1;  packet_duration_ms = 20;  max_output_frames = 64
  output_backpressure_ms = 250;  max_control_message_bytes = 64 * 1024;  session_token_ttl_seconds = 15 * 60
  ```
  `__post_init__` rejects `output_channels != 1` (*"the first WebRTC transport supports mono assistant audio"*) and any `packet_duration_ms not in {10, 20, 30, 40, 60}`.
- **`WebRTCSessionManager`** (`manager.py` L51) — *"Create short-lived authorized sessions and enforce one live peer each."* `create_session(customer_id, *, session_id=None, metadata=None) -> VoiceSessionTicket(session_id, token, expires_at, customer_id)` mints `secrets.token_urlsafe(32)` and stores only `hashlib.sha256(token).digest()`; `_authorize` (L227) checks expiry then `hmac.compare_digest`. `accept_offer(..., reconnect: bool = False)` raises `SessionConflictError("this voice session already has a live peer")` unless `reconnect=True` — **explicit reconnect, no silent takeover**. Pipecat has nothing comparable: `SmallWebRTCConnection.__init__(ice_servers=...)` (`connection.py` L245) has no tokens, no TTL, no customer binding; `request_handler.py` is a bare offer/answer endpoint.
- **`WebRTCPeerSession`** (`peer.py` L31) owns `RTCPeerConnection` + `InboundAudioPump` + `OutboundAudioTrack` + `OrderedControlChannel`. `_wire_events` (L83) enforces one-of-each: a **second inbound audio track is stopped** (`logger.warning("Ignoring a second inbound audio track")`), a data channel whose `label != config.data_channel_label` is closed, a duplicate control channel is rejected. `connectionstatechange` → `close()` on `{"failed", "closed"}`. `accept_offer(sdp, type="offer")` raises `SignalingError("only an SDP offer may be accepted")` — **answer-only, boson never initiates**. `add_ice_candidate` parses via `aiortc.sdp.candidate_from_sdp` and treats `None`/`""` as end-of-candidates.
- **Absent vs Pipecat:** no renegotiation and no ICE restart. Pipecat's `SmallWebRTCConnection` has `renegotiate(sdp, type, restart_pc=False)` (L443), `ask_to_renegotiate()` (L799), a `pc_id` (L302), and a `"disconnected"` event handler it hand-rolls because *"aiortc does not provide any way so we can be aware when we are disconnected"* (L350). boson's only recovery path is a fresh `accept_offer(reconnect=True)`. Also absent: video (`RawVideoTrack`), screen share (`capture_participant_video(video_source=...)`), and any transport other than WebRTC.
- **`InboundAudioPump`** (`tracks.py` L35) — *"Receive browser RTP audio and emit normalized 16 kHz mono AudioFrames."* One `av.AudioResampler(format="s16", layout="mono", rate=16000)`, then `media_frame.to_ndarray().tobytes()` → canonical `AudioFrame` with self-incremented `sequence` and `timestamp_samples`. Teardown detection is stringly-typed on purpose (L69-72): *"aiortc raises MediaStreamError when a remote track ends. Do not import that optional class merely to recognize teardown."* → `if type(exc).__name__ == "MediaStreamError": return`.
- **`OutboundAudioTrack`** (`tracks.py` L111) — 48 kHz, `packet_samples = sample_rate * packet_duration_ms // 1000` (960 @20 ms). Uses `av.AudioFifo` so a large TTS chunk keeps its remainder across `recv()` calls, and waits only `packet_seconds` on underflow (L149-155). `_pace()` (L168) is wall-clock catch-up: `target = self._started_at + self._pts / self.sample_rate`. On generation change it **throws away the FIFO** (L142-146, L152-154) — jitter buffer flush as cancellation. `_silence_frame` (L201) carries a hard-won comment: *"PyAV does not guarantee zero-initialized AudioFrame storage. Sending a fresh allocation as 'silence' can therefore produce full-scale random PCM"* → explicit `plane.update(b"\x00" * plane.buffer_size)`. Pipecat's `RawAudioTrack` (`transport.py` L76) is the same idea at **10 ms** granularity (`_samples_per_10ms`), with `auto_silence: bool = True` and a per-write `Future` resolved when the chunk is consumed — boson has no write-completion future.
- **`BoundedAudioOutput`** (`buffer.py` L21) is the jitter/interruption boundary: `asyncio.Queue(maxsize=64)`, `activate_generation(generation_id)` (L53) synchronously drains everything older and returns the drop count; `put()` returns `False` for a stale generation and raises `AudioBufferFull` if the live peer has not drained within `backpressure_ms=250`. Counter `discarded_frames` is exposed but **never read by anything** — the only metric in the transport, and it is orphaned.
- **`OrderedControlChannel` / `ControlEvent`** (`control.py`): `CONTROL_PROTOCOL_VERSION = 1`. `ControlEvent.__post_init__` validates the dotted type name and calls `_reject_audio_payload`, which walks the payload recursively and raises on any key in `{"audio","audio_base64","audio_data","base64_audio","pcm","pcm16","wav"}`, any `data:audio/` string, or any `bytes` — docstring L28-30: *"Audio bytes are intentionally prohibited. Microphone and assistant audio belong on RTP tracks, never in JSON or base64."* Channel construction rejects `ordered=False`, `maxRetransmits`, and `maxPacketLifeTime` (L147-154). `receive()` enforces strict in-order sequencing: `SignalingError(f"out-of-order control event: expected {self._next_inbound}, received {event.sequence}")`. `from_json` rejects unknown fields. Pipecat's equivalent is `SmallWebRTCTransport._on_app_message(message, sender)` → `on_app_message` event handler — **no schema, no sequence, no size cap, no audio ban**.
- **`WebRTCVoiceTransport`** (`transport.py` L27) is the thin `VoiceTransport` adapter; `_control_event()` (L118) is the hand-written mapping from the closed union to wire types: `VoiceEvent → event.kind.value`, `AgentTextDelta → "text_delta"`, `ASREvent → "transcript.interim"|"transcript.final"|"asr.end_of_turn"|"asr.error"`, `VADEvent → "vad.speech_started"|"vad.speech_stopped"`.
- **Migration angle:** this is the *most* replaceable module in realtime_voice and the *least* worth replacing. Pipecat's `SmallWebRTCTransport(webrtc_connection, params: TransportParams)` covers the same aiortc ground and adds renegotiation, ICE restart, video, and eleven other transports (`daily/ livekit/ websocket/ whatsapp/ moq/ local/ heygen/ tavus/ vonage/ lemonslice/ smallwebrtc/`). But porting means re-writing `WebRTCSessionManager` (HMAC token + TTL + one-live-peer) and `ControlEvent` (versioned, ordered, audio-forbidden) as app code, because Pipecat ships neither. Net: adopt Pipecat's transport only if you also need telephony ([[transport-telephony]]) or a second client type — otherwise this 960 L is already paid for and passes an aiortc loopback test.
