# s1: Simple test-time scaling
- **Core Insight:** A very small but carefully curated reasoning SFT set can teach a strong base model how to spend more test-time compute; the big gain comes from inference-time control, not from a large training corpus.
- **Guideline:** Build a 1K-scale dataset around difficult, diverse, high-quality prompts, then use budget forcing to keep the model thinking longer when it wants to stop. The same checkpoint can look much stronger when you spend more tokens at test time.
- **Authors:** Niklas Muennighoff, Zitong Yang, Weijia Shi, Xiang Lisa Li, Li Fei-Fei, Hannaneh Hajishirzi, Luke Zettlemoyer, Percy Liang, Emmanuel Candes, Tatsunori Hashimoto
- **Year:** 2025
- **URL:** https://arxiv.org/abs/2501.19393
- **Relevant topics:** reasoning-trace synthesis, long-CoT, test-time scaling, SFT curation, budget forcing

## Abstract
s1 shows that a minimal recipe - 1,000 questions paired with reasoning traces and a budget-forcing inference trick - is enough to produce a strong reasoning model from Qwen2.5-32B-Instruct. The paper reports that s1-32B exceeds o1-preview on competition math, and that increasing the forced-thinking budget can push AIME24 performance from 50% to 57% without changing weights.

## Key Contributions
- **s1K dataset:** 1,000 curated question-trace pairs selected from a much larger candidate pool.
- **Budget forcing:** an inference-time controller that suppresses early stopping by appending `"Wait"` when the model tries to end thinking.
- **Small-data SFT works when the data are good:** the project argues that difficult, diverse, high-quality traces matter more than volume.
- **Open release:** the repo ships code, data, evaluation scripts, and model artifacts.

## Data Recipe
- **Candidate pool:** the repo exposes a larger 59K question pool and the scripts used to recreate s1K.
- **Curation criteria:** difficulty, diversity, and quality, each validated through ablations in the paper.
- **Training traces:** traces are generated with Gemini, then paired with answers and filtered into the final 1,000-example set.
- **Supporting data flow:** the repo's data pipeline runs question collection, Gemini trace generation, Qwen answer generation, feature extraction, and final filtering.
- **Training base:** Qwen2.5-32B-Instruct is finetuned on s1K to produce s1-32B.

## Technical Details
- **Training:** supervised finetuning only; the repo says the run took 26 minutes on 16 H100 GPUs with PyTorch FSDP.
- **Inference control:** budget forcing is implemented by ignoring the end-of-thinking stop and repeatedly appending `"Wait"`.
- **Evaluation tasks:** AIME24, MATH500, and GPQA Diamond.
- **Reported scores:** s1-32B gets 56.7 AIME24, 93.0 MATH500, and 59.6 GPQA-Diamond in the model card table.
- **Scaling behavior:** the repo shows that forcing more thinking can extend performance beyond the native checkpoint behavior, up to the context limit.

## Risks + Gotchas
- **Teacher dependence:** the model inherits reasoning style from Gemini traces, so quality is limited by the teacher and the filtering pipeline.
- **Inference hack, not new capability:** budget forcing mostly reallocates compute already latent in the model.
- **Context limits:** very aggressive forcing can run into context-window and repetition issues.
- **Dataset narrowness:** the training set is math-heavy, so transfer outside competition-style reasoning is less certain.
