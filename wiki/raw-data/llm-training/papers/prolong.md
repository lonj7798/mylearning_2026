# ProLong: How to Train Long-Context Language Models (Effectively)
- **Core Insight:** Effective long-context training requires (a) selecting **long documents that are genuinely coherent end-to-end** (not concatenations of unrelated short texts), (b) upsampling code repositories and textbooks because they have real long-range dependencies, and (c) running long-context continued pretraining at a *specific, small token budget* (20B tokens is enough to extend Llama-3-8B from 8K to 512K) — scale is not the lever, document quality is.
- **Guideline:** For long-context continued pretraining: curate ~10–30B tokens of long *coherent* documents (heavy on code repos and books), upweight them relative to web data, apply RoPE base-extension or YaRN, and train for a small number of steps; do *not* throw petabytes of loosely-concatenated web text at the problem.
- **Authors:** Tianyu Gao, Alexander Wettig, Howard Yen, Danqi Chen (Princeton NLP)
- **Year:** 2024
- **URL:** https://arxiv.org/abs/2410.02660
- **Relevant topics:** long-context continued pretraining, data curation, RoPE extension, Llama-3

## Abstract
ProLong investigates how to effectively train long-context LMs and releases **ProLong-8B**, a Llama-3-8B extended from 8K to 512K context with only 20B tokens of continued pretraining + 5B SFT. The paper's central finding is that **long-document quality** matters more than volume: concatenating short unrelated texts into long sequences (a common shortcut) is strictly worse than curating truly long coherent documents. ProLong-8B reaches state-of-the-art among similar-size models on HELMET and InfiniteBench, and beats several much-larger closed models on some tasks.

## Key Contributions
- **Data-quality thesis:** long-document coherence dominates training mix effectiveness.
- **ProLong-Data-30B** — 30B-token curated long-doc mix, Apache-2.0.
- **Per-stage token budget** disclosed: 20B continued pretraining + 5B SFT.
- **ProLong-8B** (Llama-3-8B base) — open-weights 512K model.

## Synthesis pipeline (REQUIRED — concrete, modality-specific)

### Data curation
- **Source pool:** Llama-3 pretraining mix (web, books, code, academic) — ~15T tokens.
- **Filter by document length:** keep only documents with ≥ 64K tokens of coherent content.
- **Filter by coherence signal:**
  - Code: entire repository (not single files) concatenated in sensible order (README → source → tests).
  - Books: full-book PDFs parsed with structural fidelity.
  - Academic: full papers with references.
  - Web: discard — authors find long web docs are mostly scraped listings with weak coherence.
- **Domain upweighting:** code repos × 4, books × 2, academic × 2, web × 0.5.
- **Final mix (30B tokens):**
  - Code repositories: ~40%.
  - Books: ~25%.
  - Academic papers: ~15%.
  - StackExchange / forum long threads: ~10%.
  - Miscellaneous long web: ~10%.

### Training recipe
- **Stage 1 — Continued pretraining (20B tokens):**
  - Extend RoPE base from 500K to 128M (Llama-3.1 style NTK-aware).
  - Train at 64K context initially, expand to 512K in second half.
  - LR 1e-4 → 1e-5 cosine.
- **Stage 2 — SFT (5B tokens):**
  - Long-instruction data (LongAlign-style, generated by Claude-3) + needle-in-haystack synthetic training samples + UltraChat (to preserve chat).
- **Teacher model(s):** Claude-3 / GPT-4 for SFT generation.
- **Cost / compute:** ~200K H100-hours total.

## Modality-specific technical details (REQUIRED — long-context)
- **Token-range:** 64K (initial CPT) → 512K (final).
- **Document-type mix (in pretraining):** code 40% / books 25% / academic 15% / long-forum 10% / web 10%.
- **Position-encoding adaptation:** NTK-aware RoPE base extension — base `θ` rescaled from 500K to 128M.
- **Packing strategy:** documents kept contiguous (no packing of unrelated short docs); one document per training example.
- **Per-stage data mix:**
  - Stage 1 (CPT, 20B tokens): 100% long documents.
  - Stage 2 (SFT, 5B tokens): 70% long-instruction + 30% short-instruction + synthetic NIAH.
- **Needle-retrieval difficulty:** SFT includes multi-needle NIAH training samples to explicitly train retrieval behavior.

## Quality / diversity evaluation
- ProLong-8B on HELMET (512K): leading open 8B.
- ProLong-8B on InfiniteBench (128K): beats Llama-3.1-8B-Instruct and Qwen2-7B-Instruct.
- Short-context retention: MMLU / GSM8K within 0.5 point of Llama-3.1-8B-Instruct base.
- Ablation: replacing curated long docs with concatenated short docs costs 10+ points on HELMET.

## Risks + gotchas
- **Code-heavy mix biases the model toward code-adjacent tasks** — may underweight natural-language long-doc reasoning.
- **Coherence filter is labor-intensive** — authors' filter pipeline is not fully automated.
- **RoPE-extension math sensitive:** wrong base-θ rescaling causes training instability.
- **20B-token budget is base-specific** — a different base model (Qwen, Mistral) may need more or less.
