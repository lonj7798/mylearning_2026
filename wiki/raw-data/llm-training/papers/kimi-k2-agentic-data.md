# Kimi K2 Agentic Data Pipeline
- **Core Insight:** Kimi K2's agentic capabilities are driven by a trillion-token synthetic agentic pretraining mix (not just SFT) containing planning, tool use, and long-horizon workflow demonstrations — Moonshot argues agentic behavior is best installed *during* pretraining by mixing synthetic agent rollouts with regular text, then polished with SFT+RL, rather than bolted on post hoc.
- **Guideline:** For frontier agentic models, don't treat agent SFT as a purely post-training step; inject synthetic agent trajectories (tool use, multi-step planning, sub-agent orchestration) into the pretraining mix at ~1–5% weight so the base model naturally emits agent-format tokens.
- **Authors:** Kimi Team / Moonshot AI
- **Year:** 2025
- **URL:** https://arxiv.org/abs/2507.20534 ; https://github.com/MoonshotAI/Kimi-K2
- **Relevant topics:** agentic pretraining, trillion-token synthesis, MuonClip, long-horizon agents

## Abstract
Kimi K2 (Moonshot AI, 2025) is a 1T-parameter MoE base model (32B activated) optimized for agentic and long-horizon tasks. The K2 technical report describes a synthetic agentic data pipeline that generates a trillion+ tokens of tool-augmented trajectories and folds them into pretraining (not just SFT). The report details (a) a synthetic environment simulator, (b) a sub-agent orchestration generator, and (c) rejection sampling with a critic LLM. K2 ranks highly on SWE-Bench Verified, LiveCodeBench, τ-bench, and agentic benchmarks.

## Key Contributions
- **Agentic data at pretraining scale:** ~1T tokens of synthetic agent trajectories added to the pretraining mix.
- **MuonClip optimizer:** a variant of Muon with logit-stability fixes for stable 1T-scale training.
- **Synthetic environment simulator** — generates tool schemas, simulates tool responses at trillion-token scale.
- **K2-Instruct** post-trained with SFT + RL on top of the agentic-pretrained base.

## Synthesis pipeline (REQUIRED — concrete, modality-specific)

### Agentic pretraining data (~1T tokens)
- **Simulated tool set:** tens of thousands of synthetic tool schemas (web search, file ops, code execution, database, calendar, custom enterprise APIs).
- **Simulated environments:** generated by prompting a larger teacher (Kimi's internal pretrained model in a feedback loop, plus GPT-4/Claude) to produce realistic tool response shapes.
- **Trajectory generation:**
  - Multi-agent simulation: a "user" agent issues queries; a "planner" agent decomposes; an "executor" agent emits tool calls; a "critic" agent reviews.
  - Sub-agent orchestration — up to 5 sub-agents per trajectory, each with distinct role.
- **Filtering:**
  - Critic LLM rates task success, coherence, tool-call validity.
  - Only top-scoring trajectories enter the pretraining mix.
- **Integration into pretraining:** agentic trajectories mixed at ~3–5% of the pretraining token budget (exact ratio not fully disclosed).

### SFT + RL post-training
- **SFT:** real-world agentic tasks (SWE-Bench-style issues, τ-bench-style tasks, tool-calling datasets).
- **RL:** GRPO / RLHF with a reward model tuned for multi-turn tool-call correctness.
- **Output shape:** agentic-pretrain corpus ~1T tokens; SFT corpus millions of tasks.
- **Teacher model(s):** Moonshot's internal frontier model + external GPT-4o / Claude-3.5 for diverse simulation.
- **Cost:** not disclosed; at 1T-token pretraining scale, this is a multi-million-dollar data operation.

## Modality-specific technical details (REQUIRED — agentic)
- **Environment:** synthetic simulator — not a real OS / web. But the simulator is sophisticated enough to produce plausible tool-response schemas and multi-step state changes.
- **Action space:** unified OpenAI-style `tool_calls` JSON; tool-count per trajectory varies from 1 to 20+.
- **Trajectory length:** median several thousand tokens; tail to tens of thousands for long-horizon tasks.
- **Success criterion:** critic LLM + rule-based validators (JSON schema, no repetition loops).
- **Data scale:** ~1T tokens agentic-pretrain + millions of SFT trajectories.
- **Why pretraining (not just SFT):** Moonshot argues in the K2 report that mixing agent tokens into pretraining gives the base model a native tool-calling "vocabulary", reducing the burden on post-training and improving generalization to unseen tools.

## Quality / diversity evaluation
- K2-Instruct SWE-Bench Verified: ~65% (2025-era top open model).
- τ-bench: K2-Instruct leads open models, competitive with Claude-3.5-Sonnet.
- Tool-calling BFCL: strong multi-turn scores.
- LiveCodeBench (competitive coding agent): high ranking.

## Risks + gotchas
- **Synthetic-env mismatch:** simulator-generated tool responses may not perfectly reflect real-world API failure modes.
- **Closed data:** the 1T-token agentic-pretrain corpus is not released; only the methodology is described.
- **Contamination risk:** generated data may overlap with SWE-Bench-style benchmarks; Moonshot runs their own decontamination but opacity remains.
- **MuonClip optimizer is not drop-in** for other pretraining stacks; adoption outside Moonshot is nascent.
