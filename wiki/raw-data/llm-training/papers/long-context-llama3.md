# The Llama 3 Herd of Models — long-context sections (§3.4.2, §3.4.3, §4.3.4, §5.2.6)
- **Core Insight:** Llama 3 405B reached a 128K context by extending the window in six stages over approximately 800B pre-training tokens, and then recovered long-context ability at post-training by mixing 0.1% synthetically generated long-context data into an otherwise short-context SFT mix (§3.4.2, §4.3.4).
- **Guideline:** When a model has been extended to a long context in pre-training, keep a long-context subset in the SFT mix, because applying a short-context-only SFT recipe caused significant regressions in long-context capability in this report (§4.3.4); DPO can stay short-context-only if the SFT checkpoint is already strong on long-context tasks (§4.3.4).
- **Authors:** Llama Team, AI @ Meta (contributor list in the report appendix)
- **Year:** 2024 (arXiv v1 2024-07; this card checked against v3, 2024-11-23)
- **URL:** https://arxiv.org/abs/2407.21783
- **Source type:** official technical report
- **Relevant topics:** staged context extension, RoPE base frequency, long-context SFT data synthesis, short-context regression, needle-in-a-haystack evaluation

## Summary
The report describes Llama 3 405B pre-training as three stages: initial pre-training, long-context pre-training, and annealing (§3.4). Long-context pre-training raises the supported context length in increments up to 128K, and the report states the criteria used to decide when a stage has finished. Post-training §4.3.4 describes three synthetic long-context data families generated by earlier Llama 3 models, the length buckets used to categorize them, the mixing ratio selected by ablation, and the decision to leave DPO on short context. §5.2.6 reports the long-context evaluation suite.

## Key Contributions
- States that context extension was done in six stages from 8K to 128K, with the adaptation criterion made explicit (§3.4.2).
- States the total long-context pre-training budget as approximately 800B tokens (§3.4.2).
- Documents three synthetic long-context SFT data families and how each is constructed (§4.3.4).
- Reports the ablation-selected long-context share of the SFT mix (§4.3.4).
- Reports that short-context-only DPO did not hurt long-context performance on top of a long-capable SFT checkpoint, with the authors' suggested reason (§4.3.4).

## Technical Details
### Long-context pre-training (§3.4.2)
- Long sequences are trained on only in the final stages of pre-training; the report's stated reason is that self-attention compute grows quadratically in sequence length (§3.4.2).
- The context length was increased gradually in **six stages**, starting from the original **8K** window and ending at **128K** (§3.4.2).
- Adaptation to each increment was judged by two conditions: (1) short-context evaluation performance has recovered completely, and (2) the model perfectly solves needle-in-a-haystack tasks up to that length (§3.4.2).
- The long-context pre-training stage used **approximately 800B training tokens** (§3.4.2).
- Per-stage token budgets, per-stage context lengths beyond the 8K start and 128K end, and per-stage data-mix proportions are not given in the report.

### RoPE base frequency (§3.2)
- The RoPE base frequency hyperparameter is set to **500,000**, listed among the architecture choices of Llama 3, with Xiong et al. (2023) cited as showing this value effective for context lengths up to 32,768 (§3.2).
- The report does not describe a progressive rescaling of the base frequency across the six stages.

### Annealing (§3.4.3)
- During pre-training on the final **40M tokens**, the learning rate was linearly annealed to 0 while **maintaining a context length of 128K tokens**; the data mix was adjusted to upsample selected sources during this phase (§3.4.3).

### Long-context post-training data (§4.3.4)
Naively applying the existing SFT recipe with only short-context data "resulted in significant regressions in long-context capabilities from pre-training" (§4.3.4). Human annotation of long examples is called impractical, so the report relies predominantly on synthetic data generated by **earlier versions of Llama 3** (§4.3.4). Three families:
1. **Question answering** — long documents are curated from the pre-training mix and split into chunks of **8K tokens**; an earlier Llama 3 model generates QA pairs conditioned on randomly selected chunks; during training the **whole document** is used as context (§4.3.4).
2. **Summarization** — hierarchical: chunks of **8K** input length are summarized with the strongest Llama 3 8K-context model, then the summaries are summarized; training prompts provide the full document. QA pairs are also generated from the document summaries, so that questions require global understanding of the whole document (§4.3.4).
3. **Long-context code reasoning** — Python files are parsed for import statements to determine dependencies; the most commonly depended-upon files, specifically those referenced by **at least five other files**, are selected; one such file is removed from the repository and the model is prompted to identify which files depended on it and to generate the missing code (§4.3.4).

- Synthetic samples are categorized by sequence length into **16K, 32K, 64K, and 128K** buckets for finer-grained targeting of input lengths (§4.3.4).
- "Through careful ablations, we observe that mixing **0.1%** of synthetically generated long-context data with the original short-context data optimizes the performance across both short-context and long-context benchmarks" (§4.3.4). The ablation table itself is not printed in the report.
- **DPO:** short-context-only DPO data did not hurt long-context performance, provided the SFT model is already high quality on long-context tasks; the authors suspect this is because the DPO recipe takes fewer optimizer steps than SFT, and they therefore keep the standard short-context DPO recipe on top of long-context SFT checkpoints (§4.3.4).

### Long-context evaluation (§5.2.6, Table 21)
- Needle-in-a-Haystack: the Llama 3 models retrieve **100%** of needles at all document depths and context lengths tested (§5.2.6).
- Multi-needle (4 needles inserted, retrieval of 2 tested, average recall across 10 sequence lengths up to 128K): Llama 3 8B **98.8**, 70B **97.5**, 405B **98.1**; GPT-4 and GPT-4o **100.0**, Claude 3.5 Sonnet **90.8** (Table 21).
- InfiniteBench En.MC: 8B **65.1**, 70B **78.2**, 405B **83.4**; En.QA: 8B **27.1**, 70B **36.7**, 405B **30.5** (Table 21).
- ZeroSCROLLS validation set, QuALITY exact match: 8B **81.0**, 70B **90.5**, 405B **95.2** (Table 21).
- RULER is not among the long-context benchmarks reported.

## Findings relevant to generality
- Forgetting is the binding constraint in both directions: short-context-only SFT regressed long-context ability (§4.3.4), and the 0.1% mixing ratio is selected to optimize both short- and long-context benchmarks jointly, not long-context alone (§4.3.4).
- The stage-advance criterion in pre-training is itself a generality check: a stage is complete only when short-context evaluations have recovered completely (§3.4.2).

## Findings relevant to distillation
- All three long-context SFT data families are generated by earlier or smaller Llama 3 checkpoints, including "our strongest Llama 3 8K context model" for chunk summarization (§4.3.4). The report does not name the generator as the 405B model.
