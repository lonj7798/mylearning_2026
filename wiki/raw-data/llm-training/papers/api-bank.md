# API-Bank: A Comprehensive Benchmark for Tool-Augmented LLMs
- **Core Insight:** On 314 manually annotated tool-use dialogues executed against 73 implemented APIs, GPT-4 reached 60.24% total API-call accuracy and Alpaca-7B 15.19%, and Lynx-7B fine-tuned on 1,888 LLM-generated training dialogues reached 39.58% (Table 3).
- **Guideline:** When tool-use training data must cover many domains at low cost, split generation into separate LLM agents for domains, APIs, queries, calls/responses, and a tester, because the authors report 94% usable data from this pipeline in a 100-sample human check versus 5% (ChatGPT) and 25% (GPT-4) from one combined instruction (§4, §5); the check covers data quality, not downstream accuracy.
- **Authors:** Minghao Li, Yingxiu Zhao, Bowen Yu, Feifan Song, Hangyu Li, Haiyang Yu, et al. (Alibaba Group, Hong Kong University of Science and Technology, Peking University, Shenzhen Intelligent Strong Technology)
- **Year:** 2023 (arXiv v1 2023-04; v2 2023-10; EMNLP 2023)
- **URL:** https://arxiv.org/abs/2304.08244 ; code and data: https://github.com/AlibabaResearch/DAMO-ConvAI/tree/main/api-bank
- **Source type:** paper
- **Relevant topics:** tool-use evaluation, API calling, API retrieval, planning, multi-agent data generation, tool-use SFT

## Abstract
API-Bank addresses three questions: how well current LLMs use tools, how to improve their tool use, and what obstacles remain. For the first, the authors build a runnable evaluation system of 73 API tools and annotate 314 tool-use dialogues with 753 API calls that test planning, retrieving, and calling APIs. For the second, they construct a training set of 1,888 tool-use dialogues from 2,138 APIs spanning 1,000 domains and fine-tune Lynx from Alpaca. GPT-3.5 uses tools better than GPT-3, and GPT-4 is strongest at planning. Lynx exceeds Alpaca's tool-use performance by more than 26 points and approaches GPT-3.5. An error analysis identifies the main remaining challenges.

## Key Contributions
- Ability definitions from interviews with 500 users: Call (APIs given), Retrieve+Call (one API must be found), Plan+Retrieve+Call (several APIs must be found and chained) (§1, §2.1).
- A runnable evaluation system: 73 APIs implemented in 98 person-days, with databases and fixed external results for reproducibility (§3.1).
- A training set generated by five ChatGPT agents at $0.1 per dialogue, 98% cheaper than manual annotation (§4).
- Zero-shot evaluation of five LLMs, a fine-tuned Lynx-7B, and error distributions per model (§7, Tables 3–6).

## Technical Details
- **Ability grid:** "few APIs, single call" and "few APIs, multiple calls" were merged because their difficulty was similar, leaving three abilities (§2.1).
- **API Search:** a special API that embeds the model's keywords and all API metadata, computes cosine similarity, and returns the most similar API; in Retrieve settings an API Search is required before every other call (§3.1).
- **Annotation:** Call dialogues start from randomly sampled APIs; Retrieve+Call decomposes a requirement over 1–5 APIs into single-call queries; Plan+Retrieve+Call keeps the requirement whole and annotates a call chain (§3.2). Each dialogue involves two annotators plus two reviewers, costs $8, and 21.5% of 400 annotated dialogues were discarded (§3.2).
- **Metrics:** API-call accuracy = correct predictions / total predictions, where a call is correct if it performs the same database queries or modifications and returns the same results as the annotation; responses are scored with ROUGE-L (§3.3).
- **Call format:** `[ApiName(key1='value1', key2='value2', ...)]`; evaluation prompts are zero-shot (App. A Fig. 4, §7.3).
- **Training-set generation (§4, Fig. 3):**
  1. Agent 1 generates domains (e.g., healthcare, fitness).
  2. Agent 2 generates APIs for a domain, with examples from the public-apis GitHub list in its input.
  3. Agent 3 selects one or more APIs and an ability, then writes a matching query.
  4. Agent 4 makes the API calls, simulates their execution, and writes the response.
  5. Agent 5 (tester) checks the design principles and discards 35% of instances; the authors' inspection of the discarded data found that 78% of it violated the principles (§5).
- **Statistics (Table 2):** training 1,000 domains, 2,138 APIs, 1,888 dialogues, 5,221 turns, 2.76 turns per dialogue (Call 720 / Retrieve+Call 719 / Plan+Retrieve+Call 449); evaluation 8 domains, 73 APIs, 314 dialogues, 914 turns, 2.91 turns per dialogue (214 / 50 / 50). The training set has 4,149 API calls (§1). Combined: 1,008 domains, 2,211 APIs, 2,202 dialogues, 6,135 turns (§5).
- **Main results (Table 3, accuracy):**

| Model | Call | Retrieve+Call | Plan+Retrieve+Call | Total |
|---|---|---|---|---|
| Alpaca-7B | 24.06% | 5.19% | 0.00% | 15.19% |
| ChatGLM-6B | 23.62% | 13.33% | 0.00% | 16.42% |
| GPT-3 Davinci | 0.50% | 1.48% | 0.00% | 0.57% |
| GPT-3.5-turbo | 59.40% | 38.52% | 22.00% | 47.16% |

## Findings relevant to generality, negative feedback, agentic training
- **Distribution shift by design:** training data is LLM-generated over 1,000 domains while the evaluation set is human-annotated over 8 domains; the authors use this to assess generalization of models trained on the training set (§5).
- **Narrowing after fine-tuning (Result, single study):** 61.38% of Lynx's errors are API hallucination, calling APIs that do not match the ground truth, including APIs seen in training but not provided in the prompt (Table 5, §7.3). For Alpaca before fine-tuning the largest error type is "No API Call" at 36.77% (Table 4).
- **Frontier-model failure mode:** 67.86% of GPT-4 errors are failed API retrieval, and GPT-4 sometimes issues several calls at once against the prompt instruction (Table 6, §7.3).
- **Negatives:** the tester agent discards 35% of generated instances and 21.5% of human-annotated dialogues are discarded; discarded data is not used in training (§3.2, §4).
- **Not tested:** Lynx's general (non-tool) capabilities and larger fine-tuned models (§9 Limitations: only Lynx-7B was fine-tuned).
