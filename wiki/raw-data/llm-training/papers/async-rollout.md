# Async Rollout for LLM RL — OpenRLHF Async + verl Async
- **Core Insight:** Synchronous RL training leaves the GPU rollout engine idle during optimizer steps (and vice versa). Decoupling rollout and training into two asynchronous processes connected by a queue recovers most of that idle time — at the cost of a bounded off-policyness of ≤1 generation-cycle, which importance-sampling correction handles cleanly.
- **Guideline:** For any RL run >30 min, use async rollout. The staleness is bounded by the queue depth (usually 1–2); IS correction + vLLM-trainer logprob-difference monitoring (`vllm_kl`) keeps it safe. Expect 1.6–2.0× throughput vs sync.
- **Authors / Sources:** (i) OpenRLHF async PPO — Hu et al. 2024 ("OpenRLHF: An Easy-to-use, Scalable and High-performance RLHF Framework", https://arxiv.org/abs/2405.11143, §3.3 async); (ii) verl async architecture — ByteDance Seed team 2024 (https://arxiv.org/abs/2409.19256 "HybridFlow: A Flexible and Efficient RLHF Framework", §4); (iii) Ape-X / IMPALA ancestry (Espeholt 2018, https://arxiv.org/abs/1802.01561).

## Abstract (synthesized)
Async actor-learner architectures split generation and learning into independent processes connected by a bounded queue. OpenRLHF's async PPO (Hu 2024) implements this with Ray actors for rollouts, a trainer actor with a `rollout_queue`, and a `vllm_lock` that protects weight broadcasts. verl's HybridFlow (2024) generalizes this with a declarative dataflow graph so the same code supports sync, async, and partial-rollout modes. Both trace their lineage to IMPALA / Ape-X. The resulting policy is *bounded-off-policy* — the rollout was generated by π_{t−k} for small `k` — and this bias is corrected via V-trace-style (or truncated IS) weights in the loss. Practical deployments report 1.6×–2× throughput improvements over sync on 8×H100 setups for ~7B models.

## Key Contributions
- **OpenRLHF async loop:**
  - `RolloutActor` runs an infinite `fit` method that blocks on `rollout_slots.get()`, generates with vLLM, and pushes to `rollout_queue`.
  - `TrainingActor` consumes from `rollout_queue`, runs one PPO step, and pushes a slot token back.
  - Weight broadcast is gated by `vllm_lock` to prevent in-flight generation from running on mixed weights.
  - Partial-rollout mode allows incomplete generations to be interrupted when weights update.
- **verl HybridFlow:**
  - Async vLLM server (see [[verl-rollout]]) exposes per-request `generate(..., priority=...)`.
  - `engine to paused state` hook interrupts decoding for a weight broadcast, then resumes.
  - Dataflow graph lets the framework scale from single-GPU sync to multi-node async without code changes.
- **Bounded staleness + IS correction:** both frameworks monitor the rollout-vs-train logprob gap (`vllm_kl` in OpenRLHF) and apply TIS / iCEPO masks; see [[openrlhf-ppo]].

## Technical Details
- **OpenRLHF async primitives (from `openrlhf/trainer/ppo_trainer_async.py`):**
  - `rollout_queue`: `ray.util.queue.Queue`, capacity 1–2.
  - `rollout_slots`: companion queue carrying `global_step` tokens (backpressure).
  - `vllm_lock`: `ray` asyncio.Lock to serialize weight-broadcast vs generate.
  - Partial-rollout flag: `strategy.args.train.partial_rollout_enable`.
- **verl async primitives (from `verl/workers/rollout/vllm_rollout/vllm_async_server.py`):**
  - `engine.generate(...)` is async-for-iterated per-request.
  - `priority` parameter reorders in-flight requests.
  - Pause state (≈ line 628) blocks new generates and waits for in-flight to drain before a weight broadcast.
- **Staleness bound:** `k = queue_depth + partial_rollout_depth`; typical k=1–2.
- **Correctness tools:**
  - Per-token IS weight `exp(logπ_train − logπ_rollout)`, clipped to `[low, high]`.
  - Sequence-level mask when the IS weight exits `[low, high]` for any token.
  - Drop the rollout entirely if the sequence IS weight exceeds a hard cap.
- **Failure signature:** `vllm_kl` divergence > 0.1 plus PPO clipfrac pegged at 1 indicates the async staleness + sampler-mismatch has exceeded what IS correction can handle.

## Connections
- The async + IS correction pattern is used by every 2025 production RL stack (verl, OpenRLHF, TRL's forthcoming async trainer, NeMo-Aligner).
- Direct descendant of IMPALA V-trace — the IS-weight clip is mathematically the same object.
- Synchronous counterpart is the default flow in [[trl-ppo]].
- Deeply interacts with [[openrlhf-ppo]] IS-correction branches (TIS / iCEPO / seq-mask-tis).
- Partial rollout (continue a response after weight update) is a small but growing line — enables "continuous batching RL" where rollouts are never fully discarded and the trainer never waits.
