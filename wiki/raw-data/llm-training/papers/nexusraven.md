# NexusRaven-V2: Surpassing GPT-4 for Zero-shot Function Calling
- **Core Insight:** Nexusflow reports that NexusRaven-V2-13B, a fine-tune of CodeLlama-13b-Instruct, exceeds GPT-4 by 7% in function-calling success rate on human-generated cases with nested and composite functions, and that its training used no data generated by proprietary LLMs (model card, "Introducing NexusRaven-V2-13B").
- **Guideline:** When training data must be free of proprietary-model outputs, the V1 release splits data generation into simpler steps run by open models, because a single open generator (CodeLLaMA-34B-instruct) produced correct VirusTotal calls 48.3% of the time versus 80.8% for GPT-4 (V1 blog, "Data Curation with Multi-step Refinement"); no ablation of the pipeline is published.
- **Authors:** Nexusflow.ai team (organization, per the citation block of both releases). A related workshop paper, "NexusRaven: a commercially-permissive language model for function calling" (Venkat Krishna Srinivasan, Zhen Dong, Banghua Zhu, Brian Yu, Hanzi Mao, Damon Mosk-Aoyama, et al.; NeurIPS 2023 workshop; openreview.net/forum?id=Md6RUrGz67), is cited by [[bfcl]] and [[apigen]] but could not be retrieved for this check.
- **Year:** 2023 (V2 model repo created 2023-12-04; V1 blog dated 2023-09-28)
- **URL:** https://huggingface.co/Nexusflow/NexusRaven-V2-13B ; https://github.com/nexusflowai/NexusRaven-V2 ; predecessor https://huggingface.co/Nexusflow/NexusRaven-13B
- **Source type:** model/dataset card (official), with official GitHub README; V1 official blog
- **Relevant topics:** function calling, nested and parallel calls, commercially permissive synthetic data, CodeLlama fine-tune, function-calling evaluation

## Summary
NexusRaven-V2-13B is a 13B open-weights model that reads Python function signatures with docstrings and a user query, and emits a Python-syntax call. The model card states that it produces single calls, nested calls (the argument of the outer call is the result of another call), and parallel calls, and can append a natural-language explanation of the call. It states that the functions used in evaluation were never in training. Neither the V2 model card nor the V2 GitHub README describes the training data, its size, or the training hyperparameters; the V2 blog linked from both could not be fetched. The predecessor NexusRaven-13B (September 2023) blog describes a four-step data pipeline built on CodeLLaMA-34B-instruct and LLaMA-70B-chat, and a demonstration-retrieval inference system.

## Key Contributions
- Open 13B function-calling model covering single, nested, and parallel calls (V2 README, "Introducing NexusRaven-V2").
- Nexus Function Calling Benchmark: 9 tasks on real-world APIs, 8 released and 1 (The Stack API) kept internal "to ensure generalizability" (V2 README, "Benchmarks").
- Classification of benchmark tasks into single, parallel, and nested calls (V2 README, "Task Classification").
- Training data without proprietary-LLM generations (V2 model card; V1 blog TL;DR).
- V1: multi-step data refinement with open models, plus retrieval of demonstrations at inference (V1 blog).

## Technical Details
**V2 release**
- Base model: codellama/CodeLlama-13b-Instruct-hf; 13B parameters, BF16 safetensors (HF model tree and metadata, revision a6b84dc).
- Prompt: one `Function:` block per Python function, then `User Query: {query}<human_end>`; output `Call: ...<bot_end>` followed by `Thought: ...` (model card, "Quickstart"). Stopping at `<bot_end>` omits the explanation (same section).
- Parallel calls are enabled by adding `Setting: Allowed to issue multiple calls with semicolon\n` to the prompt; otherwise the model "will focus on nested and single calls primarily" (model card, "Quick Start Prompting Guide").
- Recommended decoding: sampling off and temperature ~0.001 (same section). The card reports that users found a no-op function with one argument works best for irrelevant queries (same section).
- Benchmark categories: OTX, NVDLibrary, VirusTotal = single; VirusTotal-Nested, Places API, NVDLibrary-Nested = nested; VirusTotal-Parallel = parallel; Climate = nested and parallel; The Stack API = mostly single (V2 README, "Task Classification").
- Headline claim wording: "surpasses GPT-4 by 7%" (model card) and "by up to 7%" (GitHub README), on human-generated nested and composite cases.
- Reproducibility note: GPT-4 outputs are not deterministic, per-task GPT-4 accuracy varies between reruns, and category averages are "relatively stable within a few percent" (V2 README, "Reproducing The Results").
- Stated limitations: many functions saturate the context window (use a retriever); calls and explanations can be incorrect (model card, "Limitations").

**V1 release (NexusRaven-13B)**
- Pipeline (V1 blog, "Data Curation with Multi-step Refinement"): (1) mine tuples of function definition, docstring, and calling code; CodeLLaMA-34B-instruct writes a capability description of each function; (2) LLaMA-70B-chat writes a natural-language query for the mined call; (3) CodeLLaMA-34B-instruct writes CoT traces for argument values, and the call is regenerated from the CoT and query; (4) embedding models attach a list of similar candidate functions.
- CodeLLaMA-13B VirusTotal accuracy: 38% → 72% after data curation and instruction tuning; 72% → 94% with demonstration retrieval from a corpus averaging 16 examples per API function, 4-shot (V1 blog, "Demonstration Retrieval Augmentation").
- With retrieval: 95% success on cybersecurity tools vs 64% for the GPT-4 function-calling API (V1 blog, TL;DR); up to 30% higher than GPT-4 on CVE/CPE Search and VirusTotal V3 (V1 blog, Figure 2 text).
- Zero-shot: 4% higher than GPT-3.5 in the generic domain; 16% above CodeLLaMA-13B-instruct and 60% above other open-source models in the cybersecurity domain (V1 blog, "Performance of the Zero-shot Model").
- Evaluation: the generic domain uses filtered ToolAlpaca-Simulated and ToolLLM data; cybersecurity uses CVE/CPE Search, VirusTotal V3, and EmailRep with expert-curated answers; a call counts as correct when executed with arguments that exactly match ground truth (V1 blog, "Evaluation Dataset and Pipeline"). Released as Nexusflow/NexusRaven_API_evaluation (318 standardized queries, 65 standardized APIs; HF dataset viewer subsets).
- V1 was trained to produce an initial answer and then a reflection; the card recommends stopping at `\nReflection:` because the final answer "is seldom better than the initial call" (V1 model card, "Limitations").

## Findings relevant to generality, agentic training, distillation
- Generality: V2 states it was never trained on the evaluation functions and keeps one benchmark task unreleased to detect overfitting (V2 README, "Introducing NexusRaven-V2", "Benchmarks"). V1 states that fine-tuning on a target tool's corpus can "risk weakening some capabilities" and uses retrieval of demonstrations instead; the risk is not measured (V1 blog, "Demonstration Retrieval Augmentation").
- Agentic training: V1 "primarily emphasizes single-round interactions", with multi-round capability left to future work (V1 blog, "Conclusion and Future Steps"). V1 zero-shot evaluation does not let models observe results of incorrect calls, because such calls can have side effects in real software (V1 blog, "Performance of the Zero-shot Model").
- Distillation: V1 does not distill GPT-3.5/4 outputs because of license terms, and instead distills from open 34B and 70B models into a 13B model through a multi-step pipeline (V1 blog, "Data Curation with Multi-step Refinement").
