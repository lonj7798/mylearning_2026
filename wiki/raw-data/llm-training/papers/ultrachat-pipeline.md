# UltraChat Pipeline: Scalable Synthetic Multi-Turn Dialogue Generation
- **Core Insight:** UltraChat showed that you can synthesize a large general-assistant chat corpus without human-written seed conversations by separating user and assistant roles, grounding generation in a hand-designed sector/topic taxonomy, and iterating the dialogue turn by turn.
- **Guideline:** If you want scalable synthetic dialogue data, do not start from random self-chat; first define a topic/task taxonomy, then use separate generator roles, sector-specific prompt scaffolds, controlled turn counts, and a cleanup/filter stage before training.
- **Authors:** Ning Ding, Yulin Chen, Bokai Xu, Yujia Qin, Zhi Zheng, Shengding Hu, Zhiyuan Liu, Maosong Sun, Bowen Zhou
- **Year:** 2023
- **URL:** https://arxiv.org/abs/2305.14233
- **Relevant topics:** synthetic data, dialogue synthesis, multi-turn chat, taxonomy-driven generation, instruction tuning, UltraLM

## Abstract
UltraChat is a systematically designed synthetic conversation dataset for chat-model fine-tuning. The paper frames the goal as covering the breadth of interactions a human might have with an AI assistant without relying on human-written queries. The resulting corpus contains about 1.5 million multi-turn dialogues generated iteratively, with public construction details centered on sector design, prompt scaffolds, and two-model role play.

## Key Contributions
- Introduces a large-scale synthetic dialogue pipeline where both the user side and assistant side are generated by LLMs rather than copied from existing prompt corpora.
- Organizes coverage through three sectors: `Questions about the World`, `Writing and Creation`, and `Assistance on Existent Materials`.
- Uses separate ChatGPT Turbo API roles for user-query generation and assistant-response generation, which is more structured than single-model self-chat.
- Makes the data multi-turn by recursively generating the next user turn conditioned on prior dialogue history rather than stopping at one instruction-response pair.
- Publishes a concrete output format and sector-specific generation recipe that later synthetic dialogue and preference pipelines build on.

## Technical Details
**What is synthetic:** public sources are explicit that both the instructions/queries and the assistant responses are automatically generated. The dataset card says UltraChat uses `two separate ChatGPT Turbo APIs`, one for generating user queries and one for generating responses. The repo also states that the system does not directly use internet prompts as prompts for generation, except that one sector starts from existing source material.

**What models generate it:** the public artifacts describe the generators as `ChatGPT Turbo APIs` / `Turbo APIs` and do not give a more granular model snapshot in the released documentation. The important modeling choice is not a specific checkpoint but the use of two separate role-conditioned API calls instead of one model talking to itself with a shared prompt.

**Top-level pipeline:**
1. Define a broad conversation taxonomy split into three sectors.
2. Build sector-specific prompt scaffolds instead of one generic generation prompt.
3. Use one model call to generate or simulate the next user turn.
4. Use a second model call to answer as the assistant.
5. Iterate this process to form a multi-turn conversation.
6. Apply post-processing and filtering before release.

**Sector 1: `Questions about the World`**
- Starts from `30` representative meta topics.
- Expands them into `1100+` subtopics.
- For each subtopic, generates up to `10` specific questions.
- Then uses Turbo APIs to generate additional relevant questions from those seeds with hand-crafted prompts designed for diversity.
- A second branch covers common entities: the repo says they gather the top-frequent `10,000` named entities from Wikidata, generate `5` meta-questions per entity, then expand each into `10` specific questions and `20` related general questions.
- Dialogues in this sector are then rolled out as `3-7` rounds using the two models iteratively.

**Sector 2: `Writing and Creation`**
- Starts from `20` writing/creation types.
- For each type, generates `200` instructions that ask an assistant to create text.
- The repo states that `80%` of these instructions are expanded and detailed further.
- Each generated instruction becomes the initial user input for a `2-4` round dialogue, typically resembling draft-and-revise interaction rather than fact lookup.

**Sector 3: `Assistance on Existent Materials`**
- Starts from existing source passages rather than pure blank-sheet prompts.
- The repo says it extracts about `~100k` diverse materials from `C4`.
- For each material, the pipeline generates up to `5` questions or instructions.
- It then combines the material with those questions via manually designed templates to form the initial user turn.
- Each such seed becomes a `2-4` round dialogue for tasks like rewriting, continuation, summarization, and inference.

**Multi-turn construction logic:** UltraChat matters because it is not just synthetic instruction-response pairs. The public recipe repeatedly conditions on dialogue history so the generated user asks follow-up questions, requests revisions, changes constraints, or continues discussion after seeing the assistant answer. That makes the training signal closer to real assistant interaction than flat single-turn datasets.

**Filtering and post-processing:** the public sources confirm that the generated dialogues undergo `post-processing and filtering`, but they do not publish a thresholded quality-control pipeline with exact rejection rules, reward-model scoring, or classifier-based filters. So the safe reading is:
- there is definitely a cleanup/filter pass before release
- the released artifacts are concrete on taxonomy and generation flow
- they are not concrete on exact filtering heuristics or thresholds

For practical study, UltraChat is therefore more informative as a **generation-protocol reference** than as a fully transparent filtering recipe.

**Data shape:** the released dataset card says each example is a JSON dictionary with:
- `id`: sample identifier
- `data`: a list of alternating turns

The list format stores the conversation as raw utterance strings rather than message objects with explicit roles. The public preview shows list lengths from `4` to `14`, which is consistent with the documented `2-4` and `3-7` round sector recipes.

**Why UltraChat matters technically:**
- It is an early clean example of **taxonomy-first synthetic data design**.
- It shows how to scale chat data without scraping prompt corpora directly.
- It separates user simulation from assistant answering, which becomes a recurring pattern in later synthetic dialogue and preference pipelines.
- It helped establish synthetic multi-turn dialogue as a practical substitute for scarce human-authored chat transcripts.

## Connections
- UltraChat is an early large-scale successor to smaller instruction-synthesis efforts like [[self-instruct]], but specialized for multi-turn chat rather than single-turn instruction pairs.
- It connects directly to [[ultrafeedback-construction]], where prompts drawn from UltraChat are reused for preference-data collection.
- It anticipates later taxonomy-heavy synthetic pipelines such as [[glan]] and persona-based expansions such as [[persona-hub]].
- It is a useful precursor to later high-scale synthetic mixtures that care more about curation, verification, or role realism than UltraChat's publicly documented filter stage.
