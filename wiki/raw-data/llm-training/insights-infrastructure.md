# Insights — Infrastructure

- Framework defaults are facts about the framework, not about the algorithm, and they differ. At the pinned commits none of verl, OpenRLHF, or TRL adds an entropy term to the loss by default (verl `entropy_coeff: 0`, OpenRLHF `entropy_coef` None, TRL PPO and GRPO have no entropy term) ([[entropy-logging-patterns]]); TRL's `PPOTrainer` subtracts a per-token KL penalty with default `kl_coef` 0.05 and uses a separate value head ([[trl-ppo]]), while OpenRLHF's `PolicyLoss` supports separate lower and upper clip ranges, dual clip, and importance-sampling weights ([[openrlhf-ppo]], [[verl-ppo-loss]]). TRL's `GRPOTrainer._compute_loss` implements eight `loss_type` values that differ in the per-token surrogate ([[trl-grpo]]).
- The sampler and the learner do not agree on token probabilities, and the disagreement is large enough to change training. With the same parameters, the vLLM sampler and the FSDP learner in verl assign different probabilities to the same tokens, with a maximum difference of 1.0 on DAPO with Qwen2.5-32B ([[rollout-training-mismatch-tis]]). The underlying cause of run-to-run nondeterminism is that reduction kernels are not batch-invariant and server load changes the batch size ([[thinkingmachines-defeating-nondeterminism]]). **Replicated** across an RL-training and an inference-serving measurement.
- Decoupling generation from training is the measured throughput lever in RL. Full decoupling reduces end-to-end training time by up to 2.77× at matched accuracy (1.5B math: 14.8 h against 41.0 h, 42.2 against 42.0 score) ([[areal-async-rl]]); OpenRLHF's async mode runs rollout and training as two Ray actors joined by a queue of capacity `--train.async_queue_size`, default 1 ([[async-rollout]]); a fully asynchronous disaggregated stack with in-flight weight updates and a bounded off-policy horizon is the 2026 production shape ([[intellect-3]], [[verl-rollout]]).
- Agent RL needs a transition format before it needs an algorithm. Treating each LLM call as one action and storing executions as (input, output, reward) transitions, with the episode's return assigned to every call, is what lets an arbitrary agent framework be trained by an RL trainer ([[agent-lightning]]); grouping actions taken from the same recurring environment state across a trajectory group yields a step-level advantage at no extra rollout cost ([[gigpo-verl-agent]]).
- Memory and throughput at the SFT stage are set by sharding and packing. FSDP keeps parameters sharded except for the unit currently computing, so peak parameter memory is O(Σψ_i/F + max_i ψ_i), and DDP ran out of memory above a size where FSDP did not ([[fsdp-sft]]); packing removes the 4.17 billion padding tokens of 8.33 billion in the length-512 Wikipedia BERT corpus ([[sequence-packing]]); mixed precision with loss scaling matches FP32 accuracy and global-norm clipping bounds the update ([[mixed-precision]], [[gradient-clipping]], [[large-batch-training-noise-scale]]).
- Reproducing a published RL result requires the run's exact configuration, and two open projects publish it. Reproducing PPO's published results requires matching 37 implementation details of the `openai/baselines` `ppo2` code that the paper does not describe ([[costa-huang-ppo-details]]); Ai2 publishes "(almost) the exact command" per Tülu 3 checkpoint ([[open-instruct-allenai-recipes]]) and maps 17 Olmo 3 post-training runs to launch scripts and run records ([[allenai-olmo3-open-instruct-scripts]]); the k3 estimator `(r − 1) − log r` is the KL diagnostic these runs log ([[john-schulman-kl-tricks]], [[hf-alignment-handbook]]).
