# Think Less, Achieve More: Cut Reasoning Costs by 50% Without Sacrificing Accuracy
- **Core Insight:** One epoch of SimPO on 10K preference pairs generated by Sky-T1-32B-Preview itself reduced average output length by 37% on AIME24 (6881 → 4365 tokens) and by 57% on LiveCodeBench-Hard (14564 → 6199 tokens), with accuracy unchanged at 43.3 and 17.9 (Results table).
- **Guideline:** When shortening a long-CoT model with length-preference pairs, add pairs whose rejected response is a short incorrect answer and add pairs from each target domain, because shortest-vs-longest-correct math pairs alone lowered AIME24 from 43.3 to 36.7 and LCB-Hard from 17.9 to 13.5 (Ablations table), and the post reports that 1K short-incorrect pairs restored math accuracy and 500 TACO pairs restored coding accuracy (Stage 1).

## Summary
The post releases Sky-T1-32B-Flash, a preference-optimized version of Sky-T1-32B-Preview. It defines overthinking as a reasoning model's tendency to produce unnecessarily long responses with redundant reasoning steps, often several proposed solutions each followed by transitions such as "Alternatively", "But wait", or "Let me reconsider" (What is overthinking?). For "What is 1+1?", Sky-T1-32B-Preview produces over 1000 tokens and more than 10 such transitions (same section). Underthinking is the opposite failure: the model proposes a final solution without validating it enough, which the post expects on the hardest benchmarks (How to reduce overthinking?). The recipe has three stages: data generation, response rewriting, and preference optimization. The team released the pipeline code, the 10K preference pairs, and the weights (introduction).

## Key Contributions
- Self-generated length-preference pairs: shortest correct response as chosen, longest correct response as rejected (Stage 1).
- Recipe Enhancement #1: 1K "short incorrect vs longer correct" (SILC) pairs to prevent underthinking on hard problems (Stage 1).
- Recipe Enhancement #2: 500 coding pairs from TACO, which improved coding accuracy and further reduced coding length (Stage 1).
- Recipe Enhancement #3: rewriting math chosen responses to the first correct sub-solution plus one more (FCS+1) (Stage 2).
- Ablations comparing SimPO, DPO, and SFT on the shortest responses (Stage 3; Ablations table). Total cost about $275 on 8xH100 (introduction).

## Technical Details
**Stage 1, data generation (Stage 1).** Sky-T1-32B-Preview generates 8 responses at temperature 1.0 for each of the 12K PRM800K questions. From each set, the shortest correct response is the positive and the longest correct response is the negative ("LS" pairs); the other responses are discarded. Questions with fewer than 2 correct responses are discarded. With LS pairs only, MATH500, GPQA, and MMLU mostly kept accuracy, but LCB-Medium, LCB-Hard, AIME24, and MATH500 Level 5 lost accuracy. The fix adds 1K pairs from the same samples: negative = shortest incorrect response; positive = shortest correct response that is longer than the negative. Math-only data reduced coding length by more than 25% with LCB-Easy accuracy maintained, but LCB-Medium and LCB-Hard dropped; 500 TACO pairs (8 samples at temperature 1.0, shortest vs longest correct) were added. Stage 1 took about 8 hours on 8xH100-80GB, about $190.

**Stage 2, response rewriting (Stage 2).** Llama3.3-70B splits a response into sub-solutions and rewrites it to keep the first correct sub-solution (FCS) plus one additional sub-solution (+1). The extra sub-solution keeps the long-CoT structure. FCS alone lost accuracy; FCS+Reflection (up to the second correct solution) gave longer outputs than FCS+1 (Recipe Enhancement #3); numbers for FCS and FCS+R are not printed. Coding responses were not rewritten because they almost never contain multiple complete code blocks. Stage 2 took about 1 hour, about $25.

**Stage 3, preference optimization (Stage 3).** SimPO ([[simpo]]) uses a length-normalized implicit reward and no reference model. Training starts from Sky-T1-32B-Preview, 1 epoch, batch size 96, with Llama-Factory. Grid: learning rate {1e-7, 5e-7, 1e-6}, gamma {0.3, 0.5, 1.0}, beta {2.0, 2.5}; best: 5e-7, 0.3, 2.0. The post states that SimPO results were sensitive to these settings. SFT on the shortest responses reduced lengths by less than 5%. Stage 3 took about 2.5 hours, about $60. The HF model card adds DeepSpeed ZeRO-3 Offload.

## Findings relevant to generality, negative feedback, distillation
**Generality.** Pairs come from math (PRM800K) and code (TACO) only. On GPQA Diamond and MMLU, which were not training domains, accuracy moved 56.8 → 56.6 and 82.4 → 81.7 while length fell 39% and 17% (Results table). The post's "MMLU" hyperlink points to the TIGER-Lab/MMLU-Pro dataset; which one was evaluated is not stated. Math-only pairs transferred a length reduction to coding (more than 25%) but cut LCB-Medium and LCB-Hard accuracy (Stage 1; Ablations table).

**Negative feedback (terms from the course standard §6.1).** Both rejected-response types enter the SimPO loss as dispreferred responses, which is negative as gradient: (a) the longest correct response, which is penalized only for length, and (b) the shortest incorrect response. Using (a) alone produced underthinking on the hardest benchmarks; adding (b) restored AIME24 (Ablations table). For an LS pair, the other 6 of the 8 samples are discarded (Stage 1). SFT on the shortest responses, which uses no rejected responses, reduced length by less than 5% (Stage 3).

**Distillation (self-generated data).** Stage: preference optimization after long-CoT SFT (Sky-T1-32B-Preview). Prompt types: competition-style math questions (PRM800K) and coding problems (TACO; question count not reported). Teacher and sampling: the model itself, 8 samples at temperature 1.0; a second model (Llama3.3-70B) rewrites chosen math responses. Quality control: correctness filter (the checker is not described), at least 2 correct samples, FCS+1 pruning.
