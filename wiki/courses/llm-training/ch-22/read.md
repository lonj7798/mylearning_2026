# Chapter 22 — Quality, Diversity, and Gradient-Based Data Selection

> **Core insight.** Selection methods that score each sample on one property (LLM-rated accuracy, instruction-following difficulty, response length) improve judge-based instruction-following scores when a 1K–10K subset is taken from a 50K–300K pool, but in the same papers knowledge benchmarks such as MMLU fall and some task categories are removed at higher rates ([[alpagasus]] Table 2, §6; [[cherry-llm]] Tables 1, 6–7). When the pool grows to 5.8M samples and evaluation covers seven tasks, IFD, perplexity, and length selection average below random selection; in multi-task selection only three of seven methods reach balanced random, and a representation-similarity method (RDS+) stays above balanced random at every budget tested from 10K to 2.5M ([[instruction-data-selection-at-scale]] Tables 1–2, Fig. 4). Diversity terms raise worst-case performance ([[qdit-data-diversity]] §4.3), and gradient-space diversity predicts out-of-distribution accuracy in math and NLI ([[prismatic-synthesis]] Table 1).
>
> **Guideline.** When the selected set must support many tasks, compare every selector against balanced random selection and a longest-response baseline on a multi-task suite that includes non-judge benchmarks, because IFD and perplexity-based selection averaged 35.7–41.3 against 47.5 for balanced random when selecting 326K samples from the 5.8M Tülu 2 pool ([[instruction-data-selection-at-scale]] Table 2). When one target capability is known and a few examples of it exist, use gradient-based selection ([[less]]) and also report non-target benchmarks, because the paper evaluates only the targets. When a quality score is used, add a diversity term or per-source quotas and report per-category retention, because quality-only selection removed coding examples at 88% against 82% overall in [[alpagasus]] (§6). Treat IFD thresholds and rater thresholds as pool-specific hyperparameters.

## Why this chapter matters for a general-purpose model

Synthetic generation (ch-19 to ch-21) produces a pool that is larger than the SFT budget. Data selection is the step that chooses a subset of that pool for training. It sits between generation and SFT in the pipeline pre-training → mid-training → **synthetic generation → selection** → SFT → preference optimization → RL → evaluation, and the same scoring ideas reappear in RL prompt filtering (ch-16).

The measurable problem has three parts. First, a selector changes the task distribution of the training set, so it can raise one benchmark and lower another. Second, AlpaGasus, Cherry LLM, DEITA, QDIT, and Long Is More report their main gains with LLM judges, whose preferences correlate with response length ([[judge-llm-bias]]). Third, results obtained by selecting 10K samples from 50K–300K pools may not hold for 1M-sample pools and multi-task targets. For a general-purpose model, a selector is useful only if it beats random selection on a broad suite at the scale that will be used.

## §1 Baselines: random, balanced random, and length

**Definitions.** A *pool* D is the set of candidate (instruction, response) pairs. A *budget* n is the number of samples to keep. *Random selection* draws n samples uniformly from D. *Balanced random selection* draws uniformly across sources and redistributes the budget of exhausted sources ([[instruction-data-selection-at-scale]] §3). *Length selection* keeps the n samples with the longest responses ([[long-is-more-for-alignment]]).

**Why baselines come first.** A selector is a claim that its score correlates with the training value of a sample. Random selection controls for the budget. Balanced random selection controls for source imbalance, which matters because the unfiltered Tülu 2 pool is dominated by FLAN and Open Orca data ([[instruction-data-selection-at-scale]] §3.2). Length selection controls for the judge preference for longer outputs.

**Evidence that data quantity alone does not raise judged quality.** In the LIMA ablation, LLaMA 7B was trained on exponentially increasing Stack Exchange sets, and ChatGPT graded helpfulness on a 1–6 scale; doubling the training set did not improve the score, while prompt diversity (Stack Exchange vs wikiHow) and response filtering (a 0.5-point difference) did ([[lima]] arXiv:2305.11206 §5, Figs. 5–6). **Result (single study).**

**Limit of that evidence.** The LIMA ablation measures helpfulness with a judge. On objective benchmarks, post-training performance on GSM8K, multihop QA, coding, and IFEval rises as a power law in the number of fine-tuning examples, and style and format saturate within about 100 examples while reasoning accuracy continues to improve ([[revisiting-superficial-alignment-hypothesis]] §2, Fig. 1). The Tülu 3 SFT mix contains 939,344 prompts ([[tulu-3-sft-mix]]). "Small curated sets are enough" therefore depends on the evaluation and the capability. **Replicated** as a caution by two sources that use objective benchmarks ([[revisiting-superficial-alignment-hypothesis]]; [[instruction-data-selection-at-scale]]).

## §2 LLM-rated quality: AlpaGasus

**Definition.** An LLM rater G receives an instruction, input, and response with a prompt p_G and returns a score. The kept set is

```
S = { x ∈ V : G(x, p_G) ≥ τ }        (AlpaGasus Eq. 1)
```

V is the instruction dataset, x one (instruction, input, response) triplet, and τ the threshold.

**Problem addressed.** Alpaca's 52,002 responses were generated by text-davinci-003 without response-level checks, so some are incorrect or unrelated to the instruction ([[alpagasus]] Abstract).

**Mechanism.**
1. ChatGPT scores each triplet from 0 to 5 on one named dimension ("accuracy" in the main runs) and writes the score on the first line (Fig. 3).
2. The score histogram is read: <3: 172; 3: 1,550; 3.5: 10,811; 4: 30,240; 4.5: 9,218; 5: 11 (Fig. 4).
3. τ = 4.5 is chosen "according to the score histogram" and keeps 9,229 examples, 17.75% of the data (§2.3, §4.1).
4. LLaMA is trained on the kept set with the Alpaca script.

**Worked example.** From the histogram, τ = 4.5 keeps 9,218 + 11 = 9,229 examples. Moving τ to 4.0 adds the 30,240 examples at 4.0 and keeps 39,469, which the paper reports as the 39k subset. A 0.5 change in τ multiplies the kept set by 4.3 because the histogram mode (30,240 examples at 4.0) is included at τ = 4.0 and excluded at τ = 4.5.

**Evidence.** Against Alpaca-52k with GPT-4 as judge, the 9k model has more wins than losses on all four test sets at 7B (for example WizardLM 83/65/70 W/T/L) and 13B (Fig. 5), and it beats a random 9k subset (Fig. 6). 7B training time fell from 80 to 14 minutes (Table 5). **Result (single study).**

**Conditions and limits.**
- MMLU fell from 40.86 to 38.78 (7B) and from 47.89 to 46.12 (13B); BBH, DROP, and HumanEval rose by 0.12–0.75 points (Table 2).
- Coding examples were removed at 88.16% (718 → 85) against 82.25% overall, and AlpaGasus-7B was not better on 7 of 29 WizardLM skills, including coding (§6).
- The rater cannot execute code or check math, and the paper does not report the rater model version or temperature.

**Implication for a general-purpose model.** A rater threshold changes category proportions. When a rater threshold is used for a general-purpose SFT set, per-category retention should be reported before training, because the coding share fell faster than the overall share in [[alpagasus]] (§6).

## §3 Instruction-Following Difficulty (IFD)

**Definition.** For a question Q (instruction and input) and answer A with N tokens, under a model with weights θ:

```
s(A|Q) = −(1/N) Σ_{i=1..N} log P(w_i | Q, w_1 … w_{i−1}; θ)     (Cherry LLM Eq. 3)
s(A)   = −(1/N) Σ_{i=1..N} log P(w_i | w_1 … w_{i−1}; θ)        (Eq. 4)
IFD(Q, A) = s(A|Q) / s(A)                                         (Eq. 5)
```

w_i is the i-th answer token and θ the weights of the scoring ("pre-experienced") model. [[superfiltering]] (Eq. 2) writes IFD as PPL(y|x)/PPL(y), where PPL = exp(mean token loss). The card [[ifd]] repeats the perplexity form; this chapter uses the loss-ratio form that Cherry LLM's released script computes ([[cherry-llm]], Cherry_LLM@01fac8d `cherry_seletion/data_by_IFD.py` L103–L120).

**Problem addressed.** Scoring with an external rater is costly and inherits the rater's limits. IFD uses only the model's own losses.

**Mechanism.**
1. Train a pre-experienced model for 1 epoch on 1,000 samples chosen as 10 per cluster from 100 K-means clusters of instruction embeddings (§2.1).
2. Compute s(A|Q) and s(A) for every sample (two forward passes).
3. Remove samples with IFD > 1, where the instruction makes the answer harder to predict (§2.2).
4. Sort the rest and keep the highest IFD values: the samples where the instruction helps least (§1, §2.2). The paper recommends the top 10% (App. G.2).
5. Train the base model on the kept set.

**Worked example (from the paper).** "Give a brief description of the coronavirus." has s(A) = 0.761 and s(A|Q) = 0.696, so IFD = 0.696 / 0.761 = 0.915. "What emotion is expressed in this tweet?" with answer "Frustration" has IFD = 0.601 / 6.593 = 0.091 ([[cherry-llm]] App. F, Fig. 9). Cherry LLM ranks the first sample above the second: the instruction reduces the loss of "Frustration" by a factor of 11, so the second sample is easy once the instruction is given.

**Worked example (the two definitions disagree).** Sample A: s(A|Q) = 0.2, s(A) = 0.4. Loss ratio 0.50; perplexity ratio exp(0.2 − 0.4) = 0.82. Sample B: s(A|Q) = 3.0, s(A) = 4.0. Loss ratio 0.75; perplexity ratio exp(−1.0) = 0.37. The loss ratio ranks B above A, and the perplexity ratio ranks A above B. A reimplementation must state which form it uses (derived).

**Evidence.** LLaMA-7B trained on 5% of Alpaca (by IFD) scores 52.06 Open LLM average and 34.74 AlpacaEval against 50.21 and 26.46 for official Alpaca (Table 1). At 5%, IFD selection averages 52.06 against 50.61 for random, 49.48 for K-means diversity, and 50.77 for low IFD (App. B Table 5). **Result (single study).**

**Conditions and limits.**
- MMLU fell from 41.73 to 36.51 (5% Alpaca) and from 37.75 to 33.08 (10% WizardLM) on LLaMA-7B (Tables 1, 3).
- The 5% Alpaca model is worse than official Alpaca on Math and Coding; the 10% WizardLM model is worse on Math, Code, Complex Format, and Counterfactual (App. C, Tables 6–7).
- Selection concentrates on open-ended generation ("write story" 119 in the top 5%) and removes editing tasks ("rewrite sentence" 155 in the bottom 5%) (Table 4).
- IFD uses only losses on the given answer; the paper does not check whether kept answers are correct (Eq. 3–5).
- At 5.8M-sample scale, IFD averages 35.8 across seven tasks against 40.7 for random selection, with SQuAD at 46.6 against 83.6 ([[instruction-data-selection-at-scale]] Table 1).

**Implication for a general-purpose model.** IFD prefers instructions whose answers are hard to predict from the instruction, which are mostly open-ended generation tasks. That preference raises judge scores and lowers extraction and knowledge scores. **Replicated** across [[cherry-llm]] (App. C) and [[instruction-data-selection-at-scale]] (§5, IFD selects more FLAN data and does well only on AlpacaEval).

The figure [figures/ifd-scatter.html](figures/ifd-scatter.html) lets the reader enter s(A|Q) and s(A), compare the loss-ratio and perplexity-ratio IFD, and see the Cherry LLM keep rule applied.

## §4 Weak-to-strong IFD: Superfiltering

**Definition.** Superfiltering computes IFD with a small pretrained model (GPT-2, 124M) instead of the model to be trained, and keeps the top k% of samples with IFD below 1 ([[superfiltering]] §3.3).

**Problem addressed.** IFD with LLaMA2-7B took 161 minutes on Alpaca, and a reward model took 1,400 minutes (Table 4).

**Mechanism.**
1. Compute IFD for every sample with GPT-2, with no further training (§3.3, §6.1).
2. Keep the top 5%, 10%, or 15% with IFD < 1.
3. Train LLaMA2-7B or 13B on the kept set.

**Formula (rank agreement).** Spearman's ρ = 1 − 6 Σ d_i² / (n(n² − 1)), where d_i is the difference between a sample's rank under the two scorers and n the number of samples.

**Worked example.** Five samples ranked (1, 2, 3, 4, 5) by LLaMA2-7B and (2, 1, 3, 5, 4) by GPT-2 give d² = 1, 1, 0, 1, 1, Σ = 4, and ρ = 1 − 24/120 = 0.80. With n = 5 and a top-2 budget, the two top sets are {1, 2} and {2, 1}: overlap 100%. The same ρ can come with low overlap in the top 5% of a large pool, which is why the paper reports overlap separately.

**Evidence.** IFD ρ between GPT-2 and LLaMA2-7B is 0.679, 0.788, and 0.802 on Alpaca, Alpaca-GPT4, and WizardLM-70k; top-15% overlap is 0.49, 0.51, and 0.61 (Table 1). LLaMA2-7B on 5% Alpaca (2,600 samples) scores 55.67 Open LLM average and 33.04 AlpacaEval against 55.25 and 27.75 for full data; MMLU is 45.21 against 47.02 (Table 2). Filtering took 8 minutes (Table 4). **Result (single study).**

**Conditions and limits.** Data chosen with LLaMA2-7B IFD beat Superfiltering data: Superfiltering's pairwise winning score against it is 0.853, 0.761, and 0.927 at 5/10/15% (Table 4). The proxy is cheaper but selects worse data than the target model.

**Implication for a general-purpose model.** A cheap proxy is appropriate when the pool is too large to score with the target model, but the proxy inherits every narrowing effect of IFD from §3.

## §5 Complexity, quality, and diversity: DEITA and QDIT

**DEITA definition.** DEITA scores each sample by s = c × q, where c is a complexity score and q a quality score, each predicted by a LLaMA-1 7B model trained on ChatGPT rankings of 6 evolved variants of 2K seed samples ([[deita]] §2.3–2.4). It then walks the pool in descending s and admits sample x only if

```
max_{y ∈ S} cos(e(x), e(y)) < τ,   τ = 0.9     (REPR FILTER, §2.5)
```

S is the selected set and e(·) the LLaMA-1 13B sentence embedding. Selection stops at m samples (Algorithm 1).

**QDIT definition.** QDIT measures the diversity of a subset A of pool V with the facility-location function and combines it linearly with quality ([[qdit-data-diversity]] Eq. 1, §3.2):

```
d(A) = Σ_{v ∈ V} max_{a ∈ A} sim(a, v)
f(a | A, α) = (1 − α) · d(a | A) + α · q(a)
```

sim is the cosine similarity of instruction embeddings, d(a|A) the gain in d from adding a, q(a) the quality score (ChatGPT or a reward model), and α ∈ [0, 1]. QDIT adds the sample with the highest f at each step (Algorithm 1).

**Worked example (the two diversity rules).** Pool V = {v1, v2, v3} with sim(v1, v2) = 0.95, sim(v1, v3) = 0.10, sim(v2, v3) = 0.20, and quality q = (0.9, 0.8, 0.3). DEITA with τ = 0.9 sorts by quality: v1 is admitted; v2 is rejected (0.95 ≥ 0.9); v3 is admitted. QDIT with α = 0.5 starting from A = {v1}: d({v1}) = 1 + 0.95 + 0.10 = 2.05. Adding v2 gives d = 1 + 1 + 0.20 = 2.20, gain 0.15, f = 0.5·0.15 + 0.5·0.8 = 0.475. Adding v3 gives d = 1 + 0.95 + 1 = 2.95, gain 0.90, f = 0.5·0.90 + 0.5·0.3 = 0.60. QDIT picks v3. With α = 0.9, f(v2) = 0.735 and f(v3) = 0.36, so QDIT picks v2. DEITA's threshold is a hard rule; QDIT's α trades quality against coverage.

**Evidence (DEITA).** On LLaMA-1-13B at 6K samples, DEITA scores 6.46 MT-Bench and 77.08 AlpacaEval against 5.84 / 73.91 for random and 5.61 / 71.21 for Alpagasus (Table 5). DEITA-Mistral-7B with 6K SFT samples scores 7.22 / 80.78 against 5.89 / 56.90 for random 10K and 5.32 / 75.12 for the 200K zephyr-beta-sft (Table 6). On the Open LLM Leaderboard, DEITA-LLaMA1-13B 10K averages 64.27 against 60.14 for random 10K (Table 7). **Result (single study).**

**Evidence (QDIT).** Averaged over five pools with LLaMA-1 7B, quality-only selection decreased the lowest-10% winning score relative to random in two of five settings; QDIT improved worst-case reward-model score by 5.2% and worst-case winning score by 6.26% over quality-only selection (§4.3). On UltraChat 10K, quality-only selection lowered DROP from 26.24 (random) to 17.01, while QDIT scored 26.73 (Table 3). α ∈ {0.5, 0.7, 0.9} gave the best results; α = 0.1 and α = 1 were worse (§4.4). **Result (single study).**

**Conditions and limits.** DEITA's metric studies use GPT-4-judged MT-Bench only and report no seeds; the authors note AlpacaEval gains are not consistent with MT-Bench gains (§2.2, §3.3). Under DEITA selection, MT-Bench rises and then falls as m grows, and 3K samples match all 300K (Fig. 2). QDIT evaluates with Claude 2 as judge and a reward model, plus six benchmarks in Table 3. Neither paper tests pools above 1.3M samples.

**Implication for a general-purpose model.** Diversity terms protect the tail of the task distribution (worst-case prompts) more than the average. **Replicated** direction: quality-only selection narrows coverage in [[alpagasus]] (§6), [[cherry-llm]] (Table 4), and [[qdit-data-diversity]] (§4.3).

## §6 Gradient-based targeted selection: LESS

**Definition.** LESS (Low-rank gradiEnt Similarity Search) scores a training sample z by how well its training update aligns with the loss gradient of a small target validation set ([[less]] arXiv:2402.04333).

**Problem addressed.** Similarity in text or embeddings selects examples that look like the target (for example Bengali text for a Bengali QA target), not examples that train the same skill (§6.2, Table 16).

**Formula.** With Adam, the per-sample update direction at checkpoint θ is Γ(z, θ) = m / (√v + ε) (element-wise). The influence of z on a validation example z′ is

```
Inf_Adam(z, z′) = Σ_{i=1..N} η̄_i · cos( ∇ℓ(z′; θ_i), Γ(z, θ_i) )     (Def. 3.1)
```

N is the number of warmup checkpoints (one per epoch), η̄_i the average learning rate in epoch i, θ_i the checkpoint after epoch i, ℓ the mean token cross-entropy of the completion, and m, v Adam's first and second moments taken from the warmup run. For a target task with subtasks j, the validation gradient is averaged within each subtask, and a sample's score is the maximum over subtasks (Eq. 2, §4.2).

**Mechanism.**
1. LoRA-train the base model on a random 5% of the pool for N = 4 epochs, saving each epoch (§4.1, §5.1).
2. For every pool sample and checkpoint, compute the LoRA gradient, form Γ, and project it with a d × P matrix Π whose entries are uniform on {−1, 1}, with d = 8192 (§4.1).
3. Store the projected features (the gradient datastore: 17.7 GB, 48 A100-hours for about 270K samples) (Table 4).
4. For each target, compute projected validation gradients, score with Eq. 2, and keep the top 5% (§5.1).
5. Train the target model on the kept set (LoRA in the paper).

**Worked example.** Two checkpoints with η̄ = (2e-5, 1e-5). Sample z has cos = 0.30 with the validation gradient at θ_1 and 0.10 at θ_2: Inf = 2e-5·0.30 + 1e-5·0.10 = 7e-6. A second training sample z₂ has cos = 0.05 and 0.40: Inf = 1e-6 + 4e-6 = 5e-6. z ranks higher because the first checkpoint has the larger average learning rate, so its cosine receives the larger weight.

**Why cosine and not the dot product.** A sequence gradient is the average of token gradients, so its norm falls as completion length grows; dot-product influence therefore upweights short training sequences, which the authors report gives worse performance (§3.2, Table 13).

**Evidence.** LLaMA-2-7B, 5% of the pool: LESS 50.2 MMLU, 56.2 TydiQA, 41.5 BBH; random 5% 46.5, 52.7, 38.9; full data 51.6, 54.0, 43.2 (Table 2). A LLaMA-2-7B datastore selecting data for LLaMA-2-13B and Mistral-7B (LESS-T) beats random selection (Table 2). BM25, DSIR, and RDS selections show "minimal improvement over random" at this 270K scale (Table 3). Warmup matters: gradients from the untrained base model give 46.7 MMLU against 50.2 after a 5% warmup (Table 5). With warmup on the full pool instead of 5%, Adam influence averages 50.5 against 49.7 for SGD influence and 47.8 for SignGD (Table 9). **Result (single study)** for each number.

**Conditions and limits.**
- The paper evaluates only the three targets it selects for. Performance on non-target tasks after selection is not reported.
- For LLaMA-2-13B and Mistral-7B, MMLU after LESS selection (54.0, 61.8) is below the untuned base model (55.3, 62.4) (App. D.3, Table 10).
- Duplicates score equally and are treated as adding value twice (Limitations 4).
- In a 200K-pool, seven-task setting, LESS averages 44.2 against 46.4 for RDS+, with HumanEval at 19.6 against 27.0 for random ([[instruction-data-selection-at-scale]] Table 1). It was not run at 5.8M because of compute cost.

**Implication for a general-purpose model.** LESS answers "which samples help this target"; it does not answer "which samples keep other abilities". When LESS is used inside a general-purpose pipeline, a held-out suite of non-target tasks should be evaluated after training ([[ch-30a]] — Forgetting and Alignment Tax in Fine-Tuning: Measurement and Control; [[ch-47]] — Evaluation Harness and Suite Design for General Capability), because the paper reports only target-task scores.

## §7 Gradient-space diversity: G-Vendi and Prismatic Synthesis

**Definition.** G-Vendi measures the diversity of a dataset D as the exponentiated entropy of the eigenvalues of a similarity matrix built from normalized, projected loss gradients of a small frozen proxy model ([[prismatic-synthesis]] §2.1).

**Formula.**

```
g(x, y)  = −∇log P(y|x; θ) / ‖−∇log P(y|x; θ)‖,   g_proj = Πᵀ g,  Π_ij ~ U({−1, 1})   (Eq. 1–2)
G-Vendi(D) = exp( − Σ_i λ_i log λ_i ),   λ_i = eigenvalues of K = G Gᵀ / |D|      (Eq. 3)
```

θ are the proxy parameters (Qwen2.5-0.5B-Instruct), d = 1024 is the projected dimension, and G ∈ ℝ^{|D|×d} stacks the projected gradients. G-Vendi equals |D| when all off-diagonal entries of K are 0 and 1 when they are all 1 (App. C).

**Worked example.** Two samples with gradient cosine c: K = [[1, c], [c, 1]] / 2 has eigenvalues (1 + c)/2 and (1 − c)/2. With c = 0, λ = (0.5, 0.5), entropy ln 2, G-Vendi = 2. With c = 0.8, λ = (0.9, 0.1), entropy −(0.9 ln 0.9 + 0.1 ln 0.1) = 0.325, G-Vendi = 1.38. With c = 1, G-Vendi = 1.

**Evidence.** Across 300 subsets drawn from 1.5M-sample synthetic pools, at the 100K subset scale reported in Table 1, G-Vendi reaches Spearman ρ = 0.899 (math) and 0.893 (NLI) with average OOD accuracy, above Embedding Vendi (0.754 math, with an encoder 14× the proxy size) and Skill-Set Entropy (0.812) (Table 1). A 10K subset with higher diversity often outperforms a 100K subset with lower diversity on OOD benchmarks (§2.3.1). PrismMath-7B averages 75.25 against 72.80 for R1-Distill-Qwen-7B (Table 4). **Result (single study).**

**Prismatic Synthesis mechanism.** (1) Compute proxy gradients and run K-means. (2) Generate new samples by few-shot prompting from the pool. (3) Keep generated samples that fall in sparse clusters (math: k = 1% of pool size, smallest k/2 clusters). (4) Filter by majority vote over sampled solutions (math N = 3, τ = 2) and decontaminate (§3.1).

**Conditions and limits.** In-distribution accuracy correlates less with G-Vendi (ρ = 0.780) and depends more on dataset size (Table 1). The correlation holds only with quality controlled, so G-Vendi should not be used alone to compare datasets from different generators (App. D). Coding, open-ended chat, and agentic data were not tested.

**Implication for a general-purpose model.** Gradient-space diversity is a candidate signal for breadth, validated on two task families. **Open question** whether it predicts held-out performance on a broad multi-domain suite.

## §8 Selection at scale: many methods fall below random

**Setting.** [[instruction-data-selection-at-scale]] builds pools from all data considered for Tülu 2 (5.8M samples after exact deduplication) and Tülu 3, selects for seven evaluations (MMLU, GSM8K, BBH, TydiQA, HumanEval-Codex, SQuAD, AlpacaEval), and fully fine-tunes Llama 2 7B for 2 epochs (§3.2–3.3). *RDS+* scores a pool sample by the cosine similarity between a position-weighted mean pool of the base model's last hidden states for the sample and for query examples, and selects round-robin across query examples and tasks (§3, §3.1).

**Evidence.**
- Single-task, 10K selected: from 200K, RDS+ averages 46.4, LESS 44.2, Length 43.5, random 40.9, IFD 38.7. From 5.8M, RDS+ 50.5, Embed (GTR) 46.4, random 40.7, IFD 35.8, Top-PPL 30.4, Length 17.8 (Table 1).
- Moving from the 200K to the 5.8M pool lowers the average of every method run at both sizes except RDS+ (46.4 → 50.5) and Embed (GTR) (42.1 → 46.4); for example, Length falls from 43.5 to 17.8 and IFD from 38.7 to 35.8 (Table 1; the authors name PPL, random, IFD, and Embed (NV) in §4.1).
- Multi-task, 326K selected (the size of the Tülu 2 mix): RDS+ 50.9, Tülu 2 49.5, Length 47.6, balanced random 47.5, IFD 35.7 (Table 2).
- Tülu 3 pool, Llama 3.1 8B, 939K selected: RDS+ 76.1, balanced random 74.7, official Tülu 3 SFT 73.3 (Table 3).
- Counting selection compute, RDS+ becomes more FLOPs-efficient than random only at about 326K selected samples and above (Fig. 3).

**Status.** **Result (single study)**: single runs for non-random settings and the mean of 3 runs for random baselines (§3.3), two pools (Limitations).

**Implication for a general-purpose model.** Results on 10K-from-50K setups do not transfer to million-sample, multi-task setups. The figure [figures/ifd-scatter.html](figures/ifd-scatter.html) lets the reader switch between the 200K and 5.8M pools and between tasks to see which methods fall below the random baseline.

## §9 Length as a confound in judge-evaluated gains

**Evidence for the confound.** Selecting the 1,000 Alpaca examples with the longest responses and fine-tuning Llama-2-7B (15 epochs, LR 1e-5) wins 67.7% / ties 16.5% / loses 15.8% against AlpaGasus-1k and wins 46.3% / ties 25.4% / loses 28.3% against LIMA-1k with GPT-4 as judge ([[long-is-more-for-alignment]] Fig. 1a, App. Table 3). The mean training-response length is 256.8 tokens for Alpaca-1k-longest against 51.4 for Alpaca-52k and 531.3 for LIMA-1k (Fig. 1b, Fig. 6c). A rule that uses only response length matches or exceeds the curated baselines under judge evaluation. **Result (single study).**

**The authors' controls.** Forcing baselines to generate longer outputs (EOS postponed) or prompting for similar lengths still leaves Alpaca-1k-longest preferred (Fig. 6); raising the generation limit from 2048 to 4096 tokens changes AlpacaEval 2.0 win rate by −0.05 points for the best Llama-2-7B model (Table 1). On the Open LLM tasks, Alpaca-1k-longest is comparable to AlpaGasus-1k on average (Fig. 5). The authors conclude the gain is not only judge length bias (**Interpretation**).

**Evidence against length as a general selector.** At 5.8M-pool scale on seven tasks, Length selection averages 17.8, with SQuAD 0.2 and GSM8K 2.4 ([[instruction-data-selection-at-scale]] Table 1). Length also biases gradient-based scores toward short sequences unless gradients are normalized ([[less]] §3.2).

**Implication for a general-purpose model.** When a selector is evaluated with LLM judges, it should be compared with a longest-response baseline at the same budget and reported with length-controlled judge metrics and non-judge benchmarks ([[ch-49]] — Judge Models: Bias, Calibration, and Judge-Specific Overfitting), because the length rule alone beat AlpaGasus-1k and LIMA-1k under GPT-4 judging here and averaged 17.8 on the seven-task suite at 5.8M scale.

## Negative samples and negative feedback

This section uses the four meanings from the course standard: (1) negative marginal value, (2) negative as content, (3) negative as conditioning, (4) negative as gradient. The full derivations are in [[ch-43a]]; supervised uses are in [[ch-31a]].

**Where negatives come from in this stage.** Every selector produces a discard pile: samples below a rater threshold ([[alpagasus]]), IFD > 1 or low-IFD samples ([[cherry-llm]]), near-duplicates rejected by a similarity threshold ([[deita]]), and the 95% not chosen by [[less]]. Labels come from an LLM rater, a model-loss ratio, an embedding threshold, or a gradient score. None of these papers measures the false-negative rate; [[less]] notes that useful data may remain in the discarded 95% (footnote 8).

**What current practice does with them.** All selection papers in this chapter discard (meaning 1). Evidence that the discarded samples have negative marginal value as positive targets: filtered 9k beats random 9k ([[alpagasus]] Fig. 6), and the lowest-IFD subset gives the lowest winning scores ([[cherry-llm]] §4.2.3). A discarded sample is not automatically a useful meaning-4 negative.

**Mechanism: why off-policy rejects make poor gradient negatives.** For a softmax over logits z, the gradient of the log-probability of token y is

```
∂ log p_y / ∂ z_j = 1[j = y] − p_j
```

p_j is the model probability of token j. A push-down step z ← z − η ∇_z log p_y changes each logit by Δz_j = −η(1[j = y] − p_j).

Worked example with p = (0.70, 0.25, 0.05) and η = 1:
- Push down the unlikely token y = 3: Δz = (+0.70, +0.25, −0.95). New probabilities (0.806, 0.183, 0.011). Token 1 gains 0.106, token 2 loses 0.067, token 3 loses 0.039. Removed mass concentrates on the most likely token, and the second token also loses mass.
- Push down the likely token y = 1: Δz = (−0.30, +0.25, +0.05). New probabilities (0.581, 0.360, 0.059). Mass moves to both alternatives.

A sample rejected by a rater or a similarity filter was usually written by another model, so the policy assigns it low probability. Pushing it down has the first pattern (derived). [[likelihood-displacement]] reports the related failure for DPO on same-kind pairs: training-set refusal rate of Llama-3-8B-Instruct fell from 74.4% to 33.4% (§6.2).

**When discarded responses can be negatives.** [[rip-rejecting-instruction-preferences]] samples N = 64 responses per prompt from the model being trained (Llama 3.1-8B-Instruct, T = 0.8, top-p 0.95), scores them with the ArmoRM reward model, and pairs the best with the worst (§3.1, §4.1.1). The rejected response is near-policy by construction. RIP then uses the rejected response as a signal about the prompt: prompts whose rejected response has low reward, short length, or a large reward gap are removed (§3.3). Keeping prompts whose rejected length and rejected reward are above the 50th percentile and whose reward gap is below the 50th percentile leaves 4,538 of 20,000 prompts and raises AlpacaEval 2 LC win rate from 48.4 to 57.8, Arena-Hard from 37.9 to 43.1, and WildBench from 41.5 to 45.6 after DPO (Table 2). IFD filtering, InsTag filtering, and LLM-as-prompt-judge filtering did not match RIP in the same setup (§5, Fig. 1). **Result (single study)**, judge-based benchmarks only. For unpaired desirable/undesirable labels, [[kto]] provides a loss that uses undesirable samples without pairs; its use on selection discards is not tested in the cited sources (**Open question**).

**Controls.** Use only near-policy rejects as meaning-4 negatives (sample them from the current model). Filter same-kind pairs (CHES in [[likelihood-displacement]] §6.3). Keep a positive NLL anchor when training on pairs (ch-31a). Mask, rather than penalize, samples whose label comes from an uncertain rater.

**Diagnostics.** Log the chosen and rejected log-probabilities separately; log the per-category share of the discard pile; sample 50 discarded and 50 kept examples for manual reading; report pass@k and abstention on held-out tasks after any preference stage that uses the discard pile.

**Effect on generality.** Discarding by a single score removes some task categories at higher rates than the overall rate (§2, §3). Using off-policy discards as gradient negatives can lower the probability of correct alternatives (worked example above). No cited source measures the share of improvement attributable to negatives in the selection stage.

## Generalization lens

**(a) What increases breadth.**
- Diversity terms in selection raise worst-case prompt performance (QDIT +6.26% worst-case winning score over quality-only; [[qdit-data-diversity]] §4.3) and kept DROP at or above random on UltraChat 10K (26.73 vs 26.24) where quality-only selection fell to 17.01; on Dolly 1K and Mixed 10K, quality-only selection scored higher on DROP than QDIT (Table 3).
- Gradient-space diversity of math and NLI training data predicts OOD accuracy (ρ ≈ 0.9) better than embedding diversity ([[prismatic-synthesis]] Table 1).
- Round-robin selection over several task query sets beats balanced random and the human-curated Tülu 2 mix on a seven-task average ([[instruction-data-selection-at-scale]] Table 2).

**(b) What causes narrowing or forgetting.**
- Single-score selection lowers MMLU: [[alpagasus]] (Table 2) and [[cherry-llm]] (Tables 1, 3). **Replicated.**
- Single-score selection removes categories: coding in [[alpagasus]] (§6); math, code, and editing in [[cherry-llm]] (App. C, Table 4). **Replicated.**
- Target-directed selection can leave non-target ability unmeasured and can fall below the untuned base on MMLU for stronger base models ([[less]] Table 10).
- IFD and Length selection fall on non-judge tasks at 5.8M scale (SQuAD 46.6 and 0.2; [[instruction-data-selection-at-scale]] Table 1).

**(c) How to measure it for this stage.**
- Compare against random, balanced random, and Length at the same budget and pool size.
- Evaluate on a multi-task suite with non-judge benchmarks (MMLU, GSM8K, SQuAD, HumanEval) and length-controlled judge metrics (ch-49).
- Report worst-10% prompt performance, as QDIT does, and per-category retention of the kept set.
- Known measurement errors: GPT-4 and ChatGPT judges prefer longer responses ([[judge-llm-bias]]); most selection papers report single runs without seeds ([[deita]], [[cherry-llm]]); query sets drawn from the evaluation distribution make selection target-aware, so results with out-of-distribution query sets (Arena Hard queries: 50.4 multi-task average) are the stricter comparison ([[instruction-data-selection-at-scale]] §3, Table 2).

## Common mistakes and how to detect them

| Mistake | Observable symptom | Check |
|---|---|---|
| Reversing the IFD direction (keeping the lowest IFD) | Kept set dominated by rewrite, edit, and classification tasks | Print top/bottom 5% verb–noun pairs; compare with [[cherry-llm]] Table 4 |
| Mixing loss-ratio and perplexity-ratio IFD across tools | Different kept sets from "the same" IFD threshold | Recompute both on 100 samples; measure top-10% overlap |
| Comparing a selector only with full data or unbalanced random | Gains that vanish against balanced random or Length | Add both baselines at the same budget ([[instruction-data-selection-at-scale]] Table 2) |
| Judging selection only with MT-Bench or AlpacaEval | Judge gain with MMLU or SQuAD drop | Report non-judge tasks and response length |
| Copying τ = 4.5 or top 5% from a paper | Kept-set size far from the planned budget | Plot the score histogram of your pool first |
| Using LESS without non-target evaluation | Target score rises; unrelated benchmarks fall | Hold out tasks not used as queries |
| Treating G-Vendi as comparable across generators | High G-Vendi from a low-quality generator | Compare G-Vendi only within one generation process ([[prismatic-synthesis]] App. D) |
| Using rater-discarded responses as DPO rejected samples | Chosen log-probability falls during DPO | Log chosen and rejected log-probs; sample rejects from the policy ([[likelihood-displacement]]) |
| Scoring a 5.8M pool with a method validated at 50K | Average score below random at the larger pool | Run the method at two pool sizes before committing |
