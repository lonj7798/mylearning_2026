Formulas (from fsdp-sft.md; b = param bytes, o = optimizer bytes/param, N = data-parallel ranks, K = GPUs per node for HYBRID):
DDP : b·P + b·P + o·P + activations ZeRO-2 : b·P + b·P/N + o·P/N + activations ZeRO-3 FULL : b·P/N + b·P/N + o·P/N + 2·b·P + activations (AllGather temp ≈ 2P bytes) HYBRID_SHARD : like FULL with N → K (per-node FULL; replicate across nodes)
Activations use the simplified estimate 2 · batch · seq · hidden · layers bytes (bf16); with checkpointing we keep ~20% of that.
What to notice.
  • DDP gives up at ~7B on 80 GB. 16·7 = 112 GB per rank, independent of N. More GPUs do not help; sharding does.
  • FSDP FULL_SHARD + bf16 + activation-ckpt is the floor at 70B. The 16P/N term collapses with N, but the 2P AllGather temp buffer never shrinks — that is the asymptote.
  • HYBRID beats FULL when cross-node bandwidth dominates. It shards only within a node (small K), so 16P/K is larger than 16P/N, but the inter-node collective becomes a classic DDP AllReduce instead of per-block AllGather — a throughput win on slow fabric.
  • The AllGather temp caps the savings. At large P/N, the 2P temp term dominates the sharded 16P/N term; doubling GPUs past that point is wasted.
