# Excerpt: Olmo 3 — named stages, Dolci SFT sizes and settings, stage deltas, RL-Zero controls

The library card [[olmo-3]] has not been verified. Every value below was read in arXiv:2512.13961v2 (2026-04-14).
Launch scripts: [[allenai-olmo3-open-instruct-scripts]], [[allenai-olmo3-open-instruct-scripts-recipe]].

## Base model stages (§3.1-3.2, §3.6)
- Pretraining on Dolma 3 Mix (5.9T tokens) at 8,192 tokens (up from OLMo 2's 4,096); sliding-window attention with a
  4,096 window on three of every four layers (§3.2).
- Midtraining on Dolma 3 Dolmino Mix (100B tokens) (§3.1).
- Long-context extension on Dolma 3 Longmino Mix: 50B tokens (7B) or 100B tokens (32B), 34% long-context data and 66%
  short-context data from Dolmino; context 8,192 → 65,536; YaRN applied to full-attention layers only; document packing
  and inter-document masking (§3.6). Mix ablation on a 10B-token extension: 66% long / 34% short lowered a subset of
  OlmoBaseEval by 2.5 points; 34% long / 66% short by 0.8 points (§3.6.3).

## Think SFT (§4.2, Table 17, App. A.6.1, Table 47)
- Dolci Think SFT prompts: 2,268,468 (7B) and 2,253,916 (32B) (Table 17 totals). Examples: Dolci Think OpenThoughts 3+
  Math 752,997; Dolci Think Python Algorithms 466,677; WildChat 83,054 (7B counts).
- Decontamination: Tülu 3 procedure, 8-gram matching with overlap threshold 0.5, plus heuristics for task-irrelevant
  chunks and math-symbol n-grams (§4.2.1 Step 4).
- Training (A.6.1): OLMo-core; batch "measured in tokens instead of instances"; "document packing instead of padding";
  1M-token batches for 7B and 4M for 32B; two epochs; 32,768 sequence length. Table 47 "Total Tokens": 45.4B (7B Think),
  45.2B (32B Think), 3.4B (7B Instruct); LR 5.0e-5 (7B Think), 1.0e-4 souped with 5.0e-5 (32B Think), 8.0e-5 (7B
  Instruct).
- Selection (§4.2): "We train all models for two epochs to avoid overfitting, and perform a learning-rate sweep to select
  the best candidate checkpoints based on our evaluation suite. We then test each candidate checkpoint with a series of
  qualitative 'vibe-test' questions ... our final thinking SFT checkpoint is a linearly weighted merge of two checkpoints
  trained with different learning rates."

## Think DPO with Delta Learning (§4.3, App. A.6.2)
- "further supervised finetuning on thinking traces generated by Qwen3 32B ... outright hurts the performance of Olmo 3
  Think SFT, indicating that we are approaching saturation on learning from imitation." Those completions are used as
  chosen responses and paired "with even worse responses"; "minimizing the quality of the rejected completions (thus
  increasing the quality delta) yields a useful contrastive signal for preference tuning" (§4.3).
- Loss: length-normalized DPO, max E[log σ((β/|y_c|) log(π_θ(y_c|x)/π_ref(y_c|x)) − (β/|y_r|) log(π_θ(y_r|x)/π_ref(y_r|x)))];
  learning rate and dataset size are swept because "performance increases up until some task-dependent optimal
  optimization point beyond which further tuning hurts" (A.6.2, Fig. 23).

## Truncated negatives in RL-Zero (App. A.6.4)
- Olmo 3.1 RL-Zero improved over 3.0 mainly from a 16k (instead of 12k) completion length and from "not masking truncated
  sequences". Masking made batch sizes vary and reduced stability, and "without training on overlong negative sequences,
  completion lengths were higher, on average."

## Instruct SFT and function calling (§5.2, Tables 26-27, 30)
- Dolci Instruct SFT prompts: 2,152,112 (Table 30), including Dolci Instruct Tool Use 227,579.
- Function-calling trajectories (Table 27): Science QA, real MCP interactions, 22.6K trajectories, 8 unique functions,
  42.3% multi-step; Web Search QA, real, 6.6K, 3 functions, 76.1% multi-step; SimFC, simulated, 200K, 42.6K functions,
  42.3% multi-turn, 23.8% multi-step.
- Tool definitions use OpenAPI specifications; calls are pythonic code blocks inside XML tags with dedicated special
  tokens; environment outputs use a separate environment role (§5.2.1).
- Instruct SFT starts from the Think SFT checkpoint: "training Olmo 3 Instruct on top of the Olmo 3 Think SFT both
  increases model performance on benchmarks, as shown in Table 29", with response length "minimally affected" (§5.5).
- DPO contrast: attempts to improve the OLMo 2 preference pipeline with stronger response generators "failed to yield
  any improvements", attributed to chosen and rejected responses no longer having "meaningful contrast" (§5.5, Table 32).

## RL-Zero and the spurious-reward control (§6)
- Motivation: open RLVR studies train on bases whose pre- and mid-training data are unknown, where contamination "makes
  spurious rewards as effective as true rewards" (§6, citing Shao et al. 2025b and Wu et al. 2025c).
- Dolci RL-Zero math: filtered DAPO Math, Klear-Reasoner Math, Open-Reasoner-Zero, Omega; semantic clustering; decontaminated
  against pretraining and evaluation data; prompts solved 8 of 8 times by the base removed; 13.3K prompts (§6.1).
- Negative control: training Olmo 3 Base on Dolci RL-Zero with random binary rewards "does not improve performance on any
  of our benchmark" suites (§6.2, Fig. 27).
- Mix run: "our general run has improved performance across different domains, but each domain is under-optimized
  compared to the single-domain setup" (§6.2).
