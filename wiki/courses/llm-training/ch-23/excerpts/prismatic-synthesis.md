## G-Vendi — the three-step definition

```
# prismatic-synthesis.md, lines 31-35
G-Vendi computation (3 steps):
  1. For each candidate example x_i, compute the normalized gradient
     g_i = ∇_θ L(x_i; θ) / ‖·‖ on the proxy.
  2. Random-project g_i to a lower dim (≈ 8K) while preserving
     dot products (Johnson-Lindenstrauss).
  3. Build the density matrix K / tr(K) where K_{ij} = <g_i, g_j>;
     G-Vendi = exp(von-Neumann entropy of K).
```

Step-by-step, what each line does:

1. **Gradient computation.** Use a small instruction-tuned proxy LM (Qwen2.5-7B-Instruct class). For each candidate example, do a single backward pass; take the gradient w.r.t. the training loss; normalize to unit norm. The gradient captures "how this example would move the model's parameters." Two examples with similar gradients pull the model the same way — they are effectively redundant. Two examples with orthogonal gradients pull the model independently — they add diversity.

2. **Random projection.** The raw gradient is parameter-dimensional (billions for a 7B model). Johnson-Lindenstrauss says: random project to ~8K dims, and pairwise dot products are approximately preserved. This makes the subsequent density-matrix computation tractable — 8K × 8K kernels are fine; billions × billions are not.

3. **Von-Neumann entropy.** Build the Gram matrix of projected gradients; normalize by trace to make it a density matrix (positive semidefinite, trace 1). Compute the von-Neumann entropy: `H = -tr(K log K)` where `K = G G^T / tr(G G^T)`. G-Vendi is `exp(H)`. Intuition: G-Vendi is the "effective number of independent gradient directions" the corpus spans.

The metric is 100% post-hoc (you measure it on a candidate corpus, after generation) and cheap enough to run per-generation in an iterative pipeline.

## Spearman ρ ≈ 0.9 — why this matters

```
# prismatic-synthesis.md, lines 44-47
Spearman ρ ≈ 0.9 between G-Vendi and OOD accuracy on NLI + math
across 300+ runs.
Beats Embedding-Vendi (SOTA text-embedding encoder, 14× larger
than proxy).
Beats Skill-Set Entropy (GPT-4 + Qwen2.5-72B).
```

ρ ≈ 0.9 is exceptionally high for a data-quality metric. Typical token-level or embedding-level diversity metrics correlate with downstream performance at ρ ≈ 0.3–0.5. G-Vendi's headline claim is that **gradient-space diversity tracks generalization, embedding-space diversity does not**.

The ablation the paper runs (300+ controlled training runs, varying generator / seed / filter) is what makes this believable. The metric isn't tuned on the data it's evaluated on; it's computed blind and checked against OOD accuracy afterward. That's a sizable sample size for a diversity-vs-downstream-acc correlation study.

Ch-23 §7's decision to include G-Vendi in the per-generation dashboard follows from this: it is the single most predictive leading indicator of downstream degradation available in 2025.

## The headline result — 7B beats 671B generator

```
# prismatic-synthesis.md, lines 20-22, 47-48
Headline: 7B student + gradient-targeted synthesis > competitor
distilled from 671B generator → diversity, not generator scale,
is the binding constraint.
7B student trained on Prismatic-synthesized reasoning data
outperforms baselines whose data was generated by a 671B teacher.
```

This is the paper's rhetorical anchor and ch-23's §5 "Gradient-targeted synthesis" row. The claim: a 7B student trained on actively-gradient-diversified synthetic data beats a 7B student trained on data distilled from a 671B teacher. The difference is not generator scale but generation *strategy* — Prismatic generates to *cover gradient space*, while naïve distillation generates to *imitate teacher output*.

The implication for ch-23's collapse narrative: **diversity is not a consequence of teacher strength; it is an independent optimization target**. A bigger teacher produces outputs that are still concentrated near the teacher's mode manifold. G-Vendi-targeted generation, by contrast, explicitly fills underpopulated gradient regions — it generates samples *off* the teacher's mode. This is a structurally anti-collapse property: the outputs are, by construction, not what a recursive self-iteration would produce.

## Anti-collapse mechanism — generating off-manifold

```
# prismatic-synthesis.md, line 49
Gains grow with synthesis scale — anti-collapse behavior: scaling
gradient-diverse synthetic data keeps improving OOD, unlike plain
teacher sampling.
```

The key line for ch-23. Plain teacher sampling, at scale, exhibits [[excerpts/model-collapse]]-predicted behavior — gains saturate or reverse past a certain scale. Gradient-diverse sampling does not saturate within measured scales. Why?

Under plain sampling, additional samples concentrate in the same high-density regions of the teacher's distribution. Each new sample adds less *new* information — diminishing returns. Eventually, the sample distribution is indistinguishable from the teacher's training distribution, and further sampling degenerates into [[excerpts/strong-model-collapse]]'s `c(p)·σ²` asymptote.

Under gradient-diverse sampling, each new sample is *selected or generated* to fill an underpopulated gradient cluster. The sample distribution's entropy keeps growing with sample count — the corpus approaches a more uniform coverage of gradient space rather than concentrating. The asymptote is different: instead of converging to teacher-mode density, it converges to uniform gradient-space coverage (bounded above by the data manifold's intrinsic dimension).

This is the generation-side analog of ch-23 §4's filtering-side verification. Both are "inject external signal to break the recursion" — the external signal here is the proxy's gradient geometry, which is independent of the teacher's output distribution.

## The synthesis pipeline (REQUIRED — concrete)

```
# prismatic-synthesis.md, lines 36-40
Generation step(s):
- Generate a large candidate pool with the synthesis teacher
  (math: persona-hub-style prompts; NLI: template perturbation).
- Score candidates by their contribution to G-Vendi — prefer those
  in low-density gradient clusters (greedy max-entropy selection
  or resample-from-underpopulated-regions).
Filtering/rescoring: standard answer-verifier for math;
NLI-label consistency filter; gradient-outlier cap.
```

The pipeline is a two-stage gate:

- **Stage 1 — over-generate candidates.** Produce a large pool (order-of-magnitude more than the target corpus size) using persona-diverse prompting or template perturbation. No gradient targeting yet — just raw diversity in the generation step.
- **Stage 2 — gradient-space selection.** Compute per-sample gradients; greedy-select samples that maximize the marginal contribution to G-Vendi. Reject samples in already-crowded gradient clusters.
- **Stage 3 — correctness gate.** Apply task-specific verifier (answer matcher for math, NLI-label consistency for NLI). This is the ch-23 Axis 2 layer.
- **Stage 4 — gradient-outlier cap.** Remove pathologically high-norm gradients (which would dominate G-Vendi for the wrong reason — numerical artifact, not genuine diversity).

Stage 2's gradient-space selection is a different *kind* of gate from APIGen's 3 layers: it's a *diversity* gate, not a *correctness* gate. Both are needed. Gradient diversity without correctness gives you diverse-but-wrong; correctness without diversity gives you correct-but-collapsed. Prismatic does both.

## Risks and limitations (source direct lift)

```
# prismatic-synthesis.md, lines 52-55
Proxy-model dependency: G-Vendi is defined relative to a proxy's
gradient geometry.
Compute overhead: gradient + projection per candidate is nontrivial
at very large candidate pools.
Random projection choice: dim & seed affect stability.
Task scope: strongly validated on math + NLI; transfer to
coding / open-ended writing is future work.
Still synthetic: gradient-space diversity does not guarantee
factual correctness — answer verifier is still mandatory.
```

Each risk is an open problem ch-23 inherits:

1. **Proxy dependency** — ch-23 §4 flags this under "G-Vendi is proxy-dependent." Use multiple proxies if you want a robust metric.
2. **Compute overhead** — one backward pass per candidate is nontrivial at 10M+ candidate pools. Amortization matters.
3. **Random projection** — report averaged results; small runs have variance.
4. **Task scope** — reasoning (math, NLI) is well-validated; open-ended generation is not. Apply cautiously.
5. **Correctness ≠ diversity** — G-Vendi doesn't gate factual errors. You still need Axis 2 (external verifier).

## Why this connects to the whole ch-23 narrative

The paper operationalizes "external signal" in a different dimension than verification. Verification (ch-23 Axis 2) asks "is this sample correct?" — a yes/no at the sample level. Coverage (ch-23 Axis 3) asks "does this sample fill an under-represented region?" — a diversity-contribution at the corpus level. Together they form the ch-23 §6 recipe: generate with coverage targeting, filter with correctness verification.

The lineage matters too. Prismatic is in the Yejin Choi group's "diversity over scale" tradition (Self-Instruct → Star → Quiet-Star → Prismatic). It is the 2025 sharpening of that theme: diversity is not a free consequence of a big generator; it must be explicitly optimized. [[excerpts/nemotron-4-synthetic]]'s Genetic Instruct is the pragmatic production version of the same idea.
