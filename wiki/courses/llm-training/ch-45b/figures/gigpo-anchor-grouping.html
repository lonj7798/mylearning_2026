GiGPO: two levels of advantage from one set of rollouts

Four rollouts of one shopping task reach the same search-results page at step 3. Change where each rollout ends and whether it succeeds, and compare the episode advantage (what GRPO would give) with the step advantage GiGPO adds. Figure for ch-45b §4.1.

The equations

A^E(τ_i) = ( R(τ_i) − mean{R(τ_j)}_{j=1..N} ) / F_norm({R(τ_j)}) (Eq. 3)
G^S(s̃) = { (a_t^(i), R_t^(i)) : s_t^(i) = s̃, 1 ≤ i ≤ N, 1 ≤ t ≤ T } (Eq. 4, Eq. 6)
R_t^(i) = Σ_{k=t..T} γ^(k−t) · r_k^(i) (Eq. 5)
A^S(a_t^(i)) = ( R_t^(i) − mean{R_t ∈ G^S(s̃)} ) / F_norm({R_t ∈ G^S(s̃)}) (Eq. 7)
A(a_t^(i)) = A^E(τ_i) + ω · A^S(a_t^(i)) (Eq. 8)

Source. Equations, the WebShop example and the settings are from "Group-in-Group Policy Optimization for LLM Agent Training", arXiv:2505.10978v3 (§4.1, §4.2, §4.3, Figure 3, §5.1). The paper sets ω = 1 "with no further tuning" and N = 8 for ALFWorld and WebShop. Anchor grouping "incurs no extra rollouts: it is entirely offline and requires only lightweight key-based grouping using hashmaps" (§4.2); measured cost is 0.01 s for grouping plus 0.53 s for the step advantages against 362.83 s per iteration for rollout, log-probability computation and the policy update (§5.6). The discount value used in the paper's experiments is not printed; 0.95 here is the figure's default, not a source value. Rewards are terminal in this example, so r_k = 0 for k < T.
