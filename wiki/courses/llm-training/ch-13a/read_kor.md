# Chapter 13a — 능력 축으로서의 다국어 범위와 어휘

> **핵심 통찰.** 크기가 고정된 모델에 언어를 더하면 언어별 성능은 두 방향으로 움직인다. 29.5M-매개변수 모델(추가 어휘를 포함하면 45.8M)에서 관련 언어의 1B 토큰은 텍스트가 1M 토큰인 언어를 데이터가 약 22% 더 많은 언어처럼 수행하게 했고, 텍스트가 1B 토큰인 언어를 데이터가 63% 더 적은 언어처럼 수행하게 했다([[multilinguality-curse-250-languages]] 그림 1, §6.2). ATLAS는 최대 8B 매개변수의 실행 774개에 걸쳐 이 절충을 적합한다. 균등 샘플링한 언어를 4배 더 제공하면서 손실을 바꾸지 않으려면 매개변수는 1.4배, 총 토큰은 2.74배가 필요하며, 이는 언어당 토큰이 32% 적은 것이다([[atlas-multilingual-scaling-laws]] §5). 손실 크기는 언어별 데이터 품질 및 같은 콘텐츠에 각 언어가 필요로 하는 토큰 수에도 좌우된다. 영어 데이터를 큐레이션하면 13개 이중언어 3B 실행 중 12개에서 비영어 점수가 올랐고([[uberweb-multilingual-curation]] §4.1.1), 같은 FLORES-200 문장은 영어보다 cl100k_base 토큰이 1.48배(포르투갈어)에서 15.05배(Shan) 더 필요하다([[tokenizer-language-unfairness]] 표 1).
>
> **지침.** 언어별 품질을 유지해야 하는 모델에 언어를 더할 때는 언어당 토큰을 고정하는 대신 ATLAS 배수(K → rK 언어에 대해 r^0.243 및 r^0.728)로 매개변수와 총 토큰을 확장하라. 이 적합은 요구량의 일부를 양의 이전에 돌리기 때문이다([[atlas-multilingual-scaling-laws]] §5). 이 적합은 균등 샘플링을 가정하고 손실만 측정하므로, 치우친 혼합은 언어별 과제 평가로 확인하라. 표적 언어의 텍스트가 적다면([[multilinguality-curse-250-languages]]에서 1M 토큰), 문법적으로 유사한 언어의 데이터를 더하고 모델에 남는 용량이 있는지 점검하라. 이득은 유사 언어에서(+33% 대 +22%) 그리고 큰 모델에서(+33% 대 +12%) 더 컸기 때문이다(§6.1). 비영어 웹 텍스트를 큐레이션할 때는 언어 식별과 필터 임계값을 각 언어 자체의 통계에서 도출하고, 설계에 쓰지 않은 언어에서 파이프라인을 시험하라. 기본 FineWeb 영어 임계값은 선택한 적응 방법보다 낮은 순위였거나(Gopher Repetition 필터 4.22 대 2.22), 적어도 한 언어에서 데이터의 75% 초과를 제거하거나 아무것도 제거하지 않아 제외되었기 때문이다([[fineweb-2]] 표 25). 토크나이저를 고를 때는 모델이 서비스해야 할 모든 언어에 대해 병렬 텍스트에서 토큰 프리미엄과 교차 언어 불평등 통계량을 측정하라. 어휘 스케일링 법칙은 영어 데이터로만 적합되었기 때문이다([[vocabulary-scaling-laws]] 부록 B.4). 그렇지 않으면 값을 가정하지 말고 언어 비율을 “보고되지 않음”으로 기록하라.

## 범용 모델에서 이 장이 중요한 이유

학습 파이프라인은 사전학습 → 중간학습 → SFT → 선호 최적화 → RL → 평가이다. 언어 범위는 사전학습에서 결정된다. 토크나이저는 첫 단계 전에 고정되고(ch-11), 각 언어의 비율은 데이터 혼합의 일부이기 때문이다(ch-13). 이후 단계는 둘 다 물려받는다. 문맥 확장(ch-32b)은 언어별 토크나이저 비용을 물려받고, 다국어 SFT(ch-30b)는 사전학습이 만든 것 위에 작은 비율을 더한다.

**언어 비율(language share)**은 한 언어 텍스트에 할당한 학습 토큰 비율(또는 샘플링 가중치)이다. 언어는 보유한 텍스트 양에 따라 **고자원** 또는 **저자원**이며, 아래 연구들은 토큰 수를 쓴다(예: [[multilinguality-curse-250-languages]]의 1B 대 1M 토큰). **교차 언어 이전**은 언어 B 학습 때문에 언어 A가 향상되는 것이고, **간섭**은 B 학습 때문에 A가 저하되는 것이다.

이 장은 측정 가능한 다섯 문제를 다룬다.
1. 고정 모델 크기에서 언어를 더할 때 언어별 홀드아웃 손실이 변한다(§1).
2. 언어별 손실을 올리지 않고 언어를 더하는 데 필요한 매개변수와 토큰 수(§2).
3. 영어에서 설계한 큐레이션 임계값은 다른 언어에서 잘못된 문서를 남기거나 제거한다(§3).
4. 같은 콘텐츠가 언어별로 서로 다른 토큰 수를 요구하며, 이는 학습 토큰, 문맥 용량, 추론 비용을 바꾼다(§4).
5. 영어 전용 또는 토크나이저 의존 평가는 다른 언어의 퇴행을 검출하지 못한다(§5).

ch-00의 범위 지도는 다국어 능력을 한 능력 영역으로, ch-09는 다국어 텍스트를 한 출처 유형으로 나열한다. 이 장은 그 영역의 범위가 용량, 데이터 품질, 토큰 비용과 어떻게 절충하는지 측정한다.

## §1 다국어성의 저주: 고정 용량에서의 간섭과 이전

**정의.** **다국어성의 저주(curse of multilinguality)**는 고정 크기 모델의 언어별 성능이 더 많은 언어로 학습할 때 낮아진다는 관찰이다([[multilinguality-curse-250-languages]] §2, Conneau 등 2020 인용).

**문제.** 추가 언어가 특정 언어를 돕는지 해치는지는 그 언어가 가진 데이터 양, 추가 언어와의 유사도, 모델 크기에 달려 있다. 이전 다국어 모델은 각각 하나의 고정 언어 분포를 사용했으므로 이 요인들을 분리하지 못했다(§1).

**통제 연구의 작동 방식** ([[multilinguality-curse-250-languages]] §3–§5):
1. 1,572개 언어(41.4B 토큰)의 텍스트를 모으고, 최소 1.5M 토큰(학습 1M, 홀드아웃 500K)을 가진 252개 언어를 남긴다.
2. 언어마다 어휘 32K의 SentencePiece 토크나이저 하나를 학습하고, 그 언어에서 평가하는 모든 모델에 고정한다. 따라서 한 언어의 퍼플렉서티는 모델 간 비교할 수 있다.
3. 1M, 10M, 100M, 1B 토큰에서 4.6M, 11.6M, 29.5M 매개변수의 단일언어 GPT-2 기준선 1,989개를 학습한다.
4. 언어와 크기별로 단일언어 데이터 크기에서 홀드아웃 로그우도까지의 곡선을 적합한다.
5. 가장 유사한 10개 또는 가장 덜 유사한 10개 언어에서 10M, 100M, 1B 토큰을 더하는 다국어 모델 8,454개를 학습하고, 각 모델 점수를 같은 로그우도를 내는 단일언어 데이터 크기로 표현한다.

**수식.**

```
relative log-likelihood  ℓ = mean_w log2 P_M(w) − mean_w log2 P_Baseline_L(w)          (Eq. 1)
fitted curve             ℓ(x) = −a · x^(−b) + c,   x = log10(monolingual tokens)       (§4.3)
```

- `w`: 언어 L의 홀드아웃 집합 토큰; `P_M(w)`: 문맥이 주어졌을 때 모델 M이 w에 할당하는 확률.
- `Baseline_L`: L의 1M 토큰으로 학습한 4.6M-매개변수 모델.
- `a, b, c`: 언어와 모델 크기별로 적합한 값. 언어에 적합할 데이터 크기가 너무 적으면 `a`는 언어들 전체의 중앙값으로 고정한다.

**계산 예시.** 기준선이 토큰당 평균 −10.0비트를, 모델 M이 −9.5비트를 할당한다고 하자. 그러면 ℓ = −9.5 − (−10.0) = 0.5이다. 퍼플렉서티는 2^10 = 1,024와 2^9.5 = 724로, 비율은 1.41 = 2^0.5이다. M이 L의 1M 토큰과 유사 언어의 1B 토큰으로 학습한 29.5M-매개변수 모델이고, 그 크기의 단일언어 곡선이 1.2M 토큰에서 같은 ℓ에 도달한다면 M의 점수는 추정 단일언어 토큰 1.2M으로 보고한다. 이는 논문 그림 3 캡션이 보인 +20% 이득이다.

**증거** ([[multilinguality-curse-250-languages]], 언어 252개, 홀드아웃 로그우도, 결과·단일 연구):

| 표적 언어 데이터 | 추가 데이터 | 모델 | 동등 단일언어 데이터의 효과 | 위치 |
|---|---|---|---|---|
| 토큰 1M | 유사 언어 10개, “최적 시나리오”(추가 양은 §6.1 본문에 명시되지 않음) | 29.5M(추가 어휘 포함 45.8M) | +33%(비유사: +22%) | §6.1 |
| 토큰 1M | 같은 최적 시나리오 | 4.6M 대 29.5M | +12% 대 +33% | §6.1 |
| 토큰 1M | 유사 언어 10개, 토큰 1B | 29.5M | +22%(그림 1 캡션); 그림 3 캡션: 동등 토큰 1.2M | 그림 1, 그림 3 |
| 토큰 1M | 토큰 10M(언어당 1M) | 모든 크기 | “본질적으로 영향 없음” | §6.1 |
| 토큰 10M | 토큰 1B | 최대 모델을 제외한 모두 | 더 낮음(p < 0.001) | §6.1 |
| 토큰 1B | 토큰 1B | 29.5M | −63% | §6.2 |
| 토큰 1B | 토큰 1B | 4.6M | −88% | §6.2 |

추가 언어의 유사도는 저자원 이득을 주로 문법을 통해 설명한다. 통사 유사도는 상대 로그우도 분산의 24.2%를 설명하고, 지리 및 어휘 유사도를 더하면 26.4%가 된다(§6.1, 그림 4). 고자원 표적에서는 더 유사한 추가 언어가 저자들이 “약간 더 큰”이라고 부르는 저하를 냈다(12개 시나리오 중 7개에서 p < 0.05)(§6.2).

**조건과 한계.** 모델은 최대 45M 매개변수, 시퀀스 길이 128, 배치 크기 128이다(부록 A.3). 각 추가 언어 집합은 최소 100M 토큰을 가진 48개 언어에서 뽑은 정확히 10개 언어이다. 지표는 과제 정확도가 아니라 언어 모델링 우도이다(§7.1). 저자들은 저하가 모델 크기와 함께 줄어든다는 점에서 이를 용량에 돌린다(§6.2, **해석**).

**범용 모델에 대한 함의.** 소규모에서 다국어 데이터는 데이터가 부족한 언어에는 추가 데이터로, 데이터가 풍부한 언어에는 용량 비용으로 작용한다. 언어를 더하면서 강한 영어를 유지해야 하는 모델은 더 많은 용량 또는 추가 언어가 영어를 낮추지 않았음을 보이는 측정이 필요하다.

## §2 다국어 스케일링 법칙: ATLAS

ATLAS(Adaptive Transfer Scaling Law)는 표적 언어의 손실을 모델 크기와 세 종류 토큰의 함수로 적합한다. 표적 언어 토큰, 가장 자주 함께 샘플링한 언어의 토큰, 그 밖의 모든 토큰이다([[atlas-multilingual-scaling-laws]] §3). MADLAD-400에서 10M–8B 매개변수의 실행 774개로 적합하며, [[vocabulary-scaling-laws]]의 어휘 비민감 손실을 사용해 언어별 홀드아웃 집합에서 손실을 측정한다(§2, 표 B.1).

### §2.1 이전과 반복을 포함한 유효 데이터

```
L(N, D_eff) = E + A / N^α + B / D_eff^β
D_eff = S_λ(D_t; U_t) + Σ_{i∈K_t} τ_i · S_λ(D_i; U_i) + τ_other · S_λ(D_other; U_other)
S_λ(D; U) = D                                    if D ≤ U
S_λ(D; U) = U · [1 + (1 − exp(−λ(D/U − 1))) / λ]   if D > U
```

- `N`: 매개변수; `E`: 환원 불가능한 손실; `A, B, α, β`: 적합 상수.
- `D_t`: 표적 언어 t에서 본 토큰; `U_t`: t에서 이용 가능한 고유 토큰; `λ`: 출처 간 공유한 반복 매개변수.
- `K_t`: t와 가장 자주 함께 샘플링한 3개 언어; `τ_i`, `τ_other`: 적합한 이전 가중치; `D_other`: 나머지 모든 토큰.

**계산 예시(λ = 1은 적합한 값이 아닌 설명용 값).** 한 언어가 고유 토큰 U = 10B를 갖고 학습에서 D = 30B 토큰을 본다고 하자. D/U = 3이므로 S = 10B · [1 + (1 − e^(−2))] = 10B · 1.865 = 유효 토큰 18.6B이다. λ = 1에서 어떤 반복량도 2U = 20B를 넘지 못한다. 반복 항은 고유 토큰이 적은 ATLAS 언어에서 중요하다. 영어의 2.8T에 비해 힌디어는 7.9B, 스와힐리어는 770M이다(표 C.1).

**증거.** 홀드아웃 언어 혼합에서 전체 법칙은 Chinchilla 법칙의 R² 0.61에 비해 R²(M) = 0.82에 도달한다. 다른 언어 항을 더하면 전체 R²는 0.70에서 0.98로 오른다(표 1, 결과·단일 연구).

### §2.2 두 언어 사이 이전 측정

```
BTS_{s→t} = −( σ_bi(L_t(d_mono)) − 2 · d_mono ) / d_mono
```

- `d_mono`: t의 단일언어 모델 참조 토큰 수(42B 토큰).
- `L_t(d)`: d 토큰 뒤 t 단일언어 모델의 손실.
- `σ_bi(ℓ)`: t에서 손실 ℓ에 도달하는 데 50/50 이중언어(s, t) 모델이 필요로 하는 총 토큰.
- BTS = 0: 이전 없음; BTS > 0: 양의 이전; BTS < 0: 간섭.

**계산 예시.** 이중언어 모델이 토큰 절반을 t에서 본다. 언어 s가 돕지도 해치지도 않으면, 42B에서 단일언어 모델과 같아지는 데 총 2 × 42B = 84B 토큰이 필요하고 BTS = −(84 − 84)/42 = 0이다. 63B가 필요하면 BTS = −(63 − 84)/42 = +0.5이고, 105B가 필요하면 BTS = −0.5이다.

**증거**(2B 모델, 38 × 38 행렬; §4에서 직접 측정한 쌍 80개, 부록 B.6에서 90개, 나머지는 교차 검증 R² = 0.85의 랜덤 포리스트로 예측):
- 영어는 표적 30개 중 19개에서 상위 5개 출발 언어이고, 프랑스어는 16개, 스페인어는 13개에서 그렇다.
- 같은 문자를 공유하는 쌍의 평균 BTS는 −0.23이고, 공유하지 않는 쌍은 −0.39이다. 문자 및 어족 효과는 p < .001이다.
- 이전은 비대칭이다. A→B와 B→A의 상관은 r = −0.11이다.
- 우르두어와 파슈토어는 다른 모든 언어에서 음의 이전을 보인다.
- 더 큰 모델은 간섭 쌍을 0 쪽으로 이동시킨다(부록 C.2).

### §2.3 언어 수를 스케일링 변수로 보기

```
L(K, N, D_t) = L∞ + A · K^ϕ / N^α + B · K^ψ / D_t^β,     D_tot = K · D_t      (Eq. 7)
```

- `K`: 균등하게 샘플링한 학습 언어 수; `D_t`: 언어당 토큰; `D_tot`: 총 토큰.
- `ϕ`: K에 따라 용량 수요가 커지는 정도; `ψ`: K에 따라 언어당 데이터 수요가 바뀌는 정도(ψ < 0은 양의 이전).
- 전체 언어 적합: ϕ = 0.11, ψ = −0.04, R² ≥ 0.87; 언어 4–50개 혼합, 모델 크기 11개, 실행 120개(§5, 표 B.1, B.5).

손실을 고정한 채 K가 rK가 되면, 항별로 `N′/N = r^(ϕ/α)`, `D_t′/D_t = r^(ψ/β)`, `D_tot′/D_tot = r^(1+ψ/β)`, `C′/C = r^(1+ϕ/α+ψ/β)`가 된다(§5, 부록 B.7). 논문의 수치 프런티어(그림 5)는 다음과 같다.

| 언어 | 총 토큰 | 매개변수 |
|---|---|---|
| 2K | ×1.66 | ×1.18 |
| 4K | ×2.74 | ×1.4 |
| 8K | ×4.54 | ×1.66 |
| 16K | ×7.52 | ×1.96 |

**계산 예시.** 400B 토큰으로 학습한 2B 모델이 K = 8개 언어에 언어당 50B 토큰을 제공한다고 하자. 언어별 손실을 바꾸지 않고 32개 언어(r = 4)로 옮기려면 2B × 1.4 = 2.8B 매개변수와 400B × 2.74 = 1,096B 토큰이 필요하다. 언어당 토큰은 1,096B / 32 = 34.25B로, 50B × 0.685이며 §5의 “언어당 데이터 32% 적음”이다. 계산량은 1.4 × 2.74 = 3.84배 오른다. [figures/language-budget-explorer.html](figures/language-budget-explorer.html)(패널 A)는 독자가 K, r, N, D를 바꾸고 네 배수를 보게 한다. 반올림한 지수를 사용하므로 논문이 2.74를 인쇄한 곳에 2.743을 출력한다.

**증거 상태.** 결과·단일 연구. K, N, D 전반에서 언어 수는 N이나 D보다 상대 손실을 더 크게 바꾸고, 더 큰 N은 더 큰 D보다 이를 더 많이 상쇄한다(§5, 그림 4).

### §2.4 처음부터 사전학습하기 대 다국어 체크포인트를 계속 학습하기

ATLAS는 2B 매개변수에서 단일언어 모델을 처음부터 사전학습하는 것과, Unimax 샘플링으로 학습한 다국어 체크포인트에서 계속 학습하는 것을 비교한다(영어 5%, 대부분의 다른 고자원 언어 1.42%; 표 B.4). 체크포인트에서 계속 학습하면 초기에 손실이 더 낮지만, 처음부터 학습이 표적 토큰 144B(영어), 145B(일본어), 148B(포르투갈어), 160B(독일어), 189B(러시아어), 234B(베트남어), 239B(스페인어), 283B(중국어) 뒤에 이를 추월한다(§6, 그림 6). 체크포인트의 학습 길이는 §6에는 1B 토큰, 부록 B.4에는 1T로 인쇄되어 있다(출처 내 충돌). 교차점은 기반 혼합과 그 학습 길이에 달려 있다(§6).

**§2의 조건과 한계.** K 법칙에서는 균등 언어 샘플링, 식 7에는 반복 항 없음, 모델 최대 8B, MADLAD-400만 사용, 64K SentencePiece 어휘, 하위 과제 정확도 없이 손실만 측정([[atlas-multilingual-scaling-laws]], 카드 섹션 “Findings relevant to generality”). 다국어 어휘와 Unimax 학습은 단일언어 어휘 및 학습과 비교해 계산 최적 프런티어를 위로 옮겼으며, 영어에서 가장 컸다(§3, 그림 1).

**범용 모델에 대한 함의.** 언어 범위에는 매개변수와 토큰의 비용이 있다. 매개변수와 총 토큰을 고정한 채 언어를 더하는 계획은 균등 샘플링 언어에 대해 ATLAS가 추정할 수 있는 언어별 손실 증가를 받아들인다.

## §3 언어별 큐레이션

### §3.1 FineWeb2: 각 언어 통계에서 도출한 임계값

**정의.** 언어 적응 파이프라인은 처리하는 언어의 통계에서 언어 식별(LID) 임계값, 휴리스틱 필터 임계값, 업샘플링 가중치를 정한다([[fineweb-2]] §4).

**문제.** 영어에 맞는 임계값은 다른 언어에서는 너무 많은 텍스트 또는 너무 적은 텍스트를 제거한다. 이 파이프라인은 9개 “카나리아” 언어(아랍어, 중국어, 프랑스어, 힌디어, 러시아어, 스와힐리어, 텔루구어, 태국어, 터키어)에서 설계했고, 설계에 쓰지 않은 5개 언어에서 시험했다(§3, §5).

**작동 방식.**
1. GlotLID(언어 1,880개)로 언어를 식별하고, 신뢰도가 언어별 임계값을 넘으면 문서를 남긴다(§4.2).
2. MinHash로 각 언어 안에서 전역 중복 제거하며, 남긴 각 문서의 중복 클러스터 크기를 저장한다(§4.3).
3. 해당 언어의 Wikipedia 또는 Common Crawl 통계에서 적응한 임계값을 가진 휴리스틱 필터를 적용한다(§4.4.2).
4. 저자원 언어에서는 그 언어에 친화도가 높은 단어가 없는 문서를 제거하고, 해당 언어 URL 허용 목록의 페이지를 복원한다(§4.4.3).
5. 필터가 제거한 중복 클러스터 크기 비율에서 정한 가중치로 남긴 문서를 업샘플링한다(재수화, §4.5).

**수식.**

```
LID threshold = max{ 0.3, min{ 0.9, Med(X) − σ(X) } }
```

- `X`: 해당 언어로 라벨링한 문서의 LID 신뢰도 점수 분포; `Med`: 중앙값; `σ`: 표준편차. 부록의 표 15 절은 중앙값 대신 “평균”이라고 말한다(부록 A.6.2).

**계산 예시.** 한 언어에서 Med(X) = 0.85, σ(X) = 0.20이면 임계값은 0.65이다. 더 잡음이 많은 언어가 Med(X) = 0.55, σ(X) = 0.35이면 Med − σ = 0.20이고, 하한이 이를 0.3으로 올린다.

**증거** ([[fineweb-2]], 1.46B 모델, 정규화한 과제의 종합 점수; 결과·단일 연구):
- LID: 스와힐리어는 문서의 거의 65%를 제거하는 임계값 0.3 근처에서 가장 잘 수행했다(§4.2). 이 수식은 중국어(0.7415 대 0.895–0.937)와 힌디어(0.6827 대 0.483–0.557)에서 최선 범위를 벗어났다(표 15).
- 필터 임계값: 29B 토큰에서 절제 모델 207개를 사용했다. 선택한 적응 방법의 순위는 FineWeb Quality, Gopher Quality, Gopher Repetition 필터군에서 각각 3.00, 3.22, 2.22였고, 필터링하지 않은 경우는 7.00, 6.33, 6.22였다(낮을수록 좋음). 기본 FineWeb 영어 임계값은 Gopher Repetition에서 4.22였으며, 다른 두 군에서는 적어도 한 언어의 데이터 75% 초과를 제거하거나 아무것도 제거하지 않아 순위를 매기지 않았다(표 25).
- 정밀도 필터링, 언어별 문서 2,000개에 대한 원어민 감사(표 28):

| 언어-문자 | 이전 정밀도 | 이후 정밀도 | 재현율 |
|---|---|---|---|
| glk_Arab | 2.10% | 27.21% | 95.24% |
| bar_Latn | 69.45% | 94.90% | 97.77% |
| ary_Arab | 1.75% | 4.14% | 88.57% |

- 350B 토큰에서 전체 파이프라인 대 LID 전용 데이터: 아랍어 21.7 → 25.2, 프랑스어 18.3 → 23.6(부록 A.8, 표 29–30).
- 100B 토큰에서 홀드아웃 언어, FineWeb2 대 최선의 다른 데이터셋: 독일어 17.0 대 17.1(HPLT2), 인도네시아어 20.3 대 22.4(HPLT2), 이탈리아어 18.6 대 17.8(HPLT2), 일본어 21.8 대 18.0(CulturaX), 베트남어 21.1 대 19.7(HPLT2)(표 40–44).

**조건과 한계.** 모든 절제 모델은 단일언어이므로, 다국어 혼합 내부에서 파이프라인의 효과는 측정하지 않았다(§3). 언어-문자 쌍 1,868개 중 70%(1,320개)에서는 문서 절반 이상이 Bible 또는 Wikipedia 관련 도메인에서 온다(부록 A.12). 따라서 데이터셋에서 언어의 범위가 있다는 것은 그 언어의 주제 범위가 있다는 뜻이 아니다.

### §3.2 ÜberWeb: 측정된 간섭의 원인으로서 데이터 품질

[[uberweb-multilingual-curation]](자체 파이프라인을 설명하지만 공개하지 않은 데이터 큐레이션 회사 DatologyAI)은 영어와 다른 13개 언어 중 하나를 50/50으로 섞어 60B 토큰에서 3B 모델을 학습한다. 세 체제는 양쪽 절반 모두 비큐레이션, 영어만 큐레이션, 양쪽 모두 큐레이션이다(§4.1.1). “비큐레이션”은 DCLM 및 FineWeb2의 무작위 표본을 뜻한다.

**증거**(결과·단일 연구; 다국어 MMLU, ARC, Belebele, cloze 형식):
- 영어를 큐레이션하면 13개 언어 중 12개(벵골어 제외)의 비영어 점수가 평균 상대 3.91% 올랐다(§4.1.1).
- 이득은 스페인어·프랑스어·독일어에서 8.56%, 힌디어·아랍어에서 3.94%였으며, 영어와의 거리에 상관했다(임베딩 거리 r = −0.62, p = 0.024; 영어 전용 모델의 로그 퍼플렉서티 r = −0.70, p = 0.018)(§4.1.2).
- 비영어 절반을 언어별로 큐레이션하면 비큐레이션 기준선보다 상대 16.87% 이득을 냈다(§1).
- 비영어 절반을 큐레이션하면 13개 쌍 중 12개에서 영어 MMLU와 ARC가 상대 1.21% 올랐다(§4.1.4).
- fastText로 선택한 영어 문서의 번역을 더하면 힌디어·벵골어·아랍어에서 상대 5.09% 이득이 났고, 무작위 문서 번역은 “한계적” 이득을 냈다(§4.2).

**단계형 비율 계산 예시.** 1T-토큰 실행은 다국어 비율 5%에서 650B 토큰, 10%에서 250B, 20%에서 100B를 쓴다(§4.3). 다국어 토큰 = 32.5B + 25B + 20B = 77.5B이며, 이는 1T의 7.75%이고 언어당 77.5B / 13 = 5.96B이다. 논문은 총합을 “약 80B”(§1) 및 “75B”(부록 A.4)로 인쇄한다.

**논문의 주된 주장 상태.** 저자들은 많은 다국어 퇴행이 “근본적 용량 한계보다 수정 가능한 데이터 품질 및 구성의 결함”에서 온다고 결론 낸다(초록). 이는 **해석**이다. 통제 실행은 한 모델 크기의 이중언어이고, §1과 §2의 변수인 고정 용량에서 언어 수를 바꾸지 않기 때문이다. 1T 토큰에서 8B 모델의 스페인어 MMLU 0.55는 Qwen3-4B의 0.67보다 낮다. 논문의 비교는 학습 FLOP당 정확도이다(부록 A.4.1 표 4; FLOP은 부록 A.2 표 3). 언어별 큐레이션 뒤에도 ATLAS의 용량 항이 얼마나 남는지는 **미해결 질문**이다.

### §3.3 공개 모델이 범위에 대해 보고하는 내용

- **Llama 3.1** ([[llama-3]] §3.1.1): 언어 176개로 fastText LID; 언어별 문서 및 줄 수준 중복 제거; 언어 특화 휴리스틱·모델 기반 필터; 다국어 Llama 2 기반 품질 순위자. 다국어 비율(8%, §3.1.2)은 “영어 및 다국어 벤치마크에서 모델 성능의 균형을 맞추며 실험적으로 결정”했으나 표는 제공하지 않는다. 8개 언어가 지원되며, 다른 언어에 대해서는 모델을 “최적화하거나 안전 조정하지 않았다”(§5.2.4, 각주 9).
- **Apertus** ([[apertus]] §3.2.2): 웹 데이터 양이 그 밖의 언어에서는 “빠르게 줄어들기” 때문에, 전체 1,811개 언어의 FineWeb-2를 “자연 빈도”로 사용하되 분류기 기반 품질 필터링(FineWeb-2-HQ)은 가장 큰 20개 언어에만 적용한다.
- **SmolLM3-3B** ([[smollm3-multilingual-configs]]): 공개한 구성은 FineWeb2 언어 14개를 샘플링하지만 블로그는 지원하는 비영어 언어 5개를 나열한다. 2단계에서 베트남어 가중치는 구성 주석 “downsample viet, too many epochs”와 함께 0.00325에서 0.00005로 내려간다(`stage3_9T_11T.yaml` L263). 이는 고유 데이터로 정한 반복 한도이다.

**풀 비율 계산 예시.** Apertus 표 6은 단계별 토큰 풀을 나열하며, 캡션은 모든 풀 토큰을 소비하지 않았다고 말한다. 1단계에는 FineWeb-Edu 4,815B, 다국어 3,557B, 코드 235B, 수학 32B, 프로브 데이터 2B로 총 8,641B가 있고, 다국어 풀은 3,557 / 8,641 = 41.2%이다. 4단계에는 1,619 + 986 + 234 + 32 + 19 + 15 = 2,905B가 있고, 986 / 2,905 = 다국어 33.9%이다. 이는 샘플링 비율이 아니라 풀 비율이므로 초록의 “약 40%”를 확인할 수 없다.

## §4 언어별 비용으로서 토크나이저 fertility와 어휘 크기

ch-11은 BPE 및 SentencePiece 어휘를 만드는 방법을 다룬다. 이 절은 고정 어휘가 각 언어에 부과하는 비용을 측정한다.

### §4.1 Fertility와 프리미엄

**정의.** **Fertility**는 토크나이저가 단어당 만들어 내는 토큰 수이다(Apertus 부록 I: 전체 토큰 / 공백으로 구분한 전체 단어). 병렬 문장 s_A, s_B에 대해 언어 A의 B 대비 **프리미엄**은 |t(s_A)| / |t(s_B)|이며, |t(s)|는 토큰화 길이이다([[tokenizer-language-unfairness]] §3). **압축 비율**은 토큰당 정규화 단위(문자, 바이트, 줄)이다.

**문제.** 더 높은 프리미엄은 같은 콘텐츠에 더 많은 토큰을 뜻하므로, 그 언어는 학습 토큰당, 문맥 창당, 추론 비용 단위당 더 적은 콘텐츠를 받는다.

**증거** ([[tokenizer-language-unfairness]], FLORES-200, 언어 200개에서 문장 2,000개; 결과·단일 연구):

| 언어 | cl100k_base(ChatGPT/GPT-4) | XLM-R | ByT5(UTF-8 바이트) |
|---|---|---|---|
| 영어 | 1.00 | 1.00 | 1.00 |
| 이탈리아어 | 1.64 | 1.19 | 1.19 |
| 중국어(간체) | 1.91 | 0.97 | 0.93 |
| 일본어 | 2.30 | 1.11 | 1.27 |
| 불가리아어 | 2.64 | 1.16 | 1.89 |
| 표준 아랍어 | 3.04 | 1.18 | 1.60 |
| Shan | 15.05 | 4.43 | 3.94 |

(표 1, 4, 5.) 표에서 세 관찰이 따른다. 다국어 서브워드 토크나이저는 격차를 줄이지만 없애지는 못한다. 다국어 토크나이저 5개 모두 프리미엄 2.5를 넘는 언어를 적어도 하나 가진다(§4.3). 바이트 수준 입력은 동등성을 주지 않는다. UTF-8은 ASCII에 1바이트, 키릴 문자 또는 아랍 문자에 2바이트, CJK 문자에 3바이트를 쓰기 때문이다(§4.4). 프랑스어·독일어·베트남어용으로 만든 토크나이저는 영어에 다른 어떤 비표적 언어보다 낮은 프리미엄을 주며, 저자들은 이를 다른 언어 문서 안의 영어 텍스트와 연결한다(§4.2, **해석**).

[[fineweb-2]]는 9개 카나리아 언어와 영어의 Wikipedia 단어에서 같은 문제를 fertility로 보여 준다(부록 A.3, 표 2; 낮을수록 좋음).

| 토크나이저(어휘) | 영어 | 아랍어 | 힌디어 | 태국어 | 텔루구어 | 평균 |
|---|---|---|---|---|---|---|
| Mistral-v3(32,768) | 1.45 | 4.76 | 4.99 | 4.87 | 9.83 | 4.12 |
| Llama3(128,000) | 1.40 | 2.32 | 2.71 | 2.18 | 10.11 | 3.04 |
| Bloom(250,680) | 1.42 | 1.86 | 1.59 | 3.96 | 2.10 | 2.16 |
| Gemma(256,000) | 1.31 | 2.19 | 2.22 | 1.92 | 3.51 | 2.10 |

**계산 예시.** 1,000단어 텔루구어 문서는 Llama3 토크나이저에서 10,110토큰, Gemma에서 3,510토큰이 되어 비율 2.88이다. 1,000단어 영어 문서는 1,400 및 1,310토큰으로 비율 1.07이다. 이 두 토크나이저 사이에서 영어 비용은 7% 바뀌고 텔루구어 비용은 2.88배 바뀐다. 어휘 크기만으로 언어별 비용이 결정되지는 않는다. Bloom(항목 250,680개)의 텔루구어 fertility는 2.10, 태국어는 3.96이고 Gemma(256,000개)는 3.51과 1.92이다. 중요한 것은 토크나이저 학습 데이터가 어느 언어를 포괄했는지이다(**해석**; 표는 어휘 구성을 보이지 않음). FineWeb2는 약 1.5B 매개변수 모델 크기에서 임베딩 행렬 때문에 층 수를 줄여야 하므로 256,000을 넘는 어휘를 제외했다(부록 A.3).

### §4.2 학습과 문맥에 대한 결과

**계산 예시.** cl100k_base(프리미엄 3.04)를 쓴 표준 아랍어에서:
- 4,096-토큰 창은 영어 토큰 4,096 / 3.04 = 1,347개 분량의 콘텐츠를 담는다.
- 영어 토큰 10B 분량의 콘텐츠를 아랍어로 모델에 보이려면 10B × 3.04 = 30.4B 토큰이 든다.
- Shan(15.05)은 같은 창에 영어 토큰 동등물 272개를 담고, 같은 콘텐츠에는 150.5B 토큰이 든다.

[figures/language-budget-explorer.html](figures/language-budget-explorer.html)의 패널 B는 세 토크나이저의 프리미엄을 창 크기와 토큰 예산에 적용한다. 두 결과가 따른다. 첫째, 토큰으로 정의한 언어 비율은 프리미엄이 높은 언어에 비율이 보여 주는 것보다 적은 콘텐츠를 준다. 둘째, 고정 토큰 길이의 장문 맥락 평가는 프리미엄이 높은 언어에서 더 적은 콘텐츠를 시험한다. [[tokenizer-language-unfairness]] §5.3은 cl100k_base에서 버마어와 종카어에는 영어 콘텐츠의 10분의 1 미만이 들어간다고 말한다.

### §4.3 영어에 적합한 계산 최적 할당으로서의 어휘 크기

**정의** ([[vocabulary-scaling-laws]] §2.2). 매개변수는 비어휘 매개변수 `N_nv`와 어휘 매개변수 `N_v = V · d`로 나뉜다. V는 어휘 크기, d는 임베딩 차원이다(논문은 출력 행렬만 계산함). 데이터는 문자 `H`로 세고, 토큰은 `D = H · f(V)`이다. 여기서 `f(V)`는 문자당 토큰이다.

**작동 방식**(§3). 더 큰 V는 f(V)를 낮추므로 고정 토큰 예산은 더 많은 문자를 포괄한다. 어느 크기를 넘으면 f(V)는 거의 변하지 않지만 희귀 토큰의 임베딩은 업데이트를 거의 받지 않는다. 각 계산 예산에서 V가 커지면 손실은 먼저 내려갔다가 올라가며, 최소화하는 V는 예산과 함께 커진다(그림 3).

**수식**(접근법 1, SlimPajama에서 IsoFLOP 적합, N_nv 33M–1.13B, V 4K–96K; §4.1):

```
N_nv = 0.08 · C^0.50        N_v = 0.20 · C^0.42        H = 6.42 · C^0.50
```

- `C`: 학습 FLOP. 어휘 매개변수는 비어휘 매개변수보다 더 느리게 증가한다. γ = 0.42 / 0.50 = 0.84(미분 방법으로는 0.83, §4.2).

**증거**(결과·단일 연구; 영어 데이터; 표 1, 표 3):
- N_nv = 3B의 예측 계산 최적 V는 세 접근법 전반에서 37K–43K, 7B는 60K–67K, 70B는 212K–231K이다.
- N_nv = 2.87B, 2.3e21 FLOP에서 V를 32K에서 43K로 올리면 7개 과제 평균은 50.3에서 51.6으로, ARC-Challenge는 29.1 ± 1.3에서 32.0 ± 1.4로 바뀌었다. 사전학습 실행은 다른 시드로 반복하지 않았다(NeurIPS 체크리스트 항목 7).

**어휘 매개변수 계산 예시.** Apertus 8B는 V = 131,072, d = 4,096이며 입력 및 출력 임베딩이 묶여 있지 않다([[apertus]] §2.1–2.2). 각 행렬은 131,072 × 4,096 = 536,870,912개 매개변수이고, 둘은 합쳐 1.07B이다. SmolLM3-3B는 V = 128,256, d = 2,048, 묶인 임베딩을 가지며([[smollm3-multilingual-configs]]), 128,256 × 2,048 = 262,668,288개 매개변수로 명목 3B의 8.8%이다.

**조건과 한계.** SmolLM3-3B의 128,256개 항목은 N_nv = 3B에 예측한 37K–43K의 3.0–3.5배이고, Apertus 8B의 131,072개 항목은 N_nv = 7B에 예측한 60K–67K의 2.0–2.2배이다. 두 모델은 표 1이 가정한 계산 최적 할당보다 많은 토큰(SmolLM3-3B 11.14T, Apertus 8B 15T)으로 학습한다. 그림 7에서는 과잉 데이터가 최선 V를 위로 움직였다(N_nv = 302M에서 16K → 24K). 그럼에도 저자들은 큰 어휘가 추론 비용을 올리므로 계산 최적 V를 권한다(§5). 이 법칙에는 언어별 항이 없다. 저자들은 “서로 다른 언어가” 모델 용량을 “두고 경쟁한다”는 이유로 다국어 어휘를 미래 연구로 나열한다(부록 B.4). 표적 언어들 사이 프리미엄이 다를 때 V를 어떻게 정할지는 이 장의 출처에서 **미해결 질문**이다. 측정한 두 점은 절충의 영어 쪽을 제한한다. Llama 3 토크나이저는 100K tiktoken 토큰에 28K 비영어 토큰을 더한다. 보고서는 이것이 “영어 토큰화에 영향 없이” 압축과 하위 과제 성능을 개선했다고 하며, 영어 압축은 Llama 2 토크나이저 대비 토큰당 문자 3.17에서 3.94로 올랐다([[llama-3]] §3.2, 하위 과제 수치는 제공하지 않음). cl100k_base 어휘의 3분의 1에서는 영어 FLORES-200 시퀀스가 약 10% 더 길다([[tokenizer-language-unfairness]] 그림 3).

### §4.4 교차 언어 불평등 통계량으로 토크나이저 선택하기

Apertus는 FLORES+ 개발 집합의 55개 언어에서 fertility, 압축 비율, 어휘 활용도, Gini 계수로 기존 토크나이저 네 개를 비교했다([[apertus]] §2.2, 부록 I).

```
Gini = (1/n) · ( n + 1 − 2 · Σ_{i=1..n} (n + 1 − i) · c_i / Σ_{i=1..n} c_i )
```

- `n`: 언어 수; `c_1 ≤ … ≤ c_n`: 오름차순으로 정렬한 언어별 토큰화 비용(정규화 단위당 평균 토큰, 예: 병렬 텍스트 줄당). 0은 모든 언어의 비용이 같다는 뜻이다.

**계산 예시.** 비용 [2, 2, 2, 2]의 언어 네 개에서 Σ(n+1−i)c_i = 4·2 + 3·2 + 2·2 + 1·2 = 20, Σc_i = 8이므로 Gini = (1/4)(5 − 2·20/8) = 0이다. 비용 [1, 1, 2, 4]에서는 Σ(n+1−i)c_i = 4 + 3 + 4 + 4 = 15, Σc_i = 8이므로 Gini = (1/4)(5 − 3.75) = 0.3125이다.

**증거.** Mistral-Nemo는 가장 낮은 Gini 계수를 보였고 fertility와 압축에서 Gemma-2와 같았으며, Apertus는 “언어 전반에서 더 공정하고 더 작은 어휘(128k 대 256k)를 사용”한다는 이유로 이를 골랐다(§2.2). 지표 값은 보고서 그림 1에만 나타나고, 토크나이저를 비교한 사전학습 절제 실험은 없다.

**범용 모델에 대한 함의.** 토크나이저는 학습이 시작되기 전에 같은 콘텐츠에 각 언어가 필요로 할 토큰 수를 고정한다. 언어 비율, 문맥 길이, 평가 길이는 각 언어 프리미엄으로 콘텐츠로 변환한 뒤에만 언어 간 비교할 수 있다.

## §5 다국어 범위 측정

### §5.1 언어별 홀드아웃 손실

토큰당 퍼플렉서티는 그 언어에 같은 토크나이저를 쓰는 모델 사이에서만 비교할 수 있다. [[multilinguality-curse-250-languages]]는 이 때문에 표적 언어마다 토크나이저를 고정한다(§5). 토크나이저를 넘어서 [[vocabulary-scaling-laws]]은 unigram 정규화 손실 `L_u = −(1/T) Σ_i log[ p(w_i | w_<i) / p(w_i) ]`을 쓴다. 여기서 `p(w_i)`는 토큰화한 코퍼스에서 토큰 w_i의 빈도이고 T는 토큰 수이다(식 4). ATLAS도 같은 손실을 쓴다(§2). V가 다른 모델들 사이에서 보통 손실은 큰 어휘가 토큰당 손실을 올리므로 하위 과제 정확도와 양의 상관을 보였고, L_u는 음의 상관을 보였다(부록 A.10, 그림 13).

**계산 예시.** 1,000문자 단락이 토크나이저 A에서는 평균 토큰당 2.4 nats 손실(600 nats)로 250토큰, 토크나이저 B에서는 토큰당 1.6 nats 손실(640 nats)로 400토큰이라고 하자. B는 토큰당 손실이 더 낮지만 A는 문자당 손실이 더 낮다. 문자당 0.60 대 0.64 nats이다. [[vocabulary-scaling-laws]]이 L_u와 상관한다고 보고한 문자당 비트(부록 A.5)는 A를 1위로 매긴다.

### §5.2 과제 평가군과 그 측정 오류

- **원어 항목 대 번역 항목.** Llama 3의 다국어 MMLU는 Google Translate로 만든 내부 번역이며, 과제 지시는 영어로 남겨 둔다([[llama-3]] §5.2.4). Qwen2.5는 번역 MMLU(okapi)와 언어 특화 MMLU 유사 벤치마크 5개(AMMLU, JMMLU, KMMLU, IndoMMLU, TurkishMMLU)를 결합한다([[qwen-2.5]] §5.2.2, 표 13). Apertus는 INCLUDE V1(언어 44개), BLEnD, CulturalBench를 Global-MMLU와 분리한 지역 특화 사실 지식으로 묶는다([[apertus]] 표 15). 번역 항목은 영어 출처의 콘텐츠를 유지하므로, 번역 평가군은 영어 맥락 콘텐츠에 대한 언어 능력을 측정한다(**해석**). 문화 벤치마크 BLEnD에서 Qwen2.5-72B-Instruct는 32.48, GPT-4o-mini는 35.91을 기록한다([[qwen-2.5]] 표 13).
- **초기 학습 신호.** FineWeb2는 단계와 점수의 평균 Spearman ρ ≥ 0.5 단조성, 네 시드 전반 신호 대 잡음비 ≥ 20, 비무작위성 ≥ 3의 기준을 충족한 197개 과제 중 84개를 남겼다. 또한 문자 형식은 초기 학습에서 우연 수준 점수를 내므로 객관식 문자를 cloze 채점으로 바꿨다([[fineweb-2]] 부록 A.5). ÜberWeb은 60B-토큰 실행에서 cloze, 1T-토큰 실행에서 객관식을 사용한다([[uberweb-multilingual-curation]] §3).
- **잘못된 언어 출력.** 다국어 모델은 생성 과제에서 잘못된 언어로 답하면서(“accidental translation”) 객관식 과제에서는 높은 점수를 낼 수 있다([[fineweb-2]] 부록 A.5.1).
- **손실과 과제 지표는 일치하지 않을 수 있다.** 영어 전용 데이터로 사전학습하고 영어-프랑스어 번역으로 미세 조정한 T5-3B에서, 사전학습을 더 해도 BLEU는 개선을 멈추거나 하락했지만 하위 과제 교차 엔트로피는 계속 감소했다([[downstream-scaling-laws-translation]] §5, 그림 3–4). ATLAS는 손실만 보고한다.
- **홀드아웃 평가군.** Apertus는 “모델 개발 중 홀드아웃했고 의사 결정에 사용하지 않은” 벤치마크를 나열한다(§5.2, 표 21). 여기에는 다국어 ARC Challenge가 있으며, Apertus-8B-Instruct는 Llama-3.1-8B-Instruct의 32.0에 비해 36.8을 기록한다.

### §5.3 저자원 및 보지 못한 언어 슬라이스

- 데이터 파이프라인 설계에 쓰지 않은 언어가 하나의 슬라이스를 이룬다. 그런 언어 5개에서 FineWeb2는 독일어 및 인도네시아어에서 HPLT2에 뒤졌고(§3.1), 저자들은 카나리아 언어와 보지 못한 언어의 경향이 일치한다고 보고한다([[fineweb-2]] §5).
- 지원 언어만이 아니라 샘플링한 모든 언어가 슬라이스를 이룬다. SmolLM3는 비영어 언어 14개를 샘플링하고 5개를 지원한다고 나열하며, Llama 3는 언어 176개를 식별하고 8개를 지원한다(§3.3).
- 저자원 생성 과제는 인식만이 아니라 그 언어로 출력하는지를 시험한다. Apertus는 BLEU로 Romansh 변종 6개에서 독일어 ↔ Romansh 번역을 평가한다([[apertus]] §5.3).
- 영어 보존이 중요할 때는, §1과 §2가 고정 크기에서 언어를 더하면 영어 손실이 오른다고 예측하므로, 같은 계산량의 영어 전용 참조가 비교 지점이다.

## 음성 샘플과 음성 피드백

이 단계에서 “음성(negative)”은 강의 표준의 의미 (1), 즉 **음의 한계 가치**를 뜻한다. 언어 식별기, 휴리스틱 필터 또는 단어 목록 검사가 이 문서들을 양성 학습 표적으로 쓰면 성능을 낮출 것으로 예측하기 때문에 제거한다. 이 장의 어떤 출처도 이 단계에서 거부한 문서를 콘텐츠, 조건화, 그래디언트로 사용하지 않는다. 의미 (2)–(4)는 ch-31a와 ch-43a에서 다룬다. 언어 간 음의 이전(§2.2)은 음성 학습 신호가 아니라 양성 학습 데이터의 성질이다.

**음성 예시의 출처와 라벨링 방식.** 언어별 임계값보다 낮은 LID 신뢰도, 휴리스틱 필터 점수, 언어 특화 단어의 부재이다([[fineweb-2]] §4.2–4.4).

**오류율.** 단어 목록 필터 감사는 남긴 집합의 정밀도와 재현율을 보고한다(§3.1의 표 28). ary_Arab에서 필터링 뒤 재현율은 88.57%이므로 감사 표본의 실제 해당 언어 문서 중 11.43%가 제거되었다. Dagbani에서는 정제하지 않은 Wikipedia에서 계산한 불용어 목록에 영어 단어가 들어 있었고, 다시 계산한 목록은 오분류 데이터의 99% 초과를 제거했다(부록 A.7.1).

**현재 관행이 하는 일.** FineWeb2는 제거한 문서를 버리지만 제거 비율은 다시 사용한다. 각 중복 클러스터 크기의 제거 비율이 그 크기에서 남긴 문서의 업샘플링 가중치를 정한다(프랑스어에서 가장 낮은 비율은 가중치 10, 전역 비율 62.4%를 넘으면 가중치 1)(§4.5).

**일반성에 미치는 효과.** 저자원 언어에서 제거 임계값은 잡음과 이용 가능한 적은 텍스트 양 사이를 절충한다. 스와힐리어는 문서의 거의 65%를 제거하는 임계값에서 가장 잘 수행했다(§4.2). Apertus는 데이터 양 때문에 20개 언어를 넘어서는 품질 필터 적용을 멈췄다([[apertus]] §3.2.2). 진단은 저자원 언어를 위한 감사 정밀도·재현율 표본이 붙은 언어별 제거율 표이다.

**소규모 범용 실행의 시작점.** 영어와 소수의 고자원 언어를 서비스해야 하는 약 11T 토큰 학습 3B dense 모델에는 SmolLM3-3B 공개 구성이 128,256-항목 토크나이저와 함께 14개 언어에 FineWeb2와 FineWeb2-HQ를 총 가중치 0.12로 샘플링하며, 고유 데이터가 너무 많이 반복될 때 언어 가중치를 자른다(베트남어, 0.00005). 다수 언어의 범위를 목표로 15T 토큰에서 학습하는 8B–70B 모델에는 Apertus가 55개 언어에서 낮은 Gini 계수로 고른 131,072-항목 바이트 수준 BPE와 함께 언어 1,811개의 FineWeb-2를 비영어 “약 40%”로 사용했다. Llama 3.1(dense, 8B–405B, 약 15T 토큰)은 다국어 토큰 8%와 비영어 토큰 28K를 더한 128K 어휘를 썼다. 언어별 큐레이션으로 1T 토큰을 학습한 3B 또는 8B 모델은 언어 13개에 걸쳐 다국어 토큰 5%, 10%, 20% 단계를 썼고 전체 7.75%였다(단계 길이에서 도출했으며, 논문의 인쇄 총계는 충돌함). 이 비율들 중 어느 것도 공개한 절제로 선택하지 않았다. 비율을 고정할 때는 세 점검이 적용된다. 각 표적 언어에서 선택한 토크나이저의 프리미엄(§4.1), 그 프리미엄에서 계획한 토큰 비율이 사는 콘텐츠(§4.2), 계획한 패스 수에 대한 언어별 고유 토큰 수(ch-14)이다.

## 일반화 렌즈

**(a) 무엇이 범위를 넓히는가.**
- 데이터가 부족한 언어에 관련 언어 데이터를 더하는 것: 유사 언어와 표적 토큰 1M에서 동등 데이터 +33%([[multilinguality-curse-250-languages]] §6.1).
- 언어 수와 함께 매개변수 및 총 토큰 확장: 손실을 바꾸지 않으며 언어 4배에서 1.4배 및 2.74배([[atlas-multilingual-scaling-laws]] §5). 더 큰 모델은 간섭 쌍을 0 쪽으로 이동시킨다(부록 C.2).
- 언어별 큐레이션: 3B 이중언어 실행에서 비큐레이션 데이터 대비 상대 16.87% 이득, 영어 큐레이션으로 다른 언어 13개 중 12개 향상([[uberweb-multilingual-curation]] §1, §4.1.1). FineWeb2의 적응 파이프라인은 350B 토큰에서 아랍어 21.7 → 25.2, 프랑스어 18.3 → 23.6([[fineweb-2]] 표 29–30).
- 더 낮은 교차 언어 불평등을 가진 토크나이저: cl100k_base의 Shan 프리미엄 15.05에 비해 XLM-R 4.43([[tokenizer-language-unfairness]] 표 1, 4); Gini로 고른 Apertus([[apertus]] §2.2).
- 저자원 언어로 선택한 고품질 문서를 번역하는 것: 무작위 문서의 한계적 이득에 비해 상대 5.09% 이득([[uberweb-multilingual-curation]] §4.2).

**(b) 무엇이 좁아짐이나 망각을 일으키는가.**
- 고정 용량에서 더 많은 언어: 추가 토큰 1B는 29.5M 매개변수에서 1B-토큰 언어가 데이터의 37%처럼, 4.6M에서는 12%처럼 수행하게 했다([[multilinguality-curse-250-languages]] §6.2).
- 언어를 더하면서 총 토큰을 고정하는 것: ATLAS의 K 항이 언어별 손실을 올린다(§5, 그림 4).
- 다른 언어에 적용한 영어 필터 임계값([[fineweb-2]] 표 25); 가장 큰 언어만을 위해 학습한 품질 분류기([[apertus]] §3.2.2); 대부분이 Bible 또는 Wikipedia 텍스트인 저자원 데이터(부록 A.12).
- 저자원 언어의 작은 고유 풀 반복: SmolLM3 구성은 “too many epochs” 때문에 베트남어 샘플링을 낮췄고([[smollm3-multilingual-configs]]), Chang 등은 20 에포크 초과에서 과적합을 보았다(부록 A.3).
- 토큰으로 표시한 비율이나 문맥 길이에서 프리미엄이 높은 언어: cl100k_base에서 아랍어 토큰 30.4B는 영어 토큰 10B 분량의 콘텐츠를 운반한다(§4.2).

**(c) 이 단계에서 이를 어떻게 측정하는가.**
- 언어별로 고정한 토크나이저의 언어별 홀드아웃 손실, 또는 토크나이저가 다를 때 어휘 비민감 손실(L_u, 문자당 비트)([[vocabulary-scaling-laws]] 식 4, 부록 A.10).
- 번역 항목 옆의 언어 특화 항목(INCLUDE, KMMLU, IndoMMLU)이 있는 언어별 과제 평가군과 문화 벤치마크([[apertus]] 표 15; [[qwen-2.5]] 표 13).
- 초기 신호로 필터링한 과제: 단조성, 신호 대 잡음비, 비무작위성, cloze 정식화([[fineweb-2]] 부록 A.5).
- 슬라이스: 파이프라인 설계에서 홀드아웃한 언어, 샘플링했지만 지원하지 않는 언어, 저자원 생성 과제, 같은 계산량의 영어 전용 참조(§5.3).
- 알려진 측정 오류: 번역 벤치마크는 영어 맥락 콘텐츠를 담고, FLORES-200에는 영어 중심 이름이 있으며([[tokenizer-language-unfairness]] §6), 객관식 점수는 잘못된 언어 생성을 숨길 수 있고([[fineweb-2]] 부록 A.5.1), 손실이 개선되는 동안 과제 지표는 하락할 수 있으며([[downstream-scaling-laws-translation]] §5), ÜberWeb은 언어별 토큰의 자체 추정으로 학습 FLOP당 정확도에서 모델과 기준선을 비교한다(부록 A.4).

## 흔한 실수와 검출 방법

| 실수 | 관찰 가능한 증상 | 점검 |
|---|---|---|
| 매개변수나 총 토큰을 바꾸지 않고 언어를 더함 | 실행 간 영어 또는 고자원 홀드아웃 손실이 오름 | ATLAS 등손실 계획(§2.3)과 언어별 손실을 비교하고, 같은 계산량에서 영어 전용 참조를 실행한다 |
| 서로 다른 토크나이저의 퍼플렉서티 비교 | 더 큰 어휘의 모델이 손실에서는 나빠 보이지만 과제에서는 더 좋음 | L_u 또는 문자당 비트를 사용한다([[vocabulary-scaling-laws]] 부록 A.10) |
| 토큰 비율을 콘텐츠 비율로 읽음 | “균형” 비율인데도 프리미엄이 높은 언어가 저조 | 병렬 텍스트에서 각 언어 비율에 1 / 프리미엄을 곱한다(§4.2) |
| 영어 LID 또는 필터 임계값 재사용 | 저자원 언어의 감사 표본에 대부분 다른 언어 텍스트가 포함됨(단어 목록 필터 전 ary_Arab 정밀도 1.75%) | 점수 분포에서 언어별 임계값을 정하고, 표본에서 정밀도 및 재현율을 감사한다([[fineweb-2]] §4.2, 표 28) |
| 공개한 비율을 샘플링 비율이라고 가정 | 풀 표에서 도출한 비율이 명시한 비율과 다름 | 공개한 구성 가중치를 읽고, 풀에서 도출한 비율은 도출로 표시한다([[apertus]] 표 6 캡션) |
| 블로그의 “다국어”를 웹 부분 비율로 취급 | 다시 계산한 혼합이 명시한 총합과 맞지 않음 | 구성에서 언어별 가중치를 합산한다([[smollm3-multilingual-configs]]) |
| 저자원 풀을 고유 토큰보다 더 반복 | 학습 후반에 그 언어의 홀드아웃 손실이 오름 | 언어별 패스를 추적하고, 패스가 데이터 제약 한도를 넘을 때 가중치를 제한한다(ch-14) |
| 지원 언어만 평가 | 샘플링했지만 지원하지 않는 언어의 퇴행을 보고하지 않음 | 샘플링한 모든 언어와 설계 홀드아웃 언어를 평가한다(§5.3) |
| 생성 능력에 객관식 점수만 사용 | 답이 잘못된 언어인데 객관식 점수는 좋음 | 생성 과제와 출력 언어-ID 점검을 더한다([[fineweb-2]] 부록 A.5.1) |
| “저주는 데이터 품질 문제”라는 주장을 확정된 것으로 인용 | 추가 용량 없이 많은 언어를 더하는 계획 | ÜberWeb의 이중언어 설계와 변하지 않은 K를 인용하고, 큐레이션만 의존하기 전에 고정 크기에서 K를 시험한다(§3.2) |

## 이해 점검

1. [[multilinguality-curse-250-languages]]에서 유사 언어의 1B 토큰을 더하면 1M-토큰 언어에는 도움이 됐지만, 1B-토큰 언어에는 비유사 언어를 더한 것보다 더 해로웠다. 이전과 용량에 기초한 하나의 설명으로 두 결과를 설명하고, 그 설명을 시험할 추가 실험을 말하라.
2. ATLAS는 언어 4배에 총 토큰 2.74배가 필요하지만 언어당 토큰은 32% 적다고 예측한다. 식 7의 어느 항이 언어당 감소를 만들며, 매개변수 배수가 여전히 1보다 큰 이유를 설명하라.
3. 한 혼합이 프랑스어와 표준 아랍어에 각각 토큰 5%를 할당하고, 학습에는 cl100k_base를 쓴다(프랑스어 프리미엄 1.60, 표준 아랍어 3.04, [[tokenizer-language-unfairness]] 표 1). 아랍어 콘텐츠와 프랑스어 콘텐츠의 비율을 계산하고, 이것이 같은 비율을 해석하는 방식을 어떻게 바꾸는지 설명하라.
4. ÜberWeb은 영어 데이터를 큐레이션하면 이중언어 실행 13개 중 12개에서 비영어 점수가 오른다고 발견한다. 이 결과만으로 다국어성의 저주가 데이터 품질 효과임을 보이지 못하는 이유를 설명하고, 품질과 용량을 분리할 실행을 설계하라.
5. 어휘 스케일링 법칙은 3B 비어휘 모델에 항목 37K–43K를 예측하지만, 다국어 3B 모델은 약 128K를 쓴다. 영어 전용 적합이 생략한 것을 설명하고, V를 고르기 전에 더할 측정을 말하라.
6. SmolLM3 구성은 “too many epochs”라는 주석과 함께 베트남어 가중치를 낮춘다. ATLAS의 반복 함수 S_λ를 사용해 저자원 언어의 가중치를 무한히 올릴 수 없는 이유와, 양의 이전의 대안 출처가 무엇인지 설명하라.
7. 새 모델은 토크나이저 변경 뒤 힌디어 홀드아웃 집합의 토큰당 퍼플렉서티를 개선했지만 힌디어 Belebele 정확도는 변하지 않는다. 두 설명과 이를 구별할 측정을 제시하라.

## 연결

- **이전(의존성):** ch-13 — 도메인 혼합: DoReMi, 혼합 법칙, 규모 전반 검증. 언어 비율은 ch-13이 최적화하는 혼합의 한 차원이다.
- **다음:** ch-14 — 데이터 제약 스케일링, 반복, 사전학습 오염 제거. 저자원 언어에서 §2.1과 §3.3의 반복 한계.
- ch-00 — 범용 능력의 의미와 측정 방법(범위 영역으로서의 다국어 능력).
- ch-08a — 스케일링 법칙과 계산 할당: 사전학습 손실에서 하위 능력까지(ATLAS가 확장하는 Chinchilla 법칙).
- ch-09 — 사전학습 데이터 구성과 능력 범위(범위 지도와 출처 유형).
- ch-10 — 휴리스틱 큐레이션 파이프라인: CCNet, C4, Dolma, FineWeb(FineWeb2가 적응한 영어 파이프라인).
- ch-10a — 모델 기반 품질 필터링과 벤치마크 표적 데이터 선택(품질 분류기의 언어 및 방언 효과).
- ch-11 — 토크나이저, 데이터 출처, PII 제거(어휘를 만드는 방법).
- ch-12 — 중복 제거: 정확 일치, 근사 중복, 의미 중복(언어별 MinHash와 재수화).
- ch-14a — 사전학습 레시피 나란히 보기: 예산, 배치, 일정, 단계 혼합(언어 비율을 포함한 단계 혼합).
- ch-17 — 실습: 범위 측정을 포함한 필터 및 혼합 절제(§5 측정 적용).
- ch-32a — 망각 없는 연속 사전학습: 리플레이, 학습률 재워밍, 합성 연속 사전학습(§2.4의 다국어 체크포인트에서 계속 학습).
- ch-32b — 문맥 길이 확장: 방법, 데이터 혼합, 짧은 문맥 퇴행(토큰 프리미엄과 문맥 용량).
- ch-30b — 다기술 SFT 혼합: 간섭, 이전, 에이전트 및 장문 맥락 비율(다국어 SFT 비율).
- ch-31a — 지도 학습의 음성 샘플: 교정, 실패 조건화, 비평, unlikelihood.
- ch-43a — 음성 샘플과 음성 그래디언트: 우도 이동, squeezing, 음의 어드밴티지.
- ch-47 — 범용 능력을 위한 평가 하니스와 평가군 설계(언어별 평가군).
- ch-50 — 슬라이스 분석, 망각 슬라이스, 실패 버킷화(언어 슬라이스).
- ch-51 — 지표 잡음, 신뢰 구간, 진행/중단 결정(다국어 과제의 신호 대 잡음 기준).
