OpenRLHF PPO: Ray actors and the two KL placements

A PPO job in OpenRLHF is a set of Ray actors plus a driver loop. Click a box to read what that actor owns, what it sends, and which flag changes it. The buttons switch between the two places the KL-to-reference term can be applied. All statements below are read from OpenRLHF@64c1cc4 (2026-04-19); file and line numbers are given for each.

The five coloured boxes are Ray actors with their own GPU placement. The dashed box is the experience maker, which runs on the driver: it collects rollouts, log-probabilities, values and rewards, applies the reward shaping, and computes advantages.

The red path shows where the KL-to-reference term enters. Use the buttons above to switch between the two placements and watch which component computes it.

What the figure asserts, with loci. Actor classes and placement: openrlhf/trainer/ray/{ppo_actor,ppo_critic,launcher,vllm_engine}.py. KL default: --algo.kl.use_loss defaults to False, so the KL term is added to the per-token reward (cli/train_ppo_ray.py L484–486; ppo_utils/experience_maker.py L205–214); with the flag on, the actor computes it during the update and adds kl_loss * kl_ctl to the policy loss (trainer/ray/ppo_actor.py L296–314). KL coefficient default 0.01 (train_ppo_ray.py L419). KL controller: --algo.kl.target defaults to None, which selects FixedKLController (trainer/ppo_trainer.py L171–176). Weight sync uses VLLMLock (trainer/ppo_trainer_async.py L19–34) in asynchronous mode. The repository reports no training results for any of these settings, so this figure contains no performance numbers.
