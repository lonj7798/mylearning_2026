Ring attention in OpenRLHF: slicing and the overlap condition

Set the interconnect, the ring group size --ds.ring_attn_size, and the number of packed tokens in one training micro-batch. The figure shows how OpenRLHF pads and slices the packed sequence across ranks, and whether the per-rank slice is long enough for key-value transfers to overlap with compute. The overlap condition and the per-host numbers are from Ring Attention with Blockwise Transformers for Near-Infinite Context (arXiv:2310.01889 v4).

What the figure asserts, with loci. Minimal block sizes and minimal sequence lengths per host are read from Table 2 of arXiv:2310.01889 v4: A100 NVLink 1.0K and 6.2K; A100 InfiniBand 24.5K and 149.5K; TPU v3 1.1K and 6.6K; TPU v4 1.0K and 6.2K; TPU v5e 1.1K and 6.3K. The maximum activation size per layer is 6bch bytes for ring attention and 2bhs² for a vanilla transformer (Table 1, bfloat16), where b is batch size, h is hidden dimension, s is sequence length and c is block size; this figure fixes b = 1 and h = 4096 so the two can be compared, and takes c as the per-rank slice length. Slicing and padding follow openrlhf/models/ring_attn_utils.py at commit 64c1cc4: ring_attn_pad_len = (ring_attn_size - seqlen % ring_attn_size) % ring_attn_size, after which each rank takes a contiguous slice of length total / ring_attn_size. OpenRLHF turns packing on automatically when --ds.ring_attn_size > 1 and --ds.packing_samples is unset (cli/train_ppo_ray.py L638–641). Neither source reports a measured speed-up for any configuration, so this figure shows the condition, not a predicted throughput.
