Clipping and loss-scale order

With fp16 loss scaling, backward() produces gradients multiplied by the loss scale S. This calculator compares clipping after scaler.unscale_ (the documented order) with clipping before it, and shows what the optimizer receives.

Documented order

  1. scaler.scale(loss).backward() → norm S·‖g‖
  2. scaler.unscale_(optimizer) → norm ‖g‖
  3. clip_grad_norm_(params, c)
  4. scaler.step(optimizer); scaler.update()

Clip before unscale

  1. scaler.scale(loss).backward() → norm S·‖g‖
  2. clip_grad_norm_(params, c) on scaled gradients
  3. scaler.step(optimizer) unscales inside the step
  4. scaler.update()

Formulas. Clip coefficient = min(1, c / (norm + 10⁻⁶)) (PyTorch v2.5.0 torch/nn/utils/clip_grad.py L105-L109). Norm the optimizer receives: documented order ‖g‖·coef(‖g‖); clip before unscale S·‖g‖·coef(S·‖g‖)/S. Relative SGD step = received norm / ‖g‖.

AdamW estimate (simplified). If every coordinate has the same magnitude, the per-coordinate gradient is r = received norm / √N. In steady state |m̂| ≈ √v̂ ≈ r, so the update is α·r/(r + ε) instead of about α. This assumption is a simplification for hand calculation; real gradients are not uniform across coordinates, so coordinates with small gradients are affected more than this estimate shows.

Sources. The unscale-then-clip order and the statement that clipping scaled gradients makes the threshold invalid are from PyTorch docs/source/notes/amp_examples.rst (v2.5.0, L67-L106); init_scale = 2.0**16 is from torch/amp/grad_scaler.py L122. See ch-01 §5.
