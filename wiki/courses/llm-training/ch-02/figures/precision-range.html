Why bf16 matches fp32 range. bf16 keeps all 8 exponent bits of fp32 and sacrifices 16 of fp32's 23 mantissa bits. Exponent bits set the dynamic range (~1e-38 to 3e38), mantissa bits set the relative precision near 1.0. So bf16 covers the same real line as fp32 but with only ~7.8e-3 relative precision (vs 1.2e-7). For LLM gradients, range beats precision — which is why 2023+ frontier runs dropped fp16.

Why fp16 needs loss scaling. fp16's minimum normal is ~6e-8. A large fraction of real LLM gradients (especially in deep transformer stacks) fall below 1e-8, so they silently underflow to zero and the update vanishes. Loss scaling multiplies the loss by S ≈ 2^15 before .backward() to shift the whole gradient distribution up into fp16's window; the optimizer unscales by S just before stepping.

Why E4M3 is used for forward and E5M2 for backward. fp8-E4M3 has one more mantissa bit (so finer precision) but one fewer exponent bit (narrower range, up to 448). Activations and weights are bounded — LayerNorm and initialization keep them near unit scale — so E4M3's range is sufficient and the extra mantissa bit helps. Gradients span many orders of magnitude, so the backward pass uses E5M2: wider range (up to 57344, floor ~6e-8, matching fp16) at the cost of one mantissa bit.
