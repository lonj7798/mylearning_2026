Choosing a post-training stack, and checking that it can see generality

Companion to ch-58 §7. Answer the questions on the left; the procedure has seven questions, five leaves, and no answer returns to an earlier question. Every recommendation is followed by the instrumentation gate of §2, which is the part a throughput comparison does not cover. Commit and date of every matrix cell is given in the table below.

Decision procedure

Result

Answer Q1 to begin.
Instrumentation gate — apply once at the leaf you reach.
  • Periodic in-loop evaluation on a held-out suite with at least one task family the reward does not target (verl trainer.test_freq, default −1; OpenRLHF --eval.steps, default −1; TRL eval_strategy). All three default to off.
  • A logged rollout-versus-training log-probability diagnostic, with a correction available (OpenRLHF vllm_kl; verl algorithm.rollout_correction, default rollout_is: null; TRL vLLM IS correction, on by default when use_vllm=True).
  • Reward or environment routing that preserves the domain identity of each score, so one domain's regression does not average away.
If a leaf fails a check and the hook cannot be added, the next candidate is taken from the fixed order A → B → C → D and the gate is applied once more. The order is fixed and has four entries, so the procedure ends after at most four gate evaluations.
