# Excerpt: Scaling LLM Multi-turn RL with End-to-end Summarization-based Context Management (SUPO)

**Authors:** Miao Lu, Weiwei Sun, Weihua Du, Zhan Ling, Xuesong Yao, Kang Liu, Jiecao Chen (ByteDance Seed; Stanford; CMU). arXiv v1 2025-10-08 (report date September 30, 2025). Source type: paper.
**Used in:** [[read]] §5, Negative feedback, Recipe.

## Problem statement (§1)
Three named difficulties from unbounded context growth in multi-turn RL: "(i) Degenerated instruction following ... (ii) Excessive rollout costs. Longer contexts lead to longer time for rollout ... (iii) Context length limits. Most importantly, the working context length of the underlying LLM fundamentally restricts the horizon of RL training."

## Mechanism (§3, §4, Algorithm 2)
- The working context is reset to "the initial prompt augmented with a task-relevant summary of past interactions". "the summary is neither pre-defined nor rule-based, but rather generated by the agent and optimized jointly as part of the agent's policy".
- Rollout loop: at step t, if the context length `L_t = |(s_t, a_t, o_t)|` is below the threshold `L`, append and continue; otherwise, if the summarization count `I` is below the maximum `S`, set `s_{t+1} := (s_t, v_sum)` — that is, issue the summarization instruction and **discard the last action-observation pair** — else stop. After a summary `a_t` is produced, `s_{t+1} := (s₁, a_t)` and `I ← I + 1`.
- Reason for discarding the last pair (§4.2, "Fine control of context length"): without it the reachable context is `L + 2L_A + L_O + |v_sum|`; with it the bound becomes `L + |v_sum| + L_A`, "ensures that the summary at the end of the trajectory is not clipped by the RL training context length due to a long observation before summarization."
- Effective context length is defined as `L_effect := L_RL × (S + 1)` (§5.1).
- Training decomposition: Theorem 3.2 "decomposes the policy gradient of a long-horizon rollout into the summation of the gradients from several summarized sub-trajectories", so one rollout `j` is treated as `I^j + 1` ordinary trajectories by existing infrastructure. Padding to `⌈N / B_mini⌉ × B_mini` uses "dummy trajectories (one with 0 mask for each token)" that "do not influence the updates".
- **Advantage**: all `I^j + 1` segments of rollout `j` share one advantage computed inside the *rollout* group (Eq. 3). The ablated alternative (Eq. 4) computes the advantage inside the *trajectory* group `{(j,i)}`, repeating the reward once per segment.
- **Overlong masking** (§4.2): "we mask the rollouts failing to give the final response before arriving the maximum step H or the maximum number of summarization S. Without masking, the objective could be biased towards suppressing long rollout that exhibits good summarization strategies despite its failure to provide answers within step or trajectory limits. This could further lead to collapse of summarization patterns in essentially long-horizon tasks."

## Setup (§5.1)
- CodeGym: 12,800 training problems, 128 evaluation problems drawn from different seed coding problems and needing more turns on average. Base model Qwen2.5-32B-Instruct. Batch B = 128, 1 epoch.
- BrowseComp-Plus: 100 of 830 questions held out for evaluation, 730 used for training; retriever Qwen3-Embedding-8B; tools `search(query, top_k)` (500-token overviews), `open_page(url)`, `finish()`. Base model Seed-OSS-36B-Instruct. Batch B = 32, 5 epochs.
- Shared: group size G = 8, no entropy loss and no KL loss, ε_low = 0.20 and ε_high = 0.28, summarization threshold L = 95% of the working context length, maximum steps H = 100, learning rate 1 × 10⁻⁶ with a constant schedule.
- CodeGym SUPO: working context 4K, S = 7 (8 trajectories), effective 32K. BrowseComp-Plus SUPO: working context 64K, S = 2 (3 trajectories), effective 192K. GRPO baselines use 32K and 64K respectively with no summarization.

## Training dynamics (§5.2.2)
- Summarization rate `p_summary = #rollout with summary / #rollout` rises through training on CodeGym and stays near 1 on BrowseComp-Plus.
- Conditional success rate `p_success on summary = #successful rollout with summary / #rollout with summary` rises during training in both environments.
