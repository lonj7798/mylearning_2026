# Chapter 10a — 모델 기반 품질 필터링과 벤치마크 표적 데이터 선택

> **핵심 통찰.** 모델 기반 품질 필터는 학습된 채점기가 가장 높은 점수를 매긴 문서를 남긴다. 아래 연구들에서 가장 많이 개선되는 벤치마크는 채점기의 양성 예시 또는 표적과 닮은 벤치마크이다(이 강의의 **해석**). 같은 200B-토큰 풀에서 선택한 29B 토큰으로 학습한 1B 모델에서 FineWeb-Edu 필터는 ARC-Easy를 9.7점, MMLU를 4.0점 올렸고, HellaSwag는 1.5점, PIQA는 1.4점, SIQA는 2.0점 낮췄으며, 필터링하지 않은 풀에서 떼어 둔 텍스트의 퍼플렉서티는 12.1에서 14.7로 올렸다([[weborganizer]] 표 1, 표 10). 두 연구에서는 선택을 풀의 더 넓은 부분에 분산했을 때 낮아진 과제의 일부 또는 전부가 회복되었다. 교육적 가치 등급에 따라 온도 τ = 2로 샘플링하면 1.3B에서 균등 선택보다 10개 과제 모두가 개선되었고([[qurating]] §5.3), 도메인별 토큰 할당량은 FineWeb-Edu의 HellaSwag를 56.0에서 62.5로, PIQA를 69.9에서 73.3으로 높였다. 다만 SIQA는 무작위 기준선보다 여전히 낮았고(49.4 대 49.9), 그 할당량은 MMLU와 HellaSwag 쪽으로 조정된 혼합에서 나왔다([[weborganizer]] 표 1, 표 10). 표적 데이터에서 얻는 벤치마크 향상의 일부는 시험 과제와의 유사성을 측정한다. 모든 기반 모델을 같은 과제 데이터로 미세 조정한 뒤에는, 같은 사전학습 계산량에서 최신 모델이 보인 MMLU 7점 및 GSM8K 19점 우위가 더는 유의하지 않았다([[training-on-the-test-task]] §2.2, 그림 1).
>
> **지침.** 품질 분류기를 선택하거나 조정할 때는 양성 예시와 닮은 과제, 닮지 않은 과제, 그리고 필터링하지 않은 풀의 도메인별 퍼플렉서티에서 평가하라. 평균은 오를 수 있지만 관계없는 과제는 하락할 수 있기 때문이다(FineWeb-Edu, 1B: 평균 +2.6, SIQA −2.0; [[weborganizer]] 표 1). 학습 기간에 상위 10% 필터가 남기는 것보다 더 많은 고유 토큰이 필요하다면, 여러 분류기와 단계화한 품질 버킷을 사용하고 낮은 점수의 텍스트를 버리지 말고 다시 표현하라. Nemotron-CC의 3개 분류기 앙상블은 같은 수준이거나 더 높은 10개 과제 평균에서 FineWeb-Edu 및 DCLM 분류기의 8%와 11%에 비해 토큰의 25%를 고품질로 라벨링했기 때문이다([[nemotron-cc]] 표 9). 선택이 이름 붙은 벤치마크에 맞춰 최적화되었다면(벤치마크 상관 선택, 데이터모델, 혼합 회귀), 표적이 아니었던 과제와 균등 샘플링 기준선을 보고하라. [[dsdm]](그림 4)과 [[weborganizer]](표 10)에서 한 과제를 표적화하면 관계없는 과제가 낮아졌기 때문이다. 그렇지 않으면 단단한 상위 k 임계값보다 온도 샘플링이나 도메인 할당량을 선호하라.

## 범용 모델에서 이 장이 중요한 이유

범용 모델의 파이프라인은 사전학습 → 중간학습 → SFT → 선호 최적화 → RL → 평가이다. 이 장은 사전학습 데이터 큐레이션에 속한다. ch-10은 휴리스틱 단계(텍스트 추출, 언어 식별, 규칙 기반 필터)를 다뤘다. 그 단계들과 중복 제거 뒤에도 남은 풀은 여전히 토큰 예산보다 크므로, 어떤 문서로 학습할지 선택해야 한다.

**모델 기반 품질 필터링**은 학습된 모델이 낸 점수로 사전학습 문서를 선택하는 일이다. 양성·음성 예시 문서로 학습한 분류기, LLM 등급으로 학습한 회귀 헤드, 문서가 벤치마크 손실에 미치는 영향을 모델링한 모델, 또는 문서 손실과 벤치마크 정확도의 상관관계를 사용할 수 있다. 측정 가능한 문제는 채점기가 “품질”을 암묵적으로 정의한다는 점이다. 선택된 분포는 이어서 어떤 과제가 개선되는지, 어떤 주제·형식·언어 변종을 모델이 덜 보게 되는지를 결정한다.

세 가지 측정된 효과가 이를 일반성 문제로 만든다. 첫째, 필터는 평균만 바꾸는 것이 아니라 과제 프로필을 바꾼다(§2, §3). 둘째, 약 10%의 문서를 남기는 필터는 0.2T–1.0T 고유 토큰만 남기지만, 15T-토큰 실행은 웹 데이터에서 7.17T 토큰을 뽑았다(§4). 셋째, 벤치마크 점수에 맞춰 조정된 선택은 시험 과제와 닮았기 때문에 그 벤치마크를 올릴 수 있다(§6). ch-09는 사전학습 데이터의 능력 범위를 정의하고, ch-12는 중복 제거, ch-13은 도메인 혼합, ch-14는 오염 제거를 다룬다. ch-17은 이 장의 측정을 적용하는 실습이다.

## §1 모델 기반 선택 방법의 구성 요소

**정의.** 선택 방법에는 네 부분이 있다. (1) 품질을 정의하는 표적(양성 예시, LLM 프롬프트, 벤치마크 또는 표적 과제 집합), (2) 채점 모델, (3) 선택 규칙, (4) (1)–(3)을 고르기 위해 쓰는 평가이다.

**문제.** 같은 풀과 예산에서도 이 부분들에 따라 다른 모델이 나온다. [[dclm]] 표 4에서 같은 RefinedWeb 재현본(RefinedWeb 휴리스틱 필터를 DCLM이 재구현한 것, §4.1)에 적용한 7개 채점기는 CORE 점수를 26.1(PageRank 상위 20%)부터 30.2(OpenHermes-2.5와 ELI5 양성 예시로 학습한 fastText)까지 만들었으며, 모델 기반 필터링이 없을 때는 27.5였다(1B-1x 규모: 1.4B 매개변수, 28.8B 토큰).

**작동 방식.**
1. 휴리스틱 정제와 중복 제거로 풀을 만든다(ch-10, ch-12).
2. 채점 모델로 모든 문서에 점수를 매긴다.
3. 선택 규칙을 적용한다. 임계값 규칙은 문서 점수가 t 이상일 때 남긴다. 백분위 규칙은 정해진 문서 비율이 남도록 t를 정한다. 샘플링 규칙은 점수에 따라 증가하는 확률로 문서를 뽑는다(§5.1).
4. 선택된 집합으로 학습하고 평가한다.

**수식.**

```
keep(d) = 1[ score(d) ≥ t ]                    (임계값 또는 백분위 규칙)
retention r = tokens kept / tokens in pool
passes = tokens needed by the training run / unique tokens available
```

여기서 d는 문서, t는 임계값, r은 보존 비율이다. “패스(passes)”는 각 고유 토큰을 평균적으로 몇 번 보는지를 뜻한다.

**계산 예시([[dclm]] 그림 4에서 도출).** 그림 4는 원래 DCLM-Pool 문서의 비율을 보고한다. 휴리스틱 정제는 19.9%를 남기고, Bloom-filter 중복 제거(ch-12)는 6.2%를 제거하여 13.7%가 남으며, fastText 필터는 12.3%를 제거하여 1.4%가 남는다. 따라서 fastText 단계는 자신이 보는 문서 중 1.4 / 13.7 = 10.2%를 남기며, 이는 §4.4의 상위 10% 규칙과 맞는다. FineWeb-Edu는 FineWeb의 15T 토큰 중 1.3T를 남기므로 r = 8.7%이다([[fineweb]]에서 도출).

**범용 모델에 대한 함의.** 방법의 각 부분은 좁은 표적이 들어갈 수 있는 지점이다. 이후 절에서는 네 가지 측정으로 각 부분을 평가한다. 양성 예시와 닮은 과제, 닮지 않은 과제, 필터링하지 않은 풀의 도메인별 퍼플렉서티, 그리고 남은 고유 토큰 수이다.

## §2 FineWeb-Edu: LLM 주석 교육 분류기와 그 임계값

**정의.** FineWeb-Edu는 0–5 교육적 가치 분류기에서 문서 점수가 최소 3인 FineWeb의 1.3T-토큰 부분집합이다([[fineweb]] §4).

**작동 방식** ([[fineweb]] §4, 부록 F.1).
1. Llama-3-70B-Instruct가 CC-MAIN-2024-10의 페이지 460,000개를 가산형 0–5 프롬프트로 채점한다. 이 프롬프트는 그 페이지가 “초등학교부터 학년 수준까지 가르치는 교육 환경에서 유용할 수 있는지”를 묻는다. 저자들은 arXiv 초록처럼 고도로 기술적인 페이지가 선호되지 않도록 이를 초등학교와 중학교 지식으로 제한했다.
2. 동결한 Snowflake-arctic-embed-m 인코더 위의 선형 회귀 헤드를 주석 410,000개로 학습률 3e-4에서 20 에포크 학습한다. 나머지 50,000개에서 F1이 가장 좋은 체크포인트를 남긴다.
3. 예측을 0–5의 정수로 반올림한다. 임계값 3은 검증 집합에서 이진 F1 82%를 준다.
4. 15T 토큰 전체를 채점하는 데 H100 GPU 6,000시간이 걸렸다.

**증거.** 350B 토큰으로 학습한 1.71B 모델에서 FineWeb-Edu는 FineWeb과 비교해 MMLU를 33%에서 37%로, ARC를 46%에서 57%로 올렸다(§4). 임계값은 28B 토큰에서 FW-Edu-2, -3, -4로 골랐고, 3은 최상의 종합 점수와 “지식 및 추론 집약적 벤치마크의 성능과 HellaSwag 같은 다른 벤치마크의 성능 사이의 최선의 절충”을 보였다(§4, 부록 F.2). 논문은 HellaSwag 비용을 그림에서만 보고한다.

한 풀에서의 독립 비교는 과제별 수치를 제공한다. [[weborganizer]]는 200B-토큰 중복 제거 Common Crawl 풀에서 선택한 데이터로 1B 모델(DCLM 1b-1x 설정, 약 29B 토큰)을 학습했다(표 1, 표 10; 변화량은 도출).

[[smollm2]](표 1, 1.7B 모델, 각각 350B 토큰)는 더 큰 토큰 수에서도 같은 분할을 보고한다. FineWeb-Edu는 MMLU(37.5 대 35.5), ARC(57.5 대 53.5), OpenBookQA(41.9 대 40.8)에서 더 높고, DCLM은 HellaSwag(62.3 대 60.1)와 CommonsenseQA(40.1 대 36.2)에서 더 높다. HellaSwag와 CommonsenseQA의 이 패턴은 [[weborganizer]]와 [[smollm2]]에 걸쳐 **복제됨**으로 분류된다.

FineWeb 논문은 분포 이동 자체를 문서화한다([[fineweb]] §4.1–4.2). 주제 군집에서 FineWeb-Edu는 “교육, 학습, 교수”(+3.2%)와 “역사, 문화, 정치”(+2.2%)를 늘리고, “비즈니스, 금융, 법”, “엔터테인먼트, 영화, 연극”, “장소, 여행, 부동산”의 샘플 비율을 낮춘다. Paloma 도메인별 퍼플렉서티([[paloma]], 546개 영어 및 코드 도메인에 대한 퍼플렉서티 벤치마크)에서는 FineWeb으로 학습한 모델이 광범위한 웹 출처, Twitter AAE, 100개 Subreddit에 더 잘 맞고, FineWeb-Edu 모델은 Wikipedia, arXiv, S2ORC 텍스트에 더 잘 맞는다.

**조건과 한계.** FineWeb 절제 실험은 명령어 조정 없이 한 모델 크기(1.71B)와 학술 벤치마크를 사용한다([[fineweb]] §6). ARC에는 3–9학년 과학 시험 문제가 들어 있으며([[dclm]] 부록 G.1), 주석 프롬프트는 초등학교 수준의 교육 내용을 요구한다. 이 강의는 ARC 향상(1.71B에서 +11점, 1B에서 ARC-Easy +9.7)을 부분적으로 그 유사성의 결과로 읽는다(**해석**). 이를 분리해 낸 출처는 없다.

**함의.** FineWeb-Edu는 지식·추론 필터이지, 범용 품질 필터가 아니다. 이것만 사용할 때는 상식, 사회적, 비격식 텍스트 능력에 별도 측정이 필요하다.

## §3 DCLM: 명령어 형식 양성 예시를 사용한 fastText, 그리고 CORE 대 EXTENDED

**정의.** DCLM-Baseline은 중복을 제거한 RefinedWeb 스타일 풀에서 fastText 분류기 점수의 상위 10%를 남겨 만든 3.8T-토큰 데이터셋이다([[dclm]] §4.4, 그림 4). fastText는 단어 n-그램 특성 위에서 작동하는 선형 텍스트 분류기이며, DCLM은 유니그램과 바이그램 특성을 쓴다(부록 J.1).

**문제.** 고전적인 품질 분류기는 Wikipedia나 책 같은 참조 코퍼스를 양성 예시로 쓴다. DCLM이 시험하는 질문은 어느 양성 예시 집합이 최선의 사전학습 데이터를 만드는가이다.

**작동 방식** ([[dclm]] 부록 J.1).
1. 학습 집합은 문서 400K개이며, 양성 200K개와 음성 200K개로 구성된다. 음성 예시는 더 이른 RefinedWeb 재현본에서 무작위로 뽑은 문서이다.
2. 양성 예시는 OpenHermes 2.5 예시 100K개(대부분 합성 명령어 및 채팅 샘플 약 1M개의 모음, [[openhermes-2-5]])와, 상위 답변과 짝지은 ELI5 질문이다. ELI5는 게시물 점수가 ≥ 0, 최고 댓글 점수가 ≥ 5, 댓글이 최소 3개일 때 남긴다.
3. 특성은 `wordNgrams = 2`를 제외하면 fastText 기본값을 쓴다.
4. 점수는 양성 라벨의 예측 확률이며, 문서 상위 10%를 남긴다.

**수식: 중심화 정확도.** DCLM은 CORE(분산이 낮은 과제 22개)와 EXTENDED(전체 과제 53개, 예를 들어 GSM8K, GPQA, SVAMP, BBQ, AGI Eval 추가)를 중심화 정확도로 보고한다. 이는 “과제별 정확도를 선형적으로 재조정하여 0은 무작위 추측에, 1은 완벽한 정확도에 대응하게” 한 것이다(§3.5).

```
centered_acc = (acc − r) / (1 − r)
CORE = mean over 22 tasks of centered_acc;   EXTENDED = mean over 53 tasks
```

여기서 acc는 원시 정확도이고 r은 그 과제의 우연 정확도이다.

**계산 예시.** 4지선다 과제에서는 r = 0.25이고, 정확도 0.40은 (0.40 − 0.25)/0.75 = 0.20을 준다. 이진 과제에서는 r = 0.5이고, 정확도 0.60은 (0.60 − 0.5)/0.5 = 0.20을 준다. 원시 정확도는 20점 차이 나지만, 둘은 평균에 같은 양만큼 기여한다.

**증거.** 7B-1x(6.9B 매개변수, 138B 토큰)에서 양성 예시 집합은 CORE를 최대 6.3점 바꿨다([[dclm]] 표 5).

| 양성 예시 | 보존 비율 | CORE | MMLU | EXTENDED |
|---|---|---|---|---|
| OH-2.5 + ELI5 | 상위 10% | 41.0 | 29.2 | 21.4 |
| Wikipedia | 상위 10% | 35.7 | 27.0 | 19.1 |
| OpenWebText2 | 상위 10% | 34.7 | 25.0 | 18.7 |
| GPT-3 근사본 | 상위 10% | 37.5 | 24.4 | 20.0 |
| OH-2.5 + ELI5 | 상위 15% | 39.8 | 27.2 | 21.5 |
| OH-2.5 + ELI5 | 상위 20% | 38.7 | 24.2 | 20.3 |
| OH-2.5 + ELI5, 유니그램만 사용 | 상위 10% | 40.0 | 28.3 | 22.1 |

두 평가군은 모든 선택에서 일치하지 않는다. CORE는 15%보다 10%를, 유니그램보다 바이그램을 선호한다. 반면 EXTENDED는 15%에서 0.1 높고 유니그램에서 0.7 높다(표 5, 표 14). 이 표들은 시드 분산을 보고하지 않았으며, 저자들은 “실행 간 변동을 충분히 탐색할 수 없었다”고 말한다(§6). 따라서 이처럼 1점 미만의 EXTENDED 차이는 잡음일 수 있다(**미해결 질문**).

다른 DCLM 결과도 일반성과 관련이 있다.
- 인간 일치는 데이터 가치를 예측하지 않는다. ROC-AUC는 모든 임계값에서 참양성률과 거짓양성률로 만든 곡선 아래 면적이며(0.5는 우연), 사람 라벨이 붙은 약 500개 문서에서 AskLLM(명령어 조정 LLM에 유용성을 판단하도록 프롬프트함)은 다수 라벨과 약 82% ROC-AUC로 일치했고 fastText 필터는 약 73%였다. 그러나 AskLLM 필터 데이터는 CORE 약 28.5를 냈고, 여러 fastText 필터는 31을 넘겼다(부록 N).
- 이 필터 뒤에 큐레이션 출처를 추가하면 점수가 낮아졌다. Llama/RedPajama 비율로 RedPajama 추가분(Wikipedia, Books, Stack Exchange, arXiv, GitHub) 33%를 섞으면 C4의 CORE는 +2.2, RefinedWeb의 CORE는 +1.4 올랐지만, DCLM-Baseline의 CORE는 31.1 → 29.9로 낮아졌다(표 6).
- 코드와 수학은 약하다. 2.5T 토큰으로 학습한 7B 모델은 표 29에서 GSM8K 2.1을 기록한다(부록 Q.1 본문은 2.5%를 제시한다). 명령어 조정은 이를 52.5로 올리지만 CORE는 56.0에서 55.0으로 낮아진다(표 29). 저자들은 모델이 “코드와 수학에서 잘 수행하지 못한다”고 명시한다(§6).
- 0.28T 토큰의 7B에서 DCLM-Baseline은 CORE 48.9, MMLU 50.8, EXTENDED 31.8을 기록했으며, FineWeb-Edu의 41.9, 37.3, 24.5와 대비된다(표 8).

**조건과 한계.** 표 5 실행은 최종 7B 설정이 아니라, 더 이른 학습률 3e-4와 가중치 감쇠 0.33을 사용했다(부록 F). CORE와 EXTENDED에는 장문 맥락, 도구 사용, 명령어 따르기 또는 코드 생성 과제가 없으며, EXTENDED에는 GSM8K와 SVAMP 같은 수학 문장제 과제가 들어 있다(부록 G.1).

**함의.** 최선의 DCLM 양성 예시는 질의응답 텍스트이다. CORE와 MMLU도 질의응답 평가이다. 이 강의는 이 향상을 더 좋은 텍스트와 평가 형식에 더 가까운 유사성이 섞인 결과로 읽는다(**해석**; §6이 형식에 관한 증거를 제시한다). 이 필터 뒤에 CORE만 보고 내린 혼합 결정은 GitHub와 arXiv 데이터를 제외할 수 있으며, CORE에는 그 비용을 드러낼 코드 생성 과제가 없다(**해석**). 최종 모델을 위해 저자들은 “수학 및 코딩 과제를 포함하여 학습한 모델이 폭넓게 유용하도록 보장하기” 위해 StarCoder와 ProofPile2를 더했다(§5).

## §4 Nemotron-CC: 긴 학습 기간에서 품질 대 고유 토큰

**정의.** Nemotron-CC는 6.3T-토큰 영어 Common Crawl 데이터셋이다. 전역 중복 제거한 실제 토큰 4.4T와 다시 표현한 텍스트 토큰 1.9T로 이루어지며, 분류기 앙상블이 이를 다섯 품질 수준으로 라벨링한다([[nemotron-cc]] §2.4, 표 4).

**문제.** Nemotron-CC는 전역 퍼지 중복 제거 후 DCLM과 FineWeb-Edu에 고유 토큰이 각각 약 1.0T와 0.2T 남고(표 4), 각 분류기가 고품질 토큰의 약 10%를 재현율로 포착한다고 추정한다(§2.2).

**계산 예시(도출).** 15T-토큰 Nemotron-CC 모델은 영어 Common Crawl에서 7.17T 토큰을 뽑았다(부록 E). 이 토큰들이 고유 토큰 U개인 데이터셋에서 왔다면, 패스 수 = 7.17T / U이다. U = 1.0T(DCLM)일 때 7.2이고, U = 0.2T(FineWeb-Edu)일 때 35.9이다. [[data-constrained-scaling]]은 약 4 에포크까지는 고유 데이터에 가까운 시험 손실을 얻으며, 그 뒤의 반복은 가치가 점차 줄어든다고 밝혔다. 실행 자체는 품질 버킷에 서로 다른 가중치를 주었고, 버킷별 반복 횟수는 보고하지 않았다.

**작동 방식** ([[nemotron-cc]] §2).
1. Justext로 추출하고, 고품질 텍스트에는 휴리스틱 필터를 적용하지 않는다. 13개 스냅샷 전체에서 고품질 토큰(FineWeb-Edu 분류기 점수 3–5)은 80B(Trafilatura, 필터 적용)에서 127B(Justext, 필터 미적용)로 늘었다. 휴리스틱 필터는 고품질 토큰의 18.1%를 제거했다(표 1, §2.1).
2. FineWeb-Edu 주석 문서 460K개에 대해 Mistral 8x22B-instruct와 Nemotron-340B-instruct가 매긴 점수로 교육적 가치 분류기 두 개(Snowflake-arctic-embed-m 위의 선형 헤드)를 학습하고, 공개된 DCLM fastText 분류기를 추가한다.
3. 각 분류기의 점수를 0–19 버킷으로 반올림한다. 각 버킷은 문서의 약 5%를 담는다.
4. 앙상블 점수 = 세 분류기 중 최대 버킷이다.
5. 8B 모델에서의 어닐링 시험으로 버킷을 다섯 라벨로 묶는다(어닐링 시험은 부분 학습된 체크포인트에서 시험 데이터를 포함하는 혼합으로 사전학습을 계속하고, 그 결과 점수를 비교한다)(표 2: High = 19, Medium-High = 18, Medium = 12–17, Medium-Low = 7–11, Low = 0–6).
6. 저품질 문서를 Wikipedia 스타일로 다시 표현하고, Mistral NeMo 12B로 고품질 문서에서 질의응답 쌍, 증류한 단락, 추출한 지식, 지식 목록을 생성한다(§2.3).

**수식.**

```
b_c(d) ∈ {0, …, 19}   bucket of document d under classifier c (about 5% of documents per bucket)
e(d) = max_c b_c(d)   ensemble bucket
```

**계산 예시.** 버킷이 (12, 19, 8)인 문서는 e = 19(High)를 받는다. (5, 6, 7)인 문서는 e = 7(Medium-Low)을 받는다. 세 분류기의 버킷-19 집합이 겹치지 않았다면 그 합집합은 문서의 15%를 담고, 완전히 겹쳤다면 5%를 담는다(도출한 경계). 표 2는 버킷 19에 토큰의 12.63%가 있다고 보고한다. 이는 문서 비율이 아니라 토큰 비율이다.

**증거.**
- 분류기들은 서로 일치하지 않는다. CC-MAIN-2021-21에서 FineWeb-Edu 또는 DCLM 분류기가 고품질로 라벨링한 문서 중, 10.1%는 양쪽 모두가 고품질로 라벨링하고, 35.4%는 FineWeb-Edu만, 54.4%는 DCLM만 고품질로 라벨링한다(표 8).
- 앙상블은 평균을 낮추지 않고 더 많은 토큰을 남긴다(표 9, 8B 모델, 1T 토큰). 고품질 비율은 앙상블에서 25%로, FineWeb-Edu 분류기의 8%와 DCLM 분류기의 11%에 비해 높다. 10개 과제 평균은 59.4로, 각각 59.0 및 58.4와 대비된다. DCLM 분류기가 선택한 데이터는 SIQA에서 33.9를 기록했으며, FineWeb-Edu는 45.8, 앙상블은 45.7이었다.
- 휴리스틱 필터를 저품질 데이터에만 적용하면 MMLU 57.5와 비-MMLU 평균 60.6을 기록했다. 필터를 모든 Justext 데이터에 적용할 때의 54.1과 60.9, 어느 데이터에도 적용하지 않을 때의 55.5와 60.3에 대비된다(표 7).
- 저품질 문서를 다시 표현하면 평균은 52.5에서 54.0으로 올랐지만 MMLU는 48.2에서 47.1로 낮아졌다. 고품질 데이터를 8회 반복하는 것 중 4회를 합성 변형으로 바꾸면 평균은 55.8에서 56.7로 올랐다(표 10).
- 1T 토큰에서 1.1T-토큰 고품질 부분집합은 MMLU 59.0 및 평균 60.1을 기록했고, DCLM은 53.4와 57.0을 기록했다. 전체 6.3T 데이터셋은 53.0과 57.8을 기록했다(표 5).
- 15T 토큰에서 8B 모델은 저자들의 하니스에서 측정한 Llama 3.1 8B의 65.3 및 64.2에 비해 MMLU 70.3, 10개 과제 평균 64.7을 기록했다. RACE(37.8 대 39.1)와 WinoGrande(73.8 대 74.7)를 포함하여 10개 과제 중 6개에서 더 낮았다(표 6).

**조건과 한계.** 하나의 앙상블 전략만 시험했으며, 다시 표현한 텍스트는 사실 정확성을 검사하지 않았고, 데이터는 영어만 포함하며 오염 제거하지 않았다([[nemotron-cc]] §6). 버킷 시험은 9개 과제를 가진 “70% 학습된 8B” 모델로 설명되기도 하고(§2.2), 13개 과제를 가진 900B-토큰 체크포인트로 설명되기도 한다(부록 C).

**함의.** 긴 학습 기간의 제약은 하나의 분류기의 정밀도가 아니라 고유한 고품질 토큰이다. 앙상블은 재현율을 높이고, 다시 표현은 낮은 점수의 문서를 제거하는 대신 바꾼다(음성 샘플 참조).

## §5 대안 선택 목표

### §5.1 QuRating: 쌍대 LLM 판단과 온도 샘플링

**정의.** QuRating은 네 가지 기준(문체, 사실과 상식, 교육적 가치, 필요한 전문성)에서 쌍대 LLM 판단으로 등급 모델을 학습하고, 등급에 따라 증가하는 확률로 문서를 샘플링한다([[qurating]] §3–4).

**작동 방식.**
1. GPT-3.5-turbo가 기준별 문서 쌍 250K개를 두 순서 모두에서 판단하며, 평균 낸 신뢰도는 p_{B≻A}이다(§3.4).
2. Bradley-Terry 모델이 판단을 스칼라 등급으로 바꾼다. 쌍대 판단은 단일 등급보다 저자들의 문서 10개 순위와 더 잘 맞았다(Kendall의 tau 0.79 대 0.61, §3.3).
3. 헤드 네 개를 가진 1.3B QuRater 모델이 260B 토큰의 등급을 매기며, 등급은 분산 1로 정규화한다.
4. 아래 확률로 문서를 비복원 추출한다(§4).

**수식.**

```
p_{B≻A} = σ(s_B − s_A)                      (Bradley-Terry)
p(d_i) ∝ exp(s_i / τ)                       (selection)
```

s는 문서 등급, σ는 시그모이드, τ는 온도이다. τ → 0은 상위 k 선택이고, τ → ∞는 균등 샘플링이다. 부록 C는 이 샘플링이 전체 코퍼스로 학습한 뒤 KL 가중치 τ를 사용해 더 높은 등급 쪽으로 RLHF를 수행하는 것을 근사함을 보인다.

**계산 예시.** 세 문서의 등급이 2, 0, −2라고 하자. τ = 1에서 가중치는 e², e⁰, e⁻² = 7.389, 1, 0.135이므로 확률은 0.867, 0.117, 0.016이다. τ = 2에서 가중치는 e¹, e⁰, e⁻¹ = 2.718, 1, 0.368이고, 확률은 0.665, 0.245, 0.090이다. τ를 두 배로 하면 최저 등급 문서의 확률은 1.6%에서 9.0%로 오른다.

풀 규모에서 이 효과는 도메인 범위에 나타난다. 등급이 평균 +0.71과 −0.71, 표준편차 0.71(전체 분산 1)인 정규분포를 따르는 크기가 같은 두 도메인으로 된 설명용 풀(출처 데이터 아님)에서, 상위 k로 30%를 선택하면 낮은 등급 도메인은 선택분의 5.6%를 차지한다. τ = 1 샘플링에서는 25.1%, τ = 2에서는 35.9%, 균등 샘플링에서는 50%이다(Gumbel 상위 k 샘플링의 대규모 풀 극한, 강의 계산). Gumbel 상위 k는 각 s/τ에 독립 Gumbel 잡음을 더하고 가장 큰 값 k개를 남긴다. 이는 p(d) ∝ exp(s/τ)에서 문서 k개를 비복원 추출한다. [figures/selection-tradeoffs.html](figures/selection-tradeoffs.html)의 두 번째 패널은 이 수치를 재현하고 독자가 τ, 도메인 격차, 선택 비율을 바꿀 수 있게 한다.

**증거** ([[qurating]] 표 1; 1.3B 모델, 260B 토큰 중 30B, 균등 선택 대비 차이).

| 필요한 전문성, 상위 k | +1.9 | −6.3 | −0.6 | −1.0 | 11.54 |
| 필요한 전문성, τ = 2 | +1.8 | +0.5 | +0.1 | +1.1 | 8.93 |
| Sheared-Llama-2.7B에서 최저 퍼플렉서티 | −2.6 | −5.4 | −1.2 | −3.2 | 11.92 |
| 균등, 데이터 +50% | +2.0 | +2.0 | +1.0 | +1.9 | 8.46 |

저자들은 상위 k가 “개별 과제에서는 강한 성능 향상을 달성하지만, 균등 선택보다 더 나쁘게 수행하는 과제가 항상 있다”고 보고한다(§5.3). τ = 2의 교육적 가치는 10개 과제 모두를 개선했고, 데이터가 50% 더 많은 균등 샘플링과 같았다.

**조건과 한계.** 1.3B 규모에서만 시험했으며, 도메인 비율은 고정했다. 따라서 이 방법은 도메인 내부에서 선택한다(§5.2, Limitations).

### §5.2 WebOrganizer: 암묵적 도메인 혼합으로서의 품질 필터

[[weborganizer]]는 증류한 140M 분류기를 사용해 각 페이지에 24개 주제 중 하나와 24개 형식 중 하나를 라벨링한다(§2.2). 도메인 내부 품질 선택을 같은 주제 × 형식 혼합에서 무작위 샘플링으로 바꾸면 FineWeb-Edu 평균 향상의 84%를 회복하지만, DCLM-fasttext 평균 향상은 35%만 회복한다(표 2). 그러므로 FineWeb-Edu의 평균 향상 대부분은 도메인 혼합 변화만으로 재현되는 반면, DCLM-fasttext 향상의 대부분은 그렇지 않다(**결과, 단일 연구**). 도메인별 할당량을 정하고 각 도메인에서 최고 점수 문서를 선택하면 FineWeb-Edu 평균은 54.2에서 56.2로, HellaSwag는 56.0에서 62.5로 올랐다(표 1). 이 할당량은 RegMix가 MMLU와 HellaSwag 쪽으로 조정한 Topic × Format 혼합이므로(§4.2–4.3), HellaSwag 회복은 부분적으로 표적화한 향상이다. SIQA는 무작위 기준선 49.9에 비해 49.4에 머물렀다(표 10). MMLU에만 맞춘 혼합은 HellaSwag를 57.5에서 54.1로, PIQA를 71.3에서 69.9로 낮췄다(표 10).

### §5.3 퍼플렉서티 상관관계: 손실이 벤치마크를 따라가는 도메인 선택

**정의.** [[perplexity-correlations-data-selection]]은 공개 모델 90개 전반에서 측정한 손실이 그 모델들의 벤치마크 점수와 상관된 웹 도메인을 선택한다. 프록시 모델은 학습하지 않는다.

**수식** (§3–4).

```
y_i = f(⟨θ*, x_i⟩ + ε_i)
γ_j = Σ_{k≠l} sign(y_k − y_l) · (rank_j(x_k,j) − rank_j(x_l,j))
```

y_i는 모델 i의 벤치마크 오차이고, x_i는 D개 도메인에서의 bits-per-byte 손실 벡터이다(bits-per-byte는 텍스트의 음의 로그우도를 ln 2와 UTF-8 바이트 수로 나눈 값이며, 토크나이저 간 손실을 비교 가능하게 한다). f는 알려지지 않은 증가 함수, θ*는 도메인 가중치, ε는 잡음, rank_j는 모든 모델 중 도메인 j에서 모델 손실의 순위이다. 선택은 토큰 예산이 찰 때까지 γ가 큰 순서로 전체 도메인을 취한다(정리 2). 이어서 fastText 분류기가 그 선택을 페이지로 일반화한다.

**계산 예시.** 네 모델의 오차가 y = (0.30, 0.40, 0.50, 0.60)이라고 하자. 도메인 j에서 손실은 (1.0, 1.2, 1.1, 1.5), 순위는 (1, 3, 2, 4)이다. 순서 없는 여섯 쌍의 기여는 +2, +1, +3, −1, +1, +2이고, 각 쌍은 순서 있는 합에 두 번 나타나므로 γ_j = 16이다. 도메인 m에서 손실 (1.5, 1.0, 1.2, 1.1)의 순위는 (4, 1, 3, 2)이고 γ_m = −8이다. 도메인 j가 먼저 선택된다. 그 도메인에서 낮은 손실이 낮은 오차와 함께 나타나기 때문이다.

**증거.** 공개 모델 90개와 도메인 9,841개를 사용하고 160M 매개변수, 3.2B 토큰에서 이 방법은 8개 평가 전반 평균 순위 1.750을 기록했다. 영어 필터를 쓴 DCLM fastText 필터의 3.750, 그리고 그 필터에 수작업 과제별 언어 필터를 더한 1.375와 대비된다(표 1). DCLM Core를 표적으로 하여 DCLM의 1B-1x 설정까지 사전등록한 실행에서, 둘 다 원시 풀을 필터링할 때 이 방법은 DCLM fastText 필터를 앞섰으며, 규모와 함께 차이가 커졌다. 상관계수가 .23에서 .33에 불과한 사전 필터링 풀에서는 둘이 비슷했고, DCLM Core의 원시 풀에서는 상관계수가 −.07에서 .32였다(§1, 그림 3, 부록 N). ARC Easy에 가장 상관된 도메인에는 www.aaeoptometry.com과 www.akronchildrens.org가 있었다(부록 O).

**조건과 한계.** 선택 범위는 표적 벤치마크만큼만 넓다. 저자들은 Phi처럼 특이한 데이터로 학습한 모델에서는 예측이 약하다고 보고한다(§5.3).

### §5.4 DsDm: 표적 과제 손실을 낮출 것으로 예측한 데이터 선택

**정의.** [[dsdm]]은 각 후보 예시를 포함할 때 표적 예시의 손실이 어떻게 바뀌는지 예측하는 선형 데이터모델을 적합하고, 예측 평균 효과가 가장 낮은 후보를 남긴다(§2).

**수식.**

```
τ_θx(1_S) = θ_xᵀ 1_S
Ŝ_DM = arg bot-k ( (1/n) Σ_{i=1..n} θ_{x_i} )
```

1_S는 후보 중 어떤 것이 부분집합 S에 있는지를 표시하는 0/1 벡터이고, θ_x는 표적 예시 x의 손실에 대한 후보별 효과, n은 표적 예시 수, bot-k는 가장 작은 항목 k개이다.

**계산 예시.** 후보 네 개와 표적 예시 두 개에서 θ_x1 = (−0.3, 0.1, 0.1, 0.2), θ_x2 = (−0.1, −0.2, 0.1, 0.3)이라고 하자. 평균은 (−0.2, −0.05, 0.1, 0.25)이다. k = 2이면 후보 1과 2를 남긴다. 후보 3과 4의 평균은 양수이므로 이들을 포함하면 표적 손실이 오를 것으로 예측된다.

**증거.** LAMBADA, SQuAD, Jeopardy를 표적으로 하고 표적이 아닌 벤치마크 15개를 사용했을 때, DsDm의 1.3B 모델은 두 배의 계산량으로 무작위 선택 데이터에서 학습한 1.8B 모델과 같았다(그림 3). “어떤 기준선 선택 방법도 무작위 데이터 선택을 능가하지 못한다”(§4). 벤치마크별로(표 1) DsDm은 CoQA에서 +6.7, NewsQA에서 +8.1을 얻었고 HellaSwag에서 −2.6, OpenBookQA에서 −2.2를 잃었다(인쇄된 정확도에서 도출). 760M 모델에서는 LAMBADA만 표적으로 할 때 세계 지식 정확도가 무작위 선택보다 낮아졌다(그림 4).

**조건과 한계.** 표적화 방법은 데이터를 4 에포크 선택한 반면, 무작위 기준선은 1 에포크를 사용했다(부록 D.1). 데이터모델은 125M 프록시로 계산했다.

## §6 벤치마크 표적 선택과 시험 과제 학습

**정의.** **벤치마크 표적 선택**은 표적, 채점기 또는 선택 규칙이 이름 붙은 평가 벤치마크 쪽으로 조정된 모든 선택을 말한다. [[training-on-the-test-task]]은 더 넓은 관행을 “시험 과제 학습(training on the test task)”이라고 부른다. 이는 학습 시점에 평가 과제에 관한 지식을 사용하는 것으로, 오염(학습 데이터에 시험 항목이 들어가는 것)과 다르며 “부정행위가 아니다”(초록).

**표적화가 데이터 파이프라인에 들어가는 방식.**
1. 평가 항목과 형식이 닮은 양성 예시: DCLM의 질의응답 양성 예시(§3), FineWeb-Edu의 초등학교 수준 교육 프롬프트(§2).
2. 벤치마크 절제 실험으로 고른 임계값과 혼합: FineWeb-Edu 임계값(§2), 그리고 어닐링 절제 실험에서 더 많은 DCLM이 “MMLU MCF를 약간 개선”함을 발견한 뒤 FineWeb-Edu/DCLM 비율을 60/40에서 40/60으로 바꾼 것을 포함한 SmolLM2의 “성능 주도 개입”([[smollm2]] §4, §4.3–4.4).
3. 벤치마크로 정의한 목표: 퍼플렉서티 상관관계(§5.3), DsDm(§5.4), MMLU와 HellaSwag 쪽의 혼합 회귀(§5.2; 소규모 실행에서 학습한 회귀 모델이 도메인 가중치로 벤치마크 점수를 예측함, [[weborganizer]] §3).
4. 후기 단계 데이터에 포함된 벤치마크 학습 집합: SmolLM2의 감쇠 단계에는 AugGSM8K 0.02%가 포함되며, 이는 “GSM8K 벤치마크 학습 집합의 증강 버전”이다([[smollm2]] §4.5). Llama 3에서 GSM8K와 MATH 학습 집합으로 어닐링하면 8B 검증 점수는 24.0%와 6.4% 올랐고 405B에서는 영향이 무시할 만했으며, 이 집합들은 최종 어닐링 데이터에서 제외되었다([[llama-3]] §3.1.3).

**그 향상이 과제 형식 유사성이라는 증거.** [[training-on-the-test-task]]은 사전학습 계산량에 대해 56개 기반 모델(70M–70B)의 정확도를 회귀했다.

```
A = α · max(0, log C − c_e) + θ · N + r + ε
```

A는 정확도, C는 사전학습 계산량, c_e는 과제가 우연 수준을 넘어서 상승하는 계산량, N = 1은 2023년 11월 이후 공개된 모델, r은 우연 정확도, θ는 같은 계산량에서 최신 모델과 이전 모델의 평균 차이이다. **cloze 형식**에서는 각 답 선택지를 질문의 연속으로서의 우도로 채점한다. **객관식 형식**에서는 선택지를 문자와 함께 나열하고 모델이 문자를 출력해야 한다. 조정 전 θ는 MMLU에서 0.073, GSM8K에서 0.191이었다. 모든 모델을 같은 과제 데이터(객관식 학습 예시 약 100,000개 또는 수학 예시 약 600,000개)로 3 에포크 미세 조정한 뒤에는 θ가 둘 다 0.005였고 유의하지 않았다(그림 1). Cloze 형식의 ARC-Challenge와 HellaSwag는 θ = 0.001과 0.012를 보였지만, MMLU 스타일 객관식으로 재구성하면 θ = 0.120과 0.114를 보였다(그림 4). Cloze 형식 MMLU는 θ = 0.008이었다(그림 5). 저자들은 표준 MMLU 형식이 “지식 검사를 모델의 객관식 질문 응답 능력 검사와 혼동한다”고 결론 내린다(**결과, 단일 연구**).

**필터 또는 혼합 결정을 위한 검출 프로토콜.**
1. 절제 실험 전에 표적, 임계값, 혼합을 고를 때 쓰는 벤치마크가 무엇인지 적어 둔다.
2. 절대 모니터링하지 않는 두 번째 평가군을 남겨 둔다. SmolLM2는 MMLU-Pro, TriviaQA, Natural Questions를 “학습 중 모니터링하지 않은 홀드아웃 벤치마크”로 보고한다(§4.7).
3. 같은 항목을 cloze와 객관식 형식으로 평가한다. 객관식 형식에서만 나타나는 향상은 형식 학습을 나타낸다([[training-on-the-test-task]] 그림 4–5).
4. 후보들이 과제 형식 데이터의 양에서 다르다면, 같은 과제 데이터로 동일하게 미세 조정한 뒤 후보를 비교한다([[training-on-the-test-task]] §2.1).
5. 오염은 별도로 검사한다. DCLM은 검출된 MMLU와 HellaSwag 중복을 제거했는데 점수가 떨어지지 않았다(MMLU 51.8 → 52.7, HellaSwag 77.9 → 78.4; [[dclm]] 표 7). 저자들은 이 향상이 데이터 내 시험 예시 때문에 발생했을 가능성이 낮다고 결론 내린다(§4.6). 이 검사는 시험 과제 유사성을 배제하지 않는다.
6. 필터링하지 않은 풀 및 Paloma 같은 출처([[paloma]])에서 도메인별 퍼플렉서티를 측정한다.
7. 학습 데이터와의 유사도로 벤치마크를 나눈다. phi-1은 자체 연습문제 집합에 가까운 일치가 있는 HumanEval 문제의 59.5–81.7%를 풀었고, 나머지는 26.9–33.8%를 풀었다([[phi-textbooks]] 표 3).

## §7 소규모 필터 결정은 더 큰 모델로 이전되는가?

**정의.** **결정 정확도(decision accuracy)**는 소규모에서 데이터 레시피 쌍의 승자가 표적 규모에서도 승자인 쌍의 비율이다([[datadecide]] 식 3).

```
DA = (1/|P|) Σ_{(A,B)∈P} 1[ sign(ŷ_A − ŷ_B) = sign(y_A − y_B) ]
```

P는 레시피 쌍의 집합이고, ŷ는 소규모 점수이며, y는 3개 시드에 걸쳐 평균 낸 표적 규모 점수이다.

**계산 예시.** 세 레시피가 150M에서 40, 42, 41을, 1B에서 50, 53, 54를 기록한다고 하자. 쌍 (A, B)에서는 B가 두 규모 모두에서 이기므로 맞다. 쌍 (A, C)에서는 C가 두 규모 모두에서 이기므로 맞다. 쌍 (B, C)에서는 B가 소규모에서 이기고 C가 큰 규모에서 이기므로 틀리다. DA = 2/3 = 0.67이다.

**증거.**
- [[datadecide]]: FineWeb-Edu, DCLM-Baseline, 그리고 서로 다른 DCLM 및 FineWeb-Edu 분류기 임계값을 지닌 DCLM-Baseline 변형 7개를 포함하는 25개 코퍼스 전반에서, 150M의 단일 규모 순위는 쌍의 약 80%에서 1B 승자를 고른다. 8개 스케일링 법칙 방법 중 어느 것도 단일 규모 순위의 계산량-정확도 프런티어를 넘지 못한다(§3.2). ARC-Easy는 표적보다 다섯 자릿수 적은 계산량으로 예측 가능하지만, SocialIQA는 시험한 모든 규모에서 예측하기 어렵다(§3.1, 그림 2). 소규모 지표로 정답의 확률을 쓰면 코드 관련 결정은 결정 정확도 80%에 이른다(§3.4).
- [[dclm]] 그림 3: 방법 10개에서 400M-1x, 1B-1x, 3B-1x의 CORE는 7B-1x CORE와 Pearson r = 0.838, 0.956, 0.982의 상관을 보인다.
- [[signal-and-noise-eval]]: 소규모에서 벤치마크의 신호 대 잡음비는 DataDecide에서 그 벤치마크의 결정 정확도와 상관한다(R = 0.791).
- 규모 의존 효과가 존재한다. 퍼플렉서티 상관관계 이득은 160M에서 1.4B까지 커졌으며([[perplexity-correlations-data-selection]] 그림 3), 8B에서 Llama 3의 벤치마크 학습 집합 어닐링 이득은 405B에서 무시할 만했다([[llama-3]] §3.1.3).

**조건과 한계.** DataDecide는 하나의 토큰 대 매개변수 비율(100)과 1B까지의 객관식 cloze 과제를 쓴다(§5). FineWeb, QuRating, DsDm의 결론은 각각 1.71B, 1.3B, 1.3B 모델에서 나온 것이다.

**함의.** DataDecide에서는 150M 실행이 쌍의 약 80%에서 1B 결과의 순위를 올바르게 매겼고, ARC-Easy는 가장 예측 가능한 과제 중 하나였다. 따라서 소규모 실행은 MMLU·ARC 유형 과제에서 필터의 순위를 매길 수 있다. 소규모에서 신호가 낮은 과제에서는 이 실행이 필터가 능력 범위에 미치는 효과를 측정하지 못하며, 이를 시험하지 않았다고 명시해야 한다.

## §8 품질 분류기의 언어, 방언, 사회적 편향

**증거.**
- [[whose-language-counts-quality-filter]]은 GPT-3 품질 필터(Wikipedia, Books3, OpenWebText를 양성으로, Common Crawl을 음성으로 쓰는 로지스틱 회귀; F1 90.4%)를 복제하고, 미국 고등학교 신문 기사 910K개에 점수를 매겼다. 968개 학교에서 평균 P(고품질)을 회귀했을 때 농촌 인구 비율의 계수는 −0.069, 학사 학위 이상 성인 비율의 계수는 +0.059였다(표 3). 의견 기사 회귀에서 1인칭 또는 2인칭 대명사가 있으면 P(고품질)이 5퍼센트포인트 낮아졌고, Trump와 대통령 선거 주제 기사는 생략된 음식 주제 기사보다 35퍼센트포인트 높게 점수화되었다(§3.3, 표 2). 이 필터의 점수는 사실성이 높은 뉴스 출처와 낮은 뉴스 출처 사이에서 차이가 없었다(p = 0.085, 그림 3).
- [[qurating]]: 평가자에게 언어를 무시하라고 지시했는데도 등급은 독일어 및 러시아어 Wikipedia보다 영어 Wikipedia를 선호했다(§6.1, 그림 4). AboutMe 페이지의 10%를 교육적 가치로 선택하면 “연구, 대학” 페이지는 16%, “패션, 여성” 페이지는 6%가 남았다. 필요한 전문성 기준에서는 “mommy”, “crafter” 같은 역할이 6%만 남았고, 상위 k는 이 비율을 “훨씬 더 악화”시켰다(§6.3, 표 2, 부록 표 10).
- [[fineweb]] §4.2와 부록 F.4 표 3(Paloma, 오염 제거 없음): Twitter AAE에서 African-American-aligned 부분집합의 퍼플렉서티는 FineWeb 모델에서 246.9, FineWeb-Edu 모델에서 575.1이다. white-aligned 부분집합에서는 98.5와 192.4이다. FineWeb-Edu 모델은 두 부분집합 모두에 더 나쁘게 맞으며, 그 비율은 African-American-aligned 부분집합에서 더 크다(2.33 대 1.95, 도출). 이 모델은 Gab, Manosphere, 100 Subreddits에도 더 나쁘게 맞는다.
- 대조적으로 C4에서 African American English와 Hispanic-aligned English 문서를 제거한 일은 단어 차단 목록으로 추적되었다. 이는 ch-10에서 다룬 휴리스틱 필터이다([[c4]], Dodge 등 요약).
- DCLM, Nemotron-CC, FineWeb-Edu는 영어 전용 파이프라인이다([[dclm]] 그림 4, [[nemotron-cc]] §6, [[fineweb]] §3.3).

**해석.** 참조 텍스트와 웹 텍스트를 구분하도록 학습한 분류기는 품질 신호와 함께 주제, 레지스터, 문체 특성을 학습한다. 그 음성 클래스가 무엇을 제거하는지 정의한다(다음 절 참조).

**함의.** 주제, 형식, 지역, 언어 변종별 보존율은 필터 평가의 일부이다. 다국어 측면은 ch-13a에서 다룬다.

## 음성 샘플과 음성 피드백

이 절은 스타일 표준의 용어를 사용한다. 이 단계에서 “음성(negative)”은 **음의 한계 가치**(포함하면 성능을 낮출 것으로 예상되어 필터가 제거하거나 가중치를 낮춘 문서)와 **품질 분류기의 음성 클래스**를 뜻한다. 언어 모델 자체는 음의 그래디언트를 받지 않는다. 선택은 보통의 교차 엔트로피로 학습하는 문서만 바꾼다. 그래디언트로서의 음성은 분류기 학습 내부에서만 나타난다. 언어 모델의 음의 그래디언트는 ch-31a와 ch-43a에서 다룬다.

**1. 음성 예시의 출처와 라벨링 방식.**
- 임계값 또는 백분위보다 낮은 문서(§2, §3). 어떤 출처도 이 제거의 거짓음성 비율을 직접 측정하지 않는다. 간접 측정으로, FineWeb-Edu와 DCLM 분류기는 둘 중 하나가 고품질로 라벨링한 문서의 10.1%에서만 일치하며([[nemotron-cc]] 표 8), 휴리스틱 필터는 분류기가 고품질로 라벨링한 토큰의 18.1%를 제거했다([[nemotron-cc]] §2.1).
- 분류기의 음성 클래스: DCLM에서는 RefinedWeb 재현본의 무작위 문서([[dclm]] 부록 J.1), GPT-3 필터에서는 Common Crawl([[whose-language-counts-quality-filter]] §3.2)이다. 이 집합에는 음성으로 라벨링된 좋은 문서가 포함된다.
- 각 쌍대 LLM 판단에서 더 낮은 문서([[qurating]]).
- 데이터모델 가중치가 더 높은 표적 손실을 예측하는 후보([[dsdm]]).

**2. 현재 관행이 이들을 다루는 방식.**
- 폐기: FineWeb-Edu(점수 < 3)와 DCLM(상위 10% 미만).
- 가중치 낮추기: 온도 샘플링은 낮은 등급 문서에 0이 아닌 확률을 남긴다([[qurating]]). SmolLM2의 소형 모델은 점수 0 DCLM 문서를 제거하고 점수 1과 2를 다운샘플링했다([[smollm2]] §6).
- 변환하여 콘텐츠로 보존: Nemotron-CC는 저품질 문서를 다시 표현하고 그 재작성본을 교차 엔트로피로 학습한다([[nemotron-cc]] §2.3).

**3. 작동 방식.** 로짓 z = w · φ(d), 라벨 y ∈ {0, 1}인 분류기에서:

```
L = −[ y log σ(z) + (1 − y) log(1 − σ(z)) ]
∂L/∂z = σ(z) − y
```

φ(d)는 문서의 특성 벡터, w는 가중치, σ는 시그모이드이다. 음성 라벨 문서에서 σ(z) = 0.8이면 ∂L/∂z = 0.8이므로, 업데이트는 그 문서에 나타난 특성의 가중치를 낮춘다. 양성 문서에서 σ(z) = 0.3이면 ∂L/∂z = −0.7이므로, 그 특성의 가중치를 높인다. 무작위 웹 표본의 잘 쓴 문서가 음성으로 라벨링될 때 그 특성(예를 들어 1인칭 서술이나 제품 어휘)은 아래로 밀리고, 그 특성을 공유하는 모든 문서가 더 낮은 점수를 받는다. [[whose-language-counts-quality-filter]] 표 2의 대명사 및 주제 계수는 이 작동 방식과 일치한다(**해석**).

언어 모델에서 온도 샘플링은 제거의 연성 버전이다. QuRating의 부록 C는 p(d) ∝ exp(s(d)/τ)로 샘플링하면 KL 정규화 최적값 π*(d) ∝ p_D(d) exp(s(d)/τ)를 근사함을 보인다. 문서의 가중치는 0으로 떨어지는 대신 등급에 따라 지수적으로 낮아진다.

**4. 수치를 포함한 증거.**
- 제거는 표적 밖에서 측정 가능한 비용이 있다. 1B FineWeb-Edu는 HellaSwag를 1.5, PIQA를 1.4, SIQA를 2.0 낮췄고, 홀드아웃 퍼플렉서티를 12.1에서 14.7로 올렸다([[weborganizer]] 표 1, 표 10).
- 한 표적에 가치가 낮은 문서는 다른 표적에는 가치가 있을 수 있다. 사실과 상식 또는 필요한 전문성에서 낮은 문서를 선택하면 “상식 과제 3개 모두에 이롭다”([[qurating]] §5.3).
- 해롭다고 예측한 데이터는 시험했을 때 해롭다. DsDm이 가장 선택하지 않을 법한 후보로 학습하는 것은 “무작위로 선택하는 것보다 나빴다”([[dsdm]] §3.2).
- 폐기 대신 변환하기: 다시 표현한 저품질 데이터는 10개 과제 평균을 52.5에서 54.0으로 올렸지만 MMLU를 48.2에서 47.1로 낮췄다([[nemotron-cc]] 표 10).
- 효과의 크기: 이 장의 어떤 출처도 필터 이득 중 낮은 가치 문서를 제거한 것과 높은 가치 문서를 집중한 것에서 각각 얼마가 오는지 측정하지 않는다. 가장 가까운 측정 분해는 암묵적 도메인 혼합으로 설명되는 비율이다(FineWeb-Edu 84%, DCLM-fasttext 35%; [[weborganizer]] 표 2).

**5. 통제.** 상위 k 대신 온도로 샘플링한다(§5.1). 선택 전에 도메인별 할당량을 정한다(§5.2). 앙상블로 재현율을 높인다(§4). 휴리스틱 필터는 낮은 점수 버킷에만 적용한다(§4). 삭제 대신 다시 표현하거나 다운샘플링한다. 대조군으로 역선택 실행을 포함한다([[qurating]] §5.2).

**6. 진단.** 주제, 형식, 지역, 언어 변종별 보존율([[weborganizer]], [[qurating]] §6.3), 제거한 슬라이스의 도메인별 퍼플렉서티([[paloma]]), 점수 백분위 5·30·70·95에서의 무작위 표본([[qurating]] §6.2), 두 분류기 사이 일치 행렬([[nemotron-cc]] 표 8), 필터링하지 않은 풀의 홀드아웃 퍼플렉서티를 본다.

**7. 일반성에 미치는 효과.** 범위가 줄어들고(높아진 홀드아웃 퍼플렉서티, 줄어든 고유 토큰), 일부 상식 및 사회 과제가 하락하며, 비격식·지역·비영어 텍스트가 덜 선택된다(§8).

**소규모 범용 실행의 시작점.** 예산보다 큰 풀에서 학습하는 1–2B 모델의 경우, 검증된 행은 다음을 뒷받침한다. 400K 문서(양성: OpenHermes-2.5와 ELI5 200K, 음성: 휴리스틱으로 정제한 풀의 무작위 문서 200K)로 유니그램·바이그램 특성을 갖는 fastText 분류기를 학습하고 상위 10%를 남긴다. 이는 DCLM이 7B-1x에서 CORE를 기준으로 선택한 방식이다. 또는 1.71B와 28B 토큰에서 선택한 방식대로 FineWeb-Edu 분류기에 임계값 3을 적용한다. SmolLM2는 1.7B에서 첫 6T 토큰 동안 둘을 60/40으로 섞었다. 후보 필터의 순위는 DCLM 1B-1x 설정(1.4B 매개변수, 28.8B 토큰, 256 × 2,048-토큰 배치, LR 3e-3, 가중치 감쇠 0.033, 워밍업 5,000단계)에서 매긴다. 이 설정의 순위는 7B-1x와 r = 0.956으로 상관했다. 계획한 기간이 필터링 집합의 고유 토큰을 여러 패스 필요로 한다면, 임계값을 더 조이는 대신 Nemotron-CC 스타일의 최대 앙상블 버킷(0–19 버킷, 분류기 간 최댓값)을 추가한다. 모든 후보를 §6 검출 프로토콜에서 평가한다.

## 일반화 렌즈

**(a) 무엇이 범위를 넓히는가.** “넓은 범위의 잠재적 주제”를 포괄하도록 고른 양성 예시([[dclm]] 부록 J.1): DCLM-fasttext는 1B에서 9개 과제 중 8개를 올렸다([[weborganizer]] 표 1). 온도를 사용한 샘플링: τ = 2의 교육적 가치는 10개 과제 모두를 올렸다([[qurating]] §5.3). 품질 필터 아래 도메인 할당량: FineWeb-Edu + 할당량(MMLU와 HellaSwag 쪽으로 조정한 혼합)은 가장 높은 평균(56.2)과 HellaSwag 62.5에 도달했다([[weborganizer]] 표 1, 표 10). 분류기 앙상블과 다시 표현: 비슷한 1T-토큰 점수에서 DCLM보다 고유 실제 토큰이 4배 더 많다([[nemotron-cc]] 표 4–5). 서로 다른 유형의 여러 표적 과제: 세 표적을 사용한 DsDm은 다른 범주를 평균적으로 낮추지 않고 독해와 세계 지식에서 향상했다([[dsdm]] §4.1).

**(b) 무엇이 좁아짐을 일으키는가.** 하나의 등급으로 상위 k 선택: 필요한 전문성 상위 k는 상식을 6.3점 낮췄다([[qurating]] 표 1). 단일 벤치마크 표적: MMLU 전용 혼합은 HellaSwag를 3.4 낮췄고([[weborganizer]] 표 10), LAMBADA 전용 DsDm 표적은 세계 지식을 낮췄다([[dsdm]] 그림 4). 평가 항목 형식으로 구성한 양성 예시 또는 한 학교 수준을 위해 작성한 표적(§2, §3, **해석**). 15T-토큰 실행이 웹 토큰 7.17T를 뽑을 때 고유 토큰 0.2T–1.0T를 남기는 필터링([[nemotron-cc]] 표 4, 부록 E). 비격식·농촌·비영어 텍스트를 제거하는 분류기 특성([[whose-language-counts-quality-filter]], [[qurating]] §6). 코드 생성 과제가 없는 평가군에서 내린 혼합 결정: GitHub와 arXiv를 포함한 RedPajama 출처를 더하면, 명령어 조정 전 7B 모델이 GSM8K에서 2.1을 기록한 DCLM-Baseline의 CORE와 EXTENDED가 낮아졌다([[dclm]] 표 6, 표 29).

**(c) 이 단계에서 이를 어떻게 측정하는가.** 표적 과제와 비표적 과제를 나눈 평가군, 그리고 DCLM EXTENDED 같은 넓은 평가군([[dclm]] §3.5); 필터링하지 않은 풀의 홀드아웃 퍼플렉서티와 도메인별 퍼플렉서티([[weborganizer]] 표 10, [[paloma]]); 데이터 결정 동안 한 번도 모니터링하지 않은 벤치마크([[smollm2]] §4.7); cloze 대 객관식 버전과 비교 전 동일 미세 조정([[training-on-the-test-task]]); 주제, 형식, 지역, 언어별 보존율([[qurating]] §6.3); 전역 중복 제거 뒤 고유 토큰 수([[nemotron-cc]] 표 4); 사용한 과제에서 시드를 포함한 결정 정확도([[datadecide]]). 알려진 측정 오류: CORE와 EXTENDED는 시드 추정 없이 1점 미만 차이로 두 설정의 순위를 다르게 매길 수 있다([[dclm]] 표 5, 14, §6). 객관식 MMLU는 형식 기술과 지식을 섞는다([[training-on-the-test-task]] 그림 5). SocialIQA 결정은 시험한 규모에서 신뢰할 수 없다([[datadecide]] §3.1). MMLU 중복 플래그는 재현율을 우선하여 오염을 과대추정한다([[dclm]] 표 25). 다른 하니스에서 외부 모델과 비교하는 일은 동등 비교가 아니다([[nemotron-cc]] 표 6).

## 이해 점검

1. FineWeb-Edu는 1B에서 ARC-Easy를 9.7점 올리고 SIQA를 2.0점 낮췄다. 주석 프롬프트와 임계값이 함께 어떻게 이 프로필을 만들 수 있는지 설명하고, 프롬프트 유사성과 더 좋은 텍스트를 분리할 실험을 제시하라.
2. WebOrganizer의 암묵적 도메인 혼합은 FineWeb-Edu 향상의 84%를 회복하지만 DCLM-fasttext 향상은 35%만 회복한다. 이것이 각 필터가 데이터를 어떻게 바꾸는지에 대해 무엇을 뜻하는지, 그리고 도메인별 할당량 선택이 FineWeb-Edu에 더 도움이 되는 이유를 설명하라.
3. [[training-on-the-test-task]]에서 ARC와 HellaSwag는 cloze 형식에서는 유의한 최신 모델 우위를 보이지 않지만, 객관식 형식에서는 θ = 0.120과 0.114를 보인다. 이것이 왜 오염보다 형식 학습을 가리키는지 설명하고, 질의응답 형식 분류기를 평가할 때 데이터 팀이 같은 비교를 어떻게 사용해야 하는지 설명하라.
4. 15T-토큰 실행에는 웹 데이터 7T 토큰이 필요하다. 고유 토큰 수를 사용하여 상위 10% 필터와 단계화 앙상블 사이의 선택이 왜 품질 결정만이 아니라 범위 결정인지 설명하라.
5. 로지스틱 손실 그래디언트를 사용하여, 음성 클래스의 무작위 웹 문서가 어떻게 분류기로 하여금 1인칭 또는 비격식 글쓰기를 제거하게 할 수 있는지 설명하고, 이를 검출할 진단 두 가지를 제시하라.
6. 퍼플렉서티 상관관계 선택은 원시 DCLM 풀에서는 DCLM fastText 필터보다 좋았지만 사전 필터링한 풀에서는 그렇지 않았다. 각 풀에서 상관계수 범위를 사용해 이를 설명하고, 기존 분류기 위에 벤치마크 상관 필터를 쌓는 것에 대해 이것이 뜻하는 바를 말하라.
7. DsDm은 데이터를 4 에포크 선택했고 무작위 선택은 1 에포크를 사용했다. 이 차이가 넓은 능력의 증거로서 “2× 계산량 배수”를 해석하는 데 어떤 영향을 주는지 설명하라.

- **다음:** ch-11 — 토크나이저, 데이터 출처, PII 제거.
- ch-00 — 범용 능력의 의미와 측정 방법(표적 평가군 대 홀드아웃 평가군).
- ch-09 — 사전학습 데이터 구성과 능력 범위(범위는 필터가 바꾸는 양).
- ch-12 — 중복 제거: 정확 일치, 근사 중복, 의미 중복(§4에서 쓰는 고유 토큰 수).
- ch-12a — 사전학습 중 암기, 지식 습득, 일반화(필터링한 데이터의 반복).
- ch-13 — 도메인 혼합: DoReMi, 혼합 법칙, 규모 전반 검증(WebOrganizer 스타일 할당량과 혼합 회귀).
- ch-13a — 능력 축으로서의 다국어 범위와 어휘(영어로 학습한 필터의 언어 효과).
- ch-14 — 데이터 제약 스케일링, 반복, 사전학습 오염 제거(고유 토큰 패스; 오염 점검).
- ch-17 — 실습: 범위 측정을 포함한 필터 및 혼합 절제(§6과 일반화 렌즈 적용).
- ch-18 — 합성 데이터 설계 패턴: 생성, 필터, 중복 제거, 검증, 선택, 혼합(합성 데이터에 이 장의 필터 사용).
- ch-22 — 품질, 다양성, 그래디언트 기반 데이터 선택(사후학습 데이터 선택).
- ch-32 — 중간학습: 어닐링 데이터, 단계 게이트, 이후 SFT와 RL에 대한 효과(어닐링의 벤치마크 학습 데이터).
- ch-31a — 지도 학습의 음성 샘플: 교정, 실패 조건화, 비평, unlikelihood.
- ch-43a — 음성 샘플과 음성 그래디언트: 우도 이동, squeezing, 음의 어드밴티지.
- ch-47a — 벤치마크 과적합과 일반화 감사: 신규, 교란, 반사실, 라이브 평가.
- ch-48 — 오염 검출과 보고 점수에 미치는 효과.
- ch-51 — 지표 잡음, 신뢰 구간, 진행/중단 결정.
