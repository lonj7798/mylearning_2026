# Excerpt: A Closer Look at System Prompt Robustness (RealGuardrails)

Authors: Norman Mu, Jonathan Lu, Michael Lavery, David Wagner (UC Berkeley). Checked against the v1 PDF on 2026-09-15. Code, data, and models: github.com/normster/RealGuardrails.

## Motivation (§1.1)
- Monkey Island stress test: a real choose-your-own-adventure system prompt with 1 to 20 added if-then guardrails, n = 100; pass rates of GPT-4o, GPT-4o mini, o3 mini, DeepSeek V3, and DeepSeek R1 "uniformly approach zero as the number of guardrails increases" (Fig. 2). Real GPT Store and HuggingChat prompts average 5.1 guardrails (Fig. 3).
- A guardrail is "any specifications of model behavior which admit objective pass/fail evaluation" (§2).

## Evaluation data (§3.1)
- 14 held-out system prompts from GPT Store / HuggingChat. Handwritten set: 239 aligned or conflicting user messages, about half with a banned-word list. Distractor set: 504 cases with 5, 10, or 20 in-context demonstrations of unrelated tasks (roleplay, translation), half as multi-turn user/assistant rounds and half concatenated in one user message.
- GPT-4o judge with per-prompt guardrail annotations; 94% agreement with author labels on 134 responses.

## Training data (§4, Fig. 4, Tables 1-2)
- 651 GPT Store prompts that do not require file uploads or custom HTTP APIs, plus HuggingChat prompts; filtered for length, duplicates, non-English, obscene content; Claude 3.5 Sonnet extracts guardrail clauses; prompts without identifiable guardrails are discarded; 1,850 training prompts remain.
- For each prompt about five conflicting and five aligned user messages are generated by Claude 3.5 Sonnet: 18,497 user prompts. Aligned messages are included "to retain model utility during training and avoid inappropriate over-refusals".
- Responses: a GPT-4o assistant with 4 tools (Brave web search, Scrapfly browsing, local Python, mock image generation); all tool traces and final responses form RealGuardrails-SFT.
- SFT+ mixture (Table 1): RealGuardrails SFT 18,497; Multifaceted Collection 20,000; Glaive v2 20,000; SPML 12,541; Tulu3 Persona IF 20,000; Tulu3 WildGuardMix 20,000; WildChat GPT-4 20,000 (multi-turn); SlimOrca 20,000. The baseline SFT uses an equivalent number of SlimOrca samples with generic system prompts.
- DPO (Table 2): RealGuardrails-DPO 9,968 pairs (chosen = GPT-4o response; rejected = worst of 3 Mistral 7B Instruct v0.3 generations with the same tools, scored by Claude 3.5 Sonnet, from 1,000 system prompts); Multifaceted Collection 10,000 (rejected = response following a different system prompt); Tulu3 Persona IF 10,000 (rejected = response with relaxed constraints).
- LR: "At similar learning rates to DPO (1e-5), SimPO resulted in unstable training and markedly worse performance"; SimPO at 1e-6 improved on SFT+ "but not nearly as much as DPO" (§5.1).

- AgentDojo (difficulty-1 tasks, Table 3): Llama 3.1 8B Instruct utility under attack 24.85%, attack success 4.24%; SFT+ 31.82% and 0.91%; SFT+ and DPO 28.18% and 0.00%.
- Distractors in multiple conversation turns are "generally more distracting than placing all the distractors in a single user message", and more demonstrations increase difficulty in the multi-turn setting (§6.2, Fig. 8).
- Authors' note on negatives: "We found the use of negative samples in DPO to be very effective" and relate it to guardrails having "clear right and wrong answers" (§6.3; Interpretation).

## Limits
- No broad capability benchmarks (MMLU, GSM8K) are reported for the fine-tunes; over-refusal is controlled in the data but not measured by a dedicated benchmark.
