# 13장 — 도메인 혼합: DoReMi, 혼합 법칙, 규모를 넘는 검증

> **핵심 통찰.** 도메인 혼합은 데이터 그룹에 대한 확률 벡터다. 이 장의 오프라인 방법(DoReMi, Data Mixing Laws, RegMix, Olmix)은 작은 프록시 모델로 벡터를 고르고 더 큰 실행에 결정을 전이한다. 280M 프록시로 찾은 DoReMi 가중치는 8B 모델의 The Pile one-shot exact match 평균을 20.03에서 26.56으로 높이고 22개 도메인 모두의 log-perplexity를 낮췄다([[doremi]] Table 5, Table 3a). 그러나 1B 프록시는 다른 가중치를 만들었고, 160M 모델 재구현에서는 DoReMi를 포함한 기존 방법이 6개 데이터 설정 모두에서 층화 샘플링을 이기지 못했다([[aioli-data-mixing]] Table 2). 프록시가 충분히 크면 많은 프록시 실행의 회귀가 순위를 전이한다(30M 프록시와 1B 대상의 Spearman 0.896, 1M 프록시는 0.73; [[olmix]] §3.3.2). 최선의 혼합은 단계와 규모에 따라 다르다. GSM8K·MATH 학습 세트에서 annealing하면 Llama 3 8B 검증 점수가 24.0%, 6.4% 올랐지만 405B에서는 효과가 거의 없었다([[llama-3]] §3.1.3).
>
> **지침.** 여러 도메인에 사전학습 가중치를 정할 때는 최소 15M 파라미터인 프록시를 최소 `3(m + 1)`회 실행하고 평가 태스크별 회귀 모델을 하나씩 맞춘다. 최적화 안에서 반복 상한을 강제하고, 제안 혼합을 자연 분포·층화 샘플링과 목표 규모에서 비교한다. 이 선택들이 [[olmix]] §3.3에서 1B 대상의 대안보다 낮은 평균 BPB를 냈고 [[aioli-data-mixing]] §6.1의 여러 발표 방법은 층화 샘플링에 졌기 때문이다. 단계의 목표가 좁다면(annealing·긴 컨텍스트 확장·SFT) 혼합을 따로 고르고 일반 짧은 컨텍스트 데이터도 남긴다. 긴 데이터 34%와 짧은 데이터 66%는 짧은 컨텍스트 스위트에서 0.8점 손실을 냈고, 긴 데이터 66%는 2.5점 손실을 냈다([[olmo-3]] §3.6.3). 벤치마크 학습 세트를 annealing 후보로 쓸 때는 제외하거나 옆에 홀드아웃 스위트를 보고한다. Llama 3은 분포 밖 일반화를 측정하기 위해 이를 제외했다([[llama-3]] §3.1.3).

## 범용 모델에서 이 장이 필요한 이유

학습 파이프라인은 사전학습 → 중간 학습 → SFT → 선호 최적화 → RL → 평가로 진행된다. 매 단계에서 혼합 결정이 이뤄진다. 사전학습 소스의 토큰 비율, annealing 단계의 업샘플 소스, 컨텍스트 확장 단계의 긴 데이터 대 짧은 데이터 비율, SFT 집합의 범주 비율이다. 이 장은 사전학습 결정을 자세히 다루고 이후 단계도 혼합 결정인 범위에서 다룬다. 이질적 소스를 유지하게 하는 구성 근거는 ch-09, 소스 내부 모델 기반 선택은 ch-10a, 반복 한계는 ch-14에 있다.

측정 가능한 문제는 고정 토큰 예산을 여러 방식으로 써서 서로 다른 모델을 만들 수 있다는 것이다. [[regmix]] Table 3에서 The Pile 25B 토큰으로 학습한 1B 모델 64개는 혼합에 따라 13개 태스크 평균 정확도 43.7~47.9, Lambada 18.9~33.5였다. 여기서 일반성 질문이 두 개 나온다. 첫째, 한 평가 스위트에 맞춘 혼합은 그 밖의 점수를 낮출 수 있다. MMLU용 혼합은 HellaSwag를 57.5에서 54.1로 낮췄다([[weborganizer]] Table 10). 둘째, 작은 모델로 고른 혼합이 큰 모델에도 맞아야 하는데 §4의 근거는 명시된 조건에서만 전이된다고 보인다.

## §1 혼합 가중치·단위와 그 가중치가 뜻하는 반복

**정의.** 도메인 `D_1, ..., D_m`이 있고 도메인 `D_i`에는 사용 가능한 토큰 `N_i`개가 있다고 하자. 혼합은 확률 단체 위의 벡터 `p`다(`p_i ≥ 0`, `Σ p_i = 1`). `R` 토큰으로 학습하면 `D_i`에서 `p_i · R` 토큰을 가져온다([[olmix]] §3.1.1). 도메인은 provenance 소스(GitHub, Wikipedia)일 수도 있고 소스의 주제 분할일 수도 있다([[olmix]] §3.1.1; 주제 도메인은 [[weborganizer]]에서 구성). 아래에서 두 기준 혼합이 반복된다. **자연 분포**는 `p_i ∝ N_i`, **층화 샘플링**은 `p_i = 1/m`이다([[aioli-data-mixing]] §6).

**단위.** DoReMi는 학습 분포를 `P_α = Σ_i α_i · unif(D_i)`로 정의한다. 이는 예시 분포이며 특정 토크나이저의 토큰 수로 가중치를 계산한다([[doremi]] §2, §1 각주 1). Llama 3은 사전학습에서 “토큰의” 비율, SFT에서 “예시의” 비율을 보고한다([[llama-3-recipe]]). 단위를 밝히지 않은 보고서는 재현할 수 없다.

**문제.** 도메인 공급량보다 큰 가중치는 반복을 강제한다. 반복은 혼합 벡터만으로 보이지 않고 `R`, `N_i`와 함께 볼 때 나타난다.

**공식.**

```text
e_i = p_i · R / N_i            (domain i의 epoch)
p_i ≤ k · N_i / R              (반복 상한)
```

`e_i`는 도메인 i를 통과하는 횟수, `p_i`는 혼합 가중치, `R`은 요구 학습 토큰, `N_i`는 사용 가능 토큰, `k`는 허용 최대 pass 수다. 이 상한은 [[olmix]] §3.3.4의 제약이다.

**계산 예(장난감 수치).** `R = 1,000B`, 웹 `N = 2,000B`, 코드 `N = 100B`, 수학 `N = 20B` 토큰이라고 하자. 혼합 `p = (0.80, 0.15, 0.05)`는 각각 800B, 150B, 50B 토큰을 사용하므로 `e = (0.4, 1.5, 2.5)`다. `k = 4`이면 코드 상한은 `4 · 100 / 1,000 = 0.40`, 수학 상한은 `4 · 20 / 1,000 = 0.08`이다. 수학 0.10을 제안하는 탐색은 수학 토큰 100B, 즉 5 epoch를 요구한다. [[data-constrained-scaling]] 적합 법칙(Eq. 5, `R*_D = 15.39`)을 사용하면 2.5 epoch는 같은 수의 새 토큰 가치 약 97%, 5 epoch는 약 90%다(도출). 이 법칙은 혼합 내부 한 도메인의 반복이 아니라 전체 데이터셋 반복에 맞춘 것이다(App. Q). 따라서 비율은 외삽이다.

**근거.**
- [[olmix]] Table 4(1B 대상, `k = 4`)에서 unconstrained optimizer는 한 도메인을 5회 반복하는 혼합을 제안했다. 제약을 적용하면 상한을 지키고 평균 BPB 최선(0.7647; 둘 다 제약한 경우 0.7855)을 냈다.
- OLMo 3은 6T 토큰 사전학습 혼합에서 어떤 도메인도 약 4~7회보다 많이 반복하지 않았다([[olmo-3]] §3.4). SmolLM2는 11T 토큰에서 약 4 epoch를 보장하기 위해 stage 1 StarCoderData를 10%로 제한했다([[smollm2]] §4.2).
- Pile의 기본 가중치는 이미 반복을 포함한다. DoReMi 기준선 가중치는 Pile 저자가 고른 epoch를 예시 수에 곱한 뒤 정규화한 것이다([[doremi]] App. C).

**시사점.** 레시피의 모든 혼합 행에는 `R`과 `N_i`를 함께 적어야 한다. `N_i`를 무시한 탐색은 작지만 유용한 도메인에 가중치를 몰아 `k`회보다 많이 반복하게 만들 수 있고, 그 가치 손실은 가중치를 제안한 회귀 모델에 들어 있지 않다.

## §2 DoReMi: 도메인에 대한 최악 그룹 목표

**정의.** DoReMi(Domain Reweighting with Minimax Optimization; Xie et al., arXiv 2023-05)는 Group DRO(그룹 분포 강건 최적화)로 작은 프록시 모델을 학습해 도메인 가중치를 고른다. Group DRO는 가장 손해 보는 도메인의 손실을 최소화하며, DoReMi는 강건 모델 대신 평균 가중치를 반환한다([[doremi]] §1–§2).

**문제.** 다운스트림 태스크로 가중치를 고르면 많은 학습 실행이 필요하고 “특정 다운스트림 태스크 집합에 과적합할 위험”이 있다([[doremi]] §1). 태스크 데이터를 사용하지 않는 일반성 기준은 모든 도메인에 대한 최악 손실이다.

**작동 방식.**
1. 기준 가중치 `α_ref`로 기준 모델 `p_ref`를 학습한다. The Pile에서는 Pile 기본 가중치, GLaM에서는 균등 가중치다([[doremi]] §3.1).
2. Group DRO로 같은 크기의 프록시 모델을 학습한다. 각 미니배치는 **균등** 도메인 가중치로 샘플링하고 현재 `α`는 각 도메인 손실을 재조정한다(Algorithm 1). 미니배치는 `α`에서 샘플링하지 않는다.
3. 토큰별 초과 손실 `ℓ_θ − ℓ_ref`를 0에서 자르고 배치의 각 도메인 토큰에 대해 평균낸 뒤, `α`에 대한 지수 경사 단계에 사용하고 균등 분포 쪽으로 smoothing한다.
4. 모든 `T` 단계의 `α_t` 평균인 `ᾱ`를 반환하고 `ᾱ`에서 재샘플링한 데이터로 큰 모델을 학습한다.

**공식.** 목표(§2, eq. 1)와 단계별 갱신(Algorithm 1)은 다음과 같다.

```text
min_θ max_{α ∈ Δ^k}  Σ_i α_i · [ (1 / Σ_{x∈D_i} |x|) · Σ_{x∈D_i} ( ℓ_θ(x) − ℓ_ref(x) ) ]

λ_t[i] = (1 / Σ_{x∈B∩D_i} |x|) · Σ_{x∈B∩D_i} Σ_j max{ ℓ_{θ_{t−1},j}(x) − ℓ_{ref,j}(x), 0 }
α'_t   = α_{t−1} ⊙ exp(η · λ_t)
α_t    = (1 − c) · α'_t / Σ_i α'_t[i] + c · u
ᾱ      = (1/T) Σ_t α_t
```

θ는 프록시 파라미터, `ℓ_θ(x)`와 `ℓ_ref(x)`는 프록시·기준 모델의 예시 x 음의 로그 가능도, `|x|`는 토큰 수, `Δ^k`는 k개 도메인 단체, B는 미니배치, j는 토큰 인덱스, η는 step size, c는 smoothing 가중치, u는 균등 벡터 `1/k`, `⊙`는 원소별 곱이다. 로그 공간에서는 `log α'_t = log α_{t−1} + η λ_t`다. 논문은 모든 실험에 η = 1, c = 1e-3을 사용했고 “광범위하게 튜닝하지 않았다”고 했다. 최적화기는 Adafactor다(§2).

**계산 예(장난감 손실).** 세 도메인, `α_{t−1} = (1/3, 1/3, 1/3)`, η = 1, c = 0.001이라고 하자. 배치의 토큰별 초과 손실은 A `(0.5, 0.1)`, B `(−0.4, +0.2)`, C `(−0.3, −0.1)`이다. 자른 뒤 `λ = (0.30, 0.10, 0.00)`이다. `α' = (1/3)(e^0.30, e^0.10, e^0) = (0.44995, 0.36839, 0.33333)`이고 정규화하면 `(0.39069, 0.31987, 0.28943)`, smoothing 후 `α_t = (0.39064, 0.31989, 0.28948)`다. 같은 λ로 두 번째 단계를 거치면 `(0.45045, 0.30211, 0.24744)`다. 자르지 않으면 `λ = (0.30, −0.10, −0.20)`이고 `α_t = (0.43910, 0.29445, 0.26646)`다. B는 프록시가 기준 모델보다 뒤처지는 토큰을 하나 가지고도 A보다 더 낮아진다. 실제 실행에서 λ는 매 단계 변한다. 도메인 업웨이트가 그 도메인의 프록시 업데이트를 키워 초과 손실을 낮추기 때문이다.

`figures/doremi-reweighting.html`에서 다른 손실·η·c로 이 단계를 반복하고, 반복 상한 아래 혼합을 도메인별 epoch로 바꾸며, 280M·1B 프록시가 발표한 Pile 가중치를 비교할 수 있다.

**근거**(8B 주 모델, 200k steps, 배치 512 × 1,024 토큰; [[doremi]] §3.1, App. C).
- Pile, 280M 프록시: 5개 생성 태스크 one-shot exact match 평균 20.03 → 26.56, 기준선 정확도에 200k 중 75k step에서 도달, 최악 도메인 log-perplexity 1.71 → 1.46, 평균 1.64 → 1.40, 22개 도메인 모두 개선(Table 5, Table 3a). 결과(단일 연구).
- 가중치는 다양한 웹 텍스트 쪽으로 이동했다: Pile-CC 0.1121 → 0.6057, OpenWebText2 0.1247 → 0.1019, Wikipedia 0.0919 → 0.0699, ArXiv 0.1052 → 0.0036, PubMed Central 0.1071 → 0.0046(Table 1). ArXiv log-perplexity도 1.64에서 1.38로 낮아졌다(Table 4).
- 1B 프록시와 주 모델: 1B 프록시 자체는 22개 도메인 중 0개에서 1B 기준선을 이겼지만, 프록시 가중치로 학습한 1B 주 모델은 기준선 정확도에 2배 이상 빠르게 도달했다. 저자들은 차이를 프록시의 손실 재가중과 주 모델의 재샘플링 차이로 설명한다(§4, Table 3b).
- 프록시 크기, 8B 주 모델: 70M/150M/280M/1B 프록시는 평균 정확도 21.11/22.51/26.56/22.35를 냈고 네 모델 모두 22개 도메인 중 22개를 개선했다(Table 5, Table 3a). 1B 프록시는 OpenWebText2에 0.3289, Pile-CC에 0.1199를 배정했다. 저자들은 여러 local minima를 제안한다(Table 8, §3.2).
- GLaM, 8개 도메인: 1라운드는 균등 기준선과 같았다. 이전 라운드 `ᾱ`를 `α_ref`로 재사용하는 반복 DoReMi는 2라운드에 다운스트림 튜닝 가중치와 같아졌고 3라운드에 수렴했다(§3.2, Table 2, Figure 3b).
- 280M 목표 어블레이션: 프록시 손실만(“hardest”) 또는 음의 기준 손실만(“easiest”)으로 가중하면 평균 log-perplexity가 2.62와 4.18이었다. 기준선은 2.32, DoReMi는 2.13이었다(Table 7).
- 연산: 280M 기준 모델과 프록시를 합친 비용은 8B 모델 학습 FLOPs의 8%였다(§3.1).

**조건과 한계.** 다운스트림 평가는 one-shot QA·cloze 태스크 5개이며 코드·수학·지시 수행 평가는 없고 시드 분산도 없다(§3.1; 카드 “Not reported”). 동일 크기 510M·760M·1B 실행에서는 DoReMi가 22개 도메인 중 각각 15·17·19개를 개선했지 전부는 아니었다(Table 6). 도메인은 provenance로 정의되며 8개보다 22개 도메인에서 효과가 컸다(§6). 규모를 넘어 가중치가 전이되는 이유는 미해결이다(§6). [[aioli-data-mixing]] Table 2(160M 모델, 층화 샘플링으로 학습한 기준, 5K 또는 40K steps)에서 DoReMi는 GitHub/C4, CommonCrawl/GitHub/Wikipedia, 전체 SlimPajama에서 층화 샘플링보다 테스트 perplexity가 각각 5.303, 6.898, 0.703 낮았고 나머지 세 설정에서는 더 좋았다. 이 설정은 모델 크기·steps·기준 가중치가 DoReMi 논문과 다르다.

**시사점.** DoReMi 목표는 형식화된 폭 기준이다. 프록시가 기준 모델보다 뒤처지는 도메인에 토큰을 쓴다. 근거는 하나의 코퍼스와 하나의 주 모델 규모에 대한 가중치를 지지하며, 반환 가중치가 프록시 크기에 의존함을 보여 준다. 따라서 전이 가능한 상수가 아니라 §4에서 검증할 후보다.

## §3 프록시 실행에 대한 혼합 법칙과 회귀

**정의.** 오프라인 혼합 방법은 서로 다른 혼합으로 작은 프록시 모델 무리를 학습하고, 혼합에서 성능으로 가는 회귀 모델을 맞춘 뒤 예측을 최적화하는 혼합을 제안한다([[olmix]] §3.1.2). **혼합 법칙**은 그 회귀의 함수 형태다.

**문제.** 후보 혼합마다 큰 모델을 하나씩 학습하는 것은 감당할 수 없다. 회귀는 관찰된 혼합 사이를 보간해야 하고, 목표 규모에서도 순위가 유지되는 규모에서 맞춰야 한다.

**Data Mixing Laws**(Ye et al., arXiv 2024-03). 검증 도메인 i의 손실은 다음과 같이 모델링한다([[data-mixing-laws]] Eq. 7).

```text
L_i(r_1..M) = c_i + k_i · exp( Σ_{j=1..M} t_ij · r_j )
```

`r_j`는 학습 도메인 j의 비율, `c_i`는 혼합 변경으로 줄일 수 없는 손실, `k_i > 0`은 규모, `t_ij`는 학습 도메인 j와 검증 도메인 i의 상호작용이다. 음의 `t_ij`는 j 데이터가 i의 손실을 낮춘다는 뜻이다(§3.2). 전체 검증 손실은 `Σ_i s_i L_i`이고, `s_i`는 구성 비율을 모를 때 학습한 검증 집합의 도메인 i 비율이다(§3.3). GitHub·Books3·Pile-CC에서 적합 혼합 24개와 검증 혼합 8개를 사용하면 검증 평균 절대 오차는 0.0365, 0.0074, 0.0078이었다. 관찰 극단 사이 무작위 추측은 0.8758, 0.1331, 0.1045였다(Table 1). 목표 규모에 도달하기 위해 저자들은 혼합별로 학습 step에 대한 power law와 모델 크기에 대한 power law를 맞춘 뒤 외삽 손실에 혼합 법칙을 맞췄다(Algorithm 1).

**계산 예(장난감 매개변수; 수작업 적합을 위해 c를 안다고 가정).** 두 도메인에서 도메인 1의 비율을 r이라 하자. 도메인 1 관측값이 `L_1(0.25) = 2.6065`, `L_1(0.50) = 2.3679`, `L_1(0.75) = 2.2231`, `c_1 = 2.0`이면 `ln(L_1 − c_1) = −0.50, −1.00, −1.50`이다. 기울기 `t = −2`, 절편 0인 직선이므로 `k_1 = 1`이고 `L_1(0.60) = 2 + e^(−1.2) = 2.3012`로 예측한다. 도메인 2가 `L_2 = 1.0 + 1.5 · exp(−3(1 − r))`이고 검증 세트가 50/50이라고 하자. 전체 `L(r) = 0.5 L_1 + 0.5 L_2`의 미분은 `dL/dr = −e^(−2r) + 2.25 e^(−3+3r)`이다. 이를 0으로 두면 `r* = (3 − ln 2.25) / 5 = 0.438`, `L = 1.847`이다. `r = 0.25`에서는 1.882, 0.50에서는 1.851, 0.75에서는 1.966이다. 각 도메인의 손실은 자기 비율이 늘면 낮아지고 다른 도메인 비율이 늘면 높아지므로 최적점은 내부에 있다.

**Data Mixing Laws 근거.** RedPajama 20개 혼합에서 70M·160M·305M·410M 프록시를 30B 토큰으로 학습했다. 예측 혼합을 1B 모델 100B 토큰에 사용하고 The Pile 검증 세트에서 평가했다. 기본 혼합의 최종 성능에 0.73 step에서 도달했고, 기본 혼합을 1.48배 더 많은 토큰으로 학습한 것과 같다고 추정했다(Figure 8). 같은 예산에서 DoGE·DoReMi 혼합보다 손실이 낮았다(Figure 9). Pile과 Python을 사용한 Pythia-70M 계속 사전학습에서는 Pile 손실을 유지하는 Python 비율을 법칙이 예측했다(§5, Figure 10). 결과(단일 연구).

**RegMix**(Liu et al., arXiv 2024-07). RegMix는 토큰 수 중심 Dirichlet 분포에서 혼합을 샘플링하고, 1M 파라미터 프록시 512개를 각각 1B 토큰으로 학습한다. LightGBM(gradient-boosted trees)으로 가중치에서 Pile-CC 검증 손실을 회귀하고 예측 상위 100개 혼합을 평균한다([[regmix]] §3). 미관찰 혼합의 예측·실제 순위 Spearman 상관은 LightGBM에서 1M 모델 98.45, 60M·1B 토큰 98.64, 1B·25B 토큰 97.12였다. 선형 회귀는 각각 90.08, 89.26, 88.01이었다(Table 2). 1B·25B 토큰에서 RegMix 혼합은 14개 태스크 평균 47.3이었다. Pile 저자 가중치는 45.1, 17개 가용 도메인에 재정규화한 DoReMi 공개 가중치는 46.8, Pile-CC만 학습한 경우도 46.8이었다. 저자들은 DoReMi 점수가 낮게 잡혔을 수 있다고 말한다. 혼합 비용은 3.5e18 FLOPs, DoReMi는 3.7e19였다(Table 4). 약 0.25B 토큰 이후에는 실행당 토큰 증가보다 프록시 실행 증가가 ρ를 더 높였다(§4.2, Figure 4).

**Aioli**(Chen, Hu et al., arXiv 2024-11). Aioli는 DoReMi·DoGE·Skill-It·Data Mixing Laws가 `L_{t+1}(p_t) = σ(A_t p_t)` 형태(σ는 identity 또는 exp)의 혼합 법칙 아래 평균 손실을 최소화한다는 것을 보이고, `A_t` 설정 방식이 다르다고 설명한다([[aioli-data-mixing]] §1, §3). 두 매개변수화는 관찰 손실-비율 관계에 맞았다(평균 MSE 0.0005, R² 0.969). 그러나 온라인 방법의 `A_t` 값은 일관되게 정확하지 않았고, 각 방법의 `A_t`와 적합값의 유사도는 2·3 그룹에서 층화 샘플링보다 개선된 정도와 중간 정도 양의 상관이었다(R² = 0.491; §4.3, Figure 3). SlimPajama 하위 집합에서 160M 모델을 학습했다(배치 2,048 토큰 시퀀스 8개; 2~3 그룹 5K step, 7그룹 40K). 현재 실행에서 `A_t`를 추정하는 Aioli는 6개 설정 모두에서 층화 샘플링보다 평균 0.274 perplexity 좋았다. 다른 모든 방법은 최소 한 설정에서 층화 샘플링에 졌고 최대 차이는 6.9였다(Table 2). Grid search와 DML은 각각 전체 실행 10회를 추가했지만 6개 중 2개에서 여전히 졌다(Table 2). 일반성 주의점: SlimPajama 모델에서 테스트 perplexity와 8개 다운스트림 태스크 macro 평균 상관은 0.529였다. 낮은 perplexity가 더 나쁜 다운스트림 점수를 예측했고, 7개 그룹 중 3개를 제외한 DML 혼합이 다운스트림 평균 최선이었다(App. F.1).

**Olmix**(Chen, Murray et al., Ai2, arXiv 2026-02). Olmix는 100B 토큰으로 학습한 1B 대상과 bits per byte(BPB)로 평가한 52개 태스크에서 오프라인 스키마의 설정 선택 7개를 연구한다([[olmix]] §3.3.1).
- 프록시 크기: 15M 이상 프록시는 1B 대상과 순위 상관 0.89 초과, 1M 프록시는 0.73, 3B 토큰의 30M 프록시는 0.896이었다(§3.3.2, Figure 3). RegMix 공개 “1M” 구현은 15M에 더 가깝다고 저자들은 확인했다(각주 1).
- 무리 크기: 필요한 실행 수는 도메인 수 m에 선형으로 증가하며 `K ≥ 3(m + 1)` 실행이면 찾은 최선 혼합과 비교한 오차가 거의 0이었다(Figure 4).
- 회귀: Data Mixing Laws에서 수정한 log-linear 형태가 `K ≥ 75`에서 가장 잘 맞고 `K = 128`에서 다운스트림 BPB가 최선이었다. LightGBM은 실행 118개 이상이 필요했다(Figure 6). 태스크별 모델 하나는 BPB 0.765, 평균 하나는 0.774였다(Table 3).
- 최적화: exact solver는 예측 BPB를 최소화했지만 자연 분포를 향한 KL penalty `λ = 0.05`가 목표 BPB 최선이었다(0.7647 대 0.7772)(Figure 8).
- 도메인 변화: 64개 도메인으로 끝나는 5번의 도메인 세트 업데이트에서 영향받지 않은 도메인 비율을 재사용하면 프록시 216회로 자연 분포보다 +11.6%였다. 832회 실행으로 처음부터 다시 계산하면 +12.2%였다(§5.1.2). 최선 혼합은 61,000 step이 아니라 약 20,000 step에서 자연 분포의 최종 BPB에 도달했다.

**조건과 한계.** 네 연구 모두 선택한 검증 세트의 손실 또는 BPB를 최적화하며, 보지 않은 태스크 스위트의 정확도를 최적화하지 않는다. Data Mixing Laws는 모델 크기와 토큰 수에 따라 혼합 순위가 바뀔 수 있다고 말한다(각주 7). 이는 단일 전이에 대한 **미해결 질문**이다. RegMix의 목표는 하나의 검증 도메인(Pile-CC)이며 0~5 shot 평균 태스크다. Aioli 모델은 160M, 배치 8이다. Olmix는 오프라인 스키마만 다루고 재사용 이론은 log-linear 형태를 가정한다(§6).

**시사점.** 회귀 방법은 추측을 적합된 표면으로 바꾸지만, 표면의 일반성은 목표만큼만 넓다. [[olmix]]에서는 태스크별 목표, 자연 분포를 향한 regularizer, 반복 상한이 각각 대상 모델을 더 낮은 평균 BPB 쪽으로 움직였다. 단일 도메인 또는 단일 벤치마크 목표는 폭을 측정하지 않는다.

## §4 규모를 넘어서 혼합 검증하기

**정의.** 순위 불변성은 프록시와 목표 모델에서 성능별 혼합의 순서가 같다는 가정이다([[regmix]] §1).

**문제.** 30M 또는 1B에서 이긴 혼합이 목표 규모에서 질 수 있으며, 비싼 실행 뒤에야 오류를 발견한다.

**메커니즘: 소스에서 조립한 검증 프로토콜.**
1. 무리를 신뢰하기 전에 의사결정에 사용하는 지표에서 두 프록시 크기의 프록시-목표 순위 상관을 측정한다([[olmix]] Figure 3; [[regmix]] Table 2).
2. 프록시 규모에서 레시피를 구분하는 평가 태스크를 사용한다. [[datadecide]](데이터 레시피 25개, 대부분 혼합 가중치보다 필터 선택)는 150M 순위로 1B 승자를 쌍별 비교의 약 80%에서 예측했지만, 시험 규모에서 SocialIQA와 BoolQ 결정은 신뢰할 수 없었다(Abstract; §3.1).
3. 후보로 중간 모델 하나를 학습하고 “여러 핵심 벤치마크”를 평가한 뒤 확정한다(Llama 3, §3.1.2).
4. 혼합을 맞추거나 선택하는 데 사용하지 않은 홀드아웃 스위트를 보고한다(아래 예시).

**전이에 대한 근거.**
- 찬성: RegMix LightGBM은 1M 프록시에서 1B 모델(25B 토큰)까지 `ρ = 97.12`였고, 100B 토큰까지 학습한 7B 모델에서 대부분의 태스크에 대해 RegMix가 사람이 고른 가중치보다 좋았다(Table 2, Figure 1). Olmix는 30M에서 1B까지 `ρ = 0.896`이었다(Figure 3).
- 반대: DoReMi 프록시 크기는 8B 정확도가 단조롭지 않았다(1B 프록시가 280M보다 나쁨)고 서로 다른 가중치를 냈다(Table 5, Table 8). Olmix는 1M 프록시를 신뢰할 수 없다고 했다(`ρ = 0.73`). Data Mixing Laws는 규모·토큰 수에 따라 순위가 바뀌는 연구를 인용한다(각주 7). 상태: 약 15M 파라미터 이상 프록시에서 순위 전이를 보고한 연구는 RegMix(Olmix가 구현을 올바르게 읽었다면)와 Olmix 두 개다. 이 임계값 자체는 **결과(단일 연구)**다.

**Llama 3 과정**([[llama-3]] §3.1.2–§3.1.3, §3.4; Llama Team, arXiv 2024-07). (1) 지식 분류기가 웹 데이터의 정보 유형을 라벨링하고, 웹에서 과대표집된 범주(“예: 예술과 엔터테인먼트”)를 다운샘플링한다. (2) 후보 혼합마다 여러 소형 모델을 학습해 큰 모델 성능을 예측하는 scaling-law 실험을 하고, 후보 선택을 위해 반복한다. (3) 후보로 더 큰 모델을 학습하고 핵심 벤치마크를 평가한다. (4) 최종 혼합은 대략 일반 지식 50%, 수학·추론 25%, 코드 17%, 다국어 토큰 8%다. (5) 405B 학습 중 혼합을 조정했다. 비영어 데이터 증가, 수학 업샘플링, 후반부 최신 웹 데이터 증가, 품질 낮은 하위 집합 다운샘플링이다. 비율은 인쇄하지 않았다(§3.4.1). (6) GSM8K·MATH 학습 세트에 annealing하면 사전학습 8B 모델의 검증 점수가 24.0%, 6.4% 개선되었지만 405B에서는 이득이 거의 없었다. “진정한 few-shot 학습 능력과 분포 밖 일반화를 평가하기 위해” 벤치마크 학습 세트를 annealing 데이터에서 제외했다(§3.1.3). (7) 작은 새 데이터셋의 가치를 평가할 때는 50% 학습된 8B 모델에 데이터셋 30%, 기본 혼합 70% 가중치를 주고 40B 토큰에 걸쳐 학습률을 0까지 선형 annealing한다(§3.1.3).

**조건과 한계.** Llama 3은 후보별 결과, 분류기 정확도, 혼합의 홀드아웃 비교를 인쇄하지 않았다. 8B 대 405B annealing 결과는 두 수학 벤치마크에 대한 모델 한 쌍의 결과이고, 보고서의 설명(405B에서 강한 문맥 내 학습)은 **해석**이다.

**공개 보고서가 사용한 홀드아웃 스위트.** SmolLM2는 MMLU-Pro, Natural Questions, TriviaQA를 “학습 중 모니터링하지 않은” 벤치마크로 보고한다([[smollm2]] §4.7, Table 4). OLMo 2는 중간 학습 표에서 개발 벤치마크와 홀드아웃 평가를 분리하고 GSM8K 1,319개 예시 중 200개만 개발에 사용했다([[olmo-2]] Table 9, 각주 6). OLMo 3는 긴 컨텍스트 레시피를 개발할 때 RULER를 사용하고 HELMET을 보지 않은 스위트로 남겼다. 다만 둘이 겹치므로 HELMET은 “완벽한 홀드아웃 스위트가 아니다”라고 밝혔다([[olmo-3]] §3.6).

**시사점.** 규모 전이는 프록시 크기·지표·태스크 집합에 대해 측정되는 속성이다. 혼합 레시피에는 그 측정을 함께 기록해야 한다. Llama 3 annealing 실험처럼 소규모에서 목표 벤치마크에 집중된 이득은 목표 규모의 홀드아웃 태스크에서 주장을 시험해야 할 이유다.

## §5 단계별 혼합

**정의.** 단계 혼합은 자체 토큰 예산과 목표를 가진 한 학습 단계에서 사용하는 혼합이다. 아래 단계는 혼합으로 무엇을 바꾸려 하는지가 다르다.

| 단계 | 혼합으로 바꾸려는 것 | 공개된 예 | 측정된 절충 |
|---|---|---|---|
| 안정 LR 사전학습 | 모든 도메인의 폭넓은 커버리지 | OLMo 3 6T 혼합: Common Crawl 76.1%, olmOCR PDF 13.6%, Stack-Edu 6.89%, FineMath 2.56%, arXiv 0.86%, Wikipedia 0.04%([[olmo-3]] Table 4) | 웹 주제 혼합으로 1B BPB 평균 0.056 개선, 54개 태스크 중 13개 하락, 어느 것도 0.035 초과 하락 없음(§3.4) |
| 다단계 사전학습 | 체크포인트에서 보이는 능력 공백 | SmolLM2 1.7B, 네 단계(아래 표) | 단계 전체에서 수학 3.21 → 22.07, 코드 8.87 → 23.21([[smollm2]] Table 3) |
| Annealing/중간 학습 | LR 감쇠 중 목표 기술 | OLMo 2 Dolmino 50B, OLMo 3 Dolmino 100B | 편향된 혼합이 수학·코드와 QA를 절충([[olmo-3]] Table 7) |
| 긴 컨텍스트 확장 | 짧은 컨텍스트 손실 없이 장거리 사용 | §6 | 긴 데이터 66%: −2.5, 긴 데이터 34%: −0.8([[olmo-3]] §3.6.3) |
| SFT | 지시 형식과 능력 커버리지 | Llama 3.1 Table 7 예시 비율 | “넓은 범위의 벤치마크 성능을 조정”하도록 매 라운드 조정([[llama-3-recipe]]) |

**SmolLM2 1.7B 단계 혼합**([[smollm2]] §4.2–§4.6, Figure 2; Hugging Face, arXiv 2025-02). 1단계(0~6T 토큰): 영어 웹 90%(FineWeb-Edu 60 / DCLM 40), StarCoderData 10%, 수학 없음. 2단계(6~8T): 웹 75%, 코드 20%, OpenWebMath 5%. 3단계(8~10T): 웹 74%(FineWeb-Edu 40 / DCLM 60), 코드 16%(Stack-Edu), 수학 10%. 4단계, decay 단계(10~11T): 웹 58%, Stack-Edu 24%, 수학 14%(AugGSM8K 0.02% 포함), Cosmopedia v2 4%. 저자들은 각 단계 뒤 벤치마크를 모니터링하고 혼합을 바꾸는 접근을 “온라인”이라고 설명한다. 처음부터 여러 스케줄을 실행하지 않은 이유는 사전학습 GPU 비용이 약 250,000달러였기 때문이다(§4). 이는 단계별 control run이 없는 연속 결정이므로 단계별 이득은 계속 학습·LR 감쇠와 분리할 수 없다.

**OLMo 2 중간 학습**([[olmo-2]] §4; Ai2, arXiv 2025-01). OLMo 2 7B의 50B Dolmino 혼합은 필터 DCLM 47.2%, 오염 제거 FLAN 16.6%, StackExchange Q&A 2.45%, peS2o 5.85%, Wikipedia/Wikibooks 7.11%, 수학 20.8%다(Table 13). 수학에는 GSM8K train split이 포함된다(Table 5). 4T 토큰 7B 체크포인트에서 50B 토큰 후보 실행을 했을 때 사전학습 혼합만 LR decay하면 OLMES가 69.6에서 74.0으로 오르고 GSM8K 개발 점수는 28.5에서 27.0으로 내려갔다. 수학·지시 데이터를 추가하면 OLMES 75.7, OLMES-Gen 70.2, GSM* 46.5였다(Table 11). Microanneal은 사전학습 7B 체크포인트에서 짧게 annealing하는 실행이다. 첫 번째에서는 약 200M 토큰 수학 혼합(TuluMath, DolminoSynthMath, MetaMath, CodeSearchNet, GSM8K train split)을 DCLM과 섞었다. 수학 35%는 GSM* 63.5, 10%는 61.0이었고 annealing 전은 28.5였다. 저자들은 이를 도메인 특화 데이터의 “큰 비율이 반드시 필요한 것은 아님”으로 해석한다(§4.4, Table 12).

**OLMo 3 중간 학습 절충**([[olmo-3]] §3.5.4, Table 7; arXiv 2025-12). 100B 토큰 탐색 annealing에서 수학·코드·thinking 데이터가 없는 Gen-QA 혼합은 Math 27.5, Code 11.9였고 최종 혼합은 57.3, 31.2였다. GenQA는 72.5 대 73.1이었다. 수학-코드-thinking 혼합은 Math 60.8, Code 35.6이었지만 MC Non-STEM은 69.6으로 최종 혼합 77.4보다 낮았다. 최종 혼합은 MC STEM 66.4와 GenQA 73.1에서 가장 높고 MC Non-STEM은 Gen-QA 혼합보다 0.7 낮았으며 Math·Code·FIM에서는 두 편향 혼합 사이였다.

**코드 비율은 단계에 따라 다르다**([[to-code-or-not-to-code]]; Cohere, arXiv 2024-08). 저자들은 “처음부터 사전학습할 때 코드와 텍스트의 균형 혼합”, “계속 사전학습에서는 상대적으로 낮은 코드 비율”, cooldown 혼합에서 코드 데이터를 권장한다(§3.6). 40B 토큰에서 코드 20% cooldown은 cooldown 없음보다 추론·지식·코드에서 각각 3.6%, 10.1%, 20% 상대 이득을 냈다. 코드 없는 cooldown은 추론·코드 이득을 내지 못했다(§3.5). 첫 권고의 근거인 코드 비율 sweep은 ch-09에 있다.

**단계 혼합의 벤치마크 학습 세트.** Llama 3은 annealing에서 이를 제외했다(§3.1.3). OLMo 2는 GSM8K train split을 포함하고 개발에 사용하지 않은 테스트 예시 1,119개에서 GSM8K를 보고했다([[olmo-2]] Table 5, 각주 6). SmolLM2는 증강 GSM8K 학습 세트인 AugGSM8K 0.02%를 4단계에 넣었다([[smollm2]] §4.5). 이 혼합에서 GSM8K 이득은 GSM8K 형식 학습 데이터를 본 단계의 이득이므로, 일반적인 이득으로 해석하려면 홀드아웃 수학 스위트가 필요하다.

**SFT 혼합.** Llama 3.1 SFT 데이터는 예시 비율 기준 일반 영어 52.66%, 코드 14.89%, 다국어 3.01%, 시험 형식 8.14%, 추론·도구 21.19%, 긴 컨텍스트 0.11%이며 일부 소스는 여러 epoch 반복했다([[llama-3-recipe]], Table 7). SFT 혼합은 자체 간섭 효과가 있는 별도 결정이며 ch-30b에서 다룬다. RL 프롬프트의 도메인 혼합은 ch-44b에 있다.

## §6 긴 컨텍스트 단계 혼합: 길이 업샘플링과 긴 데이터:짧은 데이터 비율

**정의.** 긴 컨텍스트 단계는 사전학습 모델을 더 긴 시퀀스로 계속 학습한다. 혼합은 두 가지를 정한다. 긴 문서의 비율, 긴 부분과 짧은 부분 각각의 도메인 구성이다.

**문제.** 긴 문서는 대부분 책·코드 저장소·논문이므로 문서 길이와 소스 도메인이 뒤섞인다([[long-context-data-engineering]] §3). 긴 문서를 업샘플해 긴 비율을 높이면 도메인 혼합도 바뀌고, 바뀐 혼합은 짧은 웹 텍스트 손실을 높일 수 있다.

**Fu et al.이 비교한 네 데이터 전략**([[long-context-data-engineering]] §3; arXiv 2024-02; SlimPajama의 LLaMA-2 7B, 80K로 패킹한 5B 토큰, 상수 LR 2e-5, 배치 4M 토큰).
1. **4K에서 자르기 / 128K에서 자르기:** 원래 혼합을 유지한다. SlimPajama 문서의 약 30%는 자연스럽게 4K보다 길다(Figure 2).
2. **전체 업샘플링:** 소스와 관계없이 긴 문서를 업샘플해 도메인 혼합을 바꾼다.
3. **Arxiv/Book/Github 업샘플:** 긴 도메인을 높여 길이와 도메인을 모두 바꾼다.
4. **소스별 업샘플링:** SlimPajama 도메인 비율(CommonCrawl 67%, C4 15%, GitHub 4.5%, Wikipedia 4.5%, books 4.5%, ArXiv 2.5%, StackExchange 2.0%)을 유지하고 각 소스 안에서 4K 초과 시퀀스 비율을 약 30%에서 70%로 높인다(§5.3).

**계산 예(장난감 수치).** 웹이 토큰 90%, 그중 긴 문서 토큰 20%이고 책이 토큰 10%, 그중 긴 토큰 90%라 하자. 전체 긴 비율은 `0.9 · 0.2 + 0.1 · 0.9 = 27%`다. 모든 긴 문서 토큰의 샘플링 가중치를 3배로 하면 전체 업샘플에서 웹은 `54 + 72 = 126`, 책은 `27 + 1 = 28` 단위다. 책은 10%에서 `28/154 = 18.2%`로 오르고 전체 긴 비율은 52.6%가 된다. 각 소스 내부에서 같은 배율을 적용한 뒤 90/10 비율을 복원하면 웹 긴 비율은 42.9%, 책은 96.4%, 전체는 48.2%이며 책은 여전히 10%다.

**근거.**
- Fu et al. Table 5(원래 혼합 대비 손실 변화, 0~4K 컨텍스트): 소스별 업샘플은 C4/CommonCrawl/StackExchange 손실을 +0.002/+0.008/−0.001 바꿨다. 전체 업샘플은 +0.008/+0.010/+0.015, 책 업샘플은 +0.010/+0.016/+0.021이고 GitHub 손실은 +0.029 높였다. 코드 업샘플은 책 손실을 +0.030 높였다. 7B 소스별 모델은 Needle-in-a-Haystack 88.0, MMLU 43.3이었다(Table 3). 원래 혼합은 소스별 혼합과 거의 같은 검증 손실이었지만 retrieval 정확도는 낮았다(Figure 4).
- ProLong([[prolong]]; Princeton, arXiv 2024-10; Llama-3-8B, SFT 후 64K에서 5B 토큰 어블레이션): 긴 비율이 100%로 오르면 PG19 perplexity는 계속 좋아졌지만 다운스트림 긴 컨텍스트 평균은 낮아졌고 짧은 태스크 평균은 긴 비율에 따라 단조 하락했다. 긴 60%와 짧은 40%가 평균 최선이었다(§2.1, Figure 1; §3.2, Figure 3). 책과 코드 저장소 1:1이 최선의 긴 소스(54.6), 큐레이션 ShortMix가 최선의 짧은 소스였다(Table 4, Table 6). Fu et al. SlimPajama 긴 혼합으로 Llama-3-8B를 fine-tuning하면 MMLU 66.5→63.1, GSM8K 44.7→40.6이었다(Table 2). 일치 재현에서 Fu 혼합은 긴 51.8/짧은 65.4, ProLong 혼합은 54.6/67.5였다(App. B.6, Table 24).
- 공개 비율: ProLong-64k-Base는 20B 토큰에서 코드 저장소 30%, 책 30%, 교과서 3%, ShortMix 37%였다([[prolong-recipe]], Table 9). Qwen2.5-1M은 65,536~262,144 토큰 단계에서 현재 최대 길이 시퀀스 75%, 더 짧은 시퀀스 25%를 사용했다([[qwen-long-context-synth]] §3). OLMo 3은 Longmino 34% 긴 문서와 Dolmino 중간 학습 66%를 7B 50B·32B 100B 토큰에 섞었다. 10B 토큰 시험에서 긴 66%는 OlmoBaseEval 일부에서 2.5점, 긴 34%는 0.8점 비용이었다([[olmo-3]] §3.6, §3.6.3). SmolLM2는 최종 75B 토큰 전 체크포인트에서 2K→8K로 확장하며 8K 이상 문서 40%(DCLM 10%, FineWeb-Edu 10%, Dolma books 20%)와 4단계 혼합 60%를 사용했고 “거의 손실 없음”을 보고했다([[smollm2]] §4.6–§4.7).
- Llama 3.1 405B는 약 800B 토큰 동안 여섯 단계로 컨텍스트를 8K→128K로 늘렸다. 짧은 컨텍스트 평가가 “완전히 회복”되고 해당 길이에서 needle-in-a-haystack가 해결될 때만 다음 단계로 넘어갔다([[llama-3]] §3.4.2). 긴/짧은 비율은 보고하지 않았다.
- 긴 단계 후 SFT: Llama 3은 짧은 컨텍스트 데이터만 SFT하면 긴 능력이 회귀하여 합성 긴 컨텍스트 비율 0.1%를 사용했다([[llama-3]] §4.3.4). ProLong SFT 어블레이션에서는 짧은 UltraChat만 사용하면 긴 컨텍스트 평균 55.7, 합성 긴 지시 데이터 1%면 54.1, 50%면 43.3이었다(§5, Table 8). 두 결과는 긴 학습량과 평가가 다르다.

**사전학습 컨텍스트 창 스케줄링.** SkyLadder([[skyladder]]; arXiv 2025-03)는 데이터 혼합이 아니라 attention window를 바꾼다. 고정 100B 토큰에서 짧은 창으로 사전학습한 1B 모델은 9개 표준 벤치마크에서 더 높은 점수를 냈다. 창을 32토큰에서 8K로 선형 증가시키면 CommonCrawl 표준 평균이 46.3→50.0으로 올랐다(Table 1). 저자들은 문서 길이로 데이터를 정렬하면 긴 문서가 책 같은 도메인에 모이므로 도메인 편향이 생긴다고 주장한다(§2, §4.6; 해석). 이는 Fu et al.이 Table 5에서 측정한 같은 혼란이다.

**조건과 한계.** Fu et al.은 SFT 없이 도메인별 손실·needle retrieval·BookQA·MMLU로 평가했다. ProLong 어블레이션은 Llama-3 8B에서, OLMo 3 비율 시험은 스위트 일부의 10B 토큰에서 수행했다. 어느 보고서도 한 모델 크기 초과에서 비율을 어블레이션하지 않았다.

**시사점.** 폭을 위해 긴 컨텍스트 단계는 두 제약이 있는 혼합 문제다. 일반 데이터의 도메인 비율을 유지하고 짧은 컨텍스트 평가가 떨어지지 않을 만큼 짧은 데이터를 남겨야 한다. 긴 텍스트 perplexity와 needle retrieval이 다운스트림 긴 컨텍스트 점수와 같은 방식으로 혼합 순위를 매기지 않았으므로, 짧은 컨텍스트 스위트와 SFT 후 긴 컨텍스트 태스크에서 단계를 평가한다(ProLong §2.1; Fu et al. Figure 4).

## §7 구성에서 다른 도메인으로 전이

앞 절들은 한 도메인의 혼합 결정이 다른 도메인의 성능을 바꾼다는 것을 보여 준다. 측정 사례와 상태는 다음과 같다.

- **다양한 웹 텍스트가 많은 태스크를 지원한다.** DoReMi는 Wikipedia 가중치를 0.0919에서 0.0699로 낮췄지만 Wikipedia에서 파생된 TriviaQA는 24.55에서 34.86으로 올랐다([[doremi]] Table 1, Table 5). RegMix는 Pile 도메인 중 Pile-CC 검증 손실이 다운스트림 성능과 가장 상관이 높다고 했고, Pile-CC만 학습해도 DoReMi 가중치와 같은 46.8을 얻었다([[regmix]] §5.2, Table 4). **재현됨:** The Pile에 대한 두 연구에서 방향이 재현되었다. DoReMi의 설명(중간 엔트로피 도메인이 모든 도메인으로 전이됨, App. D)은 **해석**이다.
- **코드는 일정 비율까지 추론을 돕지만 이후 지식에 비용을 준다.** 84B 토큰 중 Python을 최대 50% 사용해도 4.2B에서 19개 자연어 태스크 평균이 낮아지지 않았고 bAbI가 0.0에서 23.2로 올랐다([[data-constrained-scaling]] §7, App. M). 논문의 470M 규모 어블레이션(§3.3은 크기를 다시 쓰지 않음)에서는 코드 25%가 추론 최선, 코드 75%가 코드 없음 대비 세계 지식을 31% 낮췄다([[to-code-or-not-to-code]] §3.3). **재현됨:** 추론 방향은 재현되었고 지식 비용은 한 연구에서 나온다.
- **대상 혼합은 일부 전이된다.** 100B 토큰으로 학습한 1B 모델에서 QA 대상 혼합은 자연 분포 대비 수학·코드 BPB도 낮췄다(0.643 대 0.719, 0.535 대 0.592). 각 단일 대상 혼합은 자기 대상에서 가장 낮은 BPB였고, 다중 목표 혼합은 어느 열에서도 최저가 아니지만 세 열 모두 자연 분포보다 낮았다([[olmo-3]] Table 38). MMLU 대상 혼합은 HellaSwag와 PIQA를 낮췄다([[weborganizer]] Table 10). 각각 결과(단일 연구).
- **중간 학습 추가가 다른 기술을 바꾼다.** OLMo 2의 고품질 웹 중간 학습 혼합에 수학 데이터를 추가하면 OLMES-Gen이 63.8에서 69.7로 오르고 MMLU는 63.1에서 62.3으로 낮아졌다([[olmo-2]] Table 11). 긴 도메인 하나를 업샘플하면 다른 도메인의 짧은 컨텍스트 손실이 올라갔다([[long-context-data-engineering]] Table 5).
- **혼합 법칙은 상호작용을 표현한다.** Data Mixing Laws 형태에서 음의 `t_ij`는 j 도메인 학습 데이터가 i 검증 손실을 낮춘다는 뜻이다. 거친 Pile 도메인 5개 중 대부분 쌍은 관계가 작았지만, 일부 쌍은 촉진(인터넷 텍스트에 대한 대화 데이터), 일부는 충돌(산문에 대한 기호 데이터)이었다([[data-mixing-laws]] §3.2, Figure 4).

**소형 범용 실행의 출발점.** 수십 개 도메인에서 100B 토큰을 학습하는 1B 모델의 경우 표에서 완전히 지정된 혼합 탐색은 OlmixBase다. 3B 토큰의 30M 프록시, 최소 `3(m+1)`회 실행, 태스크별 log-linear 모델, 자연 분포 KL 0.05 exact solver, 반복 상한 4(1B 대상, 100B, BPB 태스크 52개)다. 제안 혼합은 대상 모델에서 자연 분포와 함께 학습해 검증한다. m이 작으면 여러 방법이 [[aioli-data-mixing]] Table 2에서 진 층화 샘플링을 세 번째 기준선으로 둔다. 처음부터 단계화하면 SmolLM2 네 단계가 11T 토큰 1.7B 모델의 검증된 순서다. 4단계 decay 혼합(웹 58%, 코드 24%, 수학 14%, 합성 교과서 4%)은 후보 annealing이며, GSM8K가 홀드아웃에 있으면 AugGSM8K를 제거한다. 컨텍스트 확장에서는 34% 긴/66% 짧은(Olmo 3 7B, 50B, 8K→65K)과 40%/60%(SmolLM2 1.7B, 2K→8K)가 검증된 비율이다. 확장 단계는 Llama 3.1처럼 짧은 컨텍스트 평가가 회복된 뒤 진행한다.

## 일반화 관점

**(a) 폭을 넓히는 요인.**
- 태스크 데이터가 없는 최악 도메인 목표: DoReMi 가중치는 8B에서 Pile 22개 도메인 모두와 최악 도메인 log-perplexity를 개선했다([[doremi]] Table 3a).
- 태스크별 회귀 목표와 자연 분포를 향한 정규화: 1B에서 BPB는 태스크별 0.765 대 집계 0.774, KL 0.05는 exact 대비 0.7647 대 0.7772였다([[olmix]] Table 3, Figure 8).
- 균형 잡힌 중간 학습 혼합: 최종 OLMo 3 혼합은 GenQA 편향 혼합의 72.5 대비 73.1 GenQA를 냈고, Math는 27.5 대비 57.3을 유지했다([[olmo-3]] Table 7).
- 긴 컨텍스트 학습에서 일반 짧은 데이터를 유지하고 도메인 비율을 유지한다([[prolong]] Figure 3; [[olmo-3]] §3.6.3; [[long-context-data-engineering]] Table 5).

**(b) 범위를 좁히거나 망각을 일으키는 요인.**
- 단일 목표 혼합: MMLU 대상 혼합은 HellaSwag 57.5→54.1, PIQA 71.3→69.9로 낮췄고([[weborganizer]] Table 10), 편향된 중간 학습 혼합은 MC Non-STEM 7.8점 또는 Math 29.8점을 잃었다([[olmo-3]] Table 7).
- 단계 혼합에 벤치마크 형식 학습 데이터를 포함: 8B에서 GSM8K +24.0%가 405B에서는 나타나지 않았다([[llama-3]] §3.1.3).
- 긴 데이터만으로 계속 학습: 긴 비율이 증가할수록 짧은 태스크 점수가 단조롭게 하락했고, 긴 데이터 100%는 SFT 후 다운스트림 긴 컨텍스트 점수를 낮췄다([[prolong]] §3.2).
- perplexity 목표를 능력 목표로 읽기: Aioli SlimPajama 모델에서 낮은 테스트 perplexity가 더 나쁜 다운스트림 평균을 예측했다(상관 0.529; [[aioli-data-mixing]] App. F.1).
- 작은 도메인을 무제한 업웨이트: 반복 상한 4에 대해 한 도메인을 5회 반복하는 결과를 냈다([[olmix]] Table 4).

**(c) 이 단계에서 측정하는 방법.**
- 오염 제거 평가 텍스트에서 도메인별 perplexity 또는 BPB의 macro 평균을 계산하고 최악 도메인을 보고한다([[paloma]] §3–§4; [[doremi]] Table 3a).
- 혼합 적합에 사용한 개발 태스크와 선택에 사용하지 않은 홀드아웃 태스크로 스위트를 나눈다([[smollm2]] Table 4; [[olmo-2]] Table 9). OLMo 3에서는 RULER와 태스크가 겹치지만 HELMET을 보지 않은 스위트로 유지했다([[olmo-3]] §3.6).
- 사용 지표의 프록시-목표 순위 상관과 자연·층화 혼합 대비 목표 규모 비교를 보고한다([[olmix]] Figure 3; [[aioli-data-mixing]] Table 2).
- 긴 컨텍스트 단계에서는 짧은 컨텍스트 회귀 게이트와 SFT 후 긴 컨텍스트 태스크를 사용한다([[llama-3]] §3.4.2; [[prolong]] §2.2).

| 최적화에서 도메인 공급량 무시 | 작은 도메인에 4~5 epoch 초과를 요구하는 가중치가 제안됨 | 모든 행에서 `e_i = p_i R / N_i`를 계산하고 optimizer에 `p_i ≤ k N_i / R`를 추가한다 |
| 의사결정에 1M 파라미터 프록시 사용 | 1B 점검 실행과 순위가 다름 | 프록시-목표 Spearman ρ를 측정한다. Olmix는 1M에서 0.73을 얻었다 |
| 하나의 검증 도메인 또는 벤치마크 최적화 | 목표 점수는 오르지만 다른 태스크는 하락 | 태스크별 모델을 맞추고 비대상 태스크와 홀드아웃 스위트를 보고한다 |
| 낮은 perplexity를 더 좋은 다운스트림으로 취급 | perplexity 최선 혼합의 태스크 평균이 더 낮음 | 둘 다 보고한다. Aioli App. F.1은 반상관을 보였다 |
| 긴 문서를 전체적으로 업샘플 | 책·코드 비율이 오르고 웹 짧은 컨텍스트 손실이 증가 | 업샘플 전후 도메인 비율과 0~4K 도메인별 손실을 비교한다 |
| 홀드아웃 점검 없이 annealing 데이터에 벤치마크 학습 세트 포함 | 해당 벤치마크만 크게 상승 | 학습 세트를 제거하거나 같은 도메인의 홀드아웃 스위트와 비교한다 |
| 토큰·단위·단계를 적지 않고 단계 혼합 보고 | 혼합을 재현할 수 없고 토큰 비율과 예시 비율이 혼동됨 | 행마다 `R`, `N_i`, 비율 단위, 단계, 모델 크기를 기록한다 |

## 이해도 확인

1. DoReMi는 미니배치를 균등하게 샘플링하고 손실에 `α`를 적용하지만 최종 모델은 `ᾱ`에서 재샘플링한 데이터로 학습한다. 저자 설명을 사용해 1B 프록시가 22개 도메인 모두에서 기준선보다 나빴는데도 그 가중치가 1B 주 모델을 빠르게 만든 이유를 설명하라.
2. 계산 예에서 clipping은 도메인 B의 초과 손실을 −0.10에서 0.10으로 올렸다. clipping이 목표를 어떻게 바꾸며 Group DRO에 음이 아닌 손실이 필요한 이유를 설명하라.
3. Pile-CC는 280M에서 DoReMi 가중치 0.6057을 받았지만 1B에서는 0.1199였고, OpenWebText2는 반대였다. 두 결과가 최악 그룹 목표와 일치할 수 있는 이유와 70B에서 어떤 가중치를 사용할지 결정할 실험을 설명하라.
4. RegMix는 1M 프록시→1B 대상에서 ρ = 97.12, Olmix는 1M 프록시에서 0.73을 보고했다. RegMix 구현 각주를 포함해 불일치를 만들 수 있는 설정 차이 두 가지를 제시하라.
5. Aioli는 낮은 테스트 perplexity가 더 나쁜 다운스트림 평균을 예측한다고 했다. 그룹별 평균 perplexity를 최소화하는 혼합 방법이 모델 능력을 좁힐 수 있는 방식을 설명하라.
6. Llama 3은 8B에서 GSM8K 학습 데이터 annealing으로 24.0% 이득, 405B에서 거의 이득 없음을 얻었다. 이 결과가 수학 데이터 품질보다 일반성 측정에 관한 근거인 이유를 설명하라.
7. Fu et al. Table 5와 소스별 계산 예를 사용해 전체 길이 업샘플이 짧은 웹 손실을 높였지만 소스별 업샘플은 그렇지 않은 이유를 설명하라. ProLong이 Llama-3-8B에서 Fu 혼합의 짧은 컨텍스트 비용을 여전히 찾은 이유도 설명하라.
8. OLMo 3의 수학-코드-thinking 중간 학습 혼합은 Math를 57.3→60.8으로 높였지만 MC Non-STEM을 77.4→69.6으로 낮췄다. 최종 혼합을 찾았을 혼합 탐색 목표와 일반화를 보일 홀드아웃 근거를 제안하라.
