# Excerpt: SWE-RL — rule-based reward RL on GitHub PR data

**Authors:** Yuxiang Wei, Olivier Duchenne, Jade Copet, Quentin Carbonneaux, Lingming Zhang, Daniel Fried, et al. (Meta AI; UIUC; CMU). arXiv v1 2025-02, v2 2025-12-01; NeurIPS 2025.

## Data (§2, App. A)
- GitHub events from GHArchive, Jan 1 2015 to Aug 31 2024; 4.6M repositories cloned; 24M aggregated PR instances.
- All repositories used by SWE-bench are excluded to prevent contamination.
- Relevant but unmodified files are predicted with Llama-3.1-70B-Instruct and added to the context, because training on changed files only taught the model to edit every file shown.
- Filters: bot PRs (keywords "[bot]", "dependabot", "renovate", "bump", "automerge"), empty or extremely large changes, CodeLlama hunk-level filters. Result: about 11M unique PR instances.
- RL seeds: 273k PRs with at least one linked issue, a bug-fix request, and changes to programming files.

## Task and reward (§2.1, Fig. 2, Eq. 1–2)
- Single-turn: given the issue and the full content of the code context, produce `<think>` reasoning and search/replace edits in `<solution>`.
- R(o) = −1 if the response has a wrong format; otherwise `difflib.SequenceMatcher` similarity between the predicted and oracle patch, in [0, 1].
- GRPO objective with clipped ratio, KL penalty β·D_KL(π_θ ‖ π_ref), and group-normalized advantage Aᵢ = (rᵢ − mean(r)) / std(r). ε and β values are not reported.

## Settings (§3.1)
- Base: Llama-3.3-70B-Instruct. 1,600 steps, 16k context window, global batch 512 = 32 problems × 16 rollouts, one Adam optimization step per global step, 512 H100 GPUs, about 32 wall-clock hours.
- Learning rate: not reported (checked §2–3, App. A–D).
- Scaffold for evaluation: Agentless Mini (file-level localization, repair on full files, generated reproduction tests, regression tests, reranking); main evaluation samples 500 patches at temperature 1.0 and uses 30 reproduction tests.
- SFT baseline Llama3-SWE-SFT-70B: synthetic localization and editing data generated by Llama-3.3-70B-Instruct from the same PR seeds, filtered by the oracle, mixed with Llama 3 coding and general SFT data; 16k context, 2B tokens (App. C).

## Results
- SWE-bench Verified (Table 1): Llama3-SWE-RL-70B 41.0; Llama3-SWE-SFT-70B 36.2; SWE-Gym-32B 32.0; SWE-Fixer-72B 32.8; Lingma-SWE-GPT-72B 28.8; GPT-4o with Agentless 38.8.
- Repair with oracle files, greedy (Table 2): correct format / repair — base 12.2% / 5.4; base majority-of-20 44.6% / 16.6; SFT 96.2% / 29.6; RL 95.6% / 34.8.
- Scaling (Fig. 4): 20 → 160 repair samples 33.6 → 40.0; 500 samples 41.0.
- Reward ablation (§3.6, Fig. 5): exact-match 0/1 reward 94.2% format / 29.0 repair vs continuous 95.6% / 34.8; the discrete reward's average stayed near zero.

## Out-of-domain (Table 3; zero-shot greedy)
| Benchmark | Llama-3.3-70B-Instruct | SWE-SFT-70B | SWE-RL-70B |
|---|---|---|---|
| HumanEval+ | 76.2 | 73.2 | 79.9 |
| BigCodeBench-Hard (I) | 28.4 | 25.7 | 28.4 |
| BigCodeBench-Hard (C) | 29.1 | 24.3 | 29.1 |
| CRUXEval-I | 60.5 | 68.4 | 71.6 |
| CRUXEval-O | 61.9 | 75.1 | 75.5 |
| MATH (strict) | 63.2 | 54.0 | 73.7 |
| MATH (lenient) | 70.9 | 71.7 | 73.7 |
| MMLU | 86.49 | 85.26 | 86.82 |

- Authors: the SFT version "on average, underperforms relative to the original model"; RL "enables the model to generalize its reasoning capabilities across various domains" (Interpretation, §3.5).
- Significance (§3.5): via Eval Arena, gains > 0.8 on MMLU, 3 on CRUXEval, > 3 on MATH are individually significant; taken together significant at 0.05.
- BBH is not evaluated.
