# Excerpt: Kimi K2 — agentic data at pretraining scale

**Source library:** `wiki/raw-data/llm-training/papers/kimi-k2-agentic-data.md`
**Paper:** Kimi Team (Moonshot AI), 2025, "Kimi K2: Open Agentic Intelligence."

---

## Why this source anchors ch-27 §4

Ch-27 §4's contentious claim — "agentic behavior is best installed during pretraining, not bolted on post hoc" — is Moonshot's claim, not a consensus position. This excerpt documents the specific evidence and the specific methodology from the K2 report.

## The pretraining-mix claim

From the source (lines 7-8):

> - **Core Insight:** Kimi K2's agentic capabilities are driven by a trillion-token synthetic agentic pretraining mix (not just SFT) containing planning, tool use, and long-horizon workflow demonstrations — Moonshot argues agentic behavior is best installed *during* pretraining by mixing synthetic agent rollouts with regular text, then polished with SFT+RL, rather than bolted on post hoc.
> - **Guideline:** For frontier agentic models, don't treat agent SFT as a purely post-training step; inject synthetic agent trajectories (tool use, multi-step planning, sub-agent orchestration) into the pretraining mix at ~1–5% weight so the base model naturally emits agent-format tokens.

The ~1–5% weight is the operational number. The underlying hypothesis is that the base model's "next token" distribution includes tool-call tokens natively, so post-training isn't fighting the base.

This is testable in principle — you could A/B test a model trained with vs without agentic-pretrain mix and measure SFT convergence speed and final quality. Moonshot's report claims the A/B but doesn't publish the ablation; you take their word or you don't.

## The synthetic simulator

From the source (lines 27-29):

> - **Simulated tool set:** tens of thousands of synthetic tool schemas (web search, file ops, code execution, database, calendar, custom enterprise APIs).
> - **Simulated environments:** generated by prompting a larger teacher (Kimi's internal pretrained model in a feedback loop, plus GPT-4/Claude) to produce realistic tool response shapes.

Two components: schemas (cheap — they're just JSON) and response shapes (expensive — they require a strong teacher to produce plausible values). At 20K+ schemas × many responses per schema, the data production itself is a multi-million-dollar operation.

## The multi-agent simulation

From the source (lines 30-31):

> - **Trajectory generation:**
>   - Multi-agent simulation: a "user" agent issues queries; a "planner" agent decomposes; an "executor" agent emits tool calls; a "critic" agent reviews.
>   - Sub-agent orchestration — up to 5 sub-agents per trajectory, each with distinct role.

Four named roles (user, planner, executor, critic) plus headroom for a fifth. Compare to Lumos (Plan/Ground/Execute, 3 roles), AutoAct (Plan/Tool/Reflect, 3 roles), AgentInstruct's suggester/editor/generator. **Role specialization is the recurring pattern across 2023-2025 literature**, and Kimi-K2 is its pretraining-scale expression.

## The critic-LLM filter

From the source (lines 32-34):

> - **Filtering:**
>   - Critic LLM rates task success, coherence, tool-call validity.
>   - Only top-scoring trajectories enter the pretraining mix.

Critic filtering is where the gameability risk lives. A self-critiquing loop can drift — the critic shares biases with the generator. Moonshot mitigates by using *different* model families (Moonshot internal + GPT-4 + Claude) for different stages, but the report is opaque about the exact mixing.

## The joint RL stage

From the source `kimi-k2.md` (lines 42-46):

> Kimi K2 runs a joint RL stage that combines two reward streams:
> 1. **RLVR (verifiable rewards)** — for tasks with checkable outcomes (math, code, tool-call correctness).
> 2. **Self-critique rubric reward** — the model produces both (a) a rubric appropriate for the task and (b) its own completion, then scores completions against the rubric. This extends alignment to open-ended tasks where no automated verifier exists.

The self-critique rubric reward is the alignment-side contribution. The model *generates* the rubric, so there's no external rubric to calibrate against — it's the descendant of Constitutional AI's self-rating idea, scaled to 1T-MoE.

Joint RL combines the two streams into a single scalar. One RL stage trains both skill slices — that's the efficiency argument.

## The benchmark numbers

From the source (lines 52-55):

> - K2-Instruct SWE-Bench Verified: ~65% (2025-era top open model).
> - τ-bench: K2-Instruct leads open models, competitive with Claude-3.5-Sonnet.
> - Tool-calling BFCL: strong multi-turn scores.

~65% SWE-Bench Verified. Compare to SWE-RL 70B at 41.0% and SWE-Gym 32B at 32.0%. K2 at 1T-MoE with agentic pretraining + SFT + joint RL is ~1.5× better than the strongest pure-post-training recipes. The ablation you'd want (K2 *without* agentic pretrain, everything else equal) is not published.

## Synthetic-env mismatch — the one caveat

From the source (line 58):

> - **Synthetic-env mismatch:** simulator-generated tool responses may not perfectly reflect real-world API failure modes.

The simulator emits plausible responses but doesn't emit `429 rate limited`, `500 upstream timeout`, stale caches. Real APIs do. K2 mitigates by mixing real-env trajectories (τ-bench, SWE-Bench-style tasks) into SFT, but the pretraining mix is simulator-dominated.

## What to take from Kimi-K2 for ch-27

1. **Pretraining injection at 1–5% weight.** The magnitude matters — 0.1% is probably too small to matter; 10% dilutes pretraining.
2. **Role specialization scales.** 4-5 sub-agents per trajectory, same pattern as Lumos/AutoAct/AgentInstruct.
3. **Critic filtering needs multi-model diversity.** A single self-critic drifts; multiple model families mitigate.
4. **Joint RL (RLVR + rubric) combines two skill slices.** One stage, two reward streams.
5. **Synthetic envs miss real failure modes.** Mix real-env trajectories into SFT to patch.
