Chapter 6 — The Attention Kernel Zoo · Activation memory vs. sequence length

Per-layer attention activation memory (GiB, log axis) against sequence length (tokens, log axis). The naive/MATH backend materializes the full N×N score matrix → O(N²). FlashAttention / xFormers memory_efficient_attention / cuDNN stream it → O(N). SageAttention is also O(N) but stores the QKᵀ path in INT8 (~half the bytes). Ring Attention / CP exact yes O(L/D) per device — blockwise, D ring rounds multi-device ring (NVLink/IB); Megatron --context-parallel-size
PagedAttention n/a (serving KV mgmt) no paged KV cache — ≤4% fragmentation (vs 60–80% waste) inference serving only; grows across decode steps (no training analog)

Model. The plotted naive curve is the dominant O(N²) term batch × heads × N² × bytes (the score-matrix activation, per layer). The O(N) curve is the retained working set batch × heads × N × head_dim × bytes + logsumexp — what FlashAttention keeps after discarding the N×N matrix (read.md §2 pins this at ~200 MB where the same-config N×N matrix is ~40× larger). SageAttention stores the QKᵀ path in INT8 (1 B) rather than bf16 (2 B), so it tracks the O(N) family at ~half the bytes on that path. The int8 dtype toggle halves the per-element bytes (2 B→1 B) for every curve — it rescales the whole plot and moves the O(N²) crossovers right by ~√2× in N. Ring Attention / CP and PagedAttention are in the table but not plotted: Ring is O(L/D)-per-device (a horizontal shift by device count, not a curve shape), and Paged manages a serving KV cache that does not exist during training.
