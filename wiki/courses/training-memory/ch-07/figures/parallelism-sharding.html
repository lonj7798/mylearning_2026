Parallelism Taxonomy — Per-GPU Sharding

Turn each axis and watch what it divides on a single GPU. Every primitive shards exactly one item: ZeRO the optimizer/grad/weights, TP weights+activations, PP weights, EP experts, CP activations. Identity: world_size = TP×PP×CP×DP. ch-07 · read.md

Controls

ZeRO shards weights/grads/opt across these DP ranks (the sharding denominator). Also the divisor for EP.
Splits weight matrices & linear-op activations by 1/TP. Needs NVLink; TP ≤ 8 = one node. TP>8 crosses the node → slow inter-node AllReduce on the critical path.
Each stage holds 1/PP of the layers → weights & their grads/opt divide by PP. Activations: only the local stage (1F1B caps in-flight at PP microbatches).
Context parallel shards the sequence across CP ranks (Ring attention) → activations divide by 1/CP. Orthogonal to TP.
MoE only. Places E/EP experts per GPU → expert weights divide by 1/EP. Must satisfy EP ≤ DP.
Dense model has no experts — EP is inactive.
Activations grow with seq (attention term ≈ s²). Micro-batch b = 1. Gradient checkpointing is off here.
Both 40 & 80 GiB lines are drawn; this picks the OOM threshold. NVLink node = 8 GPUs @ ~0.9 TB/s (A100) / 0.45 TB/s inter-node.

Ledger (bf16 + AdamW, the 16-Ψ decomposition from read.md §3): weights = 2 B/param, gradients = 2 B/param, optimizer = 12 B/param (fp32 master + m + v). Sharding denominators (each axis divides only what it owns): ZeRO-1 opt÷DP; ZeRO-2 +grad÷DP; ZeRO-3 +weights÷DP; TP weights & activations÷TP; PP weights÷PP; EP expert-weights÷EP; CP activations÷CP. For the MoE model, weights split into dense (attention/embedding/router — sharded by DP·TP·PP) and expert FFN (sharded by EP·PP). EP ≤ DP is enforced. Activations use the illustrative form L·b·h·(34 + 5·a·s/h)·s then ÷(TP·CP); teaching-scale, not a specific run. Values in GiB; bandwidth reference: A100 ≈ 2.0 TB/s HBM, NVLink ≈ 0.9 TB/s intra-node.
