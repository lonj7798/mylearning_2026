3 · step multiplier: 이 stage vs SGD

현재 stage SGD (= |gt|) 기준선 1.0
scale invariance. SGD의 multiplier는 곧 |g| — gradient가 100배 작으면 step도 100배 작다. Adam은 m̂/√v̂가 무차원(dimensionless)이라 gradient 크기와 무관하게 ≈ 1.0에 붙는다. "미세" preset으로 확인해봐.

5 · 공식 → ledger 매핑 (bf16 mixed precision, 1 step)

# parameter tensor 하나 기준. 오른쪽은 ch-01 ledger의 어느 줄인지.
g_bf16 = backward()                      → item 2  gradients   2 B/param (transient)
g      = g_bf16.float()                  → fp32 임시 버퍼

m  = β₁*m + (1-β₁)*g                 → item 3a first moment  4 B/param (persistent)
v  = β₂*v + (1-β₂)*g*g               → item 3b second moment 4 B/param (persistent)

m̂  = m / (1 - β₁**t)                 → 0 B — t는 scalar
v̂  = v / (1 - β₂**t)                 → 0 B — t는 scalar

w32 -= η * ( m̂/(√v̂ + ε) + λ*w32 )   → item 3c fp32 master   4 B/param (precision 소유)
                                              λ*w32 는 0 B — w32를 재사용
w_bf16 = w32.to(bf16)                 → item 1  weights     2 B/param (persistent)
g_bf16 = None  # zero_grad              → gradient 해제
돈을 내는 건 EMA 두 줄뿐이다. bias correction(1-β^t)과 decoupled decay (λ·w)는 공식은 늘렸지만 0 B다 — 각각 scalar와 이미 있는 weight만 쓰니까. "state를 새로 들고 있느냐"가 memory를 가르는 유일한 기준이야.

그래서 optimizer 고유 비용은 m + v = 8 B/param이고, 나머지 4 B(master)는 mixed precision의 청구서다. 순수 fp32였다면 master = weight 그 자체라 별도 줄이 없다 → 4+4+4+4 = 16 B/param, bf16 mixed의 2+2+12 = 16과 같은 총액. Rule of 16(§2)은 precision이 아니라 optimizer가 만드는 바닥이라는 뜻.
