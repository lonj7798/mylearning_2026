Multi-head + RoPE — head를 나누는 것과 위치를 넣는 것

ch-extra companion · 왼쪽 절반은 head를 h개로 쪼개도 parameter와 FLOP은 그대로인데 memory만 h배가 되는 이유, 오른쪽 절반은 attention이 순서를 전혀 모른다는 사실과 RoPE가 그걸 고치는 방식. 모든 숫자는 d_model = 8짜리 장난감에서 실제로 계산된다 — 손으로 검산할 수 있게.

Part A · Multi-head attention — 쪼개고, 각자 보고, 붙이고, 섞는다

A0 · 장난감 설정 — 문장 4개 token, d_model = 8, head 2개

N = 4 tokensd_model = 8h = 2 d_head = 8/2 = 4√d_head = 2causal mask 없음
이 그림에서 WQ, WK, WV는 학습된 값이 아니라 내가 손으로 고른 값이다 (illustrative). 실제 모델에서 어떤 head가 무슨 일을 하는지는 학습 결과를 측정해야 알 수 있고, 대부분의 head는 이렇게 깔끔하게 해석되지 않는다. 여기서 손으로 심은 이유는 딱 하나 — "head마다 attention pattern이 달라질 수 있다"는 구조적 사실을 눈으로 보여주기 위해서다. pattern 자체는 지어낸 것이지만, 그 pattern으로부터 나오는 모든 산술(softmax, P·V, concat, WO)은 전부 진짜다.

참고: 이 장난감엔 causal mask가 없어서 head가 뒤쪽 token을 볼 수도 있다 (아래 head 1에서 "loudly → ran"이 그렇다). encoder나 bidirectional attention에서는 정상이고, decoder-only LM이라면 mask가 그 절반을 -inf로 지운다 — [[causal-mask-neg-inf]].

A2 · 같은 문장, 두 head, 완전히 다른 pattern

head가 하나뿐이라면? 한 position당 softmax 가중평균이 딱 하나다. 즉 "직전 token을 본다"와 "동사가 주어를 본다"를 동시에 표현할 수 없고, 억지로 하나의 분포에 섞으면 둘 다 흐려진다. Vaswani §3.2.2 원문이 그 얘기다: "Multi-head attention allows the model to jointly attend to information from different representation subspaces at different positions. With a single attention head, averaging inhibits this."

A3 · 정산 — parameter는 h에 불변, FLOP도 불변, 그런데 memory는 h에 비례

왜 h가 정확히 소거되는가. QKT 비용은 head 하나당 2·N²·d_head이고 head가 h개니까 2·N²·h·d_head = 2·N²·d_model — h가 곱해졌다가 d_head에서 나눠지며 완전히 사라진다. parameter도 같은 논리: WQ는 head 개수와 무관하게 (d_model × d_model) 한 장이고, "head를 나눈다"는 건 그 한 장의 column을 h등분해서 본다는 뜻일 뿐이다 (view + transpose, 복사 없음).

그런데 score tensor는 [B, h, N, N]이다. N² 판이 head마다 하나씩 생기므로 저장 byte는 h에 정확히 선형으로 늘어난다. 같은 FLOP에 memory만 두 배 — element당 산술 강도가 2·d_head FLOPs (bf16이면 byte당 d_head FLOPs)라서, h를 두 배로 하면 d_head가 반이 되고 강도도 반이 된다.

이 a가 바로 ch-03의 그 a다. Korthikanti 공식 34·s·b·h + 5·a·s²·b에서 s² 항에만 붙어 있는 head 수. reference config(s=4096, h=4096, a=32)에서 5as/h = 5·32·4096/4096 = 160 — 즉 s² 항 하나가 나머지 34 sbh 전체의 4.7배다. 둘이 같아지는 지점은 s = 34h/(5a) = 34·4096/(5·32) = 870.4 tokens. 상대거리 Δ = m − n

이 값만 바뀌면 아래 내적이 바뀐다
⟨Rmq, Rnk⟩
—

회전 없는 원래 내적 q·k
—
Δ = 0 일 때의 값과 정확히 같다
Δ 에 대한 내적 곡선 (m, n 각각과는 무관) 현재 (m, n) Δ = 0 → 회전 없는 q·k

pair별 분해 — 왜 절대 위치가 사라지는가

같은 Δ, 다른 (m, n) — 내적이 전부 같은지 직접 확인

왜 이렇게 되는가 — 두 줄 유도. 회전 행렬은 orthogonal이라 RmT = R−m이고, 각도는 더해지므로 R−mRn = Rn−m이다. 따라서
(Rmq)T(Rnk) = qTRmTRnk = qTRn−mk
— m과 n이 각각 사라지고 n − m 만 남는다. 위 표의 pair별 닫힌 형태 (q2ik2i + q2i+1k2i+1)·cos(Δθi) + (q2ik2i+1 − q2i+1k2i)·sin(Δθi)가 같은 얘기를 성분으로 쓴 것 — cos에는 pair의 내적, sin에는 pair의 외적(2D 행렬식)이 붙는다.

유일성. ① 내적이 m−n에만 의존할 것 ② f(x, 0) = x ③ 크기 보존 — 이 세 조건을 동시에 만족하는 f는 f(q, m) = q·eimθ 하나뿐이다. 극형식 f = R·eiΘ로 두면 ②가 R을 |q|로 고정하고(위치는 돌릴 수만 있고 늘릴 수는 없다), ①이 위상을 Θ(q) + mθ라는 선형 형태로 강제한다. [[rope-rotary-position-embedding]]
memory 관점에서 왜 RoPE가 공짜인가. 회전은 attention kernel 바깥에서 Q와 K에 적용된다. FlashAttention/SDPA 입장에서는 그냥 평범한 (Q, K, V) 삼총사가 들어올 뿐이라 O(T) activation 계약이 그대로 유지된다. 반면 ALiBi·T5 RPE처럼 logit에 더하는 방식은 [B, H, T, T] bias tensor를 실체화해야 한다 — B=1, H=32, T=8192, bf16이면 4.000 GiB / layer, A100-40GB의 10%다. RoPE가 쓰는 건 cos/sin 캐시 [L, d_head/2] 두 장뿐 (fp32, L=8192, d_head=128 → 4.00 MiB, 전 layer 공유, trainable parameter 0, gradient 0, optimizer state 0).

가장 느린 pair의 파장은 54,410.1 position이다 — 62,832이 아니다. 2π×10000 = 62,831.85는 지수가 정확히 1.0일 때의 값인데, 실제로 도달하는 최대 지수는 (d−2)/d = 126/128 = 0.9844 뿐이다. 흔한 오기라서 못 박아 둔다.

B5 · 그래서 long context에서 무슨 일이 벌어지나

학습에서 본 적 없는 각도로 extrapolate 된다. 위 표의 마지막 열 ri = L·θi/2π 는 "학습 길이 동안 그 pair가 몇 바퀴 돌았나"다. d_head=128, L=8192에서 i ≥ 50인 pair는 r < 1 — 한 바퀴도 못 돌았다. 즉 그 pair가 학습 중 실제로 경험한 각도는 [0, 2π)의 일부 구간뿐인데, context를 32k로 늘리면 곧바로 본 적 없는 각도 영역으로 들어간다. attention score가 그대로 무너지는 이유다.

그래서 보간(interpolation)을 한다. YaRN은 대역별로 다르게 취급한다 — d_head=128, L=8192, α=1, β=32 기준 경계가 i ≈ 25.76과 i ≈ 49.84이라 pair 0–25는 손대지 않고(국소 관계는 이미 잘 배웠으니 건드리면 손해), 26–49는 램프 θ'i = θi(1−γi) + (θi/s)γi, 50–63은 완전히 θi/s로 축소한다. NTK-aware는 더 거칠게 base 자체를 올린다: base' = base·sd/(d−2), d=128에서 지수 1.01587 → s=4면 40,890 · s=8이면 82,685 · s=16이면 167,199 · s=32면 338,097. Llama 3이 base=500000을 쓰는 것도 같은 계열의 조치이고(가장 느린 파장이 54,410 → 2,559,196 position으로 늘어난다), 그래서 "base를 올리는 것"은 거친 형태의 interpolation이라고 부른다.
