1. Protocol Stack

Each layer adds a header to the payload below. When you await websocket.send("hello"), "hello" travels down four layers before leaving your machine.

Application (L7) HTTP / WebSocket / SSH / DNS / gRPC
Transport (L4) TCP · UDP · QUIC
Network (L3) IP (v4/v6) · ICMP
Link (L2) Ethernet · WiFi
Physical (L1) cables · radio waves
boson-agent lives in L7 (WebSocket). Everything below happens in the OS kernel.

2. TCP 3-Way Handshake

Before any data flows, TCP does a three-step handshake to establish a connection. Click Start to animate.

Each arrow is a packet. After three round-trips both sides agree they are connected — now a TCP connection exists between them, with sequence numbers initialized and buffers allocated. Application data can start flowing.

4b. Where is IN and where is OUT — the two independent channels

The key insight: each side has two separate channels — one for sending (OUT) and one for receiving (IN). They operate independently; no lock, no coordination needed. Start the animation to see packets flowing in both channels at the same time.

Press "Start Flow" to see packets move independently in both lanes.
Key observations:
  • Blue lane (top): client's OUT → server's IN. Only the client puts things here.
  • Green lane (bottom): server's OUT → client's IN. Only the server puts things here.
  • The two lanes are physically different channels (different TCP sequence space, different OS send/recv buffers). A packet in one lane cannot interfere with a packet in the other.
  • That is why both sides can write at the same time without any lock, mutex, or turn-taking.

5. WebSocket Frame Structure

Every message sent over a WebSocket is wrapped in a frame. Key fields shown below (simplified).

FIN
1 bit
last fragment?
opcode
4 bits
0x1=text, 0x2=bin, 0x8=close
MASK
1 bit
client→server must be masked
length
7/16/64 bits
payload byte count
Payload
variable length
actual message bytes — boson-agent puts JSON here, e.g. {"type":"text_delta","text":"hi"}
This framing is what lets WebSocket restore message boundaries that raw TCP streams lose. When your code does await ws.recv(), you get exactly one complete frame's payload — no partial reads, no concatenation.
