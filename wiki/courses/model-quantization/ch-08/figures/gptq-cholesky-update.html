What changes vs OBS. OBS in ch-05 touches all remaining columns on every step — that's O(N) memory bandwidth per step, the bottleneck for transformer rows of length 10k+. GPTQ amortizes this: (1) divide columns into blocks of 128; (2) inside a block, do per-column OBS but only update the columns within the block; (3) at the block boundary, apply one dense GEMM that flushes all accumulated corrections to every later block. This is compute-bound (fast GPU GEMM) instead of memory-bound, and reuses the Cholesky factor R once instead of recomputing H⁻¹ per column. percdamp adds δ · mean(diag(H)) to the diagonal — without it, H from a few hundred calibration samples is often singular. act_order=True processes high-importance columns first so their quant error has more remaining columns to absorb it.
