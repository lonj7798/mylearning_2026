SoftCap vs QK-Norm: Attention Logit Stabilization

Gemma 2 bounded outputs; Gemma 3 normalizes inputs

SoftCap (Gemma 2)

Deprecated
SoftCap(x, c) = c * tanh(x / c)
Bounds output to (-c, c)
Applied after QK^T, before softmax
Q, K vectors
unbounded norms
|
QK^T / sqrt(d)
can grow large
|
c * tanh(x/c)
clamp to [-c, c]
|
softmax
bounded input

QK-Norm (Gemma 3)

Current
Q' = RMSNorm(Q), K' = RMSNorm(K)
|q'_i * k'_j| ≤ ||q'|| * ||k'|| = 1
Applied before QK^T computation
Q, K vectors
unbounded norms
|
RMSNorm(Q), RMSNorm(K)
unit RMS norm
|
Q'K'^T / sqrt(d)
naturally bounded
|
softmax
bounded input

SoftCap Drawbacks

x Breaks Flash Attention tiling -- tanh inside the attention loop requires custom kernels
x Compresses gradients for large logits, potentially slowing learning of strong attention patterns
x Adds hyperparameters (c_attn=50, c_final=30) that need per-scale tuning
~ Effective at preventing logit explosion -- the output is strictly bounded

QK-Norm Advantages

+ Fully compatible with Flash Attention -- normalization happens before the attention kernel
+ No additional hyperparameters -- uses the same RMSNorm primitive as the rest of the model
+ Independently validated by OLMo 2 -- cross-org convergence on the same solution
+ Cauchy-Schwarz guarantee: dot products of unit-norm vectors are naturally bounded
