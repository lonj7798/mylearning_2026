Qwen 3: Dual-Mode Architecture

Same weights, different behavior. A runtime flag controls thinking vs. non-thinking mode.

User: "What is the sum of the first 50 prime numbers?"
<think> enabled
Key insight: The Transformer weights are identical in both modes. Mode switching is controlled entirely by special tokens (<think> / </think>) in the prompt prefix. No weight changes, no adapter swaps, no routing — just a token-level signal that triggers different generation behavior.
Post-Training Pipeline (builds dual-mode capability)
S1

Cold Start

Long-CoT SFT

Supervised fine-tuning on curated chain-of-thought examples. Teaches the format of multi-step reasoning — how to decompose, check work, arrive at conclusions. Foundation for thinking mode.

S2

Reasoning RL

GRPO on 3,995 Query-Verifier Pairs

Reinforcement learning with deterministic verification (compilers, math checkers). Remarkably data-efficient — reshapes how 36T tokens of pre-trained knowledge are deployed. RL optimizes strategy, not knowledge.

S3

Mode Fusion

Thinking + Non-Thinking Integration

The critical stage. Model learns to switch behavior based on <think> token presence. Training data includes both modes. Must solve mode confusion: no reasoning traces in non-thinking mode, no skipped reasoning in thinking mode.

S4

General RL

Broad Task Performance Recovery

Final RL pass ensures reasoning-focused stages 1-3 did not degrade performance on non-reasoning tasks: summarization, translation, creative writing, factual Q&A.
