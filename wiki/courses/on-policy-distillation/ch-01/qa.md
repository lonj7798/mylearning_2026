# ch-01 Q&A — Post-Training as Distribution Matching

Clarifying questions raised while reading [[read]]. Kernels only; full reasoning lives in `read.md` / discuss transcript.

---

### Q1 — off-policy면 offline training이랑 뭐가 다른가?

Different axes, not synonyms.

| term | question it answers | opposite |
|------|--------------------|----------|
| **off-policy** | did the *model being trained* generate this data, or something else (teacher / old ckpt / human)? — a *distribution-source* claim | on-policy |
| **offline** | does training draw *fresh* samples, or only a fixed pre-collected dataset? — a *timing/staticness* claim | online |

They combine freely: on-policy+online (PPO, ch-04 OPD) · off-policy+online (DQN replay, stale-student GKD) · off-policy+offline (SFT, Hinton/Kim&Rush KD — ch-02's corner).

They **co-occur in this course** because ch-01 §5's off-policy-KD corner uses a teacher-generated *static* corpus (both at once) — hence the blur. But the consequence ch-01 §2 cares about (compounding error: "the student learns in contexts frequented by the teachers, not ones the student itself will find itself in") flows from the **off-policy** property (distribution mismatch), **not** the offline one (staticness). Regenerating data every step but from the *teacher* is still off-policy → exposure bias remains.

**One line:** offline = "no fresh data (static)"; off-policy = "data not generated by *me*." ch-01 blames exposure bias on the mismatch axis (off-policy), not the static axis. — boson case: seller transcripts are exported to a fixed corpus, so it's *both*; but ch-03's complaint is off-policy ("never graded in states the deployed seller reaches"), not offline. See read.md §2, §7.

### Q2 — "학습 대상 모델의 현재 분포와 데이터 생성 분포가 일치하는가"가 무슨 뜻인가?

Reframe: **a language model IS a probability distribution** `π_θ` over sequences (given a context, it emits a prob vector over next tokens). "Running" it = sampling from `π_θ`.

Training data is also *samples from someone's distribution*: teacher-generated → `π_teacher`; student-generated → `π_student(current)`; human-written → `π_human`. **"Match?"** = is the data-generating distribution the *same* as the model being updated right now?

- on-policy: samples ~ `π_θ` (the student itself) → **match ✓**
- off-policy: samples ~ `π_teacher` / human / old ckpt → **mismatch ✗**

**"Current" matters:** `π_θ` moves every gradient step, so even the student's own stale samples drift off-policy → on-policy is expensive (must resample; root of ch-05 economics).

**Why it's fatal — state-visitation view:** the decisive distribution is *which contexts (states) get visited*, not per-token probs. A flawless teacher rarely visits "customer got annoyed"; a deployed student reaches it constantly and was never graded there → compounding error. This is read.md §2's "contexts frequented by the teachers, not ones the student itself will find itself in." See read.md §2, §5.

### Q3 — off-policy나 on-policy나 결국 둘 다 teacher로 학습시키는 것 아닌가?

Yes — both use a teacher. The difference is **the teacher's *role*, not its presence.** Distillation has two decoupled roles:

| role | job |
|------|-----|
| **actor (generator)** | writes the actual sentences → decides the training data + which *states* get visited |
| **teacher (grader)** | supplies the learning signal (target distribution) on those sentences |

- **off-policy KD:** teacher does **both** — teacher authors the text *and* grades it; student just mimics *teacher-written* text in teacher-visited contexts.
- **on-policy distillation:** **student is the actor**, teacher is **grader only** — student samples its own turns, teacher red-pens each *student-produced* token ("here's how I'd distribute at this spot YOU reached"). **Teacher writes none of the text the student trains on.**

Exam metaphor: off-policy = studying the teacher's *worked solutions*; on-policy = *you* solve it and the teacher marks up *your* answer, correcting the mistakes you actually make in the situations you actually reach.

Not "just copying teacher": the *target* is still the teacher's distribution, but it's evaluated **on the student's own sampled trajectory** — student learns "what would teacher do *here, where I actually landed*," not "replay the teacher's path."

RL completes the triangle (§5): RL = student generates + *sparse scalar* grade (no teacher dist); off-policy KD = teacher generates + dense grade; on-policy distillation = **student generates (like RL) + teacher grades densely (like distillation)**.

**One line:** the on/off-policy split is about *who authors the sentences*, not *whether a teacher is used*. See read.md §2, §5, §6.

### Q4 — on-policy이 O(N) density를 얻는 게 GRPO 같은 건가?

No — **GRPO is the O(1) *sparse* case, not O(N).** The density axis is **orthogonal** to on/off-policy; being on-policy buys nothing on density. GRPO is the counterexample: on-policy *and* O(1).

| method | data source | density |
|--------|-------------|---------|
| GRPO / PPO (RL) | on-policy | **O(1)** (one scalar reward/rollout) |
| on-policy distillation | on-policy | **O(N)** (full teacher dist / token) |

**Why GRPO stays O(1) despite per-token advantages:** it broadcasts *one scalar reward* across all N tokens; every token's advantage is a function of the same reward → info content ≈ #rewards (≈ G/prompt), **not** N. read.md §3 / TM: "a fixed number of bits per training episode **regardless of the number of tokens used**." Distillation instead emits an *independent full-vocab distribution per position* → genuinely O(N).

**Where the GRPO instinct IS right — the machinery:** OPD typically **reuses the RL rollout loop** (sample from student → per-token advantage → policy gradient). TM frames it as *reward = −KL(student‖teacher) per token* — i.e. GRPO's loop with the **sparse outcome reward swapped for a dense per-token teacher signal**. So "like GRPO" is right about the *loop*, wrong about the *density source*: O(N) comes from the teacher grading every token (distillation half), not from being on-policy. (Basis for ch-06/ch-07 "reuse your RL infra.") See read.md §3, §5.

### Q5 — figure(distribution-cube)는 on-policy distillation 코너를 "on-policy · dense O(N) · reverse KL"로 묶어 적었는데, on-policy가 O(N)을 준다는 뜻 아닌가? (Q4와 모순?)

No contradiction — the figure listing **three separate bullets** *is* the point: they're three independent axes. If on-policy implied dense, "Density: O(N)" wouldn't need its own line. The corner sets all three axes to their good value *at once*; it doesn't claim on-policy *causes* density.

- **GRPO in the same card format:** `Data: on-policy ✓ | Density: SPARSE O(1) ✗ | Geometry: reverse KL` — same on-policy line, density line differs → axes independent. OPD's O(N) is filled by the **Density** line, not the Data line.
- **The name decodes it:** "**on-policy**" = data-source axis (student generates); "**distillation**" = density axis (teacher grades every token → O(N) lives here).
- **The nrehiew quote itself decomposes by source:** "the density *of distillation*, the unbiasedness *of RL*, and the on-policy property *of both*" — density is attributed to distillation, on-policy-ness listed separately. The quote supports Q4, not against it.

**One line:** the figure's 3 bullets = 3 independent axes set well simultaneously, not a causal chain; O(N) ← "distillation" half, on-policy ← "on-policy" half. See read.md §5, [[figures/distribution-cube.html]].

### Q6 — 왜 GRPO는 O(1)이고 on-policy distillation은 O(N)인가 (bit-counting)

"bits/episode" = independent info the update extracts from the grader per rollout (not #tokens touched).

**GRPO → O(1).** N-token completion → **one scalar reward** (group of G → G scalars). The single advantage `A_i` is *broadcast to all N tokens* → external info = O(G), independent of N. Scale N 500→5000: still G scalars. The reward scores the *whole outcome* ("this 500-token answer = 0.3"), never says which token was wrong → credit assignment must be *inferred over many samples* (why RL is sample-inefficient).

**OPD → O(N).** N positions → **N independent teacher distributions** (a full vocab dist per position; position 5's target unrelated to position 500's). Loss = Σ_t KL(π_student(·|prefix_t) ‖ p_teacher(·|prefix_t)). Each token gets a *localized* correction ("at t340 you put 0.6 on X, I'd put 0.05") — no credit-assignment inference. Scale N 500→5000: 10× the signal.

**Deepest why = the SIGNAL SOURCE, not on-policy-ness.** A reward is *inherently* O(1) (scores outcomes: sequence→scalar); a teacher is *inherently* O(N) (opines per token). on/off-policy is orthogonal — being on-policy only means "student generated the trajectory," which places **no** constraint on how densely you grade it. Grade an on-policy trajectory with a scalar → GRPO (O(1)); with a per-token teacher → OPD (O(N)).

**Why GRPO can't "just be dense":** it has no per-token oracle — a reward fn scores outcomes only. If a per-token oracle existed, that *is* a teacher, i.e. distillation, not RL. RL is exactly the tool for the sparse-outcome-signal regime.

**One line:** OPD = GRPO's loop (on-policy sampling + policy gradient) with the sparse reward *replaced* by a per-token teacher −KL; the O(N) comes from that replacement (the grader), not from being on-policy. See read.md §3, §5.

### Q7 — "발산 기하: 순방향 vs 역방향 KL"이 무슨 뜻인가?

KL is **asymmetric**: `D(p‖q) ≠ D(q‖p)`. "Geometry" = *same target, different-shaped optimum depending on which direction you minimize.* Forward = mode-covering; reverse = mode-seeking.

Weighting is the whole story: `D(p‖q)=Σ p·log(p/q)` weights by **p** (target); `D(q‖p)=Σ q·log(q/p)` weights by **q** (student).

**Numeric asymmetry** — target `p=[0.5,0.5,0]` (modes A,B; C forbidden):
- **Forward `D(p‖q)`:** drop a real mode (`q(A)=0`) → `0.5·log(0.5/0)=+∞` **forbidden**; put mass in empty region (`q(C)=0.3`) → `0·log(0/0.3)=0` **free**. ⇒ "cover every mode, spilling into valleys is free" → **mode-covering / zero-avoiding** (spreads, hedges).
- **Reverse `D(q‖p)`:** put mass where `p=0` (`q(C)=0.3`) → `0.3·log(0.3/0)=+∞` **forbidden**; ignore a real mode (`q(B)=0`) → `0·log(0/0.5)=0` **free**. ⇒ "stay on the teacher's support, dropping a mode is free" → **mode-seeking / zero-forcing** (concentrates, commits).

**Post-training tie:** SFT/pretrain minimize forward KL → mode-covering → can smear/forget ("sacrificing previous modes = pre-existing capabilities"). RL & OPD minimize reverse KL → commit to teacher's best modes; MiniLLM's reason = "prevent overestimating the *low-probability regions* of the teacher"; TM's "unhackable" (can't reach forbidden regions, so low KL ⟺ desirable behavior).

**Axis connection (independent but rhyming):** reverse KL = `E_{x~q_θ}[·]` → expectation *over the student* → naturally computed with student samples = on-policy's partner (forward KL = `E_{x~p}` = off-policy-friendly). Still independent: cube corner `0,1,1` (off-policy reverse-KL KD, early MiniLLM) proves reverse KL works on fixed data too.

**One line:** forward = "cover all target mass, spilling is free" (spread/forget-risk); reverse = "never leave target support, dropping a mode is free" (commit/unhackable); geometry = optimum *shape* set by KL direction. See read.md §4, §5, [[gu-minillm-reverse-kd]], [[tm-on-policy-distillation]].

### Q8 — (trap) "reverse KL이 더 빨리 수렴하고, on-policy는 O(N)이라 필수 정보만 배운다"? — 축→이점 귀속 오류

Recurring conflation (cf Q4/Q5): **each benefit of OPD comes from a *different* axis; don't attribute them all to on-policy or to reverse-KL.**

| stated benefit | axis that actually delivers it |
|---|---|
| O(N) dense signal | **Axis 2 density** = the teacher/distillation half — **NOT** on-policy (GRPO = on-policy & O(1)) |
| "learns only relevant info" (graded only in states the student reaches) | **Axis 1 on-policy** ✓ (relevance to visited states) |
| "commit to essential modes, drop low-prob junk" | **Axis 3 reverse-KL** mode-seeking |
| speed / ~10× less compute than RL | **Axis 2 density** (O(N) bits → fewer episodes) — **NOT** reverse-KL geometry |

**"reverse KL converges faster" is backwards at the optimizer level:** forward KL (cross-entropy, `E_{x~p}`, fixed data) is low-variance/stable; reverse KL (`E_{x~q_θ}`, expectation over the *student*) needs policy-gradient/REINFORCE → **higher variance + mode-collapse risk** (ch-04). What reverse KL genuinely buys = solution *shape*: a more *achievable* target for a small student (commit to one mode < cover all) + no-forgetting + unhackable — not a faster optimizer. The *speed* is a density effect.

**One line:** OPD's three wins map to three axes — speed/efficiency ← density(teacher), exposure-bias-fix + relevance ← on-policy(student generates), commit/no-forget/unhackable ← reverse-KL. "on-policy ⇒ O(N)" and "reverse-KL ⇒ fast" are both axis-confusions. See read.md §3, §4, §5.

### Q9 — 애초에 KL이 뭔가? (step-by-step foundation)

Built bottom-up (full worked arithmetic in discuss transcript / above):

1. **surprise** of one event = `−log p` (bits if log₂). rare→big, certain→0. (coin 0.5 → 1 bit; 1/1000 → ~10 bits)
2. **entropy** `H(p)=Σ p·(−log p)` = average surprise if reality = p (irreducible minimum).
3. **cross-entropy** `H(p,q)=Σ p·(−log q)` = average surprise when reality = p but you *believe* q (weighted by p, surprised by q).
4. **KL** `= H(p,q) − H(p) = Σ p·log(p/q)` = **extra bits/event wasted by modeling true-p with belief-q.** `≥0`, `=0` iff q=p.

**Worked:** p={.5,.5}, q={.9,.1} → KL(p‖q)=0.5·log₂(.5/.9)+0.5·log₂(.5/.1)=−0.42+1.16=**0.74 bit**. Reverse KL(q‖p)=0.9·log₂(1.8)+0.1·log₂(.2)=0.76−0.23=**0.53 bit** → **0.74≠0.53 = asymmetric** (why "which direction" matters).

**The one rule:** `KL(A‖B)=Σ A·log(A/B)` — the **first argument A weights the sum** → you care about errors where A has mass. forward `KL(p‖q)`: p-weighted → penalized where teacher has mass, ∞ if q=0 there → **cover** all modes (mode-covering). reverse `KL(q‖p)`: q-weighted → ∞ if student puts mass where p=0 → **stay on teacher's support**, dropping a mode is free → **mode-seeking**.

**One line:** KL = extra surprise (bits) from believing q when reality is p; asymmetric; first arg picks which region you weight → forward covers, reverse seeks.
