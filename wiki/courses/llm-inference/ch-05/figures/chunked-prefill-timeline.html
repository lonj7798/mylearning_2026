What you should notice. Panel (a) is the baseline: 8 decode tokens per tick, steady throughput. Panel (b) shows the cliff: one 2000-token prompt arrives, the engine spends 4+ ticks doing prefill exclusively, and the 8 in-flight decodes go red — they wait. That's a 4-tick TPOT spike per request × 8 requests = 32 lost decode-token slots. Panel (c) keeps the same compute budget per tick but slices the prefill into chunks; each tick packs (8 decode + 1 chunk). TTFT for the new request rises slightly (it still needs all chunks), but in-flight TPOT degradation drops to ≤ 1 tick. Chunked prefill trades a tiny TTFT increase for a much smaller TPOT impact on in-flight decodes — chunk size is the knob.
