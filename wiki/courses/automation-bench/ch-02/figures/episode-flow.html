① Dataset Task row: prompt + info
Each HuggingFace row carries a trigger prompt and an info dict with three fields: initial_state, zapier_tools, and assertions. HuggingFace normalizes schemas across rows by padding missing keys with None; strip_none_values() removes them before Pydantic sees the dict.
prompt: trigger message info.initial_state: {} info.zapier_tools: [...] info.assertions: [...]
② setup_state Build WorldState + filter tools
Called once per episode. Constructs WorldState(**initial_state_dict) with extra="forbid" — any unknown key raises immediately. Deep-copies initial_state as a baseline for free-assertion detection. Narrows state["tool_defs"] to the per-task allowed set (see toolset modes below). Validates unknown tool names loudly.
WorldState — 44 app sub-states (extra="forbid")
Each field has a typed sub-model and a default_factory. Tools mutate world.<app>.<collection> in memory — no HTTP, no DB.
Three toolset modes — branch point at this step
zapier
Default mode. Tests both discovery and execution.
search_tools(query, top_k)
execute_tool(tool_name, arguments)
Model must discover then call — joint score
BM25 corpus over ~400 tools. search_tools returns {name, description, parameters} for top-k matches. execute_tool dispatches through the full registry. After a call to execute_tool, previous-turn search results are compressed to [Previously found: ...] by _compress_meta_messages to save context tokens. When the paper says "two tools" it means this mode.
limited_zapier
Named tools filtered per task. No discovery step.
~N named functions
(from info.zapier_tools)
Isolates execution from discovery
All ~400 tools are registered at env construction. setup_state filters to exactly those in info.zapier_tools. Model sees named functions with full typed schemas — no BM25 search required. zapier score − limited_zapier score ≈ cost of discovery.
api
REST-shaped interface. Tests HTTP reasoning.
api_search(query)
api_fetch(method, url, …)
base64_encode(data)
Ablates abstraction style
api_search runs BM25 over a tab-separated endpoint index. api_fetch routes the URL via _url_to_internal_path() to the correct in-process world mutation. ~15 known model URL hallucinations are normalized so a typo isn't scored as task failure. Tests: can the model reason about HTTP methods, URL structure, and request/response shapes?
world injection: Tools declare world: WorldState in Python but tool_wrapper.py strips it from the JSON schema via args_to_skip. update_tool_args re-injects state["world"] (by reference) at dispatch time — mutations are immediately visible to subsequent tool calls.
③ Agent Loop Tool-calling turns (max_turns = 25)
vf.StatefulToolEnv drives the loop. On each turn the model receives the full message history and state["tool_defs"]. The loop terminates on a no-tool-call response or when max_turns is reached. Note: the system prompt says "50 turns" — that is a soft hint. max_turns=25 is the hard guard.

④ Rubric Grade Evaluate assertions against final world state
After the loop terminates, the rubric reads state["world"] (the final mutated state) and state["initial_state"] (the deep-copied baseline from setup_state). Partial credit: a task with 5 assertions where 3 pass → score 0.6. The baseline copy enables detection of free assertions — assertions already satisfied before the agent did anything, a potential reward-hacking vector that is excluded from scoring.
reward ∈ [0.0, 1.0] partial credit supported free-assertion exclusion per-assertion results → _assertion_results
⑤ export_results JSON output for the visualizer
export_results(outputs, usage, model, domains, output_path, ...) collects per-task scores, per-assertion results, full message histories, token counts, and cost data. Token counts prefer state["_usage"] (accumulated per-turn) over a fallback character-count estimate. benchmark_version is read from pyproject.toml — single source of truth.
meta: model, toolset, domains, version summary: avg_score, pass_rate, total_cost tasks[]: score, messages, assertion_results usage_by_task[]: tokens, cost
